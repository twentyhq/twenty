# Gelios — создание тренировок из временной сетки

14 октября 2026. Реализовано локально, без deploy/apply и без изменения реальных записей CRM.

## Пользовательский сценарий

Календарь недели содержит сетку 07:00–23:00 с шагом 30 минут, время Europe/Moscow. Нажатие ячейки открывает форму с выбранными датой/временем; кнопка «Новая тренировка» позволяет задать любое время, включая вне сетки. Уже существующий блок открывает карточку, а не новое занятие.

Форма: название, один из семи канонических форматов CRM, дата/начало, длительность 1–1440 минут, вместимость 1–100. Данные можно изменять до отправки. Подпись действия и пояснение меняются по времени:

| Интервал | Действие / статус |
| --- | --- |
| Начало в будущем | Запланировать / PLANNED |
| Началось, но ещё не закончилось | Сохранить текущую / CONFIRMED |
| Полностью закончилось | Внести прошедшую / COMPLETED, обязательный checkbox «состоялась» |

Создание сохраняет только classSession и SESSION_CREATED. Не создаёт клиентов, бронирований, платежей или операций посещений; bookedCount/attendedCount стартуют с нуля.

Для будущей тренировки участники добавляются отдельной обычной командой бронирования с RESERVE. Для завершённой карточка предлагает «Внести фактическое посещение»: форма attendance получает время и ID занятия; выбранный пакет обязан соответствовать его формату/длительности. Перед CONSUME остаётся серверный preview. Текущая CONFIRMED тренировка не отмечается автоматически завершённой по часам; переход статуса после окончания пока выполняется в CRM.

## Отображение

Высота/позиция блока соответствует фактическому интервалу, не числу занятий в списке. Пересечения занимают отдельные полосы. Интервалы через границу дня показываются частями в соответствующих днях. Занятия целиком вне 07:00–23:00 доступны отдельными кнопками под сеткой.

На мобильном сетка прокручивается горизонтально и вертикально внутри контейнера. Общее полотно страницы не расширяется. Расстановка через CSSOM совместима с существующей CSP без unsafe-inline.

## Контракт

POST /api/v1/studio/sessions/create (JWT KateFitNotes) → POST /s/studio/sessions/create (Twenty API key). Поля:

- name, sessionFormat, startsAt с часовым поясом;
- durationMinutes, capacity — целые;
- status PLANNED/CONFIRMED/COMPLETED;
- pastConfirmed=true для COMPLETED;
- idempotencyKey.

Новая logic function studio-create-class-session имеет auth required. CRM проверяет формат, диапазоны, часовой пояс и соответствие времени/статуса. Новый metadata объект не нужен: используется существующий classSessions.recordingKey с уникальным индексом.

## Повтор и аудит

Ключ занятия: session-create:<idempotencyKey>. Повтор сверяет название/формат/время/окончание/вместимость; статус исходного запроса хранится в details события. Изменённый запрос с прежним ключом — 409, не редактирование занятия.

Событие SESSION_CREATED имеет id, равный UUID занятия (отдельная таблица событий). Ошибки записи журнала не проглатываются. Повтор восстанавливает событие без второго занятия; существующее событие не создаётся заново.

UI сохраняет тело/ключ незавершённого запроса в sessionStorage, блокирует изменения, предлагает прежний повтор после reload. Проверка времени не запрещает повтор уже созданного будущего занятия, если оно успело перейти в прошлое. Для нового, ещё не созданного занятия устаревший статус отклоняется — оператор должен проверить CRM и пересмотреть время/действие.

## Проверки

- 74 CRM tests; typecheck/lint/format.
- 66 API/settings tests, 3 DB-зависимых пропущены.
- 24 UI tests и JS syntax check.
- Chrome: ячейка → предзаполнение → будущее занятие → потерянный ответ → reload/тот же ключ → одно занятие/событие; высота интервала при CSP; клик по существующему; прошлое требует подтверждения; создание не списывает посещения; mobile.
- Регрессии календарных участников и основного UI проверены отдельно; реальные CRM мутации не выполнялись.

Тест: npm --prefix ui run test:browser:sessions, с Playwright и UI на 127.0.0.1:5184; параметры установки как в предыдущем календарном тесте.

2. Применить katfit-studio на stage.
3. Пересобрать API и UI KateFitNotes.

Операция занятие + event не является общей DB-транзакцией; частичный сбой восстанавливается повтором. Одновременные разные ключи могут создавать разные занятия в одно время: ресурсы/залы/тренеры в этом шаге не вводились, пересечения сами по себе не запрещены.
