# Журнал действий операторского UI Gelios

## Покрытие

Проверяются реализованные бизнес-операции KateFitNotes UI, а не клики, поиск, фильтрация или действия режима Terfit.

| Действие | Обязательное успешное событие |
| --- | --- |
| Добавление клиента | `CLIENT_CREATED`, создаётся API после сохранения контакта |
| Получение оплаты и оформление пакета | `PAYMENT_CONFIRMED`, создаётся командой CRM |
| Создание занятия | `SESSION_CREATED`, создаётся командой CRM |
| Добавление клиента в будущее занятие | `BOOKING_CREATED`, создаётся командой CRM |
| Внесение прошедшего посещения, отдельно или через создание занятия | `BOOKING_CREATED` с названием «Внесено прошедшее посещение» и деталями списания |
| Удаление участника | `BOOKING_CANCELLED`, создаётся командой CRM |

Запись события прошедшего посещения находится в общем `recordPastAttendance`, а не только в календарной обёртке. В событии есть ID клиента, занятия, пакета и транзакции, время посещения, причина и источник. Сам preview не пишет события и не списывает посещения.

Клиент и его событие имеют одинаковый UUID в разных таблицах. При потере ответа на сохранение контакта или события повтор проверяет сохранённого клиента и дописывает недостающее событие. Успех не возвращается до подтверждения события. Другой контакт с прежним UUID и конфликтующая запись журнала не принимаются как успешный повтор.

## Ошибки UI

Все шесть изменяющих API-маршрутов используют `perform_operation`: clients, package-payments/confirm, attendance/record-past, sessions/create, bookings/create, bookings/cancel. После отказа или неподтверждённого ответа API сохраняет `OPERATION_FAILED`, источник `KATEFIT_UI`, логин из проверенного JWT, название операции, ключ, статус/код и связанные ID. Тело запроса, токен и API-ключ не включаются в событие.

Идентификатор ошибки API детерминирован по маршруту и ключу операции: повторный отказ той же операции не создаёт ещё одну API-запись. Сохраняется первый отказ, существующее событие не переписывается. CRM-команда может дополнительно иметь собственное событие отказа: оно относится к исполнению команды, а API-событие — к ответу операторскому UI.

Ответы 5xx/тайм-ауты отмечаются `execution: UNKNOWN`: это не свидетельство отката. Ответы 4xx отмечаются `REJECTED`: команда отклонена или не завершена; частично сохранённые данные также нужно сверять по ключу. Некорректные тела, отклонённые FastAPI до маршрута (422), неавторизованные запросы, preview и чтение не включены в этот бизнес-аудит.

Если CRM недоступна и событие ошибки записать нельзя, API явно возвращает `AUDIT_UNCONFIRMED`, не скрывает проблему журнала и требует проверки/повтора с прежним ключом. Отложенной очереди доставки пока нет; гарантировать запись в недоступную CRM невозможно. Новая ошибка не отменяет уже сохранённые финансовые данные. UI сохраняет незавершённое тело и ключ в sessionStorage; после закрытия вкладки требуется ручная сверка CRM.

Логин оператора добавлен в новые события клиента и ошибок API. Существующие события успешных бронирований/оплат не получили отдельного поля логина UI; контекст API-ключа не подменяется вымышленным пользователем CRM.

## Выпуск и проверка

1. Применить метаданные `studioEvents.eventType` с новой опцией `CLIENT_CREATED` и обновлённые функции katfit-studio, включая исправление оплаты, одним выпуском CRM-приложения.
2. Убедиться, что серверный API-ключ имеет права читать и создавать `studioEvents` через REST. Новый ключ/OAuth не требуется, если действующие права достаточны.
3. Пересобрать KateFitNotes API; изменения UI для этой доработки не нужны.
4. На стейдже проверить создание клиента, оплату, отдельное прошедшее посещение, создание занятия с людьми, добавление и отмену участника, затем отказ по недостаточному остатку и повтор с прежним ключом.
5. Проверять вместе бизнес-записи, транзакции и события. Исторические пропуски автоматически не восстанавливаются; отдельная сверка/backfill не выполнены.

Локальные проверки: `yarn test:unit`, `yarn typecheck`, `yarn lint` в katfit-studio; `uv run pytest tests/test_api.py tests/test_studio_api.py tests/test_studio_records.py tests/test_studio_calendar_api.py tests/test_studio_audit.py -q` в KateFitNotes. Тесты CRM/API используют фейки, живые контакты/финансы не создаются. Проверены отсутствие повторного списания/контакта, восстановление пропущенного события, потерянный ответ журнала, конфликты, отсутствие записи на preview, отказ всех изменяющих маршрутов и явная ошибка при недоступном журнале.
