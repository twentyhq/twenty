# Gelios — основной операторский UI

14 октября 2026. Реализовано локально в KateFitNotes_telegram; staging и production не обновлялись.

## Реализованные сценарии

- Переключатель Terfit / студия Gelios над боковой навигацией. На мобильном — внутри меню. Terfit использует прежние API и данные.
- Обзор CRM: клиенты, активные пакеты, подтверждённые посещения, операции CONSUME, пакеты на исходе.
- Поиск и карточка клиента: контакты и пакеты; добавление имени, фамилии, российского телефона и email. Повтор создания с прежним UUID восстанавливается после потерянного ответа.
- Список пакетов и оформление полученной оплаты: продукт из CRM, цена/количество посещений из продукта, дата, CASH/SBP/CARD, чек. Создание через studio/package-payments/confirm, не прямой CRUD баланса.
- Внесение прошедшей тренировки: клиент, принадлежащий ему пакет, время, причина и источник; окончание вычисляется из длительности продукта. Перед записью обязательный серверный preview, затем отдельное подтверждение.
- Можно привязать посещение к существующему завершённому занятию с совпадающими временем/форматом/длительностью.
- Список посещений и журнал GRANT/RESERVE/CONSUME/RELEASE, фильтр только списаний.
- Восстановление незавершённого запроса в той же вкладке: прежнее тело/ключ, отсутствие автоматического повтора, явный сброс только после проверки CRM.

## Серверный адаптер

JWT KateFitNotes обязателен на всех маршрутах. CRM_API_KEY только в серверном Environment.

| Маршрут KateFitNotes | Twenty |
| --- | --- |
| GET /api/v1/studio/records/{resource} | GET /rest/{object}, cursor pagination, allowlist |
| POST /api/v1/studio/clients | GET/POST /rest/people, устойчивый UUID, проверка телефона |
| POST /api/v1/studio/package-payments/confirm | POST /s/studio/package-payments/confirm |
| POST /api/v1/studio/attendance/preview | POST /s/studio/attendance/record-past, previewOnly=true |
| POST /api/v1/studio/attendance/record-past | POST /s/studio/attendance/record-past, previewOnly=false |

## Проверки

- 18 UI unit tests, синтаксическая проверка всех JS-модулей.
- 56 API/settings tests прошли, 3 DB-зависимых пропущены.
- Headless Chrome: переключение режимов, создание клиента, оплата, preview, потерянный ответ после списания, повтор после перезагрузки с тем же ключом, журнал, mobile 390px, CRM disabled. Без ошибок JS; все API-запросы подменены тестовыми ответами.
- Desktop/mobile скриншоты просмотрены. Pencil документ не изменялся.
- Новый адаптер проверен read-only на crm-stage.lan: шесть списков, необходимые поля и фильтр телефона доступны. Ни одной реальной записи не создано/изменено.

## Граница готовности

Это основной поток, а не все 26 нарисованных экранов. Редактирование контактов, расписание/создание будущих слотов, бронирование/отмена, PAYG, сплиты, лиды и события пока не реализованы в этом UI. Кнопок, имитирующих готовые действия, нет.

SessionStorage сохраняет незавершённые операции в одной вкладке; закрытие вкладки может потерять ключ. При неопределённом исходе перед новой оплатой нужна ручная сверка. Несколько вкладок/параллельные операторы не получают общую блокировку. Проверка дубля телефона не атомарна. Оставшиеся риски конкурентных CRM-мутаций из первого этапа сохраняются.
