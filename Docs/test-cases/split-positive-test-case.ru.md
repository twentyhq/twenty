# Тест-кейс: позитивный сценарий сплит-блока

**Статус:** актуален для текущего сплит-флоу KATFIT Studio.
**Область:** продажа общего сплит-блока, запись пары, проведение и списание
одного посещения из общего остатка.

## Цель

Проверить, что CRM корректно ведёт один общий блок для двух закреплённых клиентов: продажа, запись на слот, проведение и списание.

## Предусловия

- Выполнены `twenty plan` и `twenty apply`; приложение KATFIT Studio применено
  в тестовом workspace.
- Есть продукт со значениями:
  - категория — `SPLIT`;
  - формат — `SPLIT_EQUIPMENT`;
  - посещений — `4`;
  - цена — `20 000 ₽`;
  - вместимость слота по умолчанию — `2`;
  - продукт активен и действует на дату теста.
- В CRM нет активной пары с этими двумя тестовыми клиентами.
- Тест проводится на будущую дату. Для финального шага потребуется либо дождаться окончания слота, либо использовать отдельный уже завершившийся тестовый слот с двумя записями и резервом.

## Тестовые данные

| Поле | Значение |
| --- | --- |
| Клиент 1 | `Тест Сплит Первый` |
| Клиент 2 | `Тест Сплит Второй` |
| Название пары | `Тест Сплит Первый + Тест Сплит Второй` |
| Продукт | `Тест: сплит-блок 4` |
| Оплата 1 | 10 000 ₽, СБП |
| Оплата 2 | 10 000 ₽, наличные |
| Слот | Будущий `SPLIT_EQUIPMENT`, вместимость 2 или больше |

## Шаги и ожидаемый результат

### 1. Создать клиентов

1. В разделе **Люди** создайте двух клиентов из тестовых данных.
2. Запомните их имена и убедитесь, что это разные записи.

**Ожидаемый результат:** существуют два разных клиента, доступных для выбора в поле участника пары.

### 2. Создать пару

1. Откройте раздел **Пары**.
2. Нажмите создать запись.
3. Заполните название пары.
4. В полях **Первый участник** и **Второй участник** выберите соответствующих клиентов.
5. Установите статус **Активна** и сохраните запись.

**Ожидаемый результат:** создана одна активная пара с двумя разными участниками.

### 3. Продать общий блок двумя платежами

1. Откройте карточку созданной пары.
2. В меню команд выберите **Оформить сплит-блок**.
3. Выберите тестовый сплит-продукт.
4. Оставьте включённым вариант **Два платежа по половине**.
5. Укажите дату оплаты не в будущем, способ оплаты и подтвердите операцию.
6. Откройте созданный блок в разделе **Пакеты клиентов** и связанные записи в **Оплатах**.

**Ожидаемый результат:**

- создан ровно один общий блок, связанный с парой;
- его статус — `ACTIVE`;
- начислено `4`, доступно `4`, зарезервировано `0`, использовано `0`;
- создано две оплаты по 10 000 ₽, каждая связана с одним из участников и с тем же общим блоком;
- не создано двух независимых пакетов — по одному на клиента.

### 4. Внести сплит-слот в программу

1. Откройте раздел **Занятия**.
2. Создайте слот на будущее.
3. В поле **Продукт-источник** выберите тестовый сплит-продукт и убедитесь, что CRM подставила формат **Сплит на оборудовании**, длительность и вместимость `2`.
4. Укажите статус **Подтверждено**.
5. В блоке **«Доступные сплиты»** выберите `Тест Сплит Первый — Тест Сплит Второй`.
6. Нажмите **Создать занятие**.

**Ожидаемый результат:** слот создан, пара назначена, число свободных мест уменьшилось на два.

### 5. Записать пару

1. Откройте раздел **Записи** и отфильтруйте записи по созданному слоту.

**Ожидаемый результат:**

- создано ровно две записи типа `SPLIT`, по одной для каждого клиента;
- обе записи ссылаются на одну пару, один общий блок и один слот;
- статус обеих записей — `BOOKED`;
- число забронированных мест слота увеличено на 2;
- у блока: доступно `3`, зарезервировано `1`, использовано `0`;
- в журнале блока есть одна операция `RESERVE` с изменением `−1`.

### 6. Провести занятие

1. Дождитесь окончания созданного слота. Для тестового прогона допустимо заранее подготовить завершившийся слот, если он связан с теми же двумя записями и резервом.
2. Откройте любую из двух записей.
3. Выберите **Управление сплит-записью** → **Отметить пару проведённой**.
4. Откройте вторую запись, общий блок, слот и журнал операций.

**Ожидаемый результат:**

- обе записи имеют статус `ATTENDED`;
- обе записи отмечены как списывающие посещение;
- слот имеет статус `COMPLETED`, а число посетивших увеличено на 2;
- у общего блока: доступно `3`, зарезервировано `0`, использовано `1`;
- журнал содержит связку `RELEASE (+1)` и `CONSUME (−1)` для одной операции проведения;
- из общего остатка списана одна тренировка, а не две;
- в отчёте/таблице можно увидеть два клиентских визита на один проведённый сплит-слот.

### 7. Проверить повторную отправку

1. Не изменяя данные, повторите действие проведения либо отправьте тот же API-запрос с тем же ключом идемпотентности.
2. Обновите блок и журнал операций.

**Ожидаемый результат:** CRM сообщает, что операция уже выполнена, и не создаёт повторных списаний, записей или посещений.

## Критерий успешности

Тест пройден, если в финале есть один блок, две оплаты, две записи, один сплит-слот, два визита и одно списание из общего остатка.

## Очистка тестовых данных

Не удаляйте проведённые записи, оплаты и операции журнала: они составляют аудит. Пометьте тестовую пару неактивной и добавьте в её название префикс `TEST ARCHIVE`, если данные нужно исключить из операционных списков.
