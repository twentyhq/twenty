# Build our own Twenty image from a patched upstream release

Supersedes ADR-0001. The client does not want the Community and Documentation entries in the settings menu, and Twenty has no setting to hide them, so we now run our own image. The `jai-twenty-v2.41.0` branch is upstream tag `twenty/v2.41.0` plus our patches; a manual GitHub Actions workflow builds it and pushes `ghcr.io/codaswin/twenty:<tag>`, and `ops/docker-compose.yml` runs that image. Patches live only on that release branch, never on `main`, because `main` tracks arbitrary upstream commits and would ship unreleased code. Cost: each Twenty upgrade means cutting a new release branch from the new upstream tag, re-applying the patches and rebuilding. Keep the patch list short. Everything else (the Invoice app, config) still extends Twenty without patching it.
