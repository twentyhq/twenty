## نظرة عامة

الاتصالات هي بيانات اعتماد يحتفظ بها المستخدم لخدمة خارجية (Linear وGitHub وSlack، ...). يحدّد تطبيقك **كيف** يتم الحصول على تلك بيانات الاعتماد — **موفّر اتصال** — ويستخدمها وقت التشغيل لإجراء استدعاءات مُصادَقة إلى واجهة برمجة تطبيقات الطرف الثالث.

OAuth 2.0 مدمج. تستخدم الخدمات التي لها تدفق اتصال خاص بها — صفحة تسجيل دخول مستضافة، ومعرّف حساب يُسلَّم عبر webhook — موفّر `custom`، حيث يقود تطبيقك التدفق ويحتفظ Twenty بالمستخدم ومساحة العمل والاتصال المحفوظ. ستندمج الأنواع المستقبلية من بيانات الاعتماد (رموز الوصول الشخصية، مفاتيح API، المصادقة الأساسية) مع نفس الواجهة — التطبيقات التي تستخدم بالفعل `defineConnectionProvider({ type: 'oauth', ... })` لن تحتاج إلى الترحيل.

<Accordion title="defineConnectionProvider" description="عرّف كيفية الحصول على اتصالات تطبيقك">

يصف موفّر الاتصال عملية المصافحة الخاصة بـ OAuth التي يحتاجها تطبيقك. بالنسبة إلى موفّر `WORKSPACE` (الافتراضي)، ينقر أحد الأعضاء على "إضافة اتصال" في إعدادات تطبيقك، ويُكمل شاشة موافقة الموفّر، ثم يُنشأ صف `ConnectedAccount` في مساحة عمله. راجع "اتصالات مساحة العمل أو الاتصالات الشخصية" لموفّري `USER`.

يتطلّب الإعداد العملي **ملفّين** — موفّر الاتصال، وتصريح `serverVariables` مطابق في `defineApplication` يحتفظ ببيانات اعتماد عميل OAuth.

```ts src/connection-providers/linear-connection.ts
import { defineConnectionProvider } from 'twenty-sdk/define';

export default defineConnectionProvider({
  universalIdentifier: '9c7d1f5e-6a0b-4d44-be0c-3f8b5a9d4e6f',
  name: 'linear',
  displayName: 'Linear',
  icon: 'IconBrandLinear',
  // Optional: a logo bundled in your app's public/ folder, shown next to the
  // provider in the app's General tab.
  logo: 'public/linear-logomark.svg',
  type: 'oauth',
  scope: 'WORKSPACE',
  oauth: {
    authorizationEndpoint: 'https://linear.app/oauth/authorize',
    tokenEndpoint: 'https://api.linear.app/oauth/token',
    scopes: ['read', 'write'],
    // These must match keys in `defineApplication.serverVariables` below.
    clientIdVariable: 'LINEAR_CLIENT_ID',
    clientSecretVariable: 'LINEAR_CLIENT_SECRET',
    // Optional: defaults to 'json'. Some providers (Linear, Slack) want
    // 'form-urlencoded' for the token request.
    tokenRequestContentType: 'form-urlencoded',
    // Optional: defaults to true. Disable only if the provider rejects PKCE.
    usePkce: false,
    // Optional: extra query params on the authorize URL.
    // authorizationParams: { prompt: 'consent' },
    // Optional: provider's RFC 7009 token revocation endpoint, called on disconnect.
    // revokeEndpoint: 'https://example.com/oauth/revoke',
  },
  // Optional: a logic function in this app that returns a stable id for the
  // upstream account, run before the tokens are saved. See "Identify the
  // connected account".
  // identifyAccountLogicFunction: { universalIdentifier: '2f1e0d9c-...-...' },
  // Optional: a logic function in this app to run right after a connection is
  // established. See "Run a logic function on connect".
  // onConnectLogicFunction: { universalIdentifier: '3a2b1c0d-...-...' },
  // Optional: a logic function in this app to run right after a connection is
  // removed. See "Run a logic function on disconnect".
  // onDisconnectLogicFunction: { universalIdentifier: '4d5e6f70-...-...' },
});
```

```ts src/application.config.ts
import { defineApplication } from 'twenty-sdk/define';

export default defineApplication({
  universalIdentifier: '...',
  displayName: 'Linear',
  description: 'Connect Linear to Twenty.',
  // OAuth client credentials live on the app registration (one OAuth app per
  // Twenty server, configured by the admin) — not per-workspace. Declare them
  // as serverVariables so the admin can fill them in once for all installs.
  serverVariables: {
    LINEAR_CLIENT_ID: {
      description: 'OAuth client ID from your Linear OAuth application.',
      isSecret: false,
      isRequired: true,
    },
    LINEAR_CLIENT_SECRET: {
      description: 'OAuth client secret from your Linear OAuth application.',
      isSecret: true,
      isRequired: true,
    },
  },
});
```

النقاط الرئيسية:

* `name` هي سلسلة المعرّف الفريدة المستخدمة في `listConnections({ providerName })` (بصيغة kebab-case، ويجب أن تطابق `^[a-z][a-z0-9-]*$`).
* يظهر `displayName` في علامة التبويب عام الخاصة بالتطبيق وفي قائمة أدوات الذكاء الاصطناعي.
* يحدّد `scope` من يتصل: `'WORKSPACE'` (الافتراضي) للاتصالات المشتركة مع مساحة العمل بأكملها، و`'USER'` للاتصالات التي ينشئها كل عضو لنفسه. راجع "اتصالات مساحة العمل أو الاتصالات الشخصية" أدناه.
* `logo` هو مسار إلى أصل مُضمَّن في مجلد `public/` لتطبيقك، ويُقدَّم عبر الأصول العامة للتطبيق. عند حذفه، تعود علامة التبويب عام إلى عنصر نائب مُنشأ من `displayName`.
* `clientIdVariable` / `clientSecretVariable` هي **أسماء**، وليست قيماً — ويجب أن تطابق المفاتيح المصرَّح بها في `defineApplication.serverVariables`. يُدخِل مسؤول الخادم القيم الفعلية `client_id` و`client_secret` عبر واجهة تسجيل التطبيق، ولا تُضمَّن أبدًا في مستودعك.
* استخدم `serverVariables` (وليس `applicationVariables`) — بيانات اعتماد OAuth على مستوى الخادم، ويوجد تطبيق OAuth واحد لكل خادم Twenty.
* إلى أن يتم ملء كلا `serverVariables`، تعرض علامة التبويب عام الخاصة بالتطبيق تلميح "بحاجة إلى مسؤول الخادم" ويكون زر "إضافة اتصال" معطّلًا.
* `type` هو `'oauth'` (مع كتلة `oauth`) أو `'custom'` (مع كتلة `custom`، راجع "تدفقات الاتصال المخصصة"). المميِّز متوافق مع الإصدارات المستقبلية: الأنواع المستقبلية (`'pat'`، `'api-key'`، ...) ستضيف كتل تهيئة فرعية جديدة إلى جانب هذه.

عنوان URL لردّ النداء الخاص بـ OAuth الذي يحتاج موفّرك إلى إضافته إلى قائمة السماح هو:

```
https://<your-twenty-server>/auth/apps/callback
```

تربط بعض الخدمات الحسابات عبر تدفقها الخاص بدلاً من OAuth: ترسل Unipile وPlaid وMerge المستخدم إلى صفحة مستضافة ثم تُبلغ عن الحساب المتصل إلى عنوان URL الذي قدمته لها، وأحياناً من خوادمها بدلاً من المتصفح. عرّف هذه باستخدام `type: 'custom'` ودالتَي منطق:

```ts src/connection-providers/linkedin-connection.ts
import { defineConnectionProvider } from 'twenty-sdk/define';

export default defineConnectionProvider({
  universalIdentifier: '5b0e6f3a-2c4d-4e8f-9a1b-7c6d5e4f3a2b',
  name: 'linkedin',
  displayName: 'LinkedIn',
  type: 'custom',
  scope: 'USER',
  custom: {
    authorizeLogicFunction: {
      universalIdentifier: 'c4a1e2b3-6d5f-4a7b-8c9d-0e1f2a3b4c5d',
    },
    callbackLogicFunction: {
      universalIdentifier: 'd5b2f3c4-7e6a-4b8c-9d0e-1f2a3b4c5d6e',
    },
  },
  onConnectLogicFunction: {
    universalIdentifier: 'e6c3a4d5-8f7b-4c9d-0e1f-2a3b4c5d6e7f',
  },
});
```

يعمل **إضافة اتصال** و**إعادة الاتصال** كما في OAuth. يتحقق Twenty من إمكانية اتصال العضو، ويوقّع حالة قصيرة العمر للمحاولة، ويشغّل `authorizeLogicFunction` باستخدام `callbackUrl` يحملها. أعِد المكان الذي يجب إرسال المستخدم إليه:

```ts src/logic-functions/handlers/linkedin-authorize-handler.ts
import { type AuthorizeConnectionPayload } from 'twenty-sdk/logic-function';

export const linkedinAuthorizeHandler = async ({
  callbackUrl,
}: AuthorizeConnectionPayload) => {
  const response = await fetch(
    `${process.env.UNIPILE_DSN}/api/v1/hosted/accounts/link`,
    {
      method: 'POST',
      headers: {
        'X-API-KEY': process.env.UNIPILE_API_KEY ?? '',
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        type: 'create',
        providers: ['LINKEDIN'],
        api_url: process.env.UNIPILE_DSN,
        expiresOn: new Date(Date.now() + 10 * 60 * 1000).toISOString(),
        // The browser comes back here, and the account id is posted here.
        success_redirect_url: callbackUrl,
        failure_redirect_url: callbackUrl,
        notify_url: callbackUrl,
      }),
    },
  );

  const { url } = await response.json();

  return { authorizationUrl: url };
};
```

مرّر `callbackUrl` إلى الخدمة دون تغيير. يقبله Twenty كإعادة توجيه من المتصفح (`GET`) وكإشعار من الخادم (`POST`)، ويشغّل `callbackLogicFunction` لكل طلب باستخدام طريقته ومعلمات الاستعلام (من دون `state`) والرؤوس والنص المُحلل و`rawBody` (بايتات الطلب الدقيقة، و`null` في `GET`). أعِد الحساب الذي يثبته الطلب، أو `null` عندما لا يحمل أي حساب — وعادةً ما يكون ذلك عند عودة المتصفح بينما ينتقل معرّف الحساب عبر إشعار:

```ts src/logic-functions/handlers/linkedin-callback-handler.ts
import { type ConnectionCallbackPayload } from 'twenty-sdk/logic-function';

export const linkedinCallbackHandler = async ({
  httpMethod,
  body,
}: ConnectionCallbackPayload) => {
  if (httpMethod !== 'POST') {
    return null;
  }

  const { account_id: accountId } = body as { account_id: string };

  // Never trust the payload alone: confirm the account with the service.
  const account = await fetchUnipileAccount(accountId);

  return { externalAccountId: account.id, handle: account.name };
};
```

تثبت الحالة الموقعة في `callbackUrl` فقط أن الطلب يحمل عنوان URL ذلك، وليس أن الخدمة أرسلته. عندما توقّع الخدمة إشعاراتها، تحقّق من التوقيع على `rawBody` قبل الوثوق بالنص. تُحوَّل الرؤوس إلى أحرف صغيرة، ولا يتم تمرير `cookie` و`authorization` و`proxy-authorization` أبداً:

```ts src/logic-functions/handlers/hosted-callback-handler.ts
import { createHmac, timingSafeEqual } from 'node:crypto';

import { type ConnectionCallbackPayload } from 'twenty-sdk/logic-function';

export const hostedCallbackHandler = async ({
  httpMethod,
  headers,
  rawBody,
}: ConnectionCallbackPayload) => {
  if (httpMethod !== 'POST' || rawBody === null) {
    return null;
  }

  const expected = createHmac('sha256', process.env.WEBHOOK_SECRET ?? '')
    .update(rawBody)
    .digest();
  const received = Buffer.from(headers['x-signature'] ?? '', 'hex');

  if (received.length !== expected.length || !timingSafeEqual(received, expected)) {
    throw new Error('Invalid notification signature');
  }

  const { account_id: accountId } = JSON.parse(rawBody) as { account_id: string };

  return { externalAccountId: accountId };
};
```

تعيد دالة الاستدعاء:

| الحقل               | الوصف                                                                                                                                   |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `externalAccountId` | معرّف الخدمة للحساب. يؤدي استدعاء لاحق للمعرّف والعضو نفسيهما إلى تحديث ذلك الاتصال بدلاً من إضافة اتصال ثانٍ.                          |
| `معالجة`            | تسمية اختيارية معروضة للاتصال. تكون القيمة الافتراضية بريد العضو الإلكتروني.                                                            |
| `accessToken`       | رمز مميز اختياري لكل حساب، يُخزَّن مشفراً ويُعاد بواسطة `getConnection`. اتركه خارجاً عندما يستدعي تطبيقك الخدمة باستخدام مفتاحه الخاص. |

تعمل كلتا الدالتين بينما ينتظر العضو إعادة التوجيه، لذا يقتصر مهلة انتهائهما على 10 ثوانٍ. يؤدي الفشل أو الإرجاع غير الصالح إلى إلغاء الاتصال: لا يُحفظ شيء ولا تعمل `onConnectLogicFunction`. تعمل `onConnectLogicFunction` عند إنشاء اتصال أو إعادة اتصاله أو استعادته، ولا تعمل مجدداً عندما تُبلغ الخدمة عن حساب متصل بالفعل. تنتهي صلاحية الحالة بعد ساعة، لذا يُرفض الإشعار الذي يصل لاحقاً. تعيد الخدمات عادةً محاولة الإشعارات: يؤدي تكرار لحساب متصل بالفعل إلى تحديث ذلك الاتصال، لذا من الآمن إعادة الحساب نفسه مرة أخرى.

لا يقوم Twenty بتحديث الاتصالات المخصصة أو إلغائها. حرّر ما تحتفظ به الخدمة للحساب في `onDisconnectLogicFunction`.

لا يمكن تغيير `type` لموفر، مثل `scope` الخاص به، بعد مزامنته: لنقل خدمة بين `oauth` و`custom`، عرّف موفراً جديداً باستخدام `universalIdentifier` جديد.

تتوفر الموفرات المخصصة مع Twenty 2.52.0.

<Accordion title="تحديد الحساب المتصل" description="منع إعادة الاتصال من التبديل بصمت بين الحسابات المصدر">

عندما ينقر مستخدم على **Reconnect**، لا شيء يمنعه من تفويض حساب مصدر مختلف عن الحساب الذي أُنشئ الاتصال به: مساحة عمل Slack B بدلًا من مساحة العمل A، أو مؤسسة GitHub أخرى، أو حساب Google آخر. من دون طريقة للتمييز بينهما، سيستبدل Twenty رموز A المميزة برموز B، وسيبدأ كل ما أنشأه تطبيقك اعتمادًا على ذلك الاتصال بالتواصل مع B بصمت.

عيّن `identifyAccountLogicFunction` إلى دالة منطقية في التطبيق نفسه تُرجع معرّفًا ثابتًا للحساب المرتبط بالرمز المميز الصادر حديثًا:

```ts src/connection-providers/slack-connection.ts
import { defineConnectionProvider } from 'twenty-sdk/define';

import { SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER } from 'src/constants/universal-identifiers';

export default defineConnectionProvider({
  universalIdentifier: '...',
  name: 'slack',
  displayName: 'Slack',
  type: 'oauth',
  oauth: {
    /* ... */
  },
  identifyAccountLogicFunction: {
    universalIdentifier: SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER,
  },
});
```

**متى يتم تشغيلها.** بشكل متزامن داخل معاودة نداء OAuth، مباشرةً بعد استبدال رمز التفويض برموز مميزة و**قبل** حفظ أي شيء. ينتظر المستخدم إعادة التوجيه، لذا عند تثبيت التطبيق أو مزامنته، يقيّد Twenty قيمة `timeoutSeconds` للدالة بـ 10، بغض النظر عما يعلنه البيان؛ اجعلها طلبًا واحدًا إلى نقطة نهاية "من أنا" الخاصة بالموفر. يستمر تشغيل خطاف on-connect، إن وُجد، بعد ذلك، بمجرد حفظ الاتصال.

**الحمولة.** يتلقى المعالج رمز الوصول المؤقت. لم يُحفَظ بعد، لذا لا يمكن لـ `getConnection` إرجاعه؛ استخدمه مباشرةً ولا تسجّله.

```ts
type IdentifyAccountPayload = {
  connectionProviderId: string;
  connectionProviderName: string; // e.g. 'slack'
  accessToken: string;
};
```

**النتيجة.** أعد معرّف الحساب، ومعالجًا اختياريًا لعرضه:

```ts
type IdentifyAccountResult = {
  externalAccountId: string | null; // non-empty, at most 512 characters; null opts out
  handle?: string; // non-empty when present
};
```

* يجب أن يكون `externalAccountId` ثابتًا طوال عمر الحساب المصدر (معرّف فريق أو معرّف مؤسسة أو معرّف مستخدم)، وألا يكون أبدًا اسمًا يمكن للمستخدم تغييره. يقوم Twenty بتشذيبه وتخزينه في الاتصال عند أول اتصال.
* يستبدل `handle`، عند إرجاعه، المعالج الذي كان Twenty سيستنتجه بخلاف ذلك (بريد OIDC الإلكتروني في `id_token`، أو بريد المستخدم الذي يجري الاتصال). أعد شيئًا يتعرّف عليه المستخدم، مثل اسم مساحة عمل Slack.
* أعد `{ externalAccountId: null }` عندما لا يملك الموفر معرّفًا ثابتًا لتقديمه. يتصرف Twenty حينها كما لو لم يتم الإعلان عن دالة تعريف: لا يُخزَّن أي معرّف، وتؤدي إعادة الاتصال إلى مسح أي معرّف مخزن سابقًا، ولا يتم التحقق من عمليات إعادة الاتصال. يُعامل `null` المجرد أو عدم وجود قيمة معادة على أنه خطأ، لذلك لا يمكن لمعالج ينسى الإرجاع تعطيل التحقق بصمت.
* إذا أطلقت الدالة استثناءً، أو انتهت مهلتها، أو أعادت أي شيء آخر، **فلن** يُحفظ الاتصال وسيعود المستخدم إلى صفحة الإعدادات مع ظهور خطأ. أطلق استثناءً فقط عندما يتعذر عليك فعلًا تحديد الحساب.

**رفض إعادة الاتصال.** عند إعادة الاتصال، يقارن Twenty قيمة `externalAccountId` المعادة بتلك المخزنة في الاتصال. إذا اختلفا، يُرفض رد الاتصال قبل كتابة أي شيء: تبقى الرموز المميزة والمقبض والنطاق الحالية كما كانت، ولا يُشغَّل خطاف عند الاتصال، ويرى المستخدم الحساب الذي منح له التفويض والحساب الذي ينتمي إليه الاتصال. لا تحتوي الاتصالات التي أُنشئت قبل أن يعلن تطبيقك عن الدالة على معرّف مخزن بعد؛ وتخزنه عند إعادة اتصالها التالية.

لا يزيل Twenty التكرارات استنادًا إلى `externalAccountId`: يؤدي ربط الحساب المصدر نفسه مرتين عبر **إضافة اتصال** إلى إنشاء اتصالين. يُكشف عن المعرّف في `listConnections` و`getConnection`، لذا يمكن للتطبيق الذي يريد اتصالًا واحدًا لكل حساب مصدر اكتشاف التكرارات بنفسه (على سبيل المثال في خطاف on-connect الخاص به).

**كتابة الدالة.** يكشف معظم الموفرين عن نقطة نهاية واحدة تصف الرمز الحالي. بالنسبة إلى Slack، تكون هذه `auth.test`، التي تعيد مساحة العمل (`team_id`، `team`) والمستخدم المرتبط بالرمز:

```ts src/logic-functions/slack-identify-account.ts
import { defineLogicFunction } from 'twenty-sdk/define';
import type {
  IdentifyAccountPayload,
  IdentifyAccountResult,
} from 'twenty-sdk/logic-function';

import { SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER } from 'src/constants/universal-identifiers';

export default defineLogicFunction({
  universalIdentifier: SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER,
  name: 'slack-identify-account',
  timeoutSeconds: 10,
  handler: async ({
    accessToken,
  }: IdentifyAccountPayload): Promise<IdentifyAccountResult> => {
    const response = await fetch('https://slack.com/api/auth.test', {
      method: 'POST',
      headers: { Authorization: `Bearer ${accessToken}` },
    });
    const { ok, error, team_id, team } = await response.json();

    if (!ok) {
      throw new Error(`auth.test failed: ${error}`);
    }

    return { externalAccountId: team_id, handle: team };
  },
});
```

يتبع الموفرون الآخرون النمط نفسه، سواء كانت نقطة نهاية "من أنا" الخاصة بهم REST أو GraphQL. أطلق استثناءً عندما يرفض الموفر الرمز، وأعد المعرّف كسلسلة نصية: حوّل المعرّفات الرقمية، مثل معرّفات مستخدمي GitHub، باستخدام `String(id)`.

تتوفر ميزة التعريف في Twenty 2.48.0. إذا كان تطبيقك يعتمد عليها، فأعلن عن `"engines": { "twenty": ">=2.48.0" }` في `package.json` الخاص به.

</Accordion>

<Accordion title="تشغيل دالة منطقية عند الاتصال" description="التفاعل فور إنشاء الاتصال">

بعض المزوّدين يسلّمونك بيانات وقت الاتصال تحتاج إلى الاحتفاظ بها قبل أن يصبح الاتصال قابلاً للاستخدام — المثال الكلاسيكي هو Slack، حيث يحدّد رد OAuth معرّف الفريق `team_id` الخاص بمساحة العمل الذي ستُربط به الأحداث الواردة. عيِّن `onConnectLogicFunction` للإشارة إلى دالة منطقية في التطبيق نفسه (حسب `universalIdentifier` الخاص بها)، وسيتم تشغيلها مباشرة بعد إنشاء `ConnectedAccount`.

```ts src/connection-providers/slack-connection.ts
export default defineConnectionProvider({
  universalIdentifier: '...',
  name: 'slack',
  displayName: 'Slack',
  type: 'oauth',
  oauth: {
    /* ... */
  },
  // Runs claimSlackTeam after every successful Slack connection.
  onConnectLogicFunction: {
    universalIdentifier: '3a2b1c0d-1111-4222-8333-444455556666',
  },
});
```

يعمل الـ hook **بشكل غير متزامن في مساحة العمل التي تجري الاتصال** (يتم وضعه في قائمة الانتظار، ولا يُنتظر انتهاؤه)، لذلك لن يؤدي hook بطيء أو فاشل إلى حظر أو تعطيل رد نداء OAuth — اجعله قابلاً للتكرار دون آثار جانبية (idempotent) ويتولى إعادة المحاولات بنفسه. يتلقى المعالج:

```ts
type OnConnectPayload = {
  connectionProviderId: string;
  connectionProviderName: string; // e.g. 'slack'
  connectedAccountId: string;
};
```

من هناك استخدم `getConnection(connectedAccountId)` لقراءة رمز الوصول الجديد واستدعاء واجهة برمجة تطبيقات المزوّد (على سبيل المثال، Slack `auth.test`) أو حفظ تعيين باستخدام [مخزن المفاتيح والقيم](/ar/developers/extend/apps/logic/key-value-store).

</Accordion>

<Accordion title="تشغيل دالة منطقية عند قطع الاتصال" description="نظّف عند فصل اتصال أو إزالته">

أي شيء يطالب به تطبيق ما وقت الاتصال يجب تحريره عندما يزول الاتصال. على سبيل المثال، يجب على تكامل Slack الذي يطالب بـ `team_id` عند الاتصال تحرير تلك المطالبة حتى تتمكن مساحة عمل أخرى من ربط فريق Slack نفسه. عيّن `onDisconnectLogicFunction` للإشارة إلى دالة منطقية في التطبيق نفسه، ويتم تشغيلها عند فصل الاتصال ومرة أخرى عند حذفه.

```ts src/connection-providers/slack-connection.ts
export default defineConnectionProvider({
  universalIdentifier: '...',
  name: 'slack',
  displayName: 'Slack',
  type: 'oauth',
  oauth: {
    /* ... */
  },
  // Runs releaseSlackTeam after every Slack disconnection.
  onDisconnectLogicFunction: {
    universalIdentifier: '4470aba8-5ff5-4800-88db-2a427cd8677c',
  },
});
```

بخلاف خطاف الاتصال، يتم تشغيله **ضمنيًا في مساحة العمل التي يجري فصل اتصالها**، من دون إعادات محاولة: يتم تسجيل الإخفاق ويستمر إكمال الفصل أو الحذف. يتلقى المعالج نفس شكل الحمولة:

```ts
type OnDisconnectPayload = {
  connectionProviderId: string;
  connectionProviderName: string; // e.g. 'slack'
  connectedAccountId: string;
};
```

عند فصل الاتصال، يظل `ConnectedAccount` ورمزه المميز موجودين، لذا تُرجع `getConnection(connectedAccountId)` نتيجة ويمكن للمعالج تحرير أي شيء سجّله عن بُعد. عند الحذف، قد تكون بيانات الاعتماد قد اختفت بالفعل (يمكن للعضو حذف اتصال فصله سابقًا)، لذا اجعل المعالج آمنًا لإعادة التنفيذ واحتفظ بالحالة التي يحتاجها (مثل `team_id` أو معرّف اشتراك خارجي) في [مخزن المفاتيح والقيم](/ar/developers/extend/apps/logic/key-value-store)، وتُكتب عند وقت الاتصال وتُفهرس بواسطة `connectedAccountId`. اجعله قصيرًا: فهو يعمل ضمن الطلب، لذا فإن `timeoutSeconds` يمثل الحد الأقصى لمدة استغراق هذا الطلب.

يتم تشغيل الخطاف عند قطع اتصال أو إزالته من تلقاء نفسه. يؤدي إلغاء تثبيت التطبيق إلى حذف اتصالاته عبر حذف متسلسل في قاعدة البيانات، لذلك لا يتم تشغيل الخطاف في هذه الحالة. صرّح عن `uninstallLogicFunction` على `defineApplication` لذلك المسار: يتم تشغيله قبل حذف بيانات التعريف الخاصة بالتطبيق، لذا لا يزال بإمكانه استدعاء `listConnections` وتنظيف أي شيء متبقٍّ.

</Accordion>

<Accordion title="listConnections / getConnection" description="استخدم الاتصالات من دالة منطقية">

داخل معالج دالة منطقية، تُرجِع `listConnections({ providerName })` صفوف `ConnectedAccount` الخاصة بهذا التطبيق للمزوّد المحدَّد، مع رموز وصول محدَّثة.

```ts src/logic-functions/handlers/create-linear-issue-handler.ts
import { listConnections } from 'twenty-sdk/logic-function';

export const createLinearIssueHandler = async (input: {
  teamId?: string;
  title?: string;
}) => {
  if (!input.teamId || !input.title) {
    return { success: false, error: 'teamId and title are required' };
  }

  const connections = await listConnections({ providerName: 'linear' });

  // Workspace-shared credentials win when present; fall back to the first
  // personal one. For HTTP-route triggers you typically pick the
  // request user's connection via event.userWorkspaceId instead.
  const connection =
    connections.find((c) => c.scope === 'WORKSPACE') ?? connections[0];

  if (!connection) {
    return {
      success: false,
      error:
        'Linear is not connected. Open the app settings and click "Add connection".',
    };
  }

  // Use connection.accessToken to call the third-party API.
  const response = await fetch('https://api.linear.app/graphql', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${connection.accessToken}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      query: `mutation { issueCreate(input: { teamId: "${input.teamId}", title: "${input.title}" }) { success } }`,
    }),
  });

  return { success: response.ok };
};
```

يحتوي كل اتصال على:

| الحقل               | الوصف                                                                                                                                                                                                                                               |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                | معرّف صف فريد؛ مرّره إلى `getConnection(id)` لإعادة جلب واحد فقط                                                                                                                                                                                    |
| `scope`             | `'USER'` (يتبع للعضو الذي يجري الاتصال) أو `'WORKSPACE'` (مشترك مع جميع الأعضاء)                                                                                                                                                                    |
| `visibility`        | مهمل: `scope` بأحرف صغيرة (`'user'` أو `'workspace'`). استخدم `scope` بدلًا من ذلك                                                                                                                                                                  |
| `scopes`            | أذونات OAuth التي يمنحها الموفّر الأساسي (مختلفة عن `scope` — ولا علاقة بينهما)                                                                                                                                                                     |
| `userWorkspaceId`   | معرّف userWorkspace للمالك — مفيد لاختيار "اتصال مستخدم الطلب" في مشغّلات مسارات HTTP                                                                                                                                                               |
| `workspaceMemberId` | معرّف عضو مساحة عمل المالك، أو `null` إذا كان قد غادر مساحة العمل منذ ذلك الحين                                                                                                                                                                     |
| `providerType`      | `'oauth'` أو `'custom'`، نوع موفر الاتصال. تحقق منه لتضييق نطاق `accessToken`                                                                                                                                                                       |
| `accessToken`       | رمز وصول OAuth حديث (يُحدَّث تلقائياً إذا انتهت صلاحيته)، ويكون معيّناً دائماً عندما يكون `providerType` هو `'oauth'`. بالنسبة إلى `'custom'`، يكون `null` ما لم تُعد دالة الاستدعاء رمزاً                                                          |
| `name`              | الاسم المعروض للاتصال (يُستمد تلقائيًا عند ردّ نداء OAuth، وقابل لإعادة التسمية من قِبل المستخدم)                                                                                                                                                   |
| `المُعرّف`          | تسمية الحساب المصدر المتصل، التي تُحدَّث عند كل إعادة اتصال: قيمة `handle` التي تعيدها دالة التعريف عند وجودها، وإلا فالبريد الإلكتروني من OIDC `id_token` المعاد عند تبادل الرمز، مع الرجوع إلى البريد الإلكتروني لمستخدم Twenty الذي يجري الاتصال |
| `externalAccountId` | المعرّف الثابت للحساب المصدر الذي تعيده دالة التعريف، أو `null` عندما لا يعلن الموفر عن أي معرّف أو عندما يكون الاتصال سابقًا له. غير فريد: استخدمه لإزالة تكرار الاتصالات بنفسك                                                                    |
| `authFailedAt`      | يُضبط عند فشل آخر تحديث، أو عندما يُبلغ التطبيق بأن بيانات الاعتماد لم تعد صالحة عبر `reportConnectionAuthFailure`؛ يجب على المستخدم إعادة الاتصال                                                                                                  |
| `authFailedReason`  | شرح مقروء بشريًا لـ `authFailedAt`، عندما يقدمه المُبلِغ؛ يُعرض في صفحة تفاصيل الاتصال ضمن الإعدادات                                                                                                                                                |

النقاط الرئيسية:

* مرّر `{ providerName }` للتصفية حسب المزوّد؛ واحذفه للحصول على كل الاتصالات التي يملكها هذا التطبيق عبر جميع المزوّدين.
* يقوم الخادم بتحديث رمز الوصول بشفافية قبل الإرجاع. يرى معالجك دائمًا رمزًا صالحًا للاستخدام (أو سيكون `authFailedAt` مُعيّنًا).
* `getConnection(id)` هي المعادِل لصف واحد.

</Accordion>

<Accordion title="reportConnectionAuthFailure" description="أبلغ المنصة بأن بيانات الاعتماد لم تعد صالحة">

تضبط المنصة `authFailedAt` من تلقاء نفسها فقط عند فشل تجديد OAuth. يفشل المزوّدون الذين لا تُجدَّد رموزهم المميزة مطلقًا (مثل رمز روبوت Slack المميز) فقط في وقت الاستدعاء داخل معالجاتك، لذا سيظل صف الاتصال في الإعدادات يعرض **متصل** بينما يفشل كل استدعاء. عندما يواجه رمزك رفضًا نهائيًا للمصادقة، أبلغ عنه:

```ts
import { reportConnectionAuthFailure } from 'twenty-sdk/logic-function';

await reportConnectionAuthFailure({
  connectionId: connection.id,
  reason:
    'Slack rejected the stored token (invalid_auth). Reconnect to restore the integration.',
});
```

يؤدي ذلك إلى ضبط `authFailedAt` والسبب الاختياري على الاتصال. يتحول صف الإعدادات إلى **يلزم إعادة الاتصال** مع زر «إعادة الاتصال»، وتعرض صفحة تفاصيل الاتصال السبب، ويبدأ `getConnection` في إطلاق `AppConnectionAuthFailedError` لذلك الصف. يُمسح العَلَم والسبب تلقائيًا عندما يعيد المستخدم الاتصال. يُرفض `reason` الذي يزيد طوله على 1000 حرف، لذا اقتطع حمولات المزوّد قبل تمريرها.

أبلغ فقط عن الإخفاقات التي ستُصلحها إعادة الاتصال فعليًا (رفض من فئة `invalid_auth` من المزوّد)، ولا تُبلغ أبدًا عن أخطاء الشبكة العابرة. لا يمكن للتطبيق إلا الإبلاغ عن اتصالاته الخاصة، ولا يمكن لمستخدم الطلب إلا الإبلاغ عن بيانات اعتماده الشخصية.

تتوفر عملية التعديل وراء هذا المساعد مع Twenty 2.40.0، لذا يفشل استدعاؤها على خادم أقدم. إذا كان تطبيقك يستخدمها، فصرّح بالاعتماد في `package.json`: `"engines": { "twenty": ">=2.40.0" }`.

</Accordion>

<Accordion title="اتصالات مساحة العمل أو الاتصالات الشخصية" description="اختر من يتصل باستخدام نطاق الموفّر">

لكل اتصال أحد نطاقين:

* **مشتركة على مستوى مساحة العمل** (`'WORKSPACE'`) — يمكن لأي عضو في مساحة العمل استخدام بيانات الاعتماد. يمكن لمشغّلات cron/قاعدة البيانات رؤيتها أيضًا، لأنها لا تملك مستخدم طلب.
* **لي فقط** (`'USER'`) — بيانات الاعتماد تتبع للعضو الذي يجري الاتصال. في عمليات التشغيل التي تُنفَّذ نيابةً عن عضو (مشغّل مسار HTTP مع `isAuthRequired: true`)، تُرجع `listConnections` الاتصالات المشتركة بالإضافة إلى اتصالات ذلك العضو الخاصة، وتختار `findConnectionForRequest` اتصال العضو الشخصي، مع الرجوع إلى اتصال مشترك عند عدم وجود أي اتصال لديه. في عمليات التشغيل التي لا تتضمن مستخدم طلب (مثل مشغّلات cron)، تُرجع `listConnections` كل اتصال، بما في ذلك الاتصالات الشخصية لكل عضو.

يحدّد `scope` الخاص بالموفّر أيّهما تحصل عليه اتصالاته الجديدة:

* `scope: 'WORKSPACE'` (الافتراضي) — يعمل التطبيق مع الاتصالات المشتركة مع مساحة العمل. يؤدي **إضافة اتصال** في إعدادات مساحة عمل التطبيق إلى إنشاء اتصال مشترك في مساحة العمل.
* `scope: 'USER'` — يتصل كل عضو بحسابه الخاص، مما ينشئ اتصالات شخصية. يضيف الأعضاء هذه الاتصالات ويعيدون ربطها ويزيلونها من صفحة التطبيق ضمن **الإعدادات > المستخدم > تفضيلات التطبيقات**، الأمر الذي يتطلب الإذن `CONNECTED_ACCOUNTS` (تطبيقات المستخدم). لا تحتوي إعدادات مساحة عمل التطبيق على زر **إضافة اتصال** لموفّر `USER`.

<Note>
  لم يتم تمكين **تفضيلات التطبيقات** في كل مساحة عمل بعد: ففي الأماكن التي لا تكون فيها مُمكّنة،
  لا يتوفر للأعضاء مكان لإضافة اتصال `USER`، لذا لا تعتمد على اتصال واحد من أجل
  ميزة تحتاجها كل مساحة عمل الآن.
</Note>

للموفّر نطاق واحد فقط. إذا كان تطبيقك يحتاج إلى بيانات اعتماد مشتركة وأخرى لكل عضو للخدمة نفسها (مثل رمز بوت وحساب كل عضو الخاص)، فأعلن عن موفّرين.

يكون للاتصال دائمًا نطاق موفره، ويُعد نطاق الموفر جزءًا من هويته: لا يمكن لإصدار لاحق تغيير `scope` لموفر موجود، ويُرفض التحديث إذا حاول ذلك. لنقل خدمة من نطاق إلى آخر، عرّف موفرًا جديدًا باستخدام `universalIdentifier` جديد وأزل الموفر القديم. يؤدي التحديث بعد ذلك إلى حذف الموفر القديم وكل اتصال أُنشئ به عبر مسار قطع الاتصال المعتاد (`onDisconnectLogicFunction`، وإلغاء الرمز المميز، وتنظيف القناة)، ثم يعيد الأعضاء الاتصال عبر الموفر الجديد.

تتطلب إضافة اتصال **لي فقط** أو إعادة اتصاله إذن `CONNECTED_ACCOUNTS`، بينما تتطلب إضافة اتصال **مشترك في مساحة العمل** أو إعادة اتصاله إذن `APPLICATIONS`.

استخدم الاتصال المناسب لكل معالج:

```ts
// HTTP-route trigger — prefer the request user's own connection.
const conn =
  connections.find((c) => c.userWorkspaceId === event.userWorkspaceId) ??
  connections.find((c) => c.scope === 'WORKSPACE');

// Cron trigger — no request user; only shared credentials are sensible.
const conn = connections.find((c) => c.scope === 'WORKSPACE');
```

يُسمح بوجود اتصالات متعددة لكل (مستخدم، مزوّد)، لذا يمكن للمستخدم نفسه امتلاك "Linear شخصي" و"Linear للعمل" جنبًا إلى جنب.

يتوفر نطاق الموفّر مع Twenty 2.49.0. إذا كان تطبيقك يعلن `scope`، فأعلن `"engines": { "twenty": ">=2.49.0" }` في `package.json` الخاص به. في الإصدار نفسه، يستبدل `scope` الخاص بالاتصال `visibility` الخاص به، والذي يظل متاحًا كاسم مستعار مهمل بأحرف صغيرة. يقرأ `listConnections` و`getConnection` من `twenty-sdk` 2.49.0 قيمة `scope`، لذا تحتاج التطبيقات المنشأة به إلى خادم 2.49.0.

</Accordion>

<Accordion title="إعداد المزوّد لمرة واحدة" description="سجّل تطبيق OAuth الخاص بك لدى خدمة الطرف الثالث">

بالنسبة لكل موفّر اتصال، يحتاج مسؤول الخادم أولًا إلى تسجيل تطبيق OAuth لدى الطرف الثالث.

1. انتقل إلى إعدادات المطوّر لدى المزوّد (مثل https://linear.app/settings/api/applications/new).
2. عيّن **Redirect URI** إلى `\<SERVER_URL>/auth/apps/callback`.
3. انسخ **Client ID** و**Client Secret** المُنشأين.
4. افتح التطبيق المُثبَّت في Twenty كمسؤول خادم → عيّن القيم على `serverVariables` المقابلة.
5. يمكن لأعضاء مساحة العمل بعد ذلك إضافة اتصالات إلى موفّري `WORKSPACE` من قسم **الاتصالات** الخاص بكل تطبيق.

</Accordion>
