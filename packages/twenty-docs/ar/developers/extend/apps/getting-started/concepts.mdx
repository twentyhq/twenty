## كيف تعمل التطبيقات

التطبيق عبارة عن مجموعة من **الكيانات** يتم إعلانها باستخدام دوال `defineEntity()` من حزمة `twenty-sdk`. يكشف CLI هذه الإعلانات عن طريق تحليل AST في وقت البناء وينتج **مظاهر** - وصف كامل لما يضيفه التطبيق إلى مساحة عمل. تتحقق هذه الدوال من تكوينك وقت البناء وتوفّر إكمالًا تلقائيًا في بيئة التطوير وأمان الأنواع.

```
your-app/
├── src/
│   ├── application-config.ts    ← defineApplication (required, one per app)
│   ├── roles/                   ← defineRole
│   ├── objects/                 ← defineObject
│   ├── fields/                  ← defineField
│   ├── logic-functions/         ← defineLogicFunction
│   ├── front-components/        ← defineFrontComponent
│   ├── skills/                  ← defineSkill
│   ├── agents/                  ← defineAgent
│   ├── views/                   ← defineView
│   ├── navigation-menu-items/   ← defineNavigationMenuItem
│   ├── settings-menu-items/     ← defineSettingsMenuItem
│   └── page-layouts/            ← definePageLayout
├── public/                      ← Static assets (images, icons)
└── package.json
```

<Note>
  **مؤسسة الملفات متروكة لك.** الكشف عن الكيان يستند إلى AST-SDK
  العثور على 'تصدير افتراضي تعريف الكيانتي(. .))\` مكالمات بغض النظر عن المكان الذي يعيش فيه الملف
  . بنية المجلدات أعلاه هي اصطلاح وليست متطلبًا.
</Note>

## العزل

* **الدوال المنطقية** تعمل في عمليات Node.js معزولة على الخادم. يمكنهم الوصول إلى البيانات فقط من خلال عميل API المكتوب، الذي يعمل إما كشخص قام بتشغيل التشغيل أو كتطبيق نفسه. انظر [الذين وصلوا إلى استخدامات المكالمة](/ar/developers/extend/apps/logic/logic-functions#whose-access-a-call-uses).
* **المكوّنات الأمامية** تعمل ضمن Web Workers باستخدام Remote DOM — معزولة عن الصفحة الرئيسية لكنها تعرض عناصر DOM الأصلية (وليس iframes). تتواصل مع Twenty عبر واجهة API للمضيف تعتمد تمرير الرسائل.
* **الأذونات** تُطبَّق على مستوى واجهة API. يتم حقن رمزين لوقت التشغيل، وكلاهما مستمد من الدور المعلن مع `defineApplicationRole()`؛ يتم تضييق المجال الافتراضي أكثر إلى ما يمكن أن يفعله الشخص المحرك عندما يكون شخص ما وراء اللعب.

## دورة حياة التطبيق

```
┌─────────────────────────────────────────────────────────┐
│ Development                                             │
│   twenty app init → twenty app dev (live sync)   │
├─────────────────────────────────────────────────────────┤
│ Build & Deploy                                          │
│   twenty app build → twenty app publish        │
├─────────────────────────────────────────────────────────┤
│ Install flow                                            │
│   upload → [pre-install] → metadata migration →         │
│   generate SDK → [post-install] → … → [uninstall]       │
├─────────────────────────────────────────────────────────┤
│ Publish                                                 │
│   npm publish → appears in Twenty marketplace           │
└─────────────────────────────────────────────────────────┘
```

* **`20 تطبيق dev`** - يشاهد الملفات المصدرية الخاصة بك والمزامنة المباشرة التغييرات على خادم عشرين متصل. يُعاد توليد عميل API مضبوط الأنواع تلقائيًا عند تغيّر المخطط.
* **`بناء عشرين تطبيق`** - تجميع TypeScript، وحزم الدوال المنطقية والمكونات الأمامية مع esbuild، وإنتاج بيان بياني.
* **خطّافات ما قبل/ما بعد التثبيت وإلغاء التثبيت** — دوال اختيارية تعمل أثناء التثبيت أو مباشرة قبل الإزالة. راجع [خطّافات التثبيت](/ar/developers/extend/apps/config/install-hooks) للتفاصيل.
