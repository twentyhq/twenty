## ابدأ Twenty محليًا

ثبّت Docker وابدأ تشغيله، ثم نفّذ:

```bash
twenty local start
twenty auth login --url http://localhost:2020 --name local
```

يشغّل `local start` واجهة الويب وAPI والعامل وقواعد البيانات. يعمل خارج مجلد التطبيق
وينتظر حتى تصبح البيئة جاهزة، ويطبع عنوان URL الخاص بها. تسجيل الدخول
خطوة منفصلة. لتثبيت تطبيقك بعد ذلك، شغّل `twenty app apply --create --remote local` من دليله.

بالنسبة إلى مثيل جديد، مرّر إصدارًا صراحةً أو دع واجهة سطر الأوامر تختار أعلى
إصدار منشور يطابق `engines.twenty` الخاص بتطبيقك. خارج تطبيق يتضمن هذا
الإعداد، يستخدم `latest`. تحتفظ المثيلات الحالية بإصدارها وبياناتها.
بالنسبة إلى مثيل موجود، يُتحقق من التوافق مع `engines.twenty` باستخدام
`APP_VERSION` الخاص بالصورة، بما في ذلك عندما تكون علامتها `latest`. يؤدي الإصدار المفقود أو غير الصالح
أو غير المتوافق إلى إصدار تحذير ومتابعة بدء التشغيل.

```bash
twenty local start 2.53.1
twenty local status
twenty local logs
twenty local logs --lines 100 --no-follow
twenty local stop
```

تستمع المثيلات الجديدة فقط على واجهة الاسترجاع المحلي، على المنفذ `2020`. استخدم `--port \<port>` عند
إنشاء مثيل لاختيار منفذ آخر. استخدم سياق مقبس Docker محليًا؛
لا تدعم هذه الأوامر محركات Docker البعيدة.

## الترقية أو إعادة التعيين

```bash
twenty local upgrade 2.53.1
```

تسحب الترقية الصورة المطلوبة قبل استبدال المثيل. تحافظ على
منافذه وقاعدة بياناته ووحدات تخزين ملفاته وتجاوزات البيئة الخاصة به. تُطبَّق الإعدادات الافتراضية الجديدة لـ CLI على المثيلات المنشأة حديثًا؛ وتحافظ الترقيات على قيم البيئة الحالية.
من دون إصدار، يتبع اختيار الإصدار نفسه كما في بدء جديد. تُرفَض تخطيطات التخزين المخصصة. تُرفَض عمليات الرجوع إلى إصدار أقدم قبل استبدال الحاوية، بما في ذلك عند استخدام وسم مثل `latest`. يجب أن تعلن كلتا الصورتين عن `APP_VERSION` صالح حتى يتمكن CLI من مقارنة إصداريهما الفعليين.

مرّر `2.53` للبدء أو الترقية باستخدام وسم صورة `v2.53` العائم، أو `2.53.1` لاختيار إصدار تصحيح محدد.

إذا فشل إنشاء البديل أو أُلغي، يستعيد CLI الحاوية والإعدادات السابقتين. بمجرد بدء الإصدار الجديد، تحتفظ الترقيات الفاشلة بوحدات تخزين البيانات، لكنها لا تتراجع عن ترحيلات قاعدة البيانات.

يحتفظ `stop` بجميع البيانات. لحذف المثيل وبياناته نهائيًا، شغّل:

```bash
twenty local reset
twenty local start
```

يطلب إعادة التعيين التأكيد. يجب أن تمرر البرامج النصية `--yes`. لا تُزال الاتصالات البعيدة المحفوظة وبيانات الاعتماد.

## اختبارات التكامل

استخدم مثيل الاختبار المنفصل، بالمنفذ الافتراضي `2021`:

```bash
twenty local start --test
twenty local status --test
TWENTY_API_URL=http://localhost:2021 yarn test
```

عيّن `TWENTY_API_KEY` إلى مفتاح لذلك المثيل. تثبّت اختبارات التكامل تطبيقًا
وتلغي تثبيته، لذا أبقها منفصلة عن مساحة عمل التطوير الخاصة بك.
مرّر `--test` إلى السجلات أو الإيقاف أو الترقية أو إعادة التعيين عند إدارة هذا المثيل.

يوفّر سير عمل CI المُنشأ مثيلًا معزولًا عبر
`twentyhq/twenty/.github/actions/spawn-twenty-app-dev-test@main` ويثبّت
واجهة سطر الأوامر المستقلة بشكل منفصل.

## إعدادات محلية أخرى

بالنسبة إلى نسخة مصدر تم سحبها من Twenty، تعمل بيئة التطوير الحالية أيضًا:

```bash
bash packages/twenty-utils/setup-dev-env.sh
yarn start
twenty auth login --url http://localhost:3000 --name local
```

استخدم عنوان URL والمنفذ الفعليين لخادمك. بالنسبة إلى مساحات العمل ذات النطاقات الفرعية، استخدم
اسم مضيف مساحة العمل. للنشر في بيئة الإنتاج، اتبع
[دليل الاستضافة الذاتية](/ar/developers/self-host/self-host).

## تبعيّات المشروع

ثبّت `twenty-sdk` و`twenty-client-sdk` كتبعيّات للمشروع. ثبّت واجهة سطر الأوامر
`twenty` على مستوى النظام، ثم شغّل `twenty app typecheck` و`twenty app build` و
`twenty app apply` من دليل التطبيق.
