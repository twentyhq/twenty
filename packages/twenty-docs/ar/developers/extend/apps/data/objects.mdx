## نظرة عامة

تُعد **الكائنات** المخصصة أنواع سجلات جديدة يضيفها تطبيقك إلى مساحة العمل — مثل بطاقة بريدية، أو فاتورة، أو اشتراك، أو أي شيء خاص بالمجال الذي تعمل فيه. يعلن كل كائن عن مخططه (الحقول، والعلاقات، والقيم الافتراضية) ومعرّف عالمي ثابت يستمر عبر عمليات المزامنة والنشر.

```ts src/objects/post-card.object.ts
import { defineObject, FieldType } from 'twenty-sdk/define';

enum PostCardStatus {
  DRAFT = 'DRAFT',
  SENT = 'SENT',
  DELIVERED = 'DELIVERED',
  RETURNED = 'RETURNED',
}

export default defineObject({
  universalIdentifier: '54b589ca-eeed-4950-a176-358418b85c05',
  nameSingular: 'postCard',
  namePlural: 'postCards',
  labelSingular: 'Post Card',
  labelPlural: 'Post Cards',
  description: 'A post card object',
  icon: 'IconMail',
  fields: [
    {
      universalIdentifier: '58a0a314-d7ea-4865-9850-7fb84e72f30b',
      name: 'content',
      type: FieldType.TEXT,
      label: 'Content',
      description: "Postcard's content",
      icon: 'IconAbc',
    },
    {
      universalIdentifier: 'c6aa31f3-da76-4ac6-889f-475e226009ac',
      name: 'recipientName',
      type: FieldType.FULL_NAME,
      label: 'Recipient name',
      icon: 'IconUser',
    },
    {
      universalIdentifier: '95045777-a0ad-49ec-98f9-22f9fc0c8266',
      name: 'recipientAddress',
      type: FieldType.ADDRESS,
      label: 'Recipient address',
      icon: 'IconHome',
    },
    {
      universalIdentifier: '87b675b8-dd8c-4448-b4ca-20e5a2234a1e',
      name: 'status',
      type: FieldType.SELECT,
      label: 'Status',
      icon: 'IconSend',
      defaultValue: `'${PostCardStatus.DRAFT}'`,
      options: [
        {
          value: PostCardStatus.DRAFT,
          label: 'Draft',
          position: 0,
          color: 'gray',
        },
        {
          value: PostCardStatus.SENT,
          label: 'Sent',
          position: 1,
          color: 'orange',
        },
        {
          value: PostCardStatus.DELIVERED,
          label: 'Delivered',
          position: 2,
          color: 'green',
        },
        {
          value: PostCardStatus.RETURNED,
          label: 'Returned',
          position: 3,
          color: 'orange',
        },
      ],
    },
    {
      universalIdentifier: 'e06abe72-5b44-4e7f-93be-afc185a3c433',
      name: 'deliveredAt',
      type: FieldType.DATE_TIME,
      label: 'Delivered at',
      icon: 'IconCheck',
      isNullable: true,
      defaultValue: null,
    },
  ],
});
```

## النقاط الرئيسية

* `universalIdentifier` يجب أن يكون فريدًا وثابتًا عبر عمليات النشر.
* يتطلب كل حقل `name` و`type` و`label` ومعرّف `universalIdentifier` ثابتًا خاصًا به.
* المصفوفة `fields` اختيارية — يمكنك تعريف كائنات بدون حقول مخصصة.
* `openRecordIn` يحدد أين تُفتح سجلات هذا الكائن عند النقر عليها: `ObjectOpenRecordIn.USER_CHOICE` (الإعداد الافتراضي، الذي يتبع تفضيل كل عضو في مساحة العمل من Settings → Experience)، أو `ObjectOpenRecordIn.SIDE_PANEL`، أو `ObjectOpenRecordIn.RECORD_PAGE`. ثبِّتها على `RECORD_PAGE` للسجلات التي تحتاج إلى صفحة كاملة لتكون قابلة للاستخدام، كما هو الحال في سير العمل ولوحات المعلومات، أو على `SIDE_PANEL` للسجلات التي لا تكون منطقية إلا كلوحة سريعة، كما هو الحال في أحداث التقويم.
* تتحكم الخاصية `writability` في من يمكنه كتابة سجلات الكائن من الأساس، قبل تطبيق أذونات الأدوار: `MetadataWritability.OPEN` (القيمة الافتراضية — أدوار مساحة العمل هي التي تقرر)، أو `MetadataWritability.APPLICATION` (يمكن لوظائف منطق تطبيقك فقط إنشاء السجلات أو تحديثها أو حذفها؛ استخدم هذا لكائنات تشبه التهيئة التي تمنح سجلاتها سلوكًا، بحيث لا يتمكن أعضاء مساحة العمل الذين لديهم وصول واسع إلى السجلات من تعديلها عبر واجهة برمجة التطبيقات API)، أو `MetadataWritability.SYSTEM` (محجوزة للبيانات التي تُدار من قبل المنصّة). لا تتأثر عمليات القراءة — يتم فرض هذا من جانب الخادم، على عكس `isUIEditable`، التي تقتصر على إخفاء عناصر واجهة المستخدم. توجد هذه الخاصية أيضًا على مستوى الحقل، حيث لا يمكن أن تكون إلا أكثر تقييدًا من مستوى الكائن.
* يُعرّف `readability` من يمكنه قراءة سجلات الكائن: `MetadataReadability.OPEN` (الإعداد الافتراضي — تحدد أدوار مساحة العمل ذلك)، و`MetadataReadability.PRIVATE` (فقط الكيانات الرئيسية التي تمت مشاركة السجل معها)، و`MetadataReadability.INHERITED` (أيًّا كان من يقرأ السجل الأصل)، و`MetadataReadability.APPLICATION` (فقط دوال المنطق الخاصة بتطبيقك)، أو `MetadataReadability.SYSTEM` (البيانات التي تديرها المنصة). يتم دائمًا فرض جميع سياسات سهولة القراءة.
* يتوافق `readabilityParentFieldUniversalIdentifiers` مع `MetadataReadability.INHERITED`: المعرّفات العامة لحقول العلاقة التي تؤدي إلى السجلات الأصلية.
  * يسمّي حقل متعدد إلى واحد السجل الذي يشير إليه الصف. إن تعريف حقل واحد لعلاقة مورفية يغطي كل هدف لتلك العلاقة.
  * يسمّي حقل واحد إلى متعدد كائناً تابعاً تشير صفوفه مجدداً إلى السجل، مثل صفوف الربط لعلاقة متعدد إلى متعدد. يمكن عندئذ قراءة السجل عندما يؤدي صف واحد على الأقل من تلك الصفوف إلى سجل قابل للقراءة: تتبع الملاحظة الأشخاص والشركات والفرص التي تربطها بها أهداف الملاحظة الخاصة بها.
  * تُدمج عدة سجلات أصلية كاتحاد: يكفي سجل أصلي واحد قابل للقراءة.
  * يمنح الكائن الأصل حق الوصول بموجب سياسته الكاملة، وهي السياسة التي ينطبق استعلام للكائن الأصل عليها: إذن القارئ على الكائن الأصل، والقيود على مستوى الصف الخاصة بدوره، وقابلية قراءة الكائن الأصل نفسه. لا يظهر سجل مطلقًا عبر كائن أصل لا يستطيع قارئه الاستعلام عنه. تحدد الاشتراكات وخطافات الويب ومسارات العمل ودوال المنطق ما يصل من حدث لسجل `INHERITED` بموجب تلك السياسة نفسها.
  * تمنح صفوف المشاركة الموجودة على السجل نفسه حق الوصول تمامًا كما في سجل `PRIVATE`. يحصل منشئه على واحد عند إنشاء السجل أثناء تمكين مشاركة السجلات، لذا يظل أي شخص أنشأ سجلًا قادرًا على رؤيته، ويكون السجل الذي تكون جميع حقول الكائن الأصل فيه فارغة مرئيًا لمن تمت مشاركته معهم مباشرةً.
  * يتصرف كائن `INHERITED` الذي لا يحدد أي حقل أصل قابل للاستخدام مثل كائن `PRIVATE`.
* يحدد `sharingReach` مدى إمكانية مشاركة سجل لكائن ما بالاسم: `ObjectSharingReach.WORKSPACE` (الإعداد الافتراضي، يمكن مشاركة سجل مع أي شخص في مساحة العمل، حتى مع شخص لا يتيح دوره الوصول إلى الكائن أو يخفي عامل التصفية على مستوى الصف السجل؛ ولا يحصل إلا على ذلك السجل، لعرضه أو تعديله) أو `ObjectSharingReach.ROLE_ACCESS` (لا تتجاوز المشاركات أبدًا أذونات الدور وعلى مستوى الصف). اختر `ROLE_ACCESS` للكائنات الحساسة التي يجب أن يعني فيها عدم الوصول عدم الوصول. الأدوار التي يمكنها تحديث جميع الإعدادات ترى كل سجل لكائن `OPEN` بغض النظر عن قيود مشاركته؛ ولا تزال أذونات الكائن ومرشحات مستوى الصف تنطبق عليها. ينطبق ذلك فقط عندما تكون مشاركة السجلات مفعّلة في مساحة العمل، وفقط على الكائنات التي يمكن مشاركة سجلاتها: كائنات `MetadataReadability.OPEN` و`PRIVATE` و`INHERITED` التي ليست كائنات نظام. لا تتم مشاركة كائنات `APPLICATION` و`SYSTEM` أبدًا.
* يسرد `disabledObjectPermissionActions` أذونات الكائن التي لا يمكن منحها على الكائن: أي من `'canReadObjectRecords'` و`'canUpdateObjectRecords'` و`'canSoftDeleteObjectRecords'` و`'canDestroyObjectRecords'`، وهي العلامات نفسها التي يعيّنها الدور لكل كائن. يؤدي حفظ إذن كائن يمنح أحدها على هذا الكائن إلى الفشل، فعلى سبيل المثال يمنع `disabledObjectPermissionActions: ['canDestroyObjectRecords']` منح أي دور صلاحية التدمير عليه تحديدًا. لا يغيّر ذلك ما يمكن أن تفعله الأدوار التي تمنح إجراءً على جميع الكائنات.
* يضبط `color` لون الإبراز للكائن في واجهة المستخدم. احذفه، وسيختار Twenty واحدًا للكائن.
* يسمّي `imageIdentifierFieldMetadataUniversalIdentifier` الحقل الذي تُعرض قيمته بوصفها الصورة الرمزية للسجل. احذفه للسماح لـ Twenty باختيار القيمة الافتراضية.
* يحافظ `isLabelSyncedWithName`، على كائن أو حقل، على مزامنة اسم API مع التسمية عند تحرير التسمية في الإعدادات. تكون القيمة الافتراضية `false`، لذا تترك التسمية المعاد تسميتها الاسم دون تغيير.
* يؤدي `isSearchable: true` في حقل إلى تضمين قيمه في البحث النصي الكامل للكائن (البحث العام وقائمة الأوامر). يتطلب ذلك أن يكون الكائن نفسه قابلاً للبحث وأن يكون نوع الحقل متوافقًا مع النص. تعني القيمة المحذوفة أنه غير قابل للبحث، باستثناء حقل معرّف تسمية الكائن، الذي يكون قابلاً للبحث دائمًا ولا يمكن إلغاء الاشتراك فيه. تفرض كل مزامنة الحالة المُعلنة، لذا فإن الحقل الذي تم تبديله ليصبح قابلاً للبحث من الإعدادات يعود إلى حالته السابقة عند مزامنة تطبيقك التالية ما لم يعلن ملف البيان عنه.
* يؤدي تعيين `isAuditLogged: false` في حقل إلى إبقاء تغييراته خارج الخط الزمني للسجل. تكون قيمته الافتراضية `true`، باستثناء حقل `POSITION`، إذ تظهر تغييراته فارغة في الخط الزمني ولا يتم تسجيلها مطلقًا. عيّنه في الحقول التي يعيد تطبيقك كتابتها وفق جدول زمني، مثل طابع زمني لآخر اتصال أو علاقة تجميع، كي لا تضيف كل مزامنة صف نشاط إلى كل سجل تلمسه. لا ينتج عن تحديث يتكوّن فرقُه بالكامل من حقول غير مسجلة للتدقيق أي نشاط في الخط الزمني على الإطلاق. مثل `isSearchable`، تفرض كل عملية مزامنة الحالة المُعلنة.
* لا تحتاج الحقول المضمّنة المُعرَّفة هنا إلى `objectUniversalIdentifier` — إذ تُورَّث من الكائن الأب. استخدم [`defineField()`](/ar/developers/extend/apps/data/extending-objects) لإضافة حقول إلى كائنات لا تمتلكها.
* يمكنك إنشاء كائنات جديدة باستخدام `twenty app add object`، الذي يرشدك خلال التسمية والحقول والعلاقات. راجع [Architecture → Scaffolding entities](/ar/developers/extend/apps/getting-started/scaffolding).

<Note>
  **تُضاف الحقول الأساسية تلقائيًا.** عند تعريف كائن مخصص، ينشئ Twenty حقولًا قياسية مثل `id` و`name` و`createdAt` و`updatedAt` و`createdBy` و`updatedBy` و`deletedAt` من أجلك. لا تحتاج إلى تعريفها في مصفوفة `fields` — أضف فقط حقولك المخصصة. يمكنك تجاوز حقل افتراضي بتعريف حقل يحمل الاسم نفسه، لكن هذا نادرًا ما يكون فكرة جيدة.
</Note>

## أنواع الحقول

مجموعة القيم الكاملة لـ`FieldType`، والمصدَّرة من `twenty-sdk/define`:

| الفئة                | الأنواع                                                                                                                                                                                                                                                                      |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| نص                   | `TEXT`، `RICH_TEXT`، `ARRAY` (من السلاسل النصية)، `RAW_JSON`                                                                                                                                                                                                                 |
| عددية                | `NUMBER` (`universalSettings.dataType`: `'float'` / `'int'` / `'bigint'`)، `NUMERIC` (بدقة اعتباطية)، `RATING`، `POSITION`                                                                                                                                                   |
| التواريخ             | `DATE`, `DATE_TIME`                                                                                                                                                                                                                                                          |
| اختيار               | `BOOLEAN`، `SELECT`، `MULTI_SELECT`                                                                                                                                                                                                                                          |
| مركّبة               | `FULL_NAME`، `ADDRESS`، `EMAILS`، `PHONES`، `LINKS` (`universalSettings.type`: `'url'` (الافتراضي) / `'domain'` — يخزّن حقل النطاق المضيف المجرّد، لذا تُكتب `https://www.acme.com/careers` بالشكل `acme.com`، وتُرفض القيمة التي ليست مضيفًا)، `CURRENCY`، `ACTOR`، `FILES` |
| المعرِّفات والعلاقات | `UUID`، `RELATION`، `MORPH_RELATION` (انظر [العلاقات](/ar/developers/extend/apps/data/relations))                                                                                                                                                                               |
| النظام               | `TS_VECTOR` (متجه بحث نصي كامل، يُدار بواسطة الخادم)                                                                                                                                                                                                                         |

تُخزِّن الأنواع المركّبة عدّة حقول فرعية (مثلًا `FULL_NAME` = الاسم الأول + اسم العائلة؛ `CURRENCY` = `amountMicros` + `currencyCode`). `SELECT` و`MULTI_SELECT` يتطلّبان مصفوفة `options` كما في المثال أعلاه.

### حدد الخيارات

بالنسبة إلى `SELECT` و`MULTI_SELECT`، وفّر مصفوفة `options` غير فارغة من الكائنات. يحتوي كل خيار على `value` و`label` و`position`. `color` الخاص به اختياري وتكون قيمته الافتراضية `gray` عند حذفه أو عندما تكون قيمته null.

عند توفيره، يجب أن يكون `color` واحدًا مما يلي: `red`، `ruby`، `crimson`، `tomato`، `orange`، `amber`، `yellow`، `lime`، `grass`، `green`، `jade`، `mint`، `turquoise`، `cyan`، `sky`، `blue`، `iris`، `violet`، `purple`، `plum`، `pink`، `bronze`، `gold`، `brown`، `gray`.

يُرجع كلٌّ من `defineObject()` و`defineField()` أخطاء تحقق للألوان غير المدعومة أو لإدخالات الخيارات التي تكون null أو قيمًا أولية أو مصفوفات.

## القيم الافتراضية

يجب تضمين القيم النصية الافتراضية بين علامات اقتباس أحادية **داخل** السلسلة — `defaultValue: "'Draft'"`، وليس `defaultValue: "Draft"`. لهذا السبب يستخدم الحقل `status` أعلاه `` `'${PostCardStatus.DRAFT}'` ``.

السلاسل غير المحاطة بعلامات اقتباس محجوزة للقيم الافتراضية المحسوبة، والتي يتم تقييمها عند إنشاء سجل:

* `'uuid'` — يُنشِئ UUID (لحقول `UUID`)
* `'now'` — الطابع الزمني الحالي (لحقول `DATE_TIME`)

ينطبق نفس الاصطلاح على الحقول الفرعية النصية للقيم الافتراضية المركّبة (على سبيل المثال `{ source: "'MANUAL'" }` في حقل `ACTOR`) وكذلك على قيم `SELECT`/`MULTI_SELECT`. سيتسبّب ترك قيمة افتراضية نصية حرفية بدون علامات اقتباس في ظهور تحذير عند إنشاء التطبيق.

## قابلية قبول NULL

`isNullable` تتحكم في ما إذا كان الحقل يقبل `NULL`. القيمة الافتراضية هي `true` — يمكنك حذفها من الحقول الاختيارية. عيِّن `isNullable: false` لجعل الحقل مطلوبًا على مستوى قاعدة البيانات.

يتم تطبيق التغييرات على `isNullable` في كل عملية مزامنة، بما في ذلك عمليات المزامنة التي تحدّث حقلًا موجودًا — وبالتالي يمكنك تبديل قابلية الحقل لقبول NULL عن طريق تعديل ملف manifest وإعادة المزامنة.

<Note>
  **جعل حقل موجود غير قابل لأن يكون فارغًا يتطلب قيمة افتراضية.** عندما تغيّر حقلًا إلى `isNullable: false`، يجب أيضًا توفير `defaultValue` غير فارغ. تملأ القيمة الافتراضية أي صفوف موجودة تحتوي على `NULL` قبل تطبيق القيد `NOT NULL`؛ ومن دونها تفشل المزامنة مع الخطأ `Default value cannot be null for non-nullable fields`. تكون حقول العلاقات وحقول `TS_VECTOR` قابلة لأن تكون فارغة دائمًا، لذلك لا يكون لـ `isNullable` أي تأثير عليها.
</Note>

```ts
{
  universalIdentifier: 'b1a7c0de-1234-4f00-9abc-000000000000',
  name: 'reference',
  type: FieldType.TEXT,
  label: 'Reference',
  isNullable: false,
  defaultValue: "'N/A'",
}
```

## ماذا بعد؟

* **اربط هذا الكائن بغيره من الكائنات** — راجع صفحة [Relations](/ar/developers/extend/apps/data/relations) لمعرفة نمط العلاقة ثنائية الاتجاه.
* **أضف حقولًا إلى الكائنات التابعة لتطبيقات أخرى** — راجع [Extending Objects](/ar/developers/extend/apps/data/extending-objects) لمعرفة المزيد حول `defineField()`.
* **اعرض هذا الكائن في واجهة المستخدم (UI)** — راجع [عناصر قائمة التنقل](/ar/developers/extend/apps/layout/navigation-menu-items) لإضافة عنصر في الشريط الجانبي؛ وراجع [طرق العرض](/ar/developers/extend/apps/layout/views) لإضافة تكوينات قوائم مخصصة.
