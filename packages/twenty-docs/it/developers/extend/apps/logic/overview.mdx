## Cosa copre lo strato logico

Il **livello logico** di un'app Twenty è il codice che *viene eseguito* — handler TypeScript lato server che reagiscono a richieste HTTP, pianificazioni cron e modifiche ai record; skill e agenti di AI che vivono all'interno dello spazio di lavoro; connessioni (OAuth o un flusso di accesso personalizzato) che permettono alle tue funzioni di agire per conto dell'utente in servizi di terze parti; e canali di messaggistica che portano una posta in arrivo esterna in Twenty.

```text
            ┌─ HTTP route      ──┐
            │  Cron schedule     │
            │  Database event    │      ┌────────────────────┐
  triggers ─┤  AI tool call      ├─────▶│ Logic function     │
            │  Workflow action   │      │ (your handler)     │
            │  Manual exec       │      └────────────────────┘
            └────────────────────┘                │
                                                  ▼
                                  ┌────────────────────────────┐
                                  │ Twenty API (records)       │
                                  │ Third-party API            │
                                  │   (via Connection token)   │
                                  └────────────────────────────┘
```

## Tipi di trigger in sintesi

Una funzione logica sceglie uno o più trigger — ogni voce qui sotto è un campo separato su `defineLogicFunction()`:

| Scatenante              | Quando viene eseguito                                                 | Impostazione                    |
| ----------------------- | --------------------------------------------------------------------- | ------------------------------- |
| **Route HTTP**          | Una richiesta raggiunge il tuo endpoint `/s/\<path>` | `httpRouteTriggerSettings`      |
| **Cron**                | Viene soddisfatta un'espressione CRON                                 | `cronTriggerSettings`           |
| **Evento database**     | Un record dello spazio di lavoro viene creato, aggiornato o eliminato | `databaseEventTriggerSettings`  |
| **Strumento AI**        | Una funzionalità AI di Twenty decide di chiamare la tua funzione      | `toolTriggerSettings`           |
| **Azione del workflow** | Uno step di workflow richiama la tua funzione                         | `workflowActionTriggerSettings` |

Le funzioni vengono eseguite in sandbox in processi Node.js isolati e accedono allo spazio di lavoro tramite un client API tipizzato, limitato al ruolo dichiarato su [`defineApplication()`](/it/developers/extend/apps/config/application).

<Note>
**Hook di installazione** — codice che viene eseguito prima o dopo l'installazione — condividono questo runtime ma usano le proprie funzioni define e risiedono in [Config → Install Hooks](/it/developers/extend/apps/config/install-hooks).

Anche il [**controllo dello stato**](/it/developers/extend/apps/logic/logic-functions#health-check) lo condivide. Non dichiara alcun trigger: Twenty lo richiama su richiesta quando si apre la pagina delle impostazioni dell'app.
</Note>
