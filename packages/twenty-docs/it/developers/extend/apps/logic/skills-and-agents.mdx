## Panoramica

<Warning>
  Le skill e gli agenti sono attualmente in fase alfa. La funzionalità funziona ma è ancora in evoluzione.
</Warning>

Le app possono definire capacità di IA che risiedono all'interno dello spazio di lavoro — istruzioni di skill riutilizzabili e agenti con prompt di sistema personalizzati.

<AccordionGroup>
<Accordion title="defineSkill" description="Definisci le skill degli agenti IA">

Le skill definiscono istruzioni e capacità riutilizzabili che gli agenti IA possono utilizzare all'interno del tuo spazio di lavoro. Usa `defineSkill()` per definire skill con convalida integrata:

```ts src/skills/example-skill.ts
import { defineSkill } from 'twenty-sdk/define';

export default defineSkill({
  universalIdentifier: 'a1b2c3d4-e5f6-7890-abcd-ef1234567890',
  name: 'sales-outreach',
  label: 'Sales Outreach',
  description: 'Guides the AI agent through a structured sales outreach process',
  icon: 'IconBrain',
  content: `You are a sales outreach assistant. When reaching out to a prospect:
1. Research the company and recent news
2. Identify the prospect's role and likely pain points
3. Draft a personalized message referencing specific details
4. Keep the tone professional but conversational`,
});
```

Punti chiave:
* `name` è una stringa identificativa univoca per la skill (kebab-case consigliato).
* `label` è il nome di visualizzazione leggibile mostrato nell'UI.
* `content` contiene le istruzioni della skill — questo è il testo che l'agente IA utilizza.
* `icon` (opzionale) imposta l'icona visualizzata nell'UI.
* `description` (opzionale) fornisce contesto aggiuntivo sullo scopo della skill.

</Accordion>
<Accordion title="defineAgent" description="Definisci agenti IA con prompt personalizzati">

Gli agenti sono assistenti IA che vivono all'interno del tuo spazio di lavoro. Usa `defineAgent()` per creare agenti con un prompt di sistema personalizzato:

```ts src/agents/example-agent.ts
import { defineAgent } from 'twenty-sdk/define';

export default defineAgent({
  universalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  name: 'sales-assistant',
  label: 'Sales Assistant',
  description: 'Helps the sales team draft outreach emails and research prospects',
  icon: 'IconRobot',
  prompt: 'You are a helpful sales assistant. Help users with their questions and tasks.',
});
```

Punti chiave:
* `name` è la stringa identificativa univoca dell'agente (kebab-case consigliato).
* `label` è il nome visualizzato nell'UI.
* `prompt` è il prompt di sistema che definisce il comportamento dell'agente.
* `description` (opzionale) fornisce contesto su ciò che fa l'agente.
* `icon` (opzionale) imposta l'icona visualizzata nell'UI.
* `modelId` (opzionale) sostituisce il modello di IA predefinito utilizzato dall'agente.
* `responseFormat` (facoltativo) imposta il formato di output predefinito dell'agente. Per il testo in formato libero, il valore predefinito è `{ type: 'text' }`. Usa `{ type: 'json', schema }` per forzare un output JSON strutturato. Una chiamata a `runAgent()` o un passaggio AI di un workflow può richiedere un formato diverso, che ha la precedenza.
* `roleUniversalIdentifier` (facoltativo) associa l'agente a un ruolo definito dalla tua app. Quel ruolo non deve concedere più del ruolo dell'applicazione, altrimenti la build non riesce; vedi [Ruoli degli agenti](/it/developers/extend/apps/config/roles#agent-roles).
* `modelConfiguration` (facoltativo) attiva gli strumenti nativi del modello, come fa la pagina delle impostazioni dell'agente: `{ webSearch: { enabled: true }, twitterSearch: { enabled: true } }`. Ogni strumento funziona solo con i modelli che lo supportano. Omettilo per mantenerli disattivati.
* `isSystem` (facoltativo, il valore predefinito è `false`) nasconde l'agente dagli elenchi di agenti, come gli agenti che Twenty crea per i passaggi IA dei workflow. Modifica solo ciò che viene visualizzato: gli agenti di un'app possono essere modificati solo tramite l'app, indipendentemente da quanto indica questo flag.

Per impostazione predefinita, un agente restituisce testo in formato libero. Per ottenere un output strutturato, imposta `responseFormat` su `{ type: 'json' }` e fornisci uno `schema`:

```ts src/agents/structured-agent.ts
import { defineAgent } from 'twenty-sdk/define';

export default defineAgent({
  universalIdentifier: 'c4d5e6f7-a8b9-0123-cdef-456789012345',
  name: 'lead-scorer',
  label: 'Lead Scorer',
  prompt: 'Score the lead and explain your reasoning.',
  responseFormat: {
    type: 'json',
    schema: {
      type: 'object',
      properties: {
        score: { type: 'number', description: 'Lead score from 0 to 100' },
        summary: { type: 'string', description: 'Short reasoning for the score' },
      },
      required: ['score', 'summary'],
      additionalProperties: false,
    },
  },
});
```

Note sullo schema:
* Lo schema è un oggetto piatto: il `type` di ogni proprietà deve essere un primitivo (`string`, `number` o `boolean`). Gli oggetti annidati e gli array non sono supportati.
* `description` (facoltativo) su ogni proprietà guida il modello su cosa inserire lì.
* `required` (facoltativo) elenca le proprietà che il modello deve sempre restituire.
* `additionalProperties: false` (facoltativo) vieta qualsiasi proprietà non dichiarata in `properties`.

</Accordion>
<Accordion title="runAgent" description="Esegui un agente da una funzione di logica">

`runAgent()` permette a una funzione di logica di eseguire uno degli agenti della tua app (con le sue skill e i suoi strumenti). Identifica l'agente tramite l'`universalIdentifier` che hai passato a `defineAgent()` e passa ciò su cui vuoi che lavori come `input`:

```ts src/logic-functions/run-enricher.ts
import { runAgent } from 'twenty-sdk/logic-function';

const { threadId, status, result, error, success } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: 'Enrich House Ad <recordId>: fill empty fields from its listing URL.',
});
```

Punti chiave:
* `input` è una stringa o un elenco da 1 a 100 messaggi
  (`{ role: 'user' | 'assistant', content: string }`). Un messaggio `user` può
  anche includere allegati di file (vedi sotto). Per mantenere una conversazione, passa un
  `thread` invece di riprodurre tu stesso i turni precedenti.
* Per impostazione predefinita, la chiamata attende l'agente, che può leggere/aggiornare i record
  autonomamente tramite i propri strumenti — `runAgent()` viene risolta una volta completata l'esecuzione.
  Passa `waitForCompletion: false` per risolvere non appena l'esecuzione si avvia:
  `status` è quindi `RUNNING` e `result: null`, e la risposta arriva nella
  conversazione `threadId`. Un'esecuzione che supera i 15 minuti restituisce anch'essa
  `RUNNING`.
* L'agente può anche sospendersi finché un record non cambia o non è trascorso del tempo.
  `runAgent()` viene quindi risolto con `success: true`, `status: 'SUSPENDED'` e
  `result: null`; l'agente prosegue autonomamente in seguito e la sua risposta arriva nella
  conversazione `threadId`. Una chiamata a un `thread` il cui agente è ancora in attesa
  non riesce finché non termina.
* Ogni chiamata viene archiviata con il relativo input e stato, oltre alla risposta e all'utilizzo
  al completamento, così da comparire nelle esecuzioni dell'agente. Senza un `thread`, una chiamata riceve una conversazione
  propria: `threadId` la denomina e una chiamata successiva non la vede mai.
* Un'app può eseguire solo i propri agenti.
* Il [ruolo predefinito](/it/developers/extend/apps/config/roles) dell'app deve concedere il flag di autorizzazione `AI` — aggiungi `SystemPermissionFlag.AI` ai suoi `permissionFlagUniversalIdentifiers` (oppure imposta `canAccessAllTools: true`).
  In mancanza di ciò, `runAgent()` non riesce con un errore di autorizzazione.
* Imposta un valore generoso per `timeoutSeconds` sulla funzione di logica — l'esecuzione degli agenti può richiedere diversi secondi.
* `status` è `COMPLETED` con un `result` non null quando l'esecuzione viene completata
  senza attendere; `SUSPENDED` con `success: true` e `result: null` mentre
  attende; `RUNNING` con `success: true` e `result: null` quando la chiamata non
  ha atteso l'esecuzione; `FAILED` con `success: false` e `error` che contiene il
  motivo (ad esempio, quando lo spazio di lavoro esaurisce i crediti AI durante l'esecuzione).

```ts src/roles/default-role.ts
import { defineApplicationRole, SystemPermissionFlag } from 'twenty-sdk/define';

export default defineApplicationRole({
  universalIdentifier: 'b648f87b-1d26-4961-b974-0908fd991061',
  label: 'Default function role',
  // runAgent() requires the AI permission flag on the app's default role.
  permissionFlagUniversalIdentifiers: [SystemPermissionFlag.AI],
});
```

<Warning>
  **Evita i loop:** se chiami `runAgent()` da un trigger di evento del database `*.updated` e l'agente aggiorna lo stesso record, limita il trigger con `updatedFields` a un campo che l'agente non scrive mai (ad esempio l'URL di origine), oppure controlla che almeno uno dei campi di destinazione sia ancora vuoto prima di chiamare `runAgent()`.
</Warning>

### Invio di file con un messaggio

Un messaggio `user` può includere `attachments`, quindi l'agente vede uno screenshot o un
PDF anziché solo il relativo nome. Ogni voce fa riferimento a un file che la tua app ha già
caricato nella cartella `agent-chat`:

```ts src/logic-functions/describe-screenshot.ts
const { result } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: [
    {
      role: 'user',
      content: 'What does this error screen say?',
      attachments: [{ fileId: uploadedFileId, filename: 'error.png' }],
    },
  ],
});
```

Il caricamento richiede il flag di autorizzazione `UPLOAD_FILE` nel ruolo predefinito dell'app,
insieme ad `AI`. `filename` è facoltativo e serve solo a etichettare il file per il modello.

* Solo i messaggi `user` possono contenere allegati. Non possono essere rappresentati in un
  turno dell'assistente, quindi `runAgent()` li rifiuta lì anziché eliminarli.
* Al massimo **10** allegati per messaggio.
* Il `fileId` deve indicare un file completamente caricato nello stesso spazio di lavoro, nella
  cartella `agent-chat`. Qualsiasi altra cosa fa fallire la chiamata anziché rispondere silenziosamente
  senza il file.

### Richiedere un risultato strutturato

Passa `responseFormat` per ottenere un formato solo per questa chiamata. Ha la precedenza su
`responseFormat` dell'agente stesso, quindi un agente può servire chiamanti che necessitano di
output diversi. Utilizza lo stesso schema di `defineAgent()`:

```ts src/logic-functions/score-lead.ts
const { result } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: `Score this lead: ${JSON.stringify(lead)}`,
  responseFormat: {
    type: 'json',
    schema: {
      type: 'object',
      properties: {
        score: { type: 'number', description: 'Lead score from 0 to 100' },
      },
      required: ['score'],
    },
  },
});
```

### Proseguire una conversazione

Passa un `thread` e Twenty mantiene la conversazione per te: ogni chiamata invia solo
il nuovo input e l'agente vede i turni precedenti, inclusi i risultati restituiti
dai suoi strumenti. Usa come chiave qualsiasi identificatore stabile dal tuo lato, ad esempio un canale
Slack e il timestamp del thread:

```ts src/logic-functions/reply-in-thread.ts
const { result, threadId } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: 'What was the last touchpoint?',
  additionalInstructions: 'Answer in Slack markdown.',
  thread: { key: `${channelId}:${threadTs}`, title: 'Acme renewal' },
});
```

* Le chiavi hanno ambito limitato alla tua app e al tuo agente, quindi due app non condividono mai una
  conversazione. Solo i token di accesso dell'app possono passare un `thread`.
* `input` può contenere solo messaggi `user`: la conversazione contiene già le
  risposte dell'agente.
* `additionalInstructions` vengono fornite al modello solo per questa chiamata e non vengono
  archiviate, il che è adatto per indicazioni specifiche per richiesta, come regole di formattazione o una
  scadenza. Funzionano anche senza un `thread`.
* Ogni esecuzione viene archiviata come turno con il relativo stato, incluse quelle non riuscite. Il suo
  utilizzo viene archiviato quando l'agente restituisce il controllo, anche se ha esaurito i crediti. Un'
  esecuzione non riuscita non fa parte della conversazione, quindi la chiamata successiva non la vede.
* Le chiamate sullo stesso thread vengono eseguite una alla volta: una seconda chiamata attende che la
  prima termini, così ciascuna vede i turni precedenti.
* Quando i turni vengono eseguiti come membri diversi (vedi sotto), ciascuno vede solo il testo
  dei turni degli altri, mai i risultati dei loro strumenti, poiché questi sono stati letti con le
  autorizzazioni di qualcun altro.

### Esecuzione per conto di un membro dello spazio di lavoro

Passa `runAsWorkspaceMemberId` quando l'esecuzione viene attivata da una persona — ad esempio un chatbot che risponde a un messaggio — in modo che l'agente agisca come quel membro invece che come l'app:

```ts src/logic-functions/answer-question.ts
const { result } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: 'How many open opportunities do we have?',
  runAsWorkspaceMemberId: '20202020-0687-4c41-b707-ed1bfca972a7',
});
```

L’esecuzione quindi agisce con **il ruolo proprio del membro**: può fare tutto ciò che
quel membro può fare e niente di più, i record che crea sono attribuiti a lui e
si applicano i suoi permessi a livello di riga. Il ruolo dell’agente non partecipa — è l’impostazione predefinita dell’app per le esecuzioni senza nessuno dietro. Ometti il campo per
le esecuzioni autonome (attività pianificate, trigger di eventi del database): queste mantengono il ruolo proprio dell’agente. L’applicazione che agisce rimane collegata al contesto dell’esecuzione
per la tracciabilità, senza restringere i permessi del membro.

La tua app è responsabile di mappare la persona che ha attivato l'esecuzione a un membro dello spazio di lavoro. Per specificarne uno è necessario un token di accesso dell'app e ciò che un token può specificare dipende dal fatto che sia o meno associato a un utente:

* Un token senza alcun utente associato può specificare qualsiasi membro. Una funzione logica viene eseguita con uno, e così anche i token generati tramite `client_credentials` o da una chiave API.
* Un token emesso per conto di un utente, come quello che riceve un front component, può specificare solo il membro dell'utente stesso.

Qualsiasi altra cosa — una semplice sessione utente, una chiave API senza un token dell'app — non può specificare affatto un membro.

<Warning>
  `runAgent()` genera un errore quando il membro dello spazio di lavoro non può essere risolto — un
  membro sconosciuto o rimosso, o uno senza ruolo. Non ricorre mai al
  ruolo proprio dell'agente, poiché ciò concederebbe più accesso di quanto richiesto dal chiamante.
</Warning>

</Accordion>
<Accordion title="sendInboxMessage" description="Avvia o continua una conversazione nelle chat dei membri">

`sendInboxMessage()` pubblica un messaggio dalla tua app nelle chat di uno o più
membri dello spazio di lavoro. Può terminare con una chiamata a uno strumento a cui il membro risponde dalla chat, dopo la quale
la conversazione continua con l'assistente di Twenty.

```ts src/logic-functions/notify-first-recording.ts
import { sendInboxMessage } from 'twenty-sdk/logic-function';

const { threadId } = await sendInboxMessage({
  workspaceMemberIds: [workspaceMemberId],
  threadKey: 'first-call-recording',
  idempotencyKey: 'first-call-recording',
  title: 'Your first call recording is ready',
  text: 'Your first call was recorded: **Weekly sync**.',
  toolCall: {
    toolName: 'ask_question',
    input: {
      header: 'Share',
      question: 'Do you want to share it with the other attendees?',
      options: [{ label: 'Draft a recap email' }, { label: 'Not now' }],
    },
  },
});
```

Punti chiave:
* `workspaceMemberIds` elenca i membri che ricevono la conversazione, almeno
  uno. Il primo membro di una nuova conversazione ne è il proprietario e gli altri la seguono
  come partecipanti. Un invio successivo con la stessa chiave che elenca nuovi membri li
  aggiunge; i membri omessi mantengono la conversazione.
* `threadKey` seleziona la conversazione per questa app, condivisa da ogni membro a cui viene
  inviata. Una nuova chiave avvia una conversazione intitolata `title`; una chiave usata in precedenza
  aggiunge il messaggio a quella conversazione.
* `idempotencyKey` identifica il messaggio all'interno della conversazione. L'invio
  di nuovo con le stesse chiavi non scrive nulla di nuovo, quindi i tentativi ripetuti e le esecuzioni simultanee
  non duplicano mai un messaggio.
* `toolCall` (facoltativo) termina il messaggio con uno dei seguenti:
  * una chiamata a cui il membro risponde, che mette in pausa la conversazione: `ask_question`
    (una domanda a scelta multipla), `request_form` (campi da compilare) o
    `propose_tool_call` (una chiamata da approvare). Il relativo `input` accetta `toolName`,
    gli `arguments` con cui chiameresti lo strumento e un `summary` di una frase.
    Lo strumento deve essere uno che il ruolo predefinito dell'app potrebbe eseguire autonomamente, ad esempio
    `create_one_person` o `update_one_opportunity` (con l'`id` del record); un'
    email (`send_email` o `draft_email`, con `recipients`, `subject` e un
    `body` in HTML) non necessita dell'autorizzazione dell'app. Il membro esamina la chiamata
    nella stessa scheda di una chiamata proposta dall'assistente, la modifica se vuole e
    la chiamata approvata viene eseguita con il proprio accesso;
  * uno degli strumenti della tua app, tramite `logicFunctionUniversalIdentifier`, visualizzato
    dal relativo componente front-end con l'`input` e l'`output` che passi. Non
    mette in pausa la conversazione.
* Solo una chiamata a cui il membro risponde può essere in attesa in una conversazione alla volta:
  l'invio di un'altra prima che risponda non riesce e restituisce `THREAD_AWAITING_ANSWER`. I messaggi
  semplici e le chiamate agli strumenti dell'app vengono comunque accettati.
* Solo il membro proprietario di una conversazione può eliminarla e una conversazione
  eliminata scompare per tutti i membri: non viene ricreata e non vi viene
  aggiunto nulla. Gli altri membri possono annullare l'iscrizione per rimuoverla dalla propria
  posta in arrivo.
* Ogni membro deve avere l'autorizzazione `AI` e la chiamata non riesce senza
  scrivere il messaggio se uno di loro non può avere la conversazione. Il [ruolo predefinito](/it/developers/extend/apps/config/roles) della tua app deve concedere
  `SystemPermissionFlag.AI`.

</Accordion>
