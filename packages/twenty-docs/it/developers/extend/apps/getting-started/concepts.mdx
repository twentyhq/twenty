## Come funzionano le app

Un'app è una raccolta di **entità** dichiarate utilizzando le funzioni `defineEntity()` del pacchetto `twenty-sdk`. Il CLI rileva queste dichiarazioni tramite analisi AST al momento della costruzione e produce un **manifest** — una descrizione completa di ciò che la tua app aggiunge a uno spazio di lavoro. Queste funzioni convalidano la configurazione in fase di build e offrono il completamento automatico nell'IDE e la sicurezza dei tipi.

```
your-app/
├── src/
│   ├── application-config.ts    ← defineApplication (required, one per app)
│   ├── roles/                   ← defineRole
│   ├── objects/                 ← defineObject
│   ├── fields/                  ← defineField
│   ├── logic-functions/         ← defineLogicFunction
│   ├── front-components/        ← defineFrontComponent
│   ├── skills/                  ← defineSkill
│   ├── agents/                  ← defineAgent
│   ├── views/                   ← defineView
│   ├── navigation-menu-items/   ← defineNavigationMenuItem
│   ├── settings-menu-items/     ← defineSettingsMenuItem
│   └── page-layouts/            ← definePageLayout
├── public/                      ← Static assets (images, icons)
└── package.json
```

<Note>
  **L'organizzazione dei file sta a te.** Il rilevamento delle entità è basato su AST — l'SDK
  trova `export default defineEntity(. .)` chiamate indipendentemente da dove vive il file
  . La struttura delle cartelle sopra è una convenzione, non un requisito.
</Note>

## Sandboxing

* **Le funzioni logiche** vengono eseguite in processi Node.js isolati sul server. Essi accedono solo ai dati attraverso il client API digitato, che agisce sia come la persona che ha innescato la corsa o come l'app stessa. Vedi [Di chi accede a una chiamata](/it/developers/extend/apps/logic/logic-functions#whose-access-a-call-uses).
* **I componenti front-end** vengono eseguiti in Web Workers utilizzando il Remote DOM — isolati dalla pagina principale ma renderizzando elementi DOM nativi (non iframe). Comunicano con Twenty tramite un'API host basata sul passaggio di messaggi.
* **Le autorizzazioni** vengono applicate a livello di API. Vengono iniettati due token di runtime, entrambi derivati dal ruolo dichiarato con `defineApplicationRole()`; quello predefinito si restringe ulteriormente a ciò che la persona che innesca può fare ogni volta che qualcuno è dietro la corsa.

## Ciclo di vita dell'app

```
┌─────────────────────────────────────────────────────────┐
│ Development                                             │
│   twenty app init → twenty app dev (live sync)   │
├─────────────────────────────────────────────────────────┤
│ Build & Deploy                                          │
│   twenty app build → twenty app publish        │
├─────────────────────────────────────────────────────────┤
│ Install flow                                            │
│   upload → [pre-install] → metadata migration →         │
│   generate SDK → [post-install] → … → [uninstall]       │
├─────────────────────────────────────────────────────────┤
│ Publish                                                 │
│   npm publish → appears in Twenty marketplace           │
└─────────────────────────────────────────────────────────┘
```

* **`venti app dev`** — guarda i tuoi file sorgente e le modifiche live syncs in un server Twenty collegato. Il client API tipizzato viene rigenerato automaticamente quando lo schema cambia.
* **`venti app build`** — compila TypeScript, raggruppa funzioni logiche e componenti frontali con esbuild, e produce un manifesto.
* **Hook di pre/post-installazione e disinstallazione** — funzioni opzionali che vengono eseguite durante l’installazione o subito prima della rimozione. Vedi [Hook di installazione](/it/developers/extend/apps/config/install-hooks) per i dettagli.
