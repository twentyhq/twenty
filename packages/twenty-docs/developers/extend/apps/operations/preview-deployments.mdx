A preview deployment boots a disposable Twenty instance in CI, installs the app from your pull request on it, and comments a public URL on the PR. Anyone — a teammate, a customer — can click the link and try the app on real Twenty, without installing anything.

The whole thing runs on plain GitHub Actions:

- **A stock Twenty instance** from the [`twentycrm/twenty-app-dev`](https://hub.docker.com/r/twentycrm/twenty-app-dev) image — the same all-in-one container (server, worker, database, Redis, seeded demo workspace) you develop against locally. Your app is previewed on released Twenty, exactly what your users run.
- **A Cloudflare quick tunnel** for the public URL — account-less, no secret required.
- **A long-running job** that keeps the tunnel alive. GitHub kills jobs at 6 hours, so the preview lives for 5.

## Workflow

Drop this into `.github/workflows/app-preview.yaml` in your app repository:

```yaml .github/workflows/app-preview.yaml
name: App Preview

on:
  pull_request:

permissions:
  pull-requests: write

# One live preview per PR: a new push replaces the previous tunnel
# instead of stacking 5-hour keepalive runs.
concurrency:
  group: app-preview-${{ github.event.pull_request.number }}
  cancel-in-progress: true

jobs:
  preview:
    timeout-minutes: 310 # GitHub kills jobs at 6h; leave headroom for cleanup
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5

      - name: Start a Cloudflare quick tunnel
        id: tunnel
        run: |
          curl -fsSL -o cloudflared \
            https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
          chmod +x cloudflared
          ./cloudflared tunnel --url http://localhost:2021 \
            --no-autoupdate --logfile tunnel.log &

          url=''
          for _ in $(seq 1 60); do
            url=$(grep -oE 'https://[a-zA-Z0-9-]+\.trycloudflare\.com' tunnel.log | head -1 || true)
            [ -n "$url" ] && break
            sleep 2
          done
          [ -n "$url" ] || { cat tunnel.log; exit 1; }
          echo "url=$url" >> "$GITHUB_OUTPUT"

      - name: Start Twenty
        run: |
          # SERVER_URL must be the public tunnel origin at boot: cookies and
          # redirects are minted against it, and the front only authenticates
          # from the server's own origin. Pin the tag to the Twenty version
          # your app targets instead of relying on latest.
          docker run -d --name twenty -p 2021:2021 \
            -e NODE_PORT=2021 \
            -e SERVER_URL=${{ steps.tunnel.outputs.url }} \
            twentycrm/twenty-app-dev:latest

          for _ in $(seq 1 100); do
            curl -sf http://localhost:2021/healthz >/dev/null && break
            sleep 3
          done
          curl -sf http://localhost:2021/healthz >/dev/null

      - name: Comment the preview URL on the PR
        # Before installing, so the link lands even if the install fails.
        # On fork PRs the token is read-only; the URL is still in the job log.
        if: github.event.pull_request.head.repo.full_name == github.repository
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          gh pr comment ${{ github.event.pull_request.number }} \
            --repo ${{ github.repository }} \
            --edit-last --create-if-none \
            --body "📦 App preview: ${{ steps.tunnel.outputs.url }} — shuts down after 5 hours."

      - name: Install the app
        run: |
          corepack enable
          yarn install --immutable

          # The app-dev image ships a seeded demo workspace with a fixed API
          # key, so the CLI needs no interactive login. The key is public and
          # only valid against this throwaway container.
          mkdir -p ~/.twenty
          cat > ~/.twenty/config.json <<'EOF'
          {
            "version": 1,
            "remotes": {
              "preview": {
                "apiUrl": "http://localhost:2021",
                "apiKey": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIyMDIwMjAyMC0xYzI1LTRkMDItYmYyNS02YWVjY2Y3ZWE0MTkiLCJ0eXBlIjoiQVBJX0tFWSIsIndvcmtzcGFjZUlkIjoiMjAyMDIwMjAtMWMyNS00ZDAyLWJmMjUtNmFlY2NmN2VhNDE5IiwiaWF0IjoxNzM1Njg5NjAwLCJleHAiOjQ4OTE0NDk2MDAsImp0aSI6IjIwMjAyMDIwLWY0MDEtNGQ4YS1hNzMxLTY0ZDAwN2MyN2JhZCJ9.bfQjfyN0NEtTCLE_xPyNcwonDzlSXFoP8kdCQTdnuDc",
                "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIyMDIwMjAyMC0xYzI1LTRkMDItYmYyNS02YWVjY2Y3ZWE0MTkiLCJ0eXBlIjoiQVBJX0tFWSIsIndvcmtzcGFjZUlkIjoiMjAyMDIwMjAtMWMyNS00ZDAyLWJmMjUtNmFlY2NmN2VhNDE5IiwiaWF0IjoxNzM1Njg5NjAwLCJleHAiOjQ4OTE0NDk2MDAsImp0aSI6IjIwMjAyMDIwLWY0MDEtNGQ4YS1hNzMxLTY0ZDAwN2MyN2JhZCJ9.bfQjfyN0NEtTCLE_xPyNcwonDzlSXFoP8kdCQTdnuDc"
              }
            },
            "defaultRemote": "preview"
          }
          EOF

          yarn twenty app:publish --private --remote preview
          yarn twenty app:install --remote preview

      - name: Keep the preview alive
        run: timeout 300m sleep 18000

      - name: Cleanup
        if: always()
        run: docker rm -f twenty 2>/dev/null || true
```

Sign in with the prefilled demo credentials on the login screen; your app is installed in the seeded workspace.

## Notes

- **Pin the image tag.** `latest` moves with Twenty releases. Pin `twentycrm/twenty-app-dev` to the version your app's `engines.twenty` targets so previews don't shift under you.
- **The preview runs released Twenty.** If your app depends on an SDK capability newer than the pinned image, the app installs but that capability is missing at runtime — previews tell you how the app behaves for users on that release, which is the point.
- **Cost.** Actions minutes are free on public repositories. On private repositories a 5-hour job bills 300 runner-minutes per push, so consider gating the workflow on a label instead of every push.
- **Forks.** `pull_request` runs from forks get a read-only token, so the PR comment step is skipped; the tunnel URL is still printed in the job log.

## How Twenty runs this for its own app PRs

The [twentyhq/twenty](https://github.com/twentyhq/twenty) monorepo runs the same flow for pull requests that touch `packages/twenty-apps/**`, split across repositories so that fork-safe tokens never coexist with PR-controlled code: `app-preview-dispatch.yaml` (in twenty) lists the changed apps and dispatches to [ci-public](https://github.com/twentyhq/ci-public)'s `app-preview.yaml`, which starts the tunnel and hands the URL to ci-privileged for the PR comment before any app code runs. If you are building the preview for a single-app repository you own, the workflow above is the whole thing.
