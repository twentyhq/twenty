## Setup

The standalone CLI connects to a running Twenty server. It does not start or manage Docker containers.

Use the [self-hosting guide](/developers/self-host/self-host) to run Twenty with Docker. In a Twenty repository checkout, the existing development environment also works:

```bash
bash packages/twenty-utils/setup-dev-env.sh
yarn start
```

Then authenticate against the server URL for your workspace:

```bash
twenty auth login --url http://localhost:3000 --name local
twenty app apply --create --remote local
```

Use the actual URL and port of your server. For subdomain workspaces, use the workspace's hostname.

## Integration tests

Use a separate disposable server or workspace. Integration test setup installs an app and teardown uninstalls it. Set `TWENTY_API_URL` and `TWENTY_API_KEY` to that test instance before running `yarn test`.

The generated CI workflow provisions an isolated instance through `twentyhq/twenty/.github/actions/spawn-twenty-app-dev-test@main` and installs the standalone CLI separately.

## Project dependencies

Install `twenty-sdk` and `twenty-client-sdk` as project dependencies. Install the `twenty` CLI globally, then run `twenty app typecheck`, `twenty app build`, and `twenty app apply` from the app directory.
