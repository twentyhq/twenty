## Application API rate limit

The Twenty API accepts **500 requests per minute per application registration**, shared by every workspace that installed the app. Requests beyond that are refused with a `429`. A cron trigger starts in every workspace at the same minute, so every install draws on this budget at once:

```text
   pattern "0 3 * * *"                  the server, every minute
                                                  │
              ┌───────────────┬───────────────────┼───────────────┐
              ▼               ▼                   ▼               ▼
        workspace A     workspace B     workspace C   ...   workspace N
          03:00:00        03:00:00        03:00:00            03:00:00
              │               │                   │               │
              └───────────────┴─────────┬─────────┴───────────────┘
                                        ▼
                      500 requests per minute for the whole app
                                   N × calls  →  429
```

## How to deal with it

- **Batch database event triggers.** Set `batchMode: true`, declare `updatedFields`, and reduce the batch to distinct records before calling the API. See [Batching database events](/developers/extend/apps/logic/logic-functions#batching-database-events).
- **One request per batch, not per record.** Read with `in` filters, write with `createMany` and `upsert: true` or `updateMany`.
- **Collapse bursts into one delayed job.** Enqueue with `delayMs` and a deterministic `jobId` that includes a time window; the queue ignores an id it already holds. See [Choose your own job id](/developers/extend/apps/logic/background-jobs#choose-your-own-job-id).
- **Spread sweep crons with a random delay.** The cron handler only enqueues the job, with a random `delayMs` over a large window such as one hour, so the sweeps of all installs spread out instead of hitting the limit together.
- **Pace fan-outs with `delayMs`.** Group jobs into slots per minute and delay the next page by the slots used. See [Background jobs](/developers/extend/apps/logic/background-jobs).
- **Retry a `429` with backoff**, or re-enqueue with a delay instead of waiting inside the run.
- **Cache what does not change** in the [key-value store](/developers/extend/apps/logic/key-value-store).
