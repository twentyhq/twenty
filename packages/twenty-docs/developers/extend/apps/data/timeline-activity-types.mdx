A timeline activity type defines the stable vocabulary for an event shown in a record's timeline. Standard objects and app objects use the same contract: a type has a label and icon, can optionally bind to an object action, and can optionally render through one of your app's [front components](/developers/extend/apps/layout/front-components).

<Note>
  Timeline activity types are in beta and are coming soon in Twenty 2.34. The
  API can evolve while we learn from app developers' use cases.
</Note>

Create one with the scaffolder:

```bash filename="Terminal"
yarn twenty dev:add timelineActivityType
```

Or define it directly:

```ts filename="src/timeline-activity-types/post-card-created.ts"
import { defineTimelineActivityType } from 'twenty-sdk/define';

import { POST_CARD_UNIVERSAL_IDENTIFIER } from '../objects/post-card.object';

export default defineTimelineActivityType({
  universalIdentifier: 'f4fa646c-6e11-4d8f-a6be-c3b7a2fc7500',
  name: 'postCardCreated',
  label: 'created a post card',
  action: 'created',
  icon: 'IconMail',
  objectUniversalIdentifier: POST_CARD_UNIVERSAL_IDENTIFIER,
});
```

## Automatic and explicit events

Set both `action` and `objectUniversalIdentifier` when this type should describe the object's automatic audit events. The supported actions are `created`, `updated`, `deleted`, `restored`, `linked`, and `unlinked`. Only one type can handle the same action/object/target-relation combination in a workspace.

By default, the event is written on the source record's own timeline. To fan the event out to related records, set `targetRelationFieldUniversalIdentifier` to a one-to-many junction relation on the source object. Creating or deleting a junction row then produces `linked` or `unlinked`, while changes to the source record produce its normal action on every related target timeline.

For example, this is the same generic contract used by notes, tasks, messages, and calendar events:

```ts filename="src/timeline-activity-types/post-card-linked.ts"
import { defineTimelineActivityType } from 'twenty-sdk/define';

import { POST_CARD_RECIPIENTS_FIELD_UNIVERSAL_IDENTIFIER } from '../fields/post-card-recipients-on-post-card.field';
import { POST_CARD_UNIVERSAL_IDENTIFIER } from '../objects/post-card.object';

export default defineTimelineActivityType({
  universalIdentifier: 'f4fa646c-6e11-4d8f-a6be-c3b7a2fc7502',
  name: 'postCardLinked',
  label: 'received a post card',
  action: 'linked',
  icon: 'IconMail',
  objectUniversalIdentifier: POST_CARD_UNIVERSAL_IDENTIFIER,
  targetRelationFieldUniversalIdentifier:
    POST_CARD_RECIPIENTS_FIELD_UNIVERSAL_IDENTIFIER,
});
```

An `updated` relation event is emitted for every source update by default. Set `triggerFieldUniversalIdentifiers` when only changes to selected source fields should appear on the target timelines.

Omit `action` for an explicit domain event that your logic function creates itself. This avoids producing both an automatic audit row and an explicit row for the same operation.

```ts filename="src/timeline-activity-types/post-card-sent.ts"
import { defineTimelineActivityType } from 'twenty-sdk/define';

import { POST_CARD_UNIVERSAL_IDENTIFIER } from '../objects/post-card.object';

export default defineTimelineActivityType({
  universalIdentifier: 'f4fa646c-6e11-4d8f-a6be-c3b7a2fc7501',
  name: 'postCardSent',
  label: 'sent a post card',
  icon: 'IconSend',
  objectUniversalIdentifier: POST_CARD_UNIVERSAL_IDENTIFIER,
});
```

Create explicit events with [`createTimelineActivity()`](/developers/extend/apps/logic/logic-functions#create-a-timeline-activity). App code uses stable universal identifiers; Twenty resolves the installation-specific metadata IDs.

## Custom rendering

Without a front component, Twenty renders a native generic row from the type label, icon, and linked-object metadata. This works for standard and custom objects without an object-specific renderer.

For a fully custom row, set `frontComponentUniversalIdentifier` to a front component owned by the same app:

```ts
export default defineTimelineActivityType({
  universalIdentifier: 'f4fa646c-6e11-4d8f-a6be-c3b7a2fc7501',
  name: 'postCardSent',
  label: 'sent a post card',
  icon: 'IconSend',
  objectUniversalIdentifier: POST_CARD_UNIVERSAL_IDENTIFIER,
  frontComponentUniversalIdentifier: '88c15ae2-5f87-4a6b-b48f-1974bbe62eb7',
});
```

Inside that component, call `useTimelineActivityId()` from `twenty-sdk/front-component` to read the row ID and fetch any data your presentation needs. It returns `null` when the component is rendered outside a timeline row.

## Configuration fields

| Field                                    | Required | Description                                                                   |
| ---------------------------------------- | -------- | ----------------------------------------------------------------------------- |
| `universalIdentifier`                    | Yes      | Stable UUID for the type across installations and upgrades                    |
| `name`                                   | Yes      | App-local programmatic name                                                   |
| `label`                                  | Yes      | User-facing action text used by the native renderer                           |
| `action`                                 | No       | Automatic audit action handled by this type                                   |
| `icon`                                   | No       | Twenty icon name displayed beside the event                                   |
| `objectUniversalIdentifier`              | No       | Object this type describes; required for object-specific automatic handling   |
| `targetRelationFieldUniversalIdentifier` | No       | Junction relation used to route events to related record timelines            |
| `triggerFieldUniversalIdentifiers`       | No       | Source fields that can trigger an `updated` relation event                    |
| `frontComponentUniversalIdentifier`      | No       | App-owned front component that replaces the native row                        |

Twenty snapshots these values when an event is created, so historical rows retain their meaning after a type is edited or its app is uninstalled.
