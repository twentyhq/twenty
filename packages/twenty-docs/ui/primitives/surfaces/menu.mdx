Use `Menu` as a primitive for actions opened from a trigger. Its items supply keyboard navigation and the visual layout of [ListItem](/ui/primitives/navigation/list-item). Use [Dropdown](/ui/components/navigation/dropdown) for the primary menu, picker, and panel API with higher-level navigation.

## Anatomy

Compose the destination, positioning wrapper, and popup separately within `Menu.Root`. Put action or selection items inside the popup.

```text
Menu.Root
├── Menu.Trigger
└── Menu.Portal
    ├── Menu.Backdrop (optional)
    └── Menu.Positioner
        └── Menu.Popup
            ├── Menu.Arrow (optional)
            └── Menu.Viewport (optional)
                ├── Menu.Item
                ├── Menu.Separator
                └── Menu.LinkItem
```

| Part                            | Purpose and native target                                                                                                                |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `Root`                          | Owns open state, triggers, and menu interaction. Renders no DOM element.                                                                 |
| `Trigger`                       | Opens the menu and supplies its default anchor. Targets a button.                                                                        |
| `Portal`                        | Chooses the destination. Native props, handlers, render composition, and ref target its div.                                             |
| `Positioner`                    | Owns anchors, alignment, offsets, and collision handling. Targets its div.                                                               |
| `Popup`                         | Renders menu content and manages keyboard navigation and focus. Targets its div.                                                         |
| `Item`                          | Runs a command. Composes the ListItem row layout on a div.                                                                               |
| `LinkItem`                      | Navigates to a destination. Targets an anchor and retains native link behavior.                                                          |
| `CheckboxItem`                  | Toggles an independent boolean option. Composes a ListItem row on a div.                                                                 |
| `CheckboxItemIndicator`         | Optional custom indicator inside CheckboxItem. Targets a span.                                                                           |
| `RadioGroup`, `RadioItem`       | Coordinate mutually exclusive options. Target divs; radio items compose ListItem rows.                                                   |
| `RadioItemIndicator`            | Optional custom indicator inside RadioItem. Targets a span.                                                                              |
| `Group`, `GroupLabel`           | Group related items under a label. Target divs.                                                                                          |
| `Separator`                     | Separates groups visually. Targets a div.                                                                                                |
| `SubmenuRoot`, `SubmenuTrigger` | Add a nested menu with its own Portal, Positioner, and Popup. The root renders no element; the trigger composes a ListItem row on a div. |
| `Arrow`                         | Optional element positioned against the anchor, inside Popup. Targets a div.                                                             |
| `Backdrop`                      | Optional upstream backdrop inside Portal. Targets a div.                                                                                 |
| `Viewport`                      | Optional transition container for content opened by multiple triggers. Targets a div.                                                    |

All rendered parts retain the installed Base UI native attributes, handlers, refs, and element/function `render` composition. Custom components must forward the supplied props and ref. Menu items include the ListItem row layout and selection indicators. Supply labels as children and use `startIcon`, `endIcon`, and `description` for supporting content. LinkItem retains its native anchor contract; compose ListItem through its `render` prop when you need the same row presentation.

Every part has public `Menu<Part>Props` and `Menu<Part>State` types. `MenuRootProps`, `MenuTriggerProps`, and `MenuHandle` retain payload generics. Root and selection callback event details and reasons, `MenuRootActions`, and `MenuRootOrientation` are also exported from `twenty-ui/primitives/surfaces`. Import `MenuItemProps` from that family for `Menu.Item`; the separate legacy MenuItem component retains its own type in `twenty-ui/components/navigation`.

## Uncontrolled state

Use `defaultOpen` to set the initial visibility. The menu owns subsequent changes from its trigger, item selection, and dismissal interactions.

```tsx
import { IconCopy, IconTrash } from 'twenty-ui/icon';
import { Button } from 'twenty-ui/primitives/input';
import { Menu } from 'twenty-ui/primitives/surfaces';

type RecordMenuProps = { onDuplicate: () => void; onDelete: () => void };

export const RecordMenu = ({ onDuplicate, onDelete }: RecordMenuProps) => (
  <Menu.Root defaultOpen={false}>
    <Menu.Trigger render={<Button>Record actions</Button>} />
    <Menu.Portal>
      <Menu.Positioner>
        <Menu.Popup>
          <Menu.Item startIcon={<IconCopy />} onClick={onDuplicate}>
            Duplicate
          </Menu.Item>
          <Menu.Separator />
          <Menu.Item
            startIcon={<IconTrash />}
            color="danger"
            onClick={onDelete}
          >
            Delete
          </Menu.Item>
        </Menu.Popup>
      </Menu.Positioner>
    </Menu.Portal>
  </Menu.Root>
);
```

`defaultOpen` defaults to `false`, so it can be omitted. Action items close the menu when selected by default. `disabled` prevents selection. `shortcut` displays shortcut hints; register shortcut handlers in your application.

## Controlled state

Pass `open` and update it with `onOpenChange` to own the same menu's visibility in React state. The callback receives the next boolean and event details, including dismissal and item selection.

```tsx
import { useState } from 'react';
import { IconCopy, IconTrash } from 'twenty-ui/icon';
import { Button } from 'twenty-ui/primitives/input';
import { Menu } from 'twenty-ui/primitives/surfaces';

type RecordMenuProps = { onDuplicate: () => void; onDelete: () => void };

export const RecordMenu = ({ onDuplicate, onDelete }: RecordMenuProps) => {
  const [open, setOpen] = useState(false);

  return (
    <Menu.Root open={open} onOpenChange={setOpen}>
      <Menu.Trigger render={<Button>Record actions</Button>} />
      <Menu.Portal>
        <Menu.Positioner>
          <Menu.Popup>
            <Menu.Item startIcon={<IconCopy />} onClick={onDuplicate}>
              Duplicate
            </Menu.Item>
            <Menu.Separator />
            <Menu.Item
              startIcon={<IconTrash />}
              color="danger"
              onClick={onDelete}
            >
              Delete
            </Menu.Item>
          </Menu.Popup>
        </Menu.Positioner>
      </Menu.Portal>
    </Menu.Root>
  );
};
```

## Selection and submenus

Item selection is independent of popup visibility. Checkbox items use `defaultChecked` or `checked` with `onCheckedChange`. Radio groups use `defaultValue` or `value` with `onValueChange`.

For a submenu, place `SubmenuRoot` inside the parent popup, with its own trigger, portal, positioner, and popup. Each nested menu retains its own positioning and keyboard behavior.

```text
Menu.Popup
└── Menu.SubmenuRoot
    ├── Menu.SubmenuTrigger
    └── Menu.Portal
        └── Menu.Positioner
            └── Menu.Popup
                └── Menu.RadioGroup
                    ├── Menu.RadioItem
                    └── Menu.RadioItem
```

### Uncontrolled item state

Each checkbox item and radio group owns its selection. Both the menu and submenu also manage their own visibility.

```tsx
import { Button } from 'twenty-ui/primitives/input';
import { Menu } from 'twenty-ui/primitives/surfaces';

export const ViewMenu = () => (
  <Menu.Root>
    <Menu.Trigger render={<Button>View options</Button>} />
    <Menu.Portal>
      <Menu.Positioner>
        <Menu.Popup>
          <Menu.CheckboxItem defaultChecked={false}>
            Show archived records
          </Menu.CheckboxItem>
          <Menu.Separator />
          <Menu.SubmenuRoot>
            <Menu.SubmenuTrigger>Layout</Menu.SubmenuTrigger>
            <Menu.Portal>
              <Menu.Positioner>
                <Menu.Popup>
                  <Menu.RadioGroup defaultValue="list">
                    <Menu.RadioItem value="list">List</Menu.RadioItem>
                    <Menu.RadioItem value="board">Board</Menu.RadioItem>
                  </Menu.RadioGroup>
                </Menu.Popup>
              </Menu.Positioner>
            </Menu.Portal>
          </Menu.SubmenuRoot>
        </Menu.Popup>
      </Menu.Positioner>
    </Menu.Portal>
  </Menu.Root>
);
```

### Controlled item state

The application owns the same selections in React state. Popup visibility remains uncontrolled because neither root receives `open`.

```tsx
import { useState } from 'react';
import { Button } from 'twenty-ui/primitives/input';
import { Menu } from 'twenty-ui/primitives/surfaces';

export const ViewMenu = () => {
  const [showArchived, setShowArchived] = useState(false);
  const [view, setView] = useState('list');

  return (
    <Menu.Root>
      <Menu.Trigger render={<Button>View options</Button>} />
      <Menu.Portal>
        <Menu.Positioner>
          <Menu.Popup>
            <Menu.CheckboxItem
              checked={showArchived}
              onCheckedChange={setShowArchived}
            >
              Show archived records
            </Menu.CheckboxItem>
            <Menu.Separator />
            <Menu.SubmenuRoot>
              <Menu.SubmenuTrigger>Layout</Menu.SubmenuTrigger>
              <Menu.Portal>
                <Menu.Positioner>
                  <Menu.Popup>
                    <Menu.RadioGroup value={view} onValueChange={setView}>
                      <Menu.RadioItem value="list">List</Menu.RadioItem>
                      <Menu.RadioItem value="board">Board</Menu.RadioItem>
                    </Menu.RadioGroup>
                  </Menu.Popup>
                </Menu.Positioner>
              </Menu.Portal>
            </Menu.SubmenuRoot>
          </Menu.Popup>
        </Menu.Positioner>
      </Menu.Portal>
    </Menu.Root>
  );
};
```

Checkbox and radio items keep the popup open by default so users can adjust options. Use `closeOnClick` to change that behavior. Nest `SubmenuRoot`, `SubmenuTrigger`, `Portal`, `Positioner`, and `Popup` inside a parent popup for submenus. Each `SubmenuRoot` has its own `defaultOpen`, `open`, and `onOpenChange` props, independent of the parent menu.

## Compose a trigger

Use `render` to make a Twenty UI `Button` the trigger. The menu supplies the button's activation handlers and accessibility attributes.

```tsx
import { IconCopy, IconTrash } from 'twenty-ui/icon';
import { Button } from 'twenty-ui/primitives/input';
import { Menu } from 'twenty-ui/primitives/surfaces';

type RecordMenuProps = { onDuplicate: () => void; onDelete: () => void };

export const RecordMenu = ({ onDuplicate, onDelete }: RecordMenuProps) => (
  <Menu.Root>
    <Menu.Trigger render={<Button variant="outline">Record actions</Button>} />
    <Menu.Portal>
      <Menu.Positioner>
        <Menu.Popup>
          <Menu.Item startIcon={<IconCopy />} onClick={onDuplicate}>
            Duplicate
          </Menu.Item>
          <Menu.Separator />
          <Menu.Item
            startIcon={<IconTrash />}
            color="danger"
            onClick={onDelete}
          >
            Delete
          </Menu.Item>
        </Menu.Popup>
      </Menu.Positioner>
    </Menu.Portal>
  </Menu.Root>
);
```

Put `Button` in the trigger's `render` prop to preserve a single interactive control. For custom wrapper components, [forward the supplied props and ref](/ui/primitives/overview#custom-components).

## Keyboard and placement

Arrow keys move through the items, including disabled ones, which receive focus but cannot be selected; typeahead finds items by their text. Enter or Space selects an item. Escape closes the menu and returns focus to its trigger. Use clear text labels even when items have icons.

`Positioner` accepts the full installed positioning contract: element/ref/function/virtual anchors, functional offsets, `positionMethod`, `collisionBoundary`, `collisionPadding`, `collisionAvoidance`, `arrowPadding`, `sticky`, and `disableAnchorTracking`. Placement defaults depend on whether it is a top-level menu or a submenu:

| Menu           | `side`       | `align` | `sideOffset` | `alignOffset` |
| -------------- | ------------ | ------- | ------------ | ------------- |
| Top-level menu | `bottom`     | `start` | `8`          | `0`           |
| Submenu        | `inline-end` | `start` | `0`          | `-4`          |

DirectionProvider controls logical side placement and supplies the native direction attribute. An explicit `dir` overrides the attribute; use the provider to change logical positioning. Popup's `initialFocus` and `finalFocus` keep the upstream focus targets and callbacks.

```tsx
import { Button } from 'twenty-ui/primitives/input';
import { Menu } from 'twenty-ui/primitives/surfaces';

export const PositionedMenu = () => (
  <Menu.Root>
    <Menu.Trigger render={<Button>Record actions</Button>} />
    <Menu.Portal>
      <Menu.Positioner
        side="bottom"
        align="end"
        sideOffset={({ anchor }) => anchor.height / 2}
        positionMethod="fixed"
        collisionBoundary="clipping-ancestors"
        collisionPadding={12}
        collisionAvoidance={{ side: 'flip', align: 'shift' }}
      >
        <Menu.Popup>
          <Menu.Arrow />
          <Menu.Item>Duplicate</Menu.Item>
        </Menu.Popup>
      </Menu.Positioner>
    </Menu.Portal>
  </Menu.Root>
);
```

## Portal destinations and theme

Set `container` and `keepMounted` on `Portal`:

| Container                   | Resolution                                                                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Omitted or `undefined`      | Uses the nearest scoped ThemeProvider container. Without one, Base UI uses its parent portal or document body.                                |
| `null`                      | Waits without rendering portal content until the container changes.                                                                           |
| Element, ShadowRoot, or ref | Passes the supplied target to Base UI. An unresolved ref retains its parent-portal/body fallback; use explicit null when waiting is required. |

The default scoped destination preserves [theme tokens and color scheme](/ui/theming). An explicit destination inherits CSS from its actual DOM scope, so put it inside the intended theme scope or supply the theme styles there. ShadowRoot targets need the library's CSS and theme styles in that shadow tree. React context and provided text direction remain available across portals. This API does not expand the renderer's permitted portal destinations.

## Detached triggers and payloads

`Menu.createHandle<TPayload>()` connects detached triggers to a root and exposes `open(triggerId)`, `close()`, and `isOpen`. `Menu.Handle` is the installed upstream handle constructor. Root's render function receives the active trigger's payload. `Viewport` supports transitions when multiple triggers change one popup's content. Call imperative actions from event handlers or effects.

```tsx
import { useState } from 'react';
import { Button } from 'twenty-ui/primitives/input';
import { Menu } from 'twenty-ui/primitives/surfaces';

export const RecordMenus = () => {
  const [handle] = useState(() => Menu.createHandle<{ name: string }>());

  return (
    <>
      <Menu.Trigger
        handle={handle}
        id="first-record"
        payload={{ name: 'First record' }}
        render={<Button>First record</Button>}
      />
      <Menu.Trigger
        handle={handle}
        id="second-record"
        payload={{ name: 'Second record' }}
        render={<Button>Second record</Button>}
      />
      <Menu.Root handle={handle}>
        {({ payload }) => (
          <Menu.Portal>
            <Menu.Positioner>
              <Menu.Popup>
                <Menu.Viewport>
                  <Menu.Group>
                    <Menu.GroupLabel>{payload?.name}</Menu.GroupLabel>
                    <Menu.Item>Duplicate</Menu.Item>
                  </Menu.Group>
                </Menu.Viewport>
              </Menu.Popup>
            </Menu.Positioner>
          </Menu.Portal>
        )}
      </Menu.Root>
    </>
  );
};
```

Root's `onOpenChange` and selection callbacks retain their upstream event details, including `reason`, `event`, and `cancel()`. Calling `cancel()` prevents the requested change. Root details also expose `trigger` and `preventUnmountOnClose()`. Controlled roots retain `triggerId`; uncontrolled roots retain `defaultTriggerId`. `actionsRef` exposes close/unmount actions.

## Migration

Move `container` and `keepMounted` from Popup to Portal. Move positioning, anchor, and collision props to Positioner. Popup's native props, handlers, focus props, and ref continue to target the content element. Rename `MenuActionItemProps` to `MenuItemProps` and import it from `twenty-ui/primitives/surfaces` to distinguish it from the legacy component type. Dropdown keeps its existing convenient assembly and navigation behavior.

Renderer portal, geometry, scrolling, and dismissal capability work remains separate from this primitive API. Keep front components within the existing scoped portal policy and use the SDK host API for dialogs.

## Labels

Supply labels through each part’s children and native accessible attributes. `Item`, `CheckboxItem`, `RadioItem`, and `SubmenuTrigger` accept `shortcutJoinLabel` to replace the default `then` between sequential shortcut steps.
