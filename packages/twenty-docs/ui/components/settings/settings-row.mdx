`SettingsRow` combines the appearance of [ListItem](/ui/primitives/navigation/list-item) with [Switch](/ui/primitives/input/switch). It renders a native label associated with its switch. Your application supplies the row content and owns any preference updates.

## Configure the switch

Pass the complete [Switch contract](/ui/primitives/input/switch) through `switchProps`. This includes checked state, event details, disabled and read-only behavior, size, native form configuration, handlers, refs, and render composition.

Use `switchProps.checked` and `switchProps.onCheckedChange` when your application owns the value. The handler receives the next checked state and Base UI event details. Clicking the label or switch invokes it once. Call `eventDetails.cancel()` to reject a change, and keep your controlled value unchanged when the change is canceled.

```tsx
import { useState } from 'react';
import { SettingsRow } from 'twenty-ui/components/settings';
import { IconBell } from 'twenty-ui/icon';

export const NotificationSetting = () => {
  const [enabled, setEnabled] = useState(false);

  return (
    <SettingsRow
      startElement={<IconBell aria-hidden />}
      switchProps={{ checked: enabled, onCheckedChange: setEnabled }}
    >
      Notifications
    </SettingsRow>
  );
};
```

Use `switchProps.defaultChecked` for an uncontrolled setting. Keyboard users focus the switch and press Space. `switchProps.disabled` disables the control and applies the row's disabled appearance. `switchProps.readOnly` prevents changes while keeping the switch focusable.

```tsx
import { SettingsRow } from 'twenty-ui/components/settings';

export const WorkspaceSettings = () => (
  <>
    <SettingsRow switchProps={{ disabled: true }}>Notifications</SettingsRow>
    <SettingsRow switchProps={{ readOnly: true, defaultChecked: true }}>
      Activity history
    </SettingsRow>
  </>
);
```

## Row content and accessible text

`children`, `startElement`, and `description` accept caller-owned nodes. The children supply the switch's accessible name, and the description supplies its accessible description. Keep content inside the label non-interactive. For navigation or action rows, use [ListItem](/ui/primitives/navigation/list-item) with a button or link.

```tsx
import { SettingsRow } from 'twenty-ui/components/settings';

export const WeeklyDigestSetting = () => (
  <SettingsRow
    description="Sent every Monday"
    switchProps={{ defaultChecked: true, name: 'digest' }}
  >
    Weekly digest
  </SettingsRow>
);
```

Set `switchProps['aria-label']`, `switchProps['aria-labelledby']`, or `switchProps['aria-describedby']` to supply your own accessible text. An explicit `aria-label` replaces the generated name association; explicit `aria-labelledby` and `aria-describedby` values replace the corresponding generated associations.

## Native targets and composition

Label customization and control customization have separate targets:

| Props                                                                                | Target                                  |
| ------------------------------------------------------------------------------------ | --------------------------------------- |
| `SettingsRow` native attributes, handlers, `className`, `style`, `ref`, and `render` | The outer native label                  |
| `switchProps` native attributes, handlers, `className`, `style`, `ref`, and `render` | The visible Switch root                 |
| `switchProps.inputRef`, `name`, `value`, `uncheckedValue`, `required`, and `form`    | The Switch's underlying native checkbox |

The label's `htmlFor` is managed internally and follows `switchProps.id`, or a generated control ID when no ID is supplied. With the default Switch composition, this ID identifies the underlying checkbox. With `switchProps.nativeButton`, it identifies the visible button. `switchProps.ref` targets the visible root in both cases. A root `id` identifies the label.

Preserve the native label when composing the row with `render`, and forward the render callback props to your element. Its `props.children` contains the complete row, including the switch.

```tsx
import { useRef } from 'react';
import { SettingsRow } from 'twenty-ui/components/settings';

export const ComposedNotificationSetting = () => {
  const labelRef = useRef<HTMLLabelElement>(null);
  const controlRef = useRef<HTMLElement>(null);
  const inputRef = useRef<HTMLInputElement>(null);

  return (
    <SettingsRow
      id="notification-row"
      ref={labelRef}
      render={<label data-setting="notifications" />}
      switchProps={{
        id: 'notification-control',
        ref: controlRef,
        inputRef,
        nativeButton: true,
        render: <button />,
      }}
    >
      Notifications
    </SettingsRow>
  );
};
```

Native label handlers receive label events and bubbled control events. Calling `preventDefault()` on a label click prevents its native control activation. Use `switchProps.onCheckedChange` for preference updates, rather than inferring state from a label click.

The switch defaults to `switchProps.size="sm"`; use `"md"` for a larger switch. The row height stays the same. `focused` applies the row's highlighted appearance without moving keyboard focus. Switch state-based `className`, `style`, and `render` callbacks remain available through `switchProps`.

## Front component renderer

Inside a front component, use the native button composition for a switch nested in the row's label:

```tsx
import { SettingsRow } from 'twenty-ui/components/settings';

export const FrontComponentNotificationSetting = () => (
  <SettingsRow switchProps={{ nativeButton: true, render: <button /> }}>
    Notifications
  </SettingsRow>
);
```

This composition activates once when clicking the label or control. The renderer's asynchronous event bridge cannot cancel the host label's default activation in time for a span-based control, which can produce duplicate change callbacks on a direct control click. Native form validation attributes such as `required` are also filtered by the current renderer. Standalone `SettingsRow` retains the full Switch form contract.

## Forms and reset

`switchProps.name`, `value`, and `required` configure the underlying checkbox for form submission and validation. A checked switch submits its value. An unchecked switch omits the value unless `uncheckedValue` is supplied. Use `switchProps.form` to associate the input with a form outside the row's parent tree.

For controlled form reset, restore the application-owned checked value in the form's `onReset` handler. Base UI 1.8 does not restore uncontrolled switch state on native form reset. `SettingsRow` preserves this upstream behavior.

```tsx
import { useState } from 'react';
import { SettingsRow } from 'twenty-ui/components/settings';
import { Button } from 'twenty-ui/primitives/input';

export const NotificationPreferences = () => {
  const [enabled, setEnabled] = useState(true);

  return (
    <form onReset={() => setEnabled(true)}>
      <SettingsRow
        switchProps={{
          checked: enabled,
          onCheckedChange: setEnabled,
          name: 'notifications',
          value: 'enabled',
          uncheckedValue: 'disabled',
        }}
      >
        Notifications
      </SettingsRow>
      <Button type="reset">Reset</Button>
    </form>
  );
};
```
