## Cómo funcionan las aplicaciones

Una aplicación es un conjunto de **entidades** declaradas usando funciones `defineEntity()` del paquete `twenty-sdk`. La CLI detecta estas declaraciones a través de análisis AST en tiempo de construcción y produce un **manifiesto** — una descripción completa de lo que su aplicación añade a un espacio de trabajo. Estas funciones validan tu configuración en tiempo de compilación y proporcionan autocompletado en el IDE y seguridad de tipos.

```
your-app/
├── src/
│   ├── application-config.ts    ← defineApplication (required, one per app)
│   ├── roles/                   ← defineRole
│   ├── objects/                 ← defineObject
│   ├── fields/                  ← defineField
│   ├── logic-functions/         ← defineLogicFunction
│   ├── front-components/        ← defineFrontComponent
│   ├── skills/                  ← defineSkill
│   ├── agents/                  ← defineAgent
│   ├── views/                   ← defineView
│   ├── navigation-menu-items/   ← defineNavigationMenuItem
│   ├── settings-menu-items/     ← defineSettingsMenuItem
│   └── page-layouts/            ← definePageLayout
├── public/                      ← Static assets (images, icons)
└── package.json
```

<Note>
  **La organización de archivos depende de ti.** La detección de entidades está basada en AST — el SDK
  encuentra `export default defineEntity(. .)` llama independientemente del lugar donde resida el archivo
  . La estructura de carpetas anterior es una convención, no un requisito.
</Note>

## Sandboxing

* **Las funciones de lógica** se ejecutan en procesos de Node.js aislados en el servidor. Sólo acceden a los datos a través del cliente de API escrito, que actúa como la persona que activó la ejecución o como la aplicación misma. Ver [Quién accede a un uso de llamadas](/es/developers/extend/apps/logic/logic-functions#whose-access-a-call-uses).
* **Los componentes de frontend** se ejecutan en Web Workers usando Remote DOM — aislados de la página principal pero renderizando elementos DOM nativos (no iframes). Se comunican con Twenty a través de una API de host de paso de mensajes.
* **Los permisos** se aplican a nivel de API. Se inyectan dos fichas de tiempo de ejecución, ambas derivadas del rol declarado con `defineApplicationRole()`; el valor por defecto se limita más a lo que la persona activadora puede hacer cuando alguien está detrás de la ejecución.

## Ciclo de vida de la aplicación

```
┌─────────────────────────────────────────────────────────┐
│ Development                                             │
│   twenty app init → twenty app dev (live sync)   │
├─────────────────────────────────────────────────────────┤
│ Build & Deploy                                          │
│   twenty app build → twenty app publish        │
├─────────────────────────────────────────────────────────┤
│ Install flow                                            │
│   upload → [pre-install] → metadata migration →         │
│   generate SDK → [post-install] → … → [uninstall]       │
├─────────────────────────────────────────────────────────┤
│ Publish                                                 │
│   npm publish → appears in Twenty marketplace           │
└─────────────────────────────────────────────────────────┘
```

* **`veinte aplicaciones dev`** — observa tus archivos de origen y los cambios en live-syncs a un servidor conectado Veenty . El cliente de API tipado se regenera automáticamente cuando cambia el esquema.
* **`veinte apps build`** — compila TypeScript, agrupa funciones lógicas y componentes frontales con esbuild, y produce un manifiesto.
* **Hooks de pre/post-instalación y desinstalación** — funciones opcionales que se ejecutan durante la instalación o justo antes de la desinstalación. Consulta [Hooks de instalación](/es/developers/extend/apps/config/install-hooks) para más detalles.
