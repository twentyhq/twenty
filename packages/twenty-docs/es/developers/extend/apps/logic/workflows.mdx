Las aplicaciones pueden incluir flujos de trabajo. Cada llamada a `defineWorkflow()` describe un flujo de trabajo: un desencadenador y los pasos que ejecuta. Al instalarse, Twenty lo crea como un flujo de trabajo activo en el espacio de trabajo, listo para ejecutarse.

## Define un flujo de trabajo

Este flujo de trabajo se ejecuta cuando se crea una empresa. Llama a una de las funciones lógicas de la aplicación y, después, escribe el resultado en la empresa:

```ts src/workflows/score-new-companies.ts
import {
  defineWorkflow,
  STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS,
} from 'twenty-sdk/define';

const COMPANY = STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS.company.universalIdentifier;
const SCORE_COMPANY_FUNCTION = '0f6c0b3e-8a4f-4f0e-9d0a-3c1e5b7a2d41';

const SCORE_NEW_COMPANIES = {
  workflow: 'c2a4e6f8-1b3d-4f5a-8c7e-9d0b2a4c6e81',
  trigger: 'c2a4e6f8-1b3d-4f5a-8c7e-9d0b2a4c6e82',
  score: 'c2a4e6f8-1b3d-4f5a-8c7e-9d0b2a4c6e83',
  save: 'c2a4e6f8-1b3d-4f5a-8c7e-9d0b2a4c6e84',
};

export default defineWorkflow({
  universalIdentifier: SCORE_NEW_COMPANIES.workflow,
  name: 'Score new companies',
  version: {
    trigger: {
      universalIdentifier: SCORE_NEW_COMPANIES.trigger,
      type: 'DATABASE_EVENT',
      settings: {
        objectUniversalIdentifier: COMPANY,
        action: 'created',
      },
      nextStepIds: [SCORE_NEW_COMPANIES.score],
    },
    steps: [
      {
        universalIdentifier: SCORE_NEW_COMPANIES.score,
        name: 'Score the company',
        type: 'LOGIC_FUNCTION',
        logicFunctionUniversalIdentifier: SCORE_COMPANY_FUNCTION,
        input: { companyName: '{{trigger.properties.after.name}}' },
        nextStepIds: [SCORE_NEW_COMPANIES.save],
      },
      {
        universalIdentifier: SCORE_NEW_COMPANIES.save,
        name: 'Save the score',
        type: 'UPDATE_RECORD',
        input: {
          objectUniversalIdentifier: COMPANY,
          objectRecordId: '{{trigger.recordId}}',
          objectRecord: { leadScore: `{{${SCORE_NEW_COMPANIES.score}.score}}` },
          fieldsToUpdate: ['leadScore'],
        },
        nextStepIds: [],
      },
    ],
  },
});
```

Puntos clave:

* El flujo de trabajo, su desencadenador y cada paso necesitan su propio `universalIdentifier`. Mantenlos estables entre versiones: así es como Twenty encuentra el flujo de trabajo instalado en la próxima instalación.
* `nextStepIds` conecta el grafo. El desencadenador apunta a los primeros pasos, y cada paso apunta a los pasos que se ejecutan después de él.
* Un paso lee la salida anterior con `{{trigger.\<path>}}` o `{{\<step universalIdentifier>.\<path>}}`.
* La compilación valida toda la definición: los tipos de desencadenador o de paso no compatibles, los enlaces de pasos rotos y las referencias a pasos desconocidos hacen que falle.

## Referencia a otras entidades

Los pasos y los desencadenadores apuntan a metadatos mediante identificador universal, nunca por nombre o id:

* **Objetos y campos**: los propios de tu aplicación o los estándar mediante `STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS`. El ejemplo anterior supone que la aplicación también define un campo numérico `leadScore` en Company con [`defineField()`](/es/developers/extend/apps/data/extending-objects): un paso de registro que escribe en un campo que falta en el espacio de trabajo hace que falle la instalación.
* **Funciones lógicas**: las propias de tu aplicación, expuestas como una [acción de flujo de trabajo](/es/developers/extend/apps/logic/logic-functions#exposing-a-function-as-an-ai-tool-or-workflow-action) con `workflowActionTriggerSettings`.
* **Agentes**: los propios de tu aplicación, de [`defineAgent()`](/es/developers/extend/apps/logic/skills-and-agents).

Una referencia que Twenty no puede resolver hace que falle la instalación.

## Disparadores

| Tipo             | Se ejecuta cuando                                      | Configuración                                                                                                                                                                            |
| ---------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MANUAL`         | Un usuario lo inicia                                   | `availability` (opcional): `GLOBAL`, o `SINGLE_RECORD` / `BULK_RECORDS` con un `objectUniversalIdentifier`. Añade una entrada al menú de comandos, con `icon` e `isPinned` opcionales.   |
| `CRON`           | Según una programación                                 | `type`: `DAYS`, `HOURS` o `MINUTES` con un `schedule`, o `CUSTOM` con un `pattern` de cron.                                                                                              |
| `DATABASE_EVENT` | Un registro cambia                                     | `objectUniversalIdentifier`, `action` (`created`, `updated`, `deleted`, `upserted`), `fieldUniversalIdentifiers` opcionales para supervisar (solo actualizaciones y upserts) y `filter`. |
| `WEBHOOK`        | Una solicitud HTTP llega a la URL del flujo de trabajo | `httpMethod` (`GET` o `POST`) y `expectedBody` para `POST`.                                                                                                                              |

Un flujo de trabajo manual sin `availability` no obtiene ninguna entrada en el menú de comandos.

Un flujo de trabajo de webhook escucha en `https://\<your-twenty-domain>/webhooks/workflows/\<workspaceId>/\<workflowId>`, donde `workflowId` es el id del flujo de trabajo instalado. El cuerpo de la solicitud está disponible como `{{trigger.\<path>}}`.

## Pasos

Los flujos de trabajo de aplicación admiten estos tipos de pasos: `LOGIC_FUNCTION`, `AI_AGENT`, `HTTP_REQUEST`, `CLASSIFY`, `CREATE_RECORD`, `UPDATE_RECORD`, `UPSERT_RECORD`, `DELETE_RECORD`, `FIND_RECORDS`, `PICK_RECORD`, `FILTER`, `IF_ELSE`, `ITERATOR`, `FORM`, `DELAY`, `WAIT_FOR_EVENT` y `EMPTY`.

Sus entradas coinciden con los pasos del [generador de flujos de trabajo](/es/user-guide/workflows/capabilities/workflow-actions), con identificadores universales en lugar de nombres:

* Los pasos de registro usan `objectUniversalIdentifier` en lugar de un nombre de objeto.
* Los filtros y las ordenaciones apuntan a campos con `fieldMetadataUniversalIdentifier`.
* Para ejecutar tu propio código, usa un paso `LOGIC_FUNCTION`. El paso Código del generador no está disponible, ni tampoco los pasos de correo electrónico y calendario.

## Después de la instalación

* El flujo de trabajo está activo en cuanto se instala la aplicación, y sus ejecuciones aparecen junto con las otras ejecuciones de flujos de trabajo del espacio de trabajo.
* La instalación de una nueva versión de la aplicación actualiza el flujo de trabajo en el mismo lugar.
* Los usuarios no pueden editar un flujo de trabajo instalado. Para personalizar uno, lo duplican: la copia es suya para editarla.
