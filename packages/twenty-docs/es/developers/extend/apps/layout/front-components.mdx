## Resumen

Los componentes de frontend son componentes de React que se renderizan directamente dentro de la UI de Twenty. Se ejecutan en un **Web Worker aislado** usando Remote DOM: tu código se ejecuta dentro de un iframe de origen opaco y aislado (sandboxed), pero su interfaz de usuario sigue renderizándose de forma nativa en la página en lugar de quedar confinada a ese iframe.

<Warning>
  Los componentes de Front todavía están en desarrollo activo. Tu código se ejecuta contra un DOM parcial, no una página real del navegador, por lo que los usos avanzados pueden fallar, a menudo de forma silenciosa. Consulta [Limitaciones actuales](#current-limitations).
</Warning>

## Dónde se pueden usar los componentes de front

Los componentes de front pueden renderizarse en cuatro ubicaciones dentro de Twenty:

* **Panel lateral** — Los componentes de front no headless se abren en el panel lateral derecho. Este es el comportamiento predeterminado cuando un componente de front se activa desde el menú de comandos.
* **Widgets (tableros y páginas de registros)** — Los componentes de front pueden incrustarse como widgets dentro de los [diseños de página](/es/developers/extend/apps/layout/page-layouts). Al configurar un tablero o el diseño de una página de registro, los usuarios pueden agregar un widget de componente de front.
* **Configuración de la aplicación** — Señalada por una declaración de [`defineSettingsMenuItem()`](#settings-menu-items), el componente de frontend renderiza la página detrás de uno de los elementos del menú de configuración de la aplicación. Una aplicación puede declarar varios.
* **Chat de IA** — Una [función lógica expuesta como herramienta de IA](/es/developers/extend/apps/logic/logic-functions#exposing-a-function-as-an-ai-tool-or-workflow-action) puede nombrar un componente de front, que luego renderiza las llamadas de esa herramienta integradas en el chat en lugar de la fila de pasos predeterminada.

No se puede acceder a un componente de front por sí solo desde la interfaz de usuario — necesitas *exponerlo*. Las cuatro formas de hacerlo son:

* **Emparejarlo con un [elemento del menú de comandos](/es/developers/extend/apps/layout/command-menu-items)**: lo registra en el menú de comandos (Cmd+K) y, de forma opcional, como una acción rápida fijada.
* **Incrustarlo como widget en un [diseño de página](/es/developers/extend/apps/layout/page-layouts)**: lo coloca en la página de detalles de un registro o en un tablero.
* **Señala con una [`defineSettingsMenuItem()`](#settings-menu-items)** — la renderiza detrás de uno de los elementos del menú de configuración de la aplicación.
* **Nómbralo desde los [ajustes de `toolTriggerSettings` de una función lógica](/es/developers/extend/apps/logic/logic-functions#exposing-a-function-as-an-ai-tool-or-workflow-action)** — renderiza las llamadas de la herramienta en el chat de IA.

## Ejemplo básico

La forma más rápida de ver un componente de front en acción es emparejarlo con un [`defineCommandMenuItem`](/es/developers/extend/apps/layout/command-menu-items), de modo que aparezca como un botón de acción rápida en la esquina superior derecha de la página:

```tsx src/front-components/hello-world.tsx
import { defineFrontComponent } from 'twenty-sdk/define';

const HelloWorld = () => {
  return (
    <div style={{ padding: '20px', fontFamily: 'sans-serif' }}>
      <h1>Hello from my app!</h1>
      <p>This component renders inside Twenty.</p>
    </div>
  );
};

export default defineFrontComponent({
  universalIdentifier: '74c526eb-cb68-4cf7-b05c-0dd8c288d948',
  name: 'hello-world',
  description: 'A simple front component',
  component: HelloWorld,
});
```

```ts src/command-menu-items/hello-world.command-menu-item.ts
import { defineCommandMenuItem } from 'twenty-sdk/define';

export default defineCommandMenuItem({
  universalIdentifier: 'd4e5f6a7-b8c9-0123-defa-456789012345',
  shortLabel: 'Hello',
  label: 'Hello World',
  isPinned: true,
  availabilityType: 'GLOBAL',
  frontComponentUniversalIdentifier: '74c526eb-cb68-4cf7-b05c-0dd8c288d948',
});
```

Después de sincronizar con `twenty app dev` (o ejecutar una sola vez `twenty app apply`), la acción rápida aparece en la esquina superior derecha de la página:

<div style={{ textAlign: 'center' }}>
  <img src="/images/docs/developers/extends/apps/quick-action.png" alt="Botón de acción rápida en la esquina superior derecha" />
</div>

Haz clic para renderizar el componente en línea.

## Campos de configuración

| Campo                 | Obligatorio | Descripción                                                                                                                     |
| --------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `universalIdentifier` | Sí          | ID único estable para este componente                                                                                           |
| `component`           | Sí          | Una función de componente de React                                                                                              |
| `name`                | No          | Nombre para mostrar                                                                                                             |
| `description`         | No          | Descripción de lo que hace el componente                                                                                        |
| `isHeadless`          | No          | Configura en `true` si el componente no tiene UI visible (ver abajo)                                                            |
| `widgetAvailability`  | No          | Selector de widgets que ofrece el componente: páginas de registro, opcionalmente limitadas a objetos, o paneles (ver más abajo) |

## Colocar un componente de frontend en una página

Más allá de los comandos, puedes incrustar un componente de frontend directamente en una página de registro agregándolo como un widget en un **diseño de página**. Consulta [Diseños de página](/es/developers/extend/apps/layout/page-layouts) para más detalles.

`widgetAvailability` decide qué selector de widgets ofrece el componente mientras se edita un diseño de página. Un componente front se crea para páginas de registro, donde funciona con el registro mostrado, o para paneles, por lo que declara un `pageLayoutType`:

| `widgetAvailability`                                                                | Se ofrece en                            |
| ----------------------------------------------------------------------------------- | --------------------------------------- |
| omitido                                                                             | ningún selector de widgets              |
| `{ pageLayoutType: PageLayoutType.RECORD_PAGE }`                                    | cada página de registro                 |
| `{ pageLayoutType: PageLayoutType.RECORD_PAGE, objectUniversalIdentifiers: [...] }` | las páginas de registro de esos objetos |
| `{ pageLayoutType: PageLayoutType.DASHBOARD }`                                      | tableros                                |

```tsx
import {
  defineFrontComponent,
  PageLayoutType,
  STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS,
} from 'twenty-sdk/define';

export default defineFrontComponent({
  universalIdentifier: '...',
  name: 'company-notes',
  component: CompanyNotes,
  widgetAvailability: {
    pageLayoutType: PageLayoutType.RECORD_PAGE,
    objectUniversalIdentifiers: [
      STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS.company.universalIdentifier,
    ],
  },
});
```

Omita `widgetAvailability` para un componente que solo se abre desde un comando, un [elemento del menú de configuración](#settings-menu-items) o una fila de línea de tiempo. Nunca limita dónde se muestra un componente: los comandos, los elementos del menú de configuración y los diseños de página que declara su aplicación lo renderizan independientemente de su valor. La compilación advierte sobre un componente visible que no declara ninguno y no se abre desde ningún otro lugar.

## Elementos del menú de configuración

Una aplicación puede añadir sus propias entradas al menú de configuración, cada una de las cuales renderiza un componente de frontend. Declara uno con `defineSettingsMenuItem()` en su propio archivo, apuntando al componente que lo renderiza:

```tsx src/settings-menu-items/sync-settings.ts
import { defineSettingsMenuItem } from 'twenty-sdk/define';

export default defineSettingsMenuItem({
  universalIdentifier: 'a1b2c3d4-e5f6-7890-abcd-ef1234567890',
  frontComponentUniversalIdentifier: '88c15ae2-5f87-4a6b-b48f-1974bbe62eb7',
  title: 'Sync',
  icon: 'IconRefresh',
  position: 1,
});
```

El elemento del menú apunta al componente de frontend en lugar de al componente que se declara a sí mismo como una entrada de configuración. Por lo tanto, un componente puede respaldar varios elementos de menú, y un elemento puede redirigirse a otro componente sin modificar ninguno de los dos.

Cada elemento se renderiza como una pestaña en la página de la aplicación, en **Configuración > Aplicaciones**, después de **General**, según el orden de `position`.

Declara tantos como necesites. El elemento propio **General** de Twenty — actualización automática, URL de la aplicación y conexiones — siempre aparece primero y no puede ser anulado por una aplicación; la URL de la aplicación solo se muestra cuando la aplicación tiene funciones activadas por HTTP.

### Campos

| Campo                               | Descripción                                                                                         |
| ----------------------------------- | --------------------------------------------------------------------------------------------------- |
| `universalIdentifier`               | Un UUID que generas una vez y te pertenece, estable entre sincronizaciones                          |
| `frontComponentUniversalIdentifier` | El `universalIdentifier` del componente de frontend que renderiza este elemento                     |
| `título`                            | La etiqueta del elemento. `General` está reservado y provoca un error en la compilación             |
| `icon` *(opcional)*                 | Nombre del icono, resuelto del lado del cliente; un nombre desconocido recurre a uno predeterminado |
| `position` *(opcional)*             | Orden de clasificación, ascendente. El valor predeterminado es `0`                                  |
| `scope` *(opcional)*                | `WORKSPACE` (predeterminado) o `USER`                                                               |

`position` es un decimal, por lo que se puede insertar un elemento entre dos existentes sin renumerarlos. Los elementos se ordenan por `position` ascendente, y los empates se resuelven mediante `universalIdentifier`, de modo que el orden es el mismo en todos los espacios de trabajo. Dos elementos de una aplicación no pueden compartir una posición en el mismo ámbito: la sincronización lo rechaza en lugar de permitir que el orden de instalación decida cuál se renderiza primero.

### Ámbito de espacio de trabajo y de usuario

`scope` indica quién configura un elemento:

* **`WORKSPACE`** (predeterminado) — se configura una vez para todo el espacio de trabajo, junto con las demás configuraciones del espacio de trabajo. Estos son los elementos que se renderizan como pestañas en la página de la aplicación.
* **`USER`** — cada miembro lo configura para sí mismo, en su propia configuración de usuario.

<Note>
  Un elemento `USER` se muestra como una pestaña en la página de la app, en \*\*Configuración > Preferencias de la app
  \*\*, donde solo lo ve el miembro que ha iniciado sesión y únicamente cuando su
  rol concede el permiso `CONNECTED_ACCOUNTS`. Esa página todavía no está habilitada en
  todos los espacios de trabajo: donde no lo está, un elemento `USER` se conserva y sincroniza,
  pero no hay nada que lo muestre.
</Note>

Un elemento `USER` se ejecuta como el miembro que lo visualiza. Para almacenar algo por persona, declara la variable con `scope: 'USER'`: `getApplicationVariable` devuelve el valor del miembro que está viendo la página, y tu componente lo guarda con `updateMyUserApplicationVariable`, que escribe únicamente el valor de ese miembro y necesita `SystemPermissionFlag.CONNECTED_ACCOUNTS` en el rol de tu app, si declara uno (consulta [Lectura y actualización de variables en tiempo de ejecución](#reading-and-updating-variables-at-runtime)). Al igual que un elemento `WORKSPACE`, un elemento `USER` reemplaza el formulario generado **Variables**, por lo que debe permitir que el miembro establezca todas las variables de usuario que necesita su aplicación. Una variable de espacio de trabajo contiene un valor compartido por todos, por lo que el guardado de un miembro sobrescribiría el de otro.

<Note>
  `defineSettingsFrontComponent()` está obsoleta en favor de
  `defineSettingsMenuItem()`. Una aplicación que todavía la usa sigue funcionando — su
  componente se trata como un único elemento de menú **Configuración** — pero solo puede
  declarar uno, una limitación que `defineSettingsMenuItem()` existe para eliminar.
</Note>

## Headless vs no headless

Los componentes de front vienen en dos modos de renderizado controlados por la opción `isHeadless`:

**No headless (predeterminado)** — El componente renderiza una UI visible. Cuando se activa desde el menú de comandos, se abre en el panel lateral. Este es el comportamiento predeterminado cuando `isHeadless` es `false` o se omite.

**Headless (`isHeadless: true`)** — El componente se monta de forma invisible en segundo plano. No abre el panel lateral. Los componentes headless están diseñados para acciones que ejecutan lógica y luego se desmontan — por ejemplo, ejecutar una tarea asíncrona, navegar a una página o mostrar un modal de confirmación. Se combinan de forma natural con los componentes Command del SDK descritos a continuación.

```tsx src/front-components/sync-tracker.tsx
import { defineFrontComponent } from 'twenty-sdk/define';
import {
  useSelectedRecordIds,
  enqueueSnackbar,
} from 'twenty-sdk/front-component';
import { useEffect } from 'react';

const SyncTracker = () => {
  const [recordId] = useSelectedRecordIds();

  useEffect(() => {
    enqueueSnackbar({
      message: `Tracking record ${recordId}`,
      variant: 'info',
    });
  }, [recordId]);

  return null;
};

export default defineFrontComponent({
  universalIdentifier: '...',
  name: 'sync-tracker',
  description: 'Tracks record views silently',
  isHeadless: true,
  component: SyncTracker,
});
```

Como el componente devuelve `null`, Twenty omite renderizar un contenedor para él — no aparece espacio vacío en el diseño. El componente sigue teniendo acceso a todos los hooks y a la API de comunicación con el host.

## Componentes Command del SDK

El paquete `twenty-sdk` proporciona cuatro componentes auxiliares Command diseñados para componentes de front headless. Cada componente ejecuta una acción al montarse, gestiona los errores mostrando una notificación tipo snackbar y desmonta automáticamente el componente de front al finalizar.

Impórtalos desde `twenty-sdk/front-component`:

* **`Command`** — Ejecuta un callback asíncrono mediante la prop `execute`.
* **`CommandLink`** — Navega a una ruta de la aplicación. Props: `to`, `params`, `queryParams`, `options`.
* **`CommandModal`** — Abre un modal de confirmación. Si el usuario confirma, ejecuta el callback `execute`. Props: `title`, `subtitle`, `execute`, `confirmButtonText`, `confirmButtonAccent`.
* **`CommandOpenSidePanelPage`** — Abre contenido en el panel lateral. Las páginas enrutadas usan las mismas propiedades tipadas `to`, `params` y `queryParams` que `CommandLink`, además de las propiedades opcionales `hash`, `pageTitle` y `resetNavigationStack`. El registro de rutas del espacio de trabajo determina si el `AppPath` solicitado admite el panel lateral. `pageTitle` reemplaza el título del encabezado del panel, mientras que `resetNavigationStack` borra las páginas anteriores del panel antes de abrir la ruta. Las herramientas del panel diseñadas específicamente usan sus propias props específicas de página.

Aquí tienes un ejemplo completo de un componente de front headless que usa `Command` para ejecutar una acción desde el menú de comandos:

```tsx src/front-components/run-action.tsx
import { defineFrontComponent } from 'twenty-sdk/define';
import { Command } from 'twenty-sdk/front-component';
import { CoreApiClient } from 'twenty-client-sdk/core';

const RunAction = () => {
  const execute = async () => {
    const client = new CoreApiClient();

    await client.mutation({
      createTask: {
        __args: { data: { title: 'Created by my app' } },
        id: true,
      },
    });
  };

  return <Command execute={execute} />;
};

export default defineFrontComponent({
  universalIdentifier: 'e5f6a7b8-c9d0-1234-efab-345678901234',
  name: 'run-action',
  description: 'Creates a task from the command menu',
  component: RunAction,
  isHeadless: true,
});
```

```ts src/command-menu-items/run-action.command-menu-item.ts
import { defineCommandMenuItem } from 'twenty-sdk/define';

export default defineCommandMenuItem({
  universalIdentifier: 'f6a7b8c9-d0e1-2345-fabc-456789012345',
  label: 'Run my action',
  frontComponentUniversalIdentifier: 'e5f6a7b8-c9d0-1234-efab-345678901234',
});
```

Y un ejemplo que usa `CommandModal` para pedir confirmación antes de ejecutar:

```tsx src/front-components/delete-draft.tsx
import { defineFrontComponent } from 'twenty-sdk/define';
import { CommandModal } from 'twenty-sdk/front-component';

const DeleteDraft = () => {
  const execute = async () => {
    // perform the deletion
  };

  return (
    <CommandModal
      title="Delete draft?"
      subtitle="This action cannot be undone."
      execute={execute}
      confirmButtonText="Delete"
      confirmButtonAccent="danger"
    />
  );
};

export default defineFrontComponent({
  universalIdentifier: 'a7b8c9d0-e1f2-3456-abcd-567890123456',
  name: 'delete-draft',
  description: 'Deletes a draft with confirmation',
  component: DeleteDraft,
  isHeadless: true,
});
```

Y un ejemplo que usa `CommandOpenSidePanelPage` para abrir el registro actual en el panel lateral en una pestaña específica. `hash` es un id de pestaña de diseño de página sin el `#` inicial (los diseños predeterminados usan ids como `company-tab-emails` o `company-tab-timeline`; los diseños personalizados usan el id propio de la pestaña). Si el id no existe en el diseño del registro, en su lugar se abre la pestaña predeterminada:

```tsx src/front-components/open-company-emails.tsx
import { defineFrontComponent } from 'twenty-sdk/define';
import {
  AppPath,
  CommandOpenSidePanelPage,
  useSelectedRecordIds,
} from 'twenty-sdk/front-component';

const OpenCompanyEmails = () => {
  const selectedRecordIds = useSelectedRecordIds();
  const recordId = selectedRecordIds.length === 1 ? selectedRecordIds[0] : null;

  if (!recordId) {
    return null;
  }

  return (
    <CommandOpenSidePanelPage
      to={AppPath.RecordShowPage}
      params={{
        objectNameSingular: 'company',
        objectRecordId: recordId,
      }}
      hash="company-tab-emails"
      resetNavigationStack={false}
    />
  );
};

export default defineFrontComponent({
  universalIdentifier: 'b8c9d0e1-f2a3-4567-bcde-678901234567',
  name: 'open-company-emails',
  description: 'Opens the current company on its Emails tab',
  component: OpenCompanyEmails,
  isHeadless: true,
});
```

## Llamar a una función de lógica

Los componentes de front se ejecutan en el navegador dentro de un Web Worker aislado (sandboxed) dentro de un iframe de origen opaco, mientras que las [funciones de lógica](/es/developers/extend/apps/logic/logic-functions) se ejecutan en el servidor. No hay una llamada directa en el mismo proceso entre ambos; en su lugar, un componente de front accede a una función de lógica a través de HTTP.

Una función de lógica declarada con `httpRouteTriggerSettings` es accesible por HTTP en su ruta. `RestApiClient` trata las rutas que comienzan con `/s/` como rutas de la aplicación, las resuelve a la URL desde la que se sirven tus funciones y las autentica con `TWENTY_APP_ACCESS_TOKEN`.

> **En Twenty Cloud, las funciones de lógica activadas por HTTP se sirven en un dominio dedicado por espacio de trabajo** en `https://\<your-workspace-subdomain>.withtwenty.com\<path>`. Para clientes externos, copia la URL exacta desde la configuración de **HTTP trigger** de la función o desde la pestaña **Settings** de la aplicación.

Un componente de front sin interfaz (headless) puede ejecutar la llamada al montar mediante el componente `Command` y luego desmontarse automáticamente:

```tsx src/front-components/sync-prs.tsx
import { RestApiClient } from 'twenty-client-sdk/rest';
import { defineFrontComponent } from 'twenty-sdk/define';
import { Command } from 'twenty-sdk/front-component';

const SyncPrs = () => {
  const execute = async () => {
    await new RestApiClient().post('/s/github/fetch-prs', {
      owner: 'twentyhq',
      repo: 'twenty',
    });
  };

  return <Command execute={execute} />;
};

export default defineFrontComponent({
  universalIdentifier: '...',
  name: 'sync-prs',
  description: 'Triggers the fetch-prs logic function',
  isHeadless: true,
  component: SyncPrs,
});
```

La ruta que se pasa a `RestApiClient` es el `httpRouteTriggerSettings.path` de la función lógica, con el prefijo `/s`. Mantén `isAuthRequired: true`; el `TWENTY_APP_ACCESS_TOKEN` que Twenty crea para tu componente autentica la solicitud:

```ts src/logic-functions/fetch-prs.logic-function.ts
import { defineLogicFunction } from 'twenty-sdk/define';
import type { RoutePayload } from 'twenty-sdk/logic-function';

const handler = async (event: RoutePayload) => {
  const { owner, repo } = (event.body ?? {}) as { owner: string; repo: string };
  // ...fetch from GitHub and persist records...
  return { ok: true };
};

export default defineLogicFunction({
  universalIdentifier: '...',
  name: 'fetch-prs',
  handler,
  httpRouteTriggerSettings: {
    path: '/github/fetch-prs',
    httpMethod: 'POST',
    isAuthRequired: true,
  },
});
```

<Note>
  `TWENTY_APP_ACCESS_TOKEN` se inyecta automáticamente — consulta Variables
  de la aplicación. Dado que las variables de aplicación secretas nunca se exponen a los componentes de front, mantén las claves de API y otra lógica confidencial en la función de lógica, no en el componente de front.
</Note>

### Llamar a la API REST de Twenty

Para llamar a rutas HTTP de la aplicación o leer y escribir registros de Twenty desde un componente de interfaz, utiliza `RestApiClient` de `twenty-client-sdk/rest`. Envía las rutas `/s/...` a la URL base de las funciones de tu espacio de trabajo y cualquier otra ruta, incluidas `/rest/...`, a `TWENTY_API_URL`.

Siempre actúa como la persona que está mirando la página. `runAs: 'application'` es una opción exclusiva de las funciones lógicas: un componente nunca recibe el propio token de tu aplicación, por lo que solicitarlo aquí genera un error. Coloca el trabajo que necesita el acceso propio de la aplicación detrás de una función lógica y llama a esa en su lugar.

| Método                            | Descripción                                                                 |
| --------------------------------- | --------------------------------------------------------------------------- |
| `get(path, options?)`             | Envía una solicitud `GET`                                                   |
| `post(path, body?, options?)`     | Envía una solicitud `POST`                                                  |
| `put(path, body?, options?)`      | Envía una solicitud `PUT`                                                   |
| `patch(path, body?, options?)`    | Envía una solicitud `PATCH`                                                 |
| `delete(path, options?)`          | Envía una solicitud `DELETE`                                                |
| `request(method, path, options?)` | Solicitud genérica con cualquier método HTTP                                |
| `resolveUrl(path, options?)`      | Resuelve una ruta a su URL completa sin enviar una solicitud (para enlaces) |

`options` acepta `headers`, `query` (un registro de parámetros de cadena de consulta; los valores nulos o indefinidos se omiten) y un `AbortSignal` mediante `signal`. Un objeto `body` que no sea de tipo `FormData` se serializa automáticamente como JSON. Ante un `401`, el cliente actualiza el token de acceso una vez a través del host y vuelve a intentar la solicitud.

La URL base y el token se resuelven desde el entorno de forma predeterminada. Pasa opciones de sobrescritura al constructor cuando sea necesario — por ejemplo, en pruebas:

```ts
const client = new RestApiClient({
  baseUrl: 'https://myworkspace.twenty.com',
  token: 'my-token',
});
```

Las solicitudes fallidas lanzan un `RestApiClientError` que expone `status`, `statusText`, `url` y el `body` analizado:

```tsx
import { RestApiClient, RestApiClientError } from 'twenty-client-sdk/rest';

const client = new RestApiClient();

try {
  const people = await client.get('/rest/people', {
    query: { limit: 10 },
  });
} catch (error) {
  if (error instanceof RestApiClientError) {
    console.error(error.status, error.body);
  }
}
```

## Acceder al contexto de ejecución

Dentro de tu componente, usa hooks del SDK para acceder al usuario actual, el registro y la instancia del componente:

```tsx src/front-components/record-info.tsx
import { defineFrontComponent } from 'twenty-sdk/define';
import {
  useUserId,
  useSelectedRecordIds,
  useFrontComponentId,
} from 'twenty-sdk/front-component';

const RecordInfo = () => {
  const userId = useUserId();
  const [recordId] = useSelectedRecordIds();
  const componentId = useFrontComponentId();

  return (
    <div>
      <p>User: {userId}</p>
      <p>Record: {recordId ?? 'No record context'}</p>
      <p>Component: {componentId}</p>
    </div>
  );
};

export default defineFrontComponent({
  universalIdentifier: 'b2c3d4e5-f6a7-8901-bcde-f23456789012',
  name: 'record-info',
  component: RecordInfo,
});
```

Hooks disponibles:

| Hook                                          | Devuelve                                         | Descripción                                                                                                                                   |
| --------------------------------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `useUserId()`                                 | `string` o `null`                                | El ID del usuario actual                                                                                                                      |
| `useSelectedRecordIds()`                      | `string[]`                                       | Todos los ID de los registros seleccionados (array vacío si no hay ninguno seleccionado)                                                      |
| `useSelectedRecordsFilter()`                  | `RecordGqlOperationFilter` o `null`              | Filtro que coincide exactamente con los registros seleccionados, incluso en Seleccionar todo                                                  |
| `useSelectedObjectMetadata()`                 | `FrontComponentSelectedObjectMetadata` or `null` | Los metadatos del objeto asociados con el contexto de registro de este componente frontal                                                     |
| `useRecordId()`                               | `string` o `null`                                | **Obsoleto.** Usa `useSelectedRecordIds()` en su lugar                                                                                        |
| `useFrontComponentId()`                       | `string`                                         | El ID de esta instancia del componente                                                                                                        |
| `useTimelineActivityId()`                     | `string` o `null`                                | El ID de actividad de la línea de tiempo actual al representar una fila personalizada de la línea de tiempo                                   |
| `useColorScheme()`                            | `'light'` o `'dark'`                             | La combinación de colores activa de la interfaz de usuario del host (`System` ya está resuelto)                                               |
| `useLocation()`                               | `FrontComponentLocation` o `null`                | La ruta de acceso, la cadena de consulta y el hash de la ruta host, además del origen de la aplicación host                                   |
| `useToolCall()`                               | `FrontComponentToolCall` o `null`                | La llamada a herramienta de IA que este componente está renderizando, cuando se ha expuesto desde `toolTriggerSettings` de una función lógica |
| `useFrontComponentExecutionContext(selector)` | varía                                            | Accede al contexto de ejecución completo con una función selectora                                                                            |

### Metadatos del objeto

Use `useSelectedObjectMetadata()` para identificar el objeto asociado a un widget de página de registro, una fila de cronología personalizada, un comando con ámbito de objeto o un componente de interfaz abierto en el panel lateral con un objeto (desde un comando o mediante `openSidePanelPage` con un `objectNameSingular`). Esto permite que una integración seleccione plantillas u otra configuración para el objeto actual sin buscar un ID de registro entre objetos.

```tsx
import {
  useSelectedObjectMetadata,
  useSelectedRecordIds,
} from 'twenty-sdk/front-component';

const TemplatePicker = () => {
  const objectMetadata = useSelectedObjectMetadata();
  const selectedRecordIds = useSelectedRecordIds();

  if (!objectMetadata) {
    return <p>Open a record to select a template.</p>;
  }

  return (
    <p>
      Select a template for {objectMetadata.nameSingular}. Selected records:{' '}
      {selectedRecordIds.length}
    </p>
  );
};
```

El resultado contiene `id` (el UUID de metadatos del objeto del espacio de trabajo), `nameSingular` y `namePlural`. Los nombres son nombres de metadatos, como `person` y `people`, en lugar de etiquetas de visualización.

Los metadatos del objeto pueden estar disponibles incluso cuando no hay registros seleccionados. Pertenece al contexto de este componente de interfaz, por lo que un panel lateral puede mostrar un objeto diferente del de la página principal. El hook se actualiza cuando cambia ese contexto y devuelve `null` cuando el objeto no se puede resolver, cuando no se proporciona ningún contexto de objeto o cuando se ejecuta en un host más antiguo que no proporciona metadatos de objetos.

### Ubicación del host

Usa `useLocation()` para leer la ruta que aloja tu componente frontal. Devuelve un objeto `FrontComponentLocation` con cuatro campos de cadena obligatorios: `pathname`, `search`, `hash` y `origin`. Por ejemplo, una página en `https://myworkspace.twenty.com/page/page-layout-id?project=abc#details` proporciona `/page/page-layout-id`, `?project=abc`, `#details` y `https://myworkspace.twenty.com`, respectivamente. `hash` incluye su `#` inicial y es `''` cuando no hay ningún fragmento.

`pathname`, `search` y `hash` siguen el contexto de React Router del componente, incluida la propia ruta de un panel lateral con ruta. `origin` proviene de la aplicación host. El hook se actualiza cuando cambia la ruta. Los hosts más antiguos pueden omitir `executionContext.location`, por lo que `useLocation()` devuelve `null` cuando la ubicación no está disponible.

Para los parámetros de consulta, lee `useLocation()?.search ?? ''` y analiza el resultado con `URLSearchParams`. `search` incluye su `?` inicial y es `''` cuando la ruta no tiene cadena de consulta. El valor de reserva también proporciona `''` cuando el host no proporciona la ubicación.

```tsx
import { useLocation } from 'twenty-sdk/front-component';

const ProjectDetails = () => {
  const search = useLocation()?.search ?? '';
  const projectId = new URLSearchParams(search).get('project');

  return <p>Project: {projectId ?? 'No project selected'}</p>;
};
```

## Variables de aplicación

Las variables de aplicación definidas en [`defineApplication()`](/es/developers/extend/apps/config/application) con `isSecret: false` están disponibles dentro de los componentes de front mediante la utilidad `getApplicationVariable`:

```tsx src/front-components/greeting.tsx
import { defineFrontComponent } from 'twenty-sdk/define';
import { getApplicationVariable } from 'twenty-sdk/front-component';

const Greeting = () => {
  const recipientName =
    getApplicationVariable('DEFAULT_RECIPIENT_NAME') ?? 'World';

  return <p>Hello, {recipientName}!</p>;
};

export default defineFrontComponent({
  universalIdentifier: '...',
  name: 'greeting',
  component: Greeting,
});
```

<Warning>
  Las variables secretas (`isSecret: true`) **no** se exponen a los componentes de front.
  Solo están disponibles en las funciones de
  lógica, que se ejecutan
  del lado del servidor. Esto evita que valores confidenciales como las claves de API se envíen al
  navegador.
</Warning>

`getApplicationVariable` siempre devuelve una **cadena** (o `undefined`), independientemente del `type` declarado de la variable. La cadena se serializa de forma coherente según el tipo (booleanos como `"true"` / `"false"`, números como cadenas decimales, arrays / objetos como JSON), el mismo formato que se usa para la función lógica `process.env` — parsea tú mismo (`Number(...)`, `JSON.parse(...)`, `=== 'true'`). Consulta [Tipos de variables](/es/developers/extend/apps/config/application#variable-types).

### Lectura y actualización de variables en tiempo de ejecución

`getApplicationVariable` devuelve los valores inyectados cuando se cargó el componente, por lo que un valor escrito posteriormente solo aparece en la siguiente carga. Para leer los valores almacenados o escribir uno (lo que hace un [elemento del menú de configuración](#settings-menu-items) cuando guarda lo que escribió el usuario), usa `MetadataApiClient`:

```tsx src/front-components/app-settings.tsx
import { MetadataApiClient } from 'twenty-client-sdk/metadata';

const APPLICATION_UNIVERSAL_IDENTIFIER = '39783023-bcac-41e3-b0d2-ff1944d8465d';

const readApplicationVariables = async () => {
  const { findOneApplication } = await new MetadataApiClient().query({
    findOneApplication: {
      __args: { universalIdentifier: APPLICATION_UNIVERSAL_IDENTIFIER },
      applicationVariables: { key: true, value: true, isSecret: true },
    },
  });

  return findOneApplication?.applicationVariables ?? [];
};

const saveRecipientName = async (recipientName: string) => {
  await new MetadataApiClient().mutation({
    updateOneApplicationVariable: {
      __args: { key: 'DEFAULT_RECIPIENT_NAME', value: recipientName },
    },
  });
};

const saveMyLanguage = async (language: string) => {
  await new MetadataApiClient().mutation({
    updateMyUserApplicationVariable: {
      __args: {
        applicationUniversalIdentifier: APPLICATION_UNIVERSAL_IDENTIFIER,
        key: 'LANGUAGE',
        value: language,
      },
    },
  });
};
```

Notas:

* El token de tu componente está vinculado a tu propia aplicación. `updateOneApplicationVariable` la selecciona como destino, por lo que `applicationId` es opcional y se rechaza nombrar otra aplicación. La lectura de las `applicationVariables` de otra aplicación se rechaza de la misma manera, y una aplicación que pertenece a otro espacio de trabajo se interpreta como no encontrada.
* La clave debe ser una que tu aplicación declare en [`defineApplication()`](/es/developers/extend/apps/config/application). Escribir una clave que no está declarada se considera no encontrada.
* Las variables secretas se leen enmascaradas, nunca como el valor almacenado. Escribirlas funciona normalmente.
* Leer el `value` de una variable y escribirlo requieren el permiso de configuración `APPLICATIONS` tanto en el rol de tu aplicación como en el rol de la persona que ha iniciado sesión, ya que el token del componente es la intersección de ambos. Añade `SystemPermissionFlag.APPLICATIONS` a `permissionFlagUniversalIdentifiers` en tu [rol de aplicación](/es/developers/extend/apps/config/roles).
* Una variable de usuario (`scope: 'USER'`) se inyecta con el valor del miembro que está viendo la página, a menos que sea secreta. `updateOneApplicationVariable` lo rechaza: guárdelo con `updateMyUserApplicationVariable`, como lo hace `saveMyLanguage` anteriormente. Escribe únicamente el valor del miembro que está viendo la página y no permite indicar otra aplicación. No necesita el permiso `APPLICATIONS`, pero necesita el permiso `CONNECTED_ACCOUNTS` en el rol del miembro que está viendo la página y en el rol de tu app, si declara uno: añade `SystemPermissionFlag.CONNECTED_ACCOUNTS` a `permissionFlagUniversalIdentifiers` en tu [rol de aplicación](/es/developers/extend/apps/config/roles). Consulte [Variables de espacio de trabajo y de usuario](/es/developers/extend/apps/config/application#workspace-and-user-variables).

### Variables del sistema

Las siguientes variables de sistema siempre están disponibles a través de `process.env`:

| Variable                  | Descripción                                                                                                                                                                                                                |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TWENTY_API_URL`          | URL base de la API principal de Twenty                                                                                                                                                                                     |
| `TWENTY_APP_ACCESS_TOKEN` | Token de corta duración limitado al rol de la persona que ha iniciado sesión, en intersección con el de tu aplicación, por lo que un componente nunca puede hacer más de lo que puede hacer la persona que lo está mirando |

### `TWENTY_FUNCTIONS_URL`

Twenty también inyecta `TWENTY_FUNCTIONS_URL` en los componentes de interfaz y en las funciones lógicas: la URL base desde la que se sirven las funciones de lógica activadas por HTTP de tu aplicación.

Existe porque esa URL no siempre es el propio servidor de Twenty. En Twenty Cloud, las rutas de la aplicación se sirven en un dominio dedicado por espacio de trabajo (`https://\<your-workspace-subdomain>.withtwenty.com`, o el dominio público principal de la aplicación cuando se configure uno) para que las respuestas definidas por la aplicación se ejecuten en su propio origen en lugar de en el origen de la aplicación de Twenty. Las instancias autoalojadas y locales sirven las rutas de la aplicación bajo el prefijo `/s` en el propio servidor y es posible que no establezcan la variable en absoluto. Dado que la URL base varía por espacio de trabajo y por instancia, tu código no puede codificarla de forma rígida: el servidor inyecta el valor correcto en tiempo de ejecución.

Rara vez necesitas leerla directamente. Llama a tus rutas a través de `RestApiClient` con una ruta con el prefijo `/s/` y el cliente resuelve la URL por ti: elimina el prefijo `/s` y apunta a `TWENTY_FUNCTIONS_URL`, recurriendo a `\<TWENTY_API_URL>/s` cuando la variable no está establecida. Utiliza `resolveUrl('/s/\<path>')` para obtener la URL absoluta sin enviar una solicitud, por ejemplo, para un enlace. Lee la variable directamente solo cuando construyas una URL manualmente:

```ts
const routeUrl = `${process.env.TWENTY_FUNCTIONS_URL || `${process.env.TWENTY_API_URL}/s`}/documents/generate`;
```

## API de comunicación con el host

Los componentes de frontend pueden activar la navegación, los modales y las notificaciones mediante funciones de `twenty-sdk/front-component`:

| Función                                            | Descripción                                                                                                                                                                                 |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `navigate(to, params?, queryParams?, options?)`    | Navegar a una página en la aplicación                                                                                                                                                       |
| `openSidePanelPage(params)`                        | Abrir un panel lateral                                                                                                                                                                      |
| `closeSidePanel()`                                 | Cerrar el panel lateral                                                                                                                                                                     |
| `openCommandConfirmationModal(params)`             | Mostrar un cuadro de diálogo de confirmación                                                                                                                                                |
| `enqueueSnackbar(params)`                          | Mostrar una notificación tipo toast                                                                                                                                                         |
| `unmountFrontComponent()`                          | Desmontar el componente                                                                                                                                                                     |
| `updateProgress(progress)`                         | Actualizar un indicador de progreso                                                                                                                                                         |
| `uploadFile(file, { fieldMetadataId, fileName? })` | Sube un `Blob` a un campo FILES; se resuelve en `{ status: 'uploaded', file: { fileId, path, url, size, mimeType } }` o `{ status: 'failed', reason: 'invalid-params' \| 'upload-failed' }` |

Use `openCommandConfirmationModal` de `twenty-sdk/front-component` para los cuadros de diálogo. Acepta opciones estructuradas de título, subtítulo y botón, y se resuelve como `'confirm'` o `'cancel'`. Twenty se encarga del modal, la gestión del foco, el cierre y el desplazamiento de la página. Los componentes de frontend no deben renderizar directamente elementos `Dialog`, `AlertDialog`, `dialog` nativos ni ventanas emergentes nativas del navegador. Proporcionar un contenedor de portal local no implica que se admita la modalidad directa propiedad de la aplicación.

Aquí tienes un ejemplo que usa la API del host para mostrar un snackbar y cerrar el panel lateral después de que una acción finaliza:

```tsx src/front-components/archive-record.tsx
import { defineFrontComponent } from 'twenty-sdk/define';
import {
  enqueueSnackbar,
  closeSidePanel,
  useSelectedRecordIds,
} from 'twenty-sdk/front-component';
import { CoreApiClient } from 'twenty-client-sdk/core';

const ArchiveRecord = () => {
  const [recordId] = useSelectedRecordIds();

  const handleArchive = async () => {
    const client = new CoreApiClient();

    await client.mutation({
      updateTask: {
        __args: { id: recordId, data: { status: 'ARCHIVED' } },
        id: true,
      },
    });

    await enqueueSnackbar({
      message: 'Record archived',
      variant: 'success',
    });

    await closeSidePanel();
  };

  return (
    <div style={{ padding: '20px' }}>
      <p>Archive this record?</p>
      <button onClick={handleArchive}>Archive</button>
    </div>
  );
};

export default defineFrontComponent({
  universalIdentifier: 'c9d0e1f2-a3b4-5678-cdef-789012345678',
  name: 'archive-record',
  description: 'Archives the current record',
  component: ArchiveRecord,
});
```

### Almacenamiento

`localStorage` y `sessionStorage` funcionan como lo hacen en una página normal, con la API síncrona estándar. Tus claves están limitadas al ámbito de la instalación de tu aplicación y del usuario que ha iniciado sesión: ninguna otra aplicación puede leerlas, y otro usuario que inicie sesión en el mismo navegador comenzará con un almacenamiento vacío. Los valores escritos en `localStorage` permanecen en el dispositivo a través de las recargas; `sessionStorage` dura mientras dure la sesión del navegador.

```tsx src/front-components/note-draft.tsx
import { useState } from 'react';
import { defineFrontComponent } from 'twenty-sdk/define';

const NoteDraft = () => {
  const [draft, setDraft] = useState(() => localStorage.getItem('draft') ?? '');

  const handleChange = (nextDraft: string) => {
    setDraft(nextDraft);
    localStorage.setItem('draft', nextDraft);
  };

  return (
    <textarea
      value={draft}
      onChange={(event) => handleChange(event.target.value)}
    />
  );
};

export default defineFrontComponent({
  universalIdentifier: 'd0e1f2a3-b4c5-6789-def0-890123456789',
  name: 'note-draft',
  description: 'Keeps an unsaved note on this device',
  component: NoteDraft,
});
```

Twenty almacena los valores en nombre de tu aplicación, por lo que una escritura se aplica localmente de inmediato y se guarda en segundo plano. Las lecturas nunca esperan al host. Nada se sincroniza: los valores no siguen al usuario a otro navegador o máquina, así que usa el [almacenamiento de clave-valor](/es/developers/extend/apps/logic/key-value-store) de una función de lógica para cualquier cosa que deba sobrevivir a un cambio de dispositivo.

Las escrituras están limitadas y cada límite cuenta caracteres en lugar de bytes: las claves tienen como máximo 512 caracteres, un solo valor como máximo 262.144 caracteres y cada almacenamiento como máximo 1.048.576 caracteres por aplicación y usuario. Una escritura que excede un límite lanza un `QuotaExceededError`, como la API del navegador.

### Trabajar con varios registros

Usa `useSelectedRecordIds()` para manejar varios registros seleccionados. Esto es útil para operaciones por lotes:

```tsx src/front-components/bulk-export.tsx
import { defineFrontComponent } from 'twenty-sdk/define';
import { useSelectedRecordIds } from 'twenty-sdk/front-component';
import { enqueueSnackbar, closeSidePanel } from 'twenty-sdk/front-component';
import { CoreApiClient } from 'twenty-client-sdk/core';

const BulkExport = () => {
  const selectedRecordIds = useSelectedRecordIds();

  const handleExport = async () => {
    const client = new CoreApiClient();

    for (const recordId of selectedRecordIds) {
      await client.mutation({
        updateTask: {
          __args: { id: recordId, data: { exported: true } },
          id: true,
        },
      });
    }

    await enqueueSnackbar({
      message: `Exported ${selectedRecordIds.length} records`,
      variant: 'success',
    });

    await closeSidePanel();
  };

  return (
    <div style={{ padding: '20px' }}>
      <p>Export {selectedRecordIds.length} selected record(s)?</p>
      <button onClick={handleExport}>Export</button>
    </div>
  );
};

export default defineFrontComponent({
  universalIdentifier: 'd0e1f2a3-b4c5-6789-defa-012345678901',
  name: 'bulk-export',
  description: 'Export selected records',
  component: BulkExport,
});
```

Muéstralo con un [elemento de menú de comando](/es/developers/extend/apps/layout/command-menu-items) restringido a selecciones de registros:

```ts src/command-menu-items/bulk-export.command-menu-item.ts
import { defineCommandMenuItem } from 'twenty-sdk/define';

export default defineCommandMenuItem({
  universalIdentifier: 'd0e1f2a3-b4c5-6789-defa-012345678902',
  label: 'Bulk Export',
  availabilityType: 'RECORD_SELECTION',
  frontComponentUniversalIdentifier: 'd0e1f2a3-b4c5-6789-defa-012345678901',
});
```

#### Seleccionar todo

Cuando el usuario selecciona todos los registros de una vista, `useSelectedRecordIds()` devuelve una matriz vacía: la selección se define mediante los filtros, la búsqueda y las filas no marcadas de la vista, y puede contener muchos más registros de los que caben en la memoria. `useSelectedRecordsFilter()` devuelve un filtro que coincide exactamente con los registros seleccionados en todos los casos, por lo que realiza consultas con él en lugar de enumerar los ID:

```tsx
import { Command, useSelectedRecordsFilter } from 'twenty-sdk/front-component';
import { CoreApiClient } from 'twenty-client-sdk/core';

const MarkExported = () => {
  const selectedRecordsFilter = useSelectedRecordsFilter();

  const execute = async () => {
    if (selectedRecordsFilter === null) {
      return;
    }

    await new CoreApiClient().mutation({
      updateTasks: {
        __args: { filter: selectedRecordsFilter, data: { exported: true } },
        id: true,
      },
    });
  };

  return <Command execute={execute} />;
};
```

Para selecciones grandes, pasa el filtro a una [función lógica](/es/developers/extend/apps/logic/logic-functions) y procesa los registros allí, página por página.

## Dependencias compartidas en los componentes frontales

Por defecto, cada componente frontal agrupa su propia copia de las librerías que importa, por lo que una aplicación con cinco componentes viene React cinco veces. Declara las dependencias compartidas en el paquete `package.json` para construir esas librerías una vez y tener cada componente de la aplicación cargarlas desde un solo archivo caché:

```json package.json
{
  "frontComponentSharedDependencies": [
    "react",
    "react-dom/client",
    "twenty-ui/primitives/input"
  ]
}
```

Cada componente importa sus dependencias exactamente como antes — nada cambia en su código de componente:

```tsx src/front-components/counter.tsx
import { useState } from 'react';
import { defineFrontComponent } from 'twenty-sdk/define';

const Counter = () => {
  const [count, setCount] = useState(0);

  return <button onClick={() => setCount(count + 1)}>{count}</button>;
};

export default defineFrontComponent({
  universalIdentifier: '...',
  name: 'counter',
  component: Counter,
});
```

Algunas cosas que debes saber:

* **Un paquete de dependencias compartidas por aplicación.** El paquete se construye a partir de las propias dependencias de tu aplicación, por lo que conservas el control total de las versiones que envías.
* **Enumera los especificadores exactos que importas.** `twenty-ui/primitives/input` y `twenty-ui/primitives/data-display` son dos entradas; el nombre de un paquete por sí solo no cubre sus subrutas. La lista `react` cubre automáticamente `react/jsx-runtime`.
* **Comparte `react-dom/client` junto a `react`.** Cada componente renderiza a través de `createRoot`, así que dejarlo fuera significa que cada componente todavía incluye React DOM.
* \*\*El paquete está en caché. \* Se sirve bajo una URL de contenido hash con un caché inmutable de larga duración, para que se descargue una vez y se vuelva a utilizar a través de todos los componentes de la aplicación hasta que una de sus dependencias cambie.
* **Los componentes que no importan ninguno de los paquetes compartidos nunca lo descargan.**

## Uso de los componentes de UI de Twenty

Twenty distribuye su biblioteca de componentes como el paquete [`twenty-ui`](https://www.npmjs.com/package/twenty-ui). Prefiere sus controles y tokens de tema para dar a los componentes front la misma apariencia e interacciones que el resto de Twenty. Explora los [componentes compartidos](/es/ui/components/overview) y las [primitivas](/es/ui/primitives/overview) para ver ejemplos, props y API de composición.

### Instalación

Las nuevas aplicaciones creadas con `twenty app init` ya incluyen `twenty-ui`. Para una aplicación existente, añádelo como dependencia de desarrollo, fijado a la misma versión que `twenty-sdk` y `twenty-client-sdk`. Por ejemplo, si tus paquetes SDK usan `2.51.0`:

```bash
yarn add -D twenty-ui@2.51.0
```

`twenty-ui` se incluye en el momento de la compilación, ya sea en cada componente front o en el [paquete de dependencias compartidas](#sharing-dependencies-across-front-components) de tu aplicación. Twenty carga las hojas de estilo de los componentes y del tema, y aplica el esquema de color activo del espacio de trabajo. No necesitas importar `twenty-ui/style.css`, las hojas de estilo del tema ni añadir un `ThemeProvider` raíz como lo harías en una aplicación independiente de React.

### Importar componentes

Importa desde la subruta pública de la familia correspondiente para mantener las dependencias centradas:

Los controles fundamentales se agrupan en `twenty-ui/primitives/\<family>`. Los preajustes de diseño compartidos y los bloques de creación de aplicaciones se agrupan en `twenty-ui/components/\<family>`. El punto de entrada agregado `twenty-ui/components` sigue disponible, pero las importaciones por familia facilitan [compartir solo las dependencias que usas](#sharing-dependencies-across-front-components).

| Subruta                              | Qué exporta                                                                               |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| `twenty-ui/components/input`         | Botones principales y ligeros, entradas de búsqueda e imagen, y selectores de país/moneda |
| `twenty-ui/components/data-display`  | Grupos de avatares, árboles JSON, métricas, bloques de comandos y mosaicos de iconos      |
| `twenty-ui/components/feedback`      | Avisos destacados, banners en línea y notificaciones                                      |
| `twenty-ui/components/layout`        | Secciones, listas con desbordamiento y transiciones de iconos                             |

import { defineFrontComponent } from 'twenty-sdk/define';
import { enqueueSnackbar } from 'twenty-sdk/front-component';
import { MainButton } from 'twenty-ui/components/input';
import { Status, Tag } from 'twenty-ui/primitives/data-display';

const StyledWidget = () => {
  const theme = useTheme();

  const handleClick = async () => {
    await enqueueSnackbar({ message: 'Clicked!', variant: 'success' });
  };

  return (
    <div
      style={{
        padding: theme.spacing[4],
        display: 'flex',
        alignItems: 'center',
        flexWrap: 'wrap',
        gap: theme.spacing[2],
      }}
    >
      <MainButton onClick={handleClick}>Click me</MainButton>
      <Tag color="green">Active</Tag>
      <Status color="green">Online</Status>
    </div>

  universalIdentifier: 'e5f6a7b8-c9d0-1234-efab-567890123456',

  component: StyledWidget,

### Iconos

Importa iconos individuales desde `twenty-ui/icon`:

```tsx
import { IconBox, IconCheck } from 'twenty-ui/icon';
```

Cada icono con nombre se optimiza con tree-shaking, por lo que importar unos pocos añade muy poco a tu bundle. Evita `IconsProvider` y `useIcons` en los componentes de Front. Los componentes de Front se empaquetan sin división de código, por lo que el catálogo dinámico de iconos del proveedor (el conjunto completo de Tabler, aproximadamente 2 MB minificado) termina en tu paquete. ### Temas y tokens de tema

Los componentes de UI de Twenty coinciden automáticamente con el tema claro y oscuro del espacio de trabajo. El renderizador aplica el esquema de color activo en el anfitrión, y los componentes resuelven sus variables CSS con respecto a él.

Para usar los mismos tokens de diseño en tus propios estilos en línea, llama a `useTheme()` dentro del cuerpo del componente. En los componentes frontales, devuelve referencias de variables CSS de forma predeterminada, por lo que los estilos siguen el tema activo del anfitrión sin un `ThemeProvider` local:

```tsx
import { useTheme } from 'twenty-ui/theme';

const Card = () => {
  const theme = useTheme();

  return (
    <div
      style={{
        padding: theme.spacing[4],
        background: theme.background.secondary,
        color: theme.font.color.primary,
      }}
    >
      Themed card
    </div>
  );
};
```

Las mismas referencias CSS se exportan como `themeCssVariables` desde `twenty-ui/theme`. Léelas dentro del cuerpo del componente: la CLI simula `twenty-ui` durante la extracción del manifiesto, por lo que desreferenciar constantes de tema importadas en el ámbito del módulo puede provocar un error de compilación.

Las cadenas de referencias CSS no son números de JavaScript resueltos, incluso para tokens como `theme.icon.size.md`. No realices operaciones aritméticas con ellas ni las pases a API que requieran números. Consulta [Temas](/es/ui/theming) y [Tokens](/es/ui/tokens) para ver las rutas semánticas y los nombres de variables CSS.

Para hacer bifurcaciones explícitamente según el esquema activo, léelo con `useColorScheme()` de `twenty-sdk/front-component`, que devuelve `'light'` o `'dark'`.

## Limitaciones actuales

Los componentes de Front están en desarrollo activo. El renderizado, el estilo, el manejo de eventos, la medición de elementos, los portales del cuerpo y el almacenamiento del navegador funcionan bien. Cualquier cosa que vaya *más allá* de eso (llamar a un método del DOM en un ref, por ejemplo) falta o está incompleta hoy, y la mayoría falla silenciosamente: no hay excepción ni error de TypeScript tampoco, ya que el andamiaje está tipado contra el DOM completo del navegador.

Si una de estas cosas te bloquea, [abre una incidencia](https://github.com/twentyhq/twenty/issues/new/choose) para que se priorice.

### Diseño y medición

Los elementos pueden medirse a sí mismos: el host refleja la geometría en el sandbox, de modo que las lecturas se responden localmente pero pueden tener hasta un fotograma de desfase, y la primera lectura de un elemento nunca medido devuelve ceros. Después de escribir, vuelve a leer en un callback de `requestAnimationFrame` o en un efecto.

| API                                                                                      | Qué ocurre                                                                                                                                         |
| ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getBoundingClientRect()`, `offsetWidth`, `clientWidth`, `scrollWidth`, `offsetTop`, ... | Funcionan desde el espejo; al asignar `scrollTop` / `scrollLeft` se desplaza el elemento en la página (consulta Desplazamiento)                    |
| `getClientRects()`                                                                       | Lanza una excepción                                                                                                                                |
| `window.matchMedia()`                                                                    | Funciona para un conjunto fijo de características, con eventos `change` (véase abajo)                                                              |
| `window.innerWidth`, `innerHeight`, `devicePixelRatio`, `scrollX`, `scrollY`             | Funcionan, informando el **viewport del navegador**; el tamaño propio de tu widget es `document.body.clientWidth` / `clientHeight`                 |
| `window.getComputedStyle()`                                                              | Valores de diseño del host para los elementos medidos y sus elementos primarios; el resto, incluidas las variables de tema, desde estilos en línea |
| `ResizeObserver`                                                                         | Funciona, desde el espejo; `document.body` informa del cuadro de tu widget                                                                         |
| `IntersectionObserver`                                                                   | `ReferenceError` (las comprobaciones con `typeof` sí funcionan)                                                                                    |
| `MutationObserver`                                                                       | Funciona, incluyendo `subtree`, `attributeFilter`, valores antiguos y `takeRecords()`                                                              |

El posicionamiento desde `getBoundingClientRect` y la observación de tamaño mediante `ResizeObserver` funcionan desde el mismo espejo, por lo que las devoluciones de llamada de redimensionamiento se retrasan respecto al host aproximadamente un fotograma. Aun así, prefiere usar CSS para el diseño: tu hoja de estilos llega a la página real, por lo que flexbox, grid, `aspect-ratio`, `clamp()` y `@container` se comportan con normalidad, sin desfase de fotogramas.

`matchMedia()` evalúa `width`, `height`, `orientation`, `-webkit-device-pixel-ratio`, `resolution`, `hover`, `pointer` y `prefers-color-scheme`, en la forma `min-`/`max-`, la forma de intervalo de nivel 4 (`(width >= 600px)`, `(400px \<= width \<= 800px)`) y la forma sin valor (`(width)`). Los anchos, las alturas y `orientation` describen **la caja de tu widget**, no la ventana gráfica del navegador, por lo que siguen `document.body.clientWidth` en lugar de `window.innerWidth`, y `em` y `rem` equivalen a 16px. `hover` y `pointer` describen la entrada principal del dispositivo del usuario. Cualquier otra condición se considera desconocida, como los navegadores tratan las características desconocidas: el elemento separado por comas en el que aparece se evalúa como `false`, incluso bajo `not`, a menos que el resto de ese elemento ya determine el resultado, como en `not print and (prefers-reduced-motion: reduce)`. Esto abarca las características desconocidas y la sintaxis que este analizador no implementa dentro de una condición, como los grupos anidados tipo `((min-width: 600px))`, `not` dentro de un grupo y valores `calc()`. Un `or` entre condiciones hace que su elemento sea `false`. Los constructores `MediaQueryList` y `MediaQueryListEvent` tampoco se exponen, por lo que las comprobaciones `instanceof` con ellos lanzan un `ReferenceError`.

Dado que esa hoja de estilos llega a la página real, el host evalúa una regla `@media (min-width: ...)` con respecto a la ventana gráfica del navegador, mientras que `matchMedia('(min-width: ...)')` responde para la caja de tu widget. Para que CSS siga la misma caja que ve tu JavaScript, declara tu propio `container-type` en un contenedor envolvente y consúltalo: una regla `@container` sin uno se resuelve con respecto al contenedor host más cercano, no a tu widget. La misma separación se aplica al esquema de colores, donde una hoja de estilos `@media (prefers-color-scheme: dark)` sigue la preferencia del navegador y del SO, mientras que `matchMedia('(prefers-color-scheme: dark)')` sigue el tema seleccionado en Twenty, así que aplica estilos usando tokens de `useTheme()` cuando ambos deban coincidir.

La altura que se te proporciona también corresponde a tu propia caja y, dependiendo de dónde te monte el host, esa caja puede dimensionarse según tu propio contenido. La ramificación del diseño según `min-height`, `max-height` u `orientation` puede entonces retroalimentarse y oscilar. Prefiere consultas basadas en el ancho o `@container` con `container-type: inline-size` para tomar decisiones de diseño.

<Note>
  `requestAnimationFrame` funciona, con o sin el prefijo `window.`. Solo
  Chrome ejecuta un fotograma de animación real dentro de un worker; Firefox y Safari reciben un
  temporizador de 16 ms, así que úsalo para aplazar una nueva lectura después de una escritura, no para controlar una
  animación.
</Note>

### Desplazamiento

Al asignar `scrollTop` o `scrollLeft`, llamar a `scrollTo()` o a su alias `scroll()`, y llamar a `scrollIntoView()` se desplaza el elemento correspondiente en la página:

* Los cambios de desplazamiento se aplican después del siguiente renderizado, en el orden en que los realizó tu código. Dentro de un mismo renderizado, los cambios en la selección de entrada se aplican primero, por lo que llamar a `setSelectionRange()` seguido de una escritura en `scrollLeft` mantiene visible el cursor.
* Las lecturas devuelven el valor que escribiste hasta que la página informa de la posición real, que el navegador limita al intervalo desplazable. En los contenedores de derecha a izquierda, `scrollLeft` es cero o negativo, como en los navegadores.
* `scrollIntoView()` acepta `block` e `inline` con `start`, `center`, `end` y `nearest`, alineando `block` verticalmente e `inline` horizontalmente, por lo que los modos de escritura verticales no se mapean. Solo desplaza los propios contenedores de desplazamiento de tu componente, nunca el marco del widget, la página ni otro componente. `focus()` sigue mostrando el elemento enfocado tal como lo hace el navegador.
* El desplazamiento es instantáneo: se ignoran `behavior` y la opción `container`, y `scrollBy()` no está disponible.
* Volver a escribir una posición que acabas de leer, como `element.scrollTop = element.scrollTop`, no hace nada, por lo que no puede deshacer un desplazamiento que el usuario haya realizado mientras tanto. Esto solo se cumple una vez que la página ha medido el elemento; hasta entonces, se aplica la escritura.
* Desplazar `document.documentElement`, `document.body` o `window` se mantiene dentro del entorno aislado y nunca desplaza la página; `window.scrollTo()`, `scroll()` y `scrollBy()` no hacen nada.
* La primera lectura de un contenedor que nunca se midió devuelve ceros (consulta Diseño y medición), por lo que una comprobación de desplazabilidad realizada justo después de que aparezca el contenedor puede indicar que no es desplazable.

### Ámbito global

Los elementos nativos propios del worker también tienen alias en `window`, por lo que funcionan con o sin el prefijo `window.`: `fetch`, `setTimeout`/`clearTimeout`, `setInterval`/`clearInterval`, `queueMicrotask`, `console`, `crypto`, `performance`, `structuredClone`, `btoa`/`atob`, `URL`/`URLSearchParams`, `AbortController`/`AbortSignal`, `Headers`/`Request`/`Response`, `Blob`, `File`, `FormData` y `TextEncoder`/`TextDecoder`.

### Acceso al DOM

Un `ref` te da un elemento sandbox, no un `HTMLElement`.

| Lo que escribes                                | Qué ocurre                                                                                                                                                                                  | Usa en su lugar                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ref.current.focus()`, `.blur()`               | Reenviar al elemento correspondiente de la página y actualizar el elemento activo del entorno aislado                                                                                       | `onFocus` / `onBlur` para observar cambios de foco                                                                                                                                                                                                                                                                   |
| `ref.current.click()`                          | Envía un `click` dentro del entorno aislado: una casilla de verificación o un botón de opción cambia de estado y se ejecuta su `onChange`, pero no se hace clic en el elemento de la página | Componentes controlados para todo lo que debe hacer la página                                                                                                                                                                                                                                                        |
| `ref.current.select()`, `.setSelectionRange()` | Funciona con `input` y `textarea`; se aplica al elemento de la página después del siguiente renderizado                                                                                     | Componentes controlados para el valor en sí                                                                                                                                                                                                                                                                          |
| `ref.current.scrollTo()`, `.scrollIntoView()`  | Desplaza los propios contenedores de desplazamiento del componente en la página (consulta Desplazamiento)                                                                                   | `focus()` cuando también quieras mover el foco                                                                                                                                                                                                                                                                       |
| `video.play()`                                 | Lanza una excepción                                                                                                                                                                         | Componentes controlados; lee los valores de `event.target`                                                                                                                                                                                                                                                           |
| `document.createTreeWalker()`                  | Lanza una excepción                                                                                                                                                                         | `querySelector()` / `querySelectorAll()`, `matches()`, `closest()` (incluidas pseudoclases como `:disabled` y `:not()`), `getElementById()`, `contains()` y `compareDocumentPosition()` funcionan; `getElementsByClassName()` también funciona, pero devuelve una colección estática, no una `HTMLCollection` activa |
| `document.activeElement`                       | Sigue el foco de la página dentro del componente y se actualiza cuando el código del entorno aislado llama a `focus()` o `blur()`                                                           | `onFocus` / `onBlur` para reaccionar al foco de la página                                                                                                                                                                                                                                                            |
| `canvas`                                       | No renderiza nada, sin error                                                                                                                                                                | SVG, o dibujar fuera de pantalla y mostrar el resultado en un elemento `img`                                                                                                                                                                                                                                         |
| `createPortal(node, document.body)`            | Se renderiza en una capa de superposición del host limitada a 200px alrededor del componente                                                                                                | Mantén las superposiciones dentro de esta área o añade desplazamiento para contenido más grande                                                                                                                                                                                                                      |

`element.classList` funciona, respaldado por el atributo `class`: `add`, `remove`, `toggle`, `replace`, `contains`, `item`, `length`, `value` y la iteración se comportan como lo hacen en un navegador, y `className` se mantiene sincronizado. `element.dataset` funciona de la misma manera, respaldado por los atributos `data-*`; escribe los nombres `data-*` en minúsculas, ya que el sandbox conserva los nombres de los atributos tal como se escribieron en lugar de convertirlos a minúsculas como lo hace un navegador.

Los portales del cuerpo pueden extenderse hasta 200px más allá de cada borde de tu componente, incluso fuera del marco de desplazamiento de un widget. Las superposiciones más grandes se recortan a esta área, así que proporciona a los menús largos su propio contenedor de desplazamiento. La navegación con teclado en las listas de Twenty UI, como Autocomplete y Select, muestra la opción resaltada dentro de ese contenedor. Las API nativas de capa superior, como `showModal()`, `showPopover()` y `requestFullscreen()`, están bloqueadas.

### Eventos

Eventos de ratón, puntero, tacto, arrastre, teclado, foco, `input`/`change`/`submit`, `scroll`/`wheel`/`contextmenu` y `animationend`/`transitionend` pasan al host, además de algunos específicos por elemento: `load`/`error` en `img`, portapapeles y composición en `input`/`textarea`, medios en `video`/`audio`, `toggle` en `details`/`dialog`. Cualquier otra cosa (`onAuxClick`, `onSelect`, `onInvalid`, `onReset`, `onAnimationStart`, captura de puntero, `onLoad` fuera de `img`) se descarta sin aviso.

Los manejadores reciben eventos tipados creados a partir del evento de la página, `PointerEvent`, `MouseEvent`, `KeyboardEvent`, `InputEvent`, `WheelEvent` o `FocusEvent`, y esos constructores existen en el sandbox para `dispatchEvent()`. Cada evento reenviado también incluye la interfaz de eventos sintéticos de React (`nativeEvent`, `isDefaultPrevented()`, `isPropagationStopped()`, `persist()`), por lo que el código escrito para eventos de React sigue funcionando aunque el sandbox entregue el objeto de evento directamente a tu manejador.

Un evento de la página cruza cuando el elemento con el que interactuó el usuario, o uno de sus antecesores en tu componente, tiene un manejador para ese tipo de evento. Cruza una vez y luego se propaga dentro del sandbox como lo hace en la página: `event.target` es el elemento con el que interactuó el usuario, `currentTarget` es el elemento cuyo manejador se está ejecutando, `stopPropagation()` impide que se ejecuten los manejadores de los antecesores y `relatedTarget` apunta al elemento del sandbox desde o hacia el que se movieron el foco o el puntero, o es `null` cuando ese elemento está fuera de tu componente. Como en React, `onFocus` y `onBlur` también se ejecutan para cambios de foco dentro del elemento, y `onClickCapture` y los demás manejadores de captura se ejecutan durante la fase de captura.

Los manejadores que una biblioteca añade con `React.cloneElement`, como los que están detrás de la prop `render` de Base UI, se ejecutan después de los propios manejadores del elemento en lugar de reemplazarlos, por lo que pasar `onClick: undefined` a `cloneElement` no elimina el manejador del elemento. Un manejador en un elemento `render` de Base UI todavía puede llamar a `event.preventBaseUIHandler()` para omitir el propio manejador de Base UI.

`event.target.value` y `checked` reflejan el control una vez que el navegador ha aplicado el cambio del usuario: en los manejadores `input`, `change`, `click`, `blur` y `focusout`, y en los manejadores `keyup` para `value`. En los manejadores `keydown`, `beforeinput` y de puntero, contienen el valor y el estado marcado del control a partir de su última edición, independientemente de lo que escuche tu componente: un manejador `Enter` lee el texto escrito hasta el momento, pero un manejador para una tecla imprimible aún no ve esa tecla, así que lee valores en tiempo real de una entrada controlada o de un manejador `onChange`.

Los listeners de `document` reciben los eventos que cruzan desde tu componente, pero nada de lo que ocurre en otra parte de la página, así que, para capturar atajos con `document.addEventListener('keydown', ...)`, coloca un `onKeyDown` en un elemento que envuelva tu componente. Los listeners de `window` solo reciben `error` y `unhandledrejection`. Los movimientos del puntero solo cruzan sobre elementos que tienen un manejador de movimiento, y la captura del puntero permanece en la página, por lo que un arrastre se detiene en cuanto el puntero sale de esos elementos. `event.preventDefault()` tampoco cruza; el envío de formularios, `dragover`/`drop` y los clics en enlaces ya están protegidos por ti.

### Atributos y estilos

Cada elemento reenvía sus propias propiedades al DOM del host (`href` en `a`, `src`/`alt` en `img`, `value`/`placeholder`/`disabled` en `input`, etc.), además de un conjunto común en cada elemento: `id`, `className`, `style`, `title`, `tabIndex`, `role`, `draggable` y cualquier atributo `aria-*` / `data-*` (con guiones, por lo que `ariaLabel` se descarta). Cualquier cosa fuera de eso se descarta silenciosamente, así que expresa el estado personalizado como `data-*`.

El CSS del componente, ya sea desde `import './styles.css'`, CSS-in-JS o un elemento `style`, se inyecta en el `head` de la página del host **sin ámbito**. Así que los nombres de clase colisionan con los de Twenty (ponles un prefijo y nunca escribas `div { ... }` como selectores), y `@media` coincide con la ventana del navegador en lugar de con tu widget (usa `@container` con tu propio `container-type`). Las props de `style` en línea no se ven afectadas.

### Almacenamiento y red

`localStorage` y `sessionStorage` son proporcionados por Twenty en lugar del navegador: el componente se ejecuta en un worker en un origen opaco, por lo que el host almacena los valores en nombre de tu aplicación. Consulta [almacenamiento](#storage) para ver su ámbito y límites. IndexedDB, las cookies, la Cache API y `BroadcastChannel` siguen sin estar disponibles. Para mantener el estado entre dispositivos, llama a una [función de lógica](/es/developers/extend/apps/logic/logic-functions) y usa su [almacenamiento de clave-valor](/es/developers/extend/apps/logic/key-value-store).

`fetch` funciona, con matices:

* Las llamadas a la API de Twenty y a las rutas de tu aplicación se hacen por proxy a través del host, así que da prioridad a [`RestApiClient`](#calling-the-twenty-rest-api). En las llamadas con proxy, `AbortSignal` y las demás opciones de `RequestInit` se descartan, y solo se admiten cuerpos de tipo `string` y `URLSearchParams`.
* Otros orígenes salen del sandbox con `Origin: null`, por lo que una API de terceros responde solo si envía `Access-Control-Allow-Origin: *`. Llámala desde una función de lógica en su lugar.
* `fetch('/rest/people')` nunca se hace coincidir con la API de Twenty, porque el sandbox no tiene URL de página contra la que resolver una ruta relativa.

### Selección de archivos

Las entradas de archivos proporcionan objetos `File` nativos con metadatos y contenido legible. Usa `text()` o `arrayBuffer()` para leer un archivo seleccionado, o pásalo a la función host `uploadFile`. Para abrir el selector nativo, es necesario llamar a `input.click()` en el plazo de un segundo desde un clic de confianza dentro de tu componente. Los flujos de React y Preact creados con el SDK se verifican en Chromium.

Las URL de objetos creadas por el worker asignadas a `img.src` admiten vistas previas. Revoca tus URL al reemplazar la imagen o desmontar tu componente. Tu aplicación se encarga de la validación de archivos, el progreso de carga y la cancelación.

### Captura de medios

Declara `microphone`, `camera` o ambos en la matriz `requestedCapabilities` que se pasa a `defineApplication()` para que estas capacidades aparezcan durante la instalación. La aprobación se aplica a todo el espacio de trabajo y requiere un miembro que pueda administrar aplicaciones.

Si una aplicación instalada llama a `navigator.mediaDevices.getUserMedia()` sin el acceso requerido, Twenty pausa la captura y muestra un cuadro de diálogo de aprobación. Esto también admite aplicaciones antiguas sin declaraciones de capacidades. Los miembros que no pueden administrar aplicaciones deben pedir a un administrador del espacio de trabajo que apruebe el acceso. Cancelar el cuadro de diálogo rechaza la solicitud antes de que se soliciten los permisos del navegador o del sistema operativo.

Las actualizaciones de paquetes conservan las autorizaciones existentes del espacio de trabajo y no conceden automáticamente acceso adicional a medios. Las aplicaciones de desarrollo sincronizadas localmente reciben las capacidades declaradas en su manifiesto. Una vez aprobado el acceso, Twenty no vuelve a solicitarlo para cada captura, pero los permisos del navegador y del sistema operativo siguen aplicándose.

Un punto naranja en la cabecera del espacio de trabajo indica una captura activa. Pase el cursor sobre el punto o selecciónelo para ver las aplicaciones que usan el micrófono o la cámara y detener su captura. Las solicitudes pendientes aparecen como un punto delineado con un control de cancelación.

`getUserMedia()` y `MediaRecorder` se ejecutan mediante polyfills de sandbox, por lo que el código de grabación estándar y `MediaRecorder.isTypeSupported()` funcionan sin cambios tras la aprobación. Se aceptan objetos de restricciones detallados, pero no se reenvían. El anfitrión captura con sus valores predeterminados para los tipos solicitados. Distintas aplicaciones pueden capturar simultáneamente, y detener una aplicación afecta solo a sus propias sesiones. Cada componente frontal admite una captura pendiente o activa a la vez. Almacena un `Blob` grabado con la función host `uploadFile`.

### Otras carencias

* **Cargas útiles de arrastrar y soltar.** Los eventos de arrastre se disparan, pero `event.dataTransfer` es `undefined`.
* **Integraciones nativas de Node.** `fs`, `path` y `node:crypto` hacen que la compilación falle, así que mueve ese trabajo a una [función de lógica](/es/developers/extend/apps/logic/logic-functions). Web Crypto reemplaza a `node:crypto`, y `fetch`, `TextEncoder` y `URL` también están disponibles; consulta el [ámbito global](#global-scope), pero nada reemplaza a `fs`: el entorno aislado no tiene sistema de archivos.
* **`iframe`** siempre se vuelve a aislar sin `allow-same-origin`, por lo que un embed que depende de su propia sesión se renderiza como desconectado. Tampoco tiene `onLoad`.
