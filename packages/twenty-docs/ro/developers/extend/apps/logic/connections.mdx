---
title: Conexiuni
description: Permite aplicației tale să acționeze în numele unui utilizator în servicii ale terților prin OAuth.
icon: plug
---

Conexiunile sunt acreditări pe care un utilizator le deține pentru un serviciu extern (Linear, GitHub, Slack, ...). Aplicația ta declară **cum** sunt obținute acele acreditări — un **furnizor de conexiune** — și le folosește în timpul execuției pentru a efectua apeluri autentificate către API-ul terț.

În prezent este acceptat doar OAuth 2.0. Tipurile viitoare de acreditări (jetoane de acces personale, chei API, autentificare de bază) se vor integra în aceeași interfață — aplicațiile care deja folosesc `defineConnectionProvider({ type: 'oauth', ... })` nu vor trebui să migreze.

<Accordion title="defineConnectionProvider" description="Declară cum sunt obținute conexiunile aplicației tale">

Un furnizor de conexiune descrie handshake-ul OAuth de care are nevoie aplicația ta. Pentru un furnizor `WORKSPACE` (implicit), un membru face clic pe "Adaugă conexiune" în setările aplicației tale, completează ecranul de consimțământ al furnizorului și este creată o înregistrare `ConnectedAccount` în spațiul său de lucru. Consultă „Conexiuni de spațiu de lucru sau personale” pentru furnizorii `USER`.

O configurație funcțională are nevoie de **două fișiere** — furnizorul de conexiune și o declarație `serverVariables` corespunzătoare în `defineApplication` care conține acreditările clientului OAuth.

```ts src/connection-providers/linear-connection.ts
import { defineConnectionProvider } from 'twenty-sdk/define';

export default defineConnectionProvider({
  universalIdentifier: '9c7d1f5e-6a0b-4d44-be0c-3f8b5a9d4e6f',
  name: 'linear',
  displayName: 'Linear',
  icon: 'IconBrandLinear',
  // Optional: a logo bundled in your app's public/ folder, shown next to the
  // provider in the app's General tab.
  logo: 'public/linear-logomark.svg',
  type: 'oauth',
  scope: 'WORKSPACE',
  oauth: {
    authorizationEndpoint: 'https://linear.app/oauth/authorize',
    tokenEndpoint: 'https://api.linear.app/oauth/token',
    scopes: ['read', 'write'],
    // These must match keys in `defineApplication.serverVariables` below.
    clientIdVariable: 'LINEAR_CLIENT_ID',
    clientSecretVariable: 'LINEAR_CLIENT_SECRET',
    // Optional: defaults to 'json'. Some providers (Linear, Slack) want
    // 'form-urlencoded' for the token request.
    tokenRequestContentType: 'form-urlencoded',
    // Optional: defaults to true. Disable only if the provider rejects PKCE.
    usePkce: false,
    // Optional: extra query params on the authorize URL.
    // authorizationParams: { prompt: 'consent' },
    // Optional: provider's RFC 7009 token revocation endpoint, called on disconnect.
    // revokeEndpoint: 'https://example.com/oauth/revoke',
  },
  // Optional: a logic function in this app that returns a stable id for the
  // upstream account, run before the tokens are saved. See "Identify the
  // connected account".
  // identifyAccountLogicFunction: { universalIdentifier: '2f1e0d9c-...-...' },
  // Optional: a logic function in this app to run right after a connection is
  // established. See "Run a logic function on connect".
  // onConnectLogicFunction: { universalIdentifier: '3a2b1c0d-...-...' },
  // Optional: a logic function in this app to run right after a connection is
  // removed. See "Run a logic function on disconnect".
  // onDisconnectLogicFunction: { universalIdentifier: '4d5e6f70-...-...' },
});
```

```ts src/application.config.ts
import { defineApplication } from 'twenty-sdk/define';

export default defineApplication({
  universalIdentifier: '...',
  displayName: 'Linear',
  description: 'Connect Linear to Twenty.',
  // OAuth client credentials live on the app registration (one OAuth app per
  // Twenty server, configured by the admin) — not per-workspace. Declare them
  // as serverVariables so the admin can fill them in once for all installs.
  serverVariables: {
    LINEAR_CLIENT_ID: {
      description: 'OAuth client ID from your Linear OAuth application.',
      isSecret: false,
      isRequired: true,
    },
    LINEAR_CLIENT_SECRET: {
      description: 'OAuth client secret from your Linear OAuth application.',
      isSecret: true,
      isRequired: true,
    },
  },
});
```

Puncte cheie:

* `name` este șirul identificator unic folosit în `listConnections({ providerName })` (kebab-case, trebuie să corespundă `^[a-z][a-z0-9-]*$`).
* `displayName` apare în fila General a aplicației și în lista de instrumente AI.
* `scope` stabilește cine se conectează: `'WORKSPACE'` (implicit) pentru conexiuni partajate cu întregul spațiu de lucru, `'USER'` pentru conexiunile pe care fiecare membru le realizează pentru sine. Consultă mai jos „Conexiuni de spațiu de lucru sau personale”.
* `logo` este o cale către un activ inclus în pachet în folderul `public/` al aplicației dvs., servit prin activele publice ale aplicației. Când este omis, fila General revine la un substituent generat din `displayName`.
* `clientIdVariable` / `clientSecretVariable` sunt **nume**, nu valori — trebuie să se potrivească cheilor declarate în `defineApplication.serverVariables`. Valorile reale `client_id` și `client_secret` sunt introduse de administratorul serverului prin interfața de înregistrare a aplicației și nu sunt niciodată comise în repo-ul tău.
* Folosește `serverVariables` (nu `applicationVariables`) — acreditările OAuth sunt la nivel de server și există o singură aplicație OAuth pentru fiecare server Twenty.
* Până când ambele `serverVariables` sunt completate, fila General a aplicației afișează un indiciu „necesită administrator de server”, iar butonul „Adaugă conexiune” este dezactivat.
* `type: 'oauth'` este singura valoare acceptată în prezent. Discriminatorul este compatibil cu versiuni viitoare: tipurile viitoare (`'pat'`, `'api-key'`, ...) vor adăuga blocuri noi de sub-configurație alături de `oauth`.

URL-ul de callback OAuth pe care furnizorul tău trebuie să îl includă pe lista albă este:

```
https://<your-twenty-server>/auth/apps/callback
```

<Accordion title="Identificați contul conectat" description="Împiedicați o reconectare să schimbe în mod silențios conturile sursă">

Când un utilizator face clic pe **Reconnect**, nimic nu îl împiedică să autorizeze un alt cont sursă decât cel cu care a fost realizată conexiunea: spațiul de lucru Slack B în locul spațiului de lucru A, o altă organizație GitHub, un alt cont Google. Fără o modalitate de a le diferenția, Twenty ar suprascrie tokenurile lui A cu cele ale lui B, iar tot ce a construit aplicația dvs. pe baza acelei conexiuni ar începe în mod silențios să comunice cu B.

Setați `identifyAccountLogicFunction` la o funcție logică din aceeași aplicație care returnează un ID stabil pentru contul asociat tokenului proaspăt emis:

```ts src/connection-providers/slack-connection.ts
import { defineConnectionProvider } from 'twenty-sdk/define';

import { SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER } from 'src/constants/universal-identifiers';

export default defineConnectionProvider({
  universalIdentifier: '...',
  name: 'slack',
  displayName: 'Slack',
  type: 'oauth',
  oauth: {
    /* ... */
  },
  identifyAccountLogicFunction: {
    universalIdentifier: SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER,
  },
});
```

**Când se execută.** Sincron, în interiorul callbackului OAuth, imediat după ce codul de autorizare este schimbat pentru tokenuri și **înainte** ca orice element să fie salvat. Utilizatorul așteaptă redirecționarea, astfel că, atunci când aplicația este instalată sau sincronizată, Twenty limitează `timeoutSeconds` al funcției la 10, indiferent de ce declară manifestul; păstrați-l la o singură cerere către endpointul furnizorului „cine sunt eu”. Hookul on-connect, dacă există, rulează totuși ulterior, după ce conexiunea este salvată.

**Încărcătură utilă.** Handlerul primește tokenul de acces provizoriu. Nu a fost încă persistat, deci `getConnection` nu îl poate returna; utilizați-l direct și nu îl înregistrați în jurnal.

```ts
type IdentifyAccountPayload = {
  connectionProviderId: string;
  connectionProviderName: string; // e.g. 'slack'
  accessToken: string;
};
```

**Rezultat.** Returnați id-ul contului și, opțional, un handle de afișat:

```ts
type IdentifyAccountResult = {
  externalAccountId: string | null; // non-empty, at most 512 characters; null opts out
  handle?: string; // non-empty when present
};
```

* `externalAccountId` trebuie să fie stabil pe durata de viață a contului din amonte (un id de echipă, un id de organizație, un id de utilizator), niciodată un nume pe care utilizatorul îl poate modifica. Twenty îl elimină de spațiile de la început și de la sfârșit și îl stochează în conexiune la prima conectare.
* `handle`, atunci când este returnat, înlocuiește handle-ul pe care Twenty l-ar deduce altfel (e-mailul OIDC din `id_token` sau e-mailul utilizatorului care se conectează). Returnați ceva ce recunoaște un utilizator, cum ar fi numele spațiului de lucru Slack.
* Returnați `{ externalAccountId: null }` atunci când furnizorul nu are un id stabil de oferit. Twenty se comportă apoi ca și cum nu ar fi fost declarată nicio funcție de identificare: nu este stocat niciun id, o reconectare șterge orice id stocat anterior, iar reconectările nu sunt verificate. Un simplu `null` sau lipsa unei valori returnate este tratată ca o eroare, astfel încât un handler care uită să returneze o valoare nu poate dezactiva verificarea în mod silențios.
* Dacă funcția generează o excepție, expiră sau returnează orice altceva, conexiunea **nu** este salvată, iar utilizatorul revine pe pagina de setări cu o eroare. Generați o excepție doar atunci când chiar nu puteți identifica contul.

**Refuzarea reconectării.** La o reconectare, Twenty compară `externalAccountId` returnat cu cel stocat în conexiune. Dacă diferă, callback-ul este refuzat înainte de a se scrie ceva: tokenurile, handle-ul și domeniul de aplicare existente rămân neschimbate, hook-ul on-connect nu se execută, iar utilizatorul vede ce cont a autorizat și cărui cont îi aparține conexiunea. Conexiunile create înainte ca aplicația dvs. să declare funcția nu au încă un id stocat; următoarea lor reconectare îl stochează.

Twenty nu elimină duplicatele pe baza `externalAccountId`: conectarea aceluiași cont din amonte de două ori prin **Adăugare conexiune** creează două conexiuni. Id-ul este expus în `listConnections` și `getConnection`, astfel încât o aplicație care dorește o conexiune per cont din amonte poate detecta ea însăși duplicatele (de exemplu, în hookul său on-connect).

**Scrierea funcției.** Majoritatea furnizorilor expun un singur endpoint care descrie tokenul curent. Pentru Slack, acesta este `auth.test`, care returnează spațiul de lucru (`team_id`, `team`) și utilizatorul din spatele tokenului:

```ts src/logic-functions/slack-identify-account.ts
import { defineLogicFunction } from 'twenty-sdk/define';
import type {
  IdentifyAccountPayload,
  IdentifyAccountResult,
} from 'twenty-sdk/logic-function';

import { SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER } from 'src/constants/universal-identifiers';

export default defineLogicFunction({
  universalIdentifier: SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER,
  name: 'slack-identify-account',
  timeoutSeconds: 10,
  handler: async ({
    accessToken,
  }: IdentifyAccountPayload): Promise<IdentifyAccountResult> => {
    const response = await fetch('https://slack.com/api/auth.test', {
      method: 'POST',
      headers: { Authorization: `Bearer ${accessToken}` },
    });
    const { ok, error, team_id, team } = await response.json();

    if (!ok) {
      throw new Error(`auth.test failed: ${error}`);
    }

    return { externalAccountId: team_id, handle: team };
  },
});
```

Alți furnizori urmează același model, indiferent dacă endpointul lor „cine sunt eu” este REST sau GraphQL. Generați o excepție atunci când furnizorul respinge tokenul și returnați id-ul ca șir: convertiți id-urile numerice, precum id-urile de utilizator GitHub, cu `String(id)`.

Identificarea este disponibilă în Twenty 2.48.0. Dacă aplicația dvs. se bazează pe aceasta, declarați `"engines": { "twenty": ">=2.48.0" }` în `package.json` al acesteia.

<Accordion title="Rulează o funcție logică la conectare" description="Reacționează în momentul în care o conexiune este stabilită">

Unii furnizori îți furnizează date în momentul conectării, pe care trebuie să le stochezi înainte ca conexiunea să poată fi utilizată — exemplul clasic este Slack, unde răspunsul OAuth identifică `team_id` al spațiului de lucru după care vor fi indexate evenimentele primite. Setează `onConnectLogicFunction` pentru a face referire la o funcție logică din aceeași aplicație (prin `universalIdentifier`), iar aceasta rulează imediat după ce `ConnectedAccount` este creat.

```ts src/connection-providers/slack-connection.ts
export default defineConnectionProvider({
  universalIdentifier: '...',
  name: 'slack',
  displayName: 'Slack',
  type: 'oauth',
  oauth: {
    /* ... */
  },
  // Runs claimSlackTeam after every successful Slack connection.
  onConnectLogicFunction: {
    universalIdentifier: '3a2b1c0d-1111-4222-8333-444455556666',
  },
});
```

Hook-ul rulează **asincron în spațiul de lucru care se conectează** (este pus în coadă, nu este așteptat), astfel încât un hook lent sau care eșuează nu blochează și nu întrerupe niciodată callback-ul OAuth — fă-l idempotent și lasă-l să își gestioneze singur reîncercările. Handlerul primește:

```ts
type OnConnectPayload = {
  connectionProviderId: string;
  connectionProviderName: string; // e.g. 'slack'
  connectedAccountId: string;
};
```

De acolo folosește `getConnection(connectedAccountId)` pentru a citi tokenul de acces proaspăt și a apela API-ul furnizorului (de ex. Slack `auth.test`) sau pentru a stoca o mapare în [magazinul cheie–valoare](/ro/developers/extend/apps/logic/key-value-store).

</Accordion>

<Accordion title="Rulează o funcție logică la deconectare" description="Curăță resursele atunci când o conexiune este eliminată">

Orice revendică o aplicație la momentul conectării trebuie eliberat atunci când conexiunea este eliminată. O integrare Slack care revendică un `team_id` la conectare, de exemplu, trebuie să elibereze acea revendicare astfel încât un alt spațiu de lucru să poată conecta aceeași echipă Slack. Setați `onDisconnectLogicFunction` să facă referire la o funcție logică din aceeași aplicație, iar aceasta rulează chiar înainte ca `ConnectedAccount` și tokenul său să fie șterse, astfel încât handlerul să poată încă apela furnizorul cu `getConnection` pentru a elibera orice a configurat hook-ul de conectare de la distanță.

```ts src/connection-providers/slack-connection.ts
export default defineConnectionProvider({
  universalIdentifier: '...',
  name: 'slack',
  displayName: 'Slack',
  type: 'oauth',
  oauth: {
    /* ... */
  },
  // Runs releaseSlackTeam after every Slack disconnection.
  onDisconnectLogicFunction: {
    universalIdentifier: '4470aba8-5ff5-4800-88db-2a427cd8677c',
  },
});
```

Spre deosebire de hook-ul de conectare, acesta rulează **inline în spațiul de lucru care se deconectează**, o singură dată, fără reîncercări: o eroare este capturată, iar deconectarea se finalizează în continuare. Handler-ul primește aceeași structură de payload:

```ts
type OnDisconnectPayload = {
  connectionProviderId: string;
  connectionProviderName: string; // e.g. 'slack'
  connectedAccountId: string;
};
```

`ConnectedAccount` și tokenul său sunt încă prezente atunci când rulează hook-ul, astfel încât `getConnection(connectedAccountId)` se rezolvă cu un token de acces nou, iar handlerul poate șterge orice a înregistrat de la distanță. Starea pe care furnizorul nu o poate returna (un `team_id`, un ID extern de abonament) trebuie totuși păstrată în [key-value store](/ro/developers/extend/apps/logic/key-value-store), scrisă la momentul conectării și indexată după `connectedAccountId`. Mențineți handlerul scurt: acesta rulează în cadrul cererii de deconectare, astfel încât `timeoutSeconds` reprezintă limita superioară pentru durata acestei cereri.

Hook-ul este declanșat atunci când o conexiune este eliminată în mod direct. Dezinstalarea aplicației elimină conexiunile acesteia printr-un mecanism în cascadă în baza de date, astfel încât hook-ul nu rulează în acest caz. Declară un `uninstallLogicFunction` pe `defineApplication` pentru acel flux: acesta rulează înainte ca metadatele aplicației să fie șterse, astfel încât poate apela în continuare `listConnections` și poate curăța tot ce a mai rămas.

</Accordion>

<Accordion title="listConnections / getConnection" description="Folosește conexiunile dintr-o funcție logică">

În interiorul unui handler de funcție logică, `listConnections({ providerName })` returnează înregistrările `ConnectedAccount` ale acestei aplicații pentru furnizorul dat, cu tokenuri de acces reîmprospătate.

```ts src/logic-functions/handlers/create-linear-issue-handler.ts
import { listConnections } from 'twenty-sdk/logic-function';

export const createLinearIssueHandler = async (input: {
  teamId?: string;
  title?: string;
}) => {
  if (!input.teamId || !input.title) {
    return { success: false, error: 'teamId and title are required' };
  }

  const connections = await listConnections({ providerName: 'linear' });

  // Workspace-shared credentials win when present; fall back to the first
  // personal one. For HTTP-route triggers you typically pick the
  // request user's connection via event.userWorkspaceId instead.
  const connection =
    connections.find((c) => c.scope === 'WORKSPACE') ?? connections[0];

  if (!connection) {
    return {
      success: false,
      error:
        'Linear is not connected. Open the app settings and click "Add connection".',
    };
  }

  // Use connection.accessToken to call the third-party API.
  const response = await fetch('https://api.linear.app/graphql', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${connection.accessToken}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      query: `mutation { issueCreate(input: { teamId: "${input.teamId}", title: "${input.title}" }) { success } }`,
    }),
  });

  return { success: response.ok };
};
```

Fiecare conexiune are:

| Câmp                | Descriere                                                                                                                                                                                                                                                                        |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                | ID unic al înregistrării; pasează-l la `getConnection(id)` pentru a reobține acea înregistrare                                                                                                                                                                                   |
| `scope`             | `'USER'` (privat pentru un membru al spațiului de lucru) sau `'WORKSPACE'` (partajat cu toți membrii)                                                                                                                                                                            |
| `visibility`        | Depreciat: `scope` cu litere mici (`'user'` sau `'workspace'`). Folosește în schimb `scope`                                                                                                                                                                                      |
| `scopes`            | Permisiunile OAuth acordate de furnizorul din amonte (distincte de `scope` — nu au legătură)                                                                                                                                                                                     |
| `userWorkspaceId`   | ID-ul userWorkspace al deținătorului — util pentru a alege "conexiunea utilizatorului care face cererea" în declanșatoarele de rută HTTP                                                                                                                                         |
| `workspaceMemberId` | ID-ul membrului spațiului de lucru al proprietarului sau `null` dacă acesta a părăsit între timp spațiul de lucru                                                                                                                                                                |
| `accessToken`       | Token de acces OAuth proaspăt (reîmprospătat automat dacă a expirat)                                                                                                                                                                                                             |
| `name`              | Numele afișat al conexiunii (derivat automat la callback-ul OAuth, poate fi redenumit de utilizator)                                                                                                                                                                             |
| `handle`            | Eticheta contului din amonte conectat, reîmprospătată la fiecare reconectare: `handle` returnat de funcția de identificare când există unul, altfel e-mailul din OIDC `id_token` returnat la schimbul de tokenuri, revenind la e-mailul utilizatorului Twenty care se conectează |
| `externalAccountId` | Id stabil al contului din amonte returnat de funcția de identificare sau `null` atunci când furnizorul nu declară niciunul ori conexiunea este anterioară acesteia. Nu este unic: utilizați-l pentru a elimina dvs. duplicatele de conexiuni                                     |
| `authFailedAt`      | Setat atunci când cea mai recentă reîmprospătare a eșuat sau când aplicația a raportat acreditarea ca fiind expirată prin `reportConnectionAuthFailure`; utilizatorul trebuie să se reconecteze                                                                                  |
| `authFailedReason`  | Explicație ușor de înțeles pentru `authFailedAt`, atunci când raportorul a furnizat una; afișată pe pagina cu detaliile conexiunii din setări                                                                                                                                    |

Puncte cheie:

* Pasează `{ providerName }` pentru a filtra după furnizor; omite-l pentru a obține toate conexiunile pe care această aplicație le deține la toți furnizorii.
* Serverul reîmprospătează transparent tokenul de acces înainte de a returna. Handlerul tău vede întotdeauna un token utilizabil (sau `authFailedAt` setat).
* `getConnection(id)` este echivalentul pentru o singură înregistrare.

</Accordion>

<Accordion title="reportConnectionAuthFailure" description="Indică platformei că o acreditare a expirat">

Platforma setează singură `authFailedAt` numai atunci când reîmprospătarea OAuth eșuează. Furnizorii ale căror tokenuri nu sunt reîmprospătate niciodată (de exemplu, un token de bot Slack) eșuează doar în momentul apelului, în gestionarele dvs., astfel încât rândul conexiunii din setări va continua să afișeze **Conectat**, în timp ce fiecare apel eșuează. Când codul dvs. întâlnește o respingere definitivă a autentificării, raportați-o:

```ts
import { reportConnectionAuthFailure } from 'twenty-sdk/logic-function';

await reportConnectionAuthFailure({
  connectionId: connection.id,
  reason:
    'Slack rejected the stored token (invalid_auth). Reconnect to restore the integration.',
});
```

Aceasta setează `authFailedAt` și motivul opțional pentru conexiune. Rândul din setări devine **Este necesară reconectarea** cu un buton Reconectare, pagina cu detaliile conexiunii afișează motivul, iar `getConnection` începe să lanseze `AppConnectionAuthFailedError` pentru acel rând. Indicatorul și motivul se șterg automat când utilizatorul se reconectează. Un `reason` mai lung de 1000 de caractere este respins, așa că trunchiați datele utile ale furnizorului înainte de a le transmite.

Raportați numai eșecurile pe care o reconectare le-ar remedia efectiv (o respingere de tip `invalid_auth` de la furnizor), niciodată erorile de rețea tranzitorii. O aplicație își poate raporta numai propriile conexiuni, iar un utilizator al cererii își poate raporta numai propriile acreditări personale.

Mutația din spatele acestei funcții auxiliare este livrată odată cu Twenty 2.40.0, astfel că apelarea ei către un server mai vechi eșuează. Dacă aplicația dvs. o utilizează, declarați dependența în `package.json`: `"engines": { "twenty": ">=2.40.0" }`.

</Accordion>

<Accordion title="Conexiuni de spațiu de lucru sau personale" description="Alege cine se conectează cu domeniul de aplicare al furnizorului">

Fiecare conexiune are unul dintre două domenii de aplicare:

* **Partajată la nivel de spațiu de lucru** (`'WORKSPACE'`) — orice membru al spațiului de lucru poate folosi acreditarea. Declanșatoarele cron / din bază de date o văd, de asemenea, deoarece nu au un utilizator al cererii.
* **Doar pentru mine** (`'USER'`) — acreditarea este privată pentru membrul care se conectează. Orice funcție logică apelată în numele lor (declanșator de rută HTTP cu `isAuthRequired: true`) o vede; declanșatoarele cron și evenimentele din bază de date nu.

`scope` al furnizorului stabilește pe care îl primesc noile sale conexiuni:

* `scope: 'WORKSPACE'` (implicit) — aplicația funcționează cu conexiuni partajate cu spațiul de lucru. **Adăugarea unei conexiuni** în setările aplicației creează o conexiune partajată în spațiul de lucru.
* `scope: 'USER'` — fiecare membru își conectează propriul cont, creând conexiuni personale. Membrii se vor conecta din **Preferințele aplicației**, care nu sunt disponibile încă: până atunci, un furnizor `USER` nu are butonul **Adaugă conexiune**, iar setările aplicației listează doar conexiunile pe care un membru le poate vedea deja.

Un furnizor are exact un domeniu de aplicare. Dacă aplicația ta are nevoie atât de o acreditare partajată, cât și de câte una pentru fiecare membru pentru același serviciu (de exemplu, un token de bot și contul propriu al fiecărui membru), declară doi furnizori.

O conexiune are întotdeauna scopul furnizorului său, iar scopul unui furnizor face parte din identitatea sa: o versiune ulterioară nu poate modifica `scope` al unui furnizor existent, iar actualizarea este refuzată dacă încearcă acest lucru. Pentru a muta un serviciu dintr-un scop în altul, declarați un furnizor nou cu un `universalIdentifier` nou și eliminați-l pe cel vechi. Actualizarea elimină apoi furnizorul vechi și fiecare conexiune realizată cu acesta prin fluxul obișnuit de deconectare (`onDisconnectLogicFunction`, revocarea tokenului, curățarea canalului), iar membrii se conectează din nou prin noul furnizor.

Adăugarea sau reconectarea unei conexiuni **Doar pentru mine** necesită permisiunea `CONNECTED_ACCOUNTS`, iar adăugarea sau reconectarea uneia **partajate în spațiul de lucru** necesită permisiunea `APPLICATIONS`.

Folosește conexiunea potrivită pentru fiecare handler:

```ts
// HTTP-route trigger — prefer the request user's own connection.
const conn =
  connections.find((c) => c.userWorkspaceId === event.userWorkspaceId) ??
  connections.find((c) => c.scope === 'WORKSPACE');

// Cron trigger — no request user; only shared credentials are sensible.
const conn = connections.find((c) => c.scope === 'WORKSPACE');
```

Sunt permise mai multe conexiuni per (utilizator, furnizor), astfel încât același utilizator poate avea "Personal Linear" și "Work Linear" una lângă alta.

Domeniul de aplicare al furnizorului este disponibil în Twenty 2.49.0. Dacă aplicația ta declară `scope`, declară `"engines": { "twenty": ">=2.49.0" }` în `package.json` al acesteia. În aceeași versiune, `scope` al unei conexiuni înlocuiește `visibility`, care rămâne disponibil ca alias depreciat cu litere mici. `listConnections` și `getConnection` din `twenty-sdk` 2.49.0 citesc `scope`, astfel încât aplicațiile construite cu acesta necesită un server 2.49.0.

<Accordion title="Configurare unică a furnizorului" description="Înregistrează-ți aplicația OAuth la serviciul terț">

Pentru fiecare furnizor de conexiune, administratorul serverului trebuie mai întâi să înregistreze o aplicație OAuth la serviciul terț.

1. Mergi la setările pentru dezvoltatori ale furnizorului (de ex. https://linear.app/settings/api/applications/new).
2. Setează **Redirect URI** la `\<SERVER_URL>/auth/apps/callback`.
3. Copiază **Client ID** și **Client Secret** generate.
4. Deschide aplicația instalată în Twenty ca administrator de server → setează valorile pe `serverVariables` corespunzătoare.
5. Membrii spațiului de lucru pot apoi să adauge conexiuni la furnizori `WORKSPACE` din secțiunea **Conexiuni** a fiecărei aplicații.
