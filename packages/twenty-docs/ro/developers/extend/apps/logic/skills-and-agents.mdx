## Prezentare generală

<Warning>
  Abilitățile și agenții sunt în prezent în stadiu alfa. Caracteristica funcționează, dar este încă în dezvoltare.
</Warning>

Aplicațiile pot defini capabilități AI care există în interiorul spațiului de lucru — instrucțiuni reutilizabile pentru abilități și agenți cu prompturi de sistem personalizate.

<AccordionGroup>
<Accordion title="defineSkill" description="Definiți abilități pentru agentul AI">

Abilitățile definesc instrucțiuni și capabilități reutilizabile pe care agenții AI le pot folosi în spațiul dvs. de lucru. Folosiți `defineSkill()` pentru a defini abilități cu validare încorporată:

```ts src/skills/example-skill.ts
import { defineSkill } from 'twenty-sdk/define';

export default defineSkill({
  universalIdentifier: 'a1b2c3d4-e5f6-7890-abcd-ef1234567890',
  name: 'sales-outreach',
  label: 'Sales Outreach',
  description: 'Guides the AI agent through a structured sales outreach process',
  icon: 'IconBrain',
  content: `You are a sales outreach assistant. When reaching out to a prospect:
1. Research the company and recent news
2. Identify the prospect's role and likely pain points
3. Draft a personalized message referencing specific details
4. Keep the tone professional but conversational`,
});
```

Puncte cheie:
* `name` este un șir identificator unic pentru abilitate (se recomandă kebab-case).
* `label` este numele lizibil afișat în interfața cu utilizatorul (UI).
* `content` conține instrucțiunile abilității — acesta este textul pe care agentul AI îl folosește.
* `icon` (opțional) setează pictograma afișată în UI.
* `description` (opțional) oferă context suplimentar despre scopul abilității.

</Accordion>
<Accordion title="defineAgent" description="Definiți agenți AI cu prompturi personalizate">

Agenții sunt asistenți AI care există în interiorul spațiului dvs. de lucru. Utilizați `defineAgent()` pentru a crea agenți cu un prompt de sistem personalizat:

```ts src/agents/example-agent.ts
import { defineAgent } from 'twenty-sdk/define';

export default defineAgent({
  universalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  name: 'sales-assistant',
  label: 'Sales Assistant',
  description: 'Helps the sales team draft outreach emails and research prospects',
  icon: 'IconRobot',
  prompt: 'You are a helpful sales assistant. Help users with their questions and tasks.',
});
```

Puncte cheie:
* `name` este un șir identificator unic pentru agent (se recomandă kebab-case).
* `label` este numele de afișare din interfața cu utilizatorul (UI).
* `prompt` conține promptul de sistem — acesta este textul de instrucțiuni care definește comportamentul agentului.
* `description` (opțional) oferă context despre ce face agentul.
* `icon` (opțional) setează pictograma afișată în UI.
* `modelId` (opțional) suprascrie modelul AI implicit utilizat de agent.
* `responseFormat` (opțional) stabilește formatul implicit al ieșirii agentului. Valoarea implicită este `{ type: 'text' }` pentru text liber. Folosește `{ type: 'json', schema }` pentru a impune ieșire JSON structurată. Un apel `runAgent()` sau un pas AI dintr-un flux de lucru poate solicita un format diferit, care are prioritate.
* `roleUniversalIdentifier` (opțional) leagă agentul de un rol definit de aplicația ta. Acel rol nu trebuie să acorde mai multe permisiuni decât rolul aplicației, altfel compilarea eșuează; consultați [Roluri de agent](/ro/developers/extend/apps/config/roles#agent-roles).
* `modelConfiguration` (opțional) activează instrumentele native ale modelului, așa cum face pagina de setări a agentului: `{ webSearch: { enabled: true }, twitterSearch: { enabled: true } }`. Fiecare instrument funcționează numai pe modelele care îl acceptă. Omiteți-l pentru a le menține dezactivate.
* `isSystem` (opțional, are implicit valoarea `false`) ascunde agentul din listele de agenți, la fel ca agenții pe care Twenty îi creează pentru pașii de IA din fluxurile de lucru. Schimbă doar ceea ce este afișat: agenții unei aplicații pot fi modificați numai prin intermediul aplicației, indiferent de valoarea acestei opțiuni.

În mod implicit, un agent returnează text liber. Pentru a obține o ieșire structurată, setează `responseFormat` la `{ type: 'json' }` și furnizează `schema`:

```ts src/agents/structured-agent.ts
import { defineAgent } from 'twenty-sdk/define';

export default defineAgent({
  universalIdentifier: 'c4d5e6f7-a8b9-0123-cdef-456789012345',
  name: 'lead-scorer',
  label: 'Lead Scorer',
  prompt: 'Score the lead and explain your reasoning.',
  responseFormat: {
    type: 'json',
    schema: {
      type: 'object',
      properties: {
        score: { type: 'number', description: 'Lead score from 0 to 100' },
        summary: { type: 'string', description: 'Short reasoning for the score' },
      },
      required: ['score', 'summary'],
      additionalProperties: false,
    },
  },
});
```

Note despre schemă:
* Schema este un obiect plat: `type` al fiecărei proprietăți trebuie să fie un tip primitiv (`string`, `number` sau `boolean`). Obiectele îmbricate și tablourile nu sunt acceptate.
* `description` (opțional) pe fiecare proprietate ghidează modelul cu privire la ce să pună acolo.
* `required` (opțional) enumeră proprietățile pe care modelul trebuie să le returneze întotdeauna.
* `additionalProperties: false` (opțional) interzice orice proprietate care nu este declarată în `properties`.

</Accordion>
<Accordion title="runAgent" description="Rulează un agent dintr-o funcție logică">

`runAgent()` permite unei funcții logice să ruleze unul dintre agenții aplicației tale (cu abilitățile și instrumentele sale). Identifică agentul prin `universalIdentifier` pe care l-ai transmis
către `defineAgent()` și transmite ca `input` ceea ce vrei să proceseze:

```ts src/logic-functions/run-enricher.ts
import { runAgent } from 'twenty-sdk/logic-function';

const { threadId, status, result, error, success } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: 'Enrich House Ad <recordId>: fill empty fields from its listing URL.',
});
```

Puncte cheie:
* `input` este un șir sau o listă de 1 până la 100 de mesaje
  (`{ role: 'user' | 'assistant', content: string }`). Un mesaj `user` poate
  include și atașamente de fișiere (vezi mai jos). Pentru a menține o conversație, transmiteți un
  `thread` în loc să reluați dvs. rândurile anterioare.
* În mod implicit, apelul așteaptă agentul, care poate citi/actualiza înregistrări
  direct prin propriile sale instrumente — `runAgent()` se finalizează după ce execuția se încheie.
  Transmiteți `waitForCompletion: false` pentru a se finaliza de îndată ce începe execuția:
  `status` este apoi `RUNNING` și `result: null`, iar răspunsul ajunge în conversația
  `threadId`. O execuție care depășește 15 minute se finalizează, de asemenea, ca
  `RUNNING`.
* Agentul poate, de asemenea, să se întrerupă până când se modifică o înregistrare sau a trecut un anumit timp.
  `runAgent()` se rezolvă apoi cu `success: true`, `status: 'SUSPENDED'` și
  `result: null`; agentul continuă singur mai târziu, iar răspunsul său ajunge în
  conversația `threadId`. Un apel către un `thread` al cărui agent încă așteaptă
  eșuează până când acesta se finalizează.
* Fiecare apel este stocat împreună cu intrarea și starea sa, precum și cu răspunsul și utilizarea sa
  atunci când se finalizează, astfel încât să apară în execuțiile agentului. Fără un `thread`, un apel primește o conversație proprie:
  `threadId` o denumește, iar un apel ulterior nu o vede niciodată.
* O aplicație poate rula doar propriii săi agenți.
* [Rolul implicit](/ro/developers/extend/apps/config/roles) al aplicației trebuie să acorde indicatorul de permisiune `AI` — adaugă `SystemPermissionFlag.AI` la `permissionFlagUniversalIdentifiers` (sau setează `canAccessAllTools: true`).
  Fără acesta, `runAgent()` eșuează cu o eroare de permisiune.
* Setează un `timeoutSeconds` generos pentru funcția logică — rulările agentului pot dura câteva secunde.
* `status` este `COMPLETED` cu un `result` care nu este null atunci când execuția se finalizează
  fără a aștepta; `SUSPENDED` cu `success: true` și `result: null` cât timp
  așteaptă; `RUNNING` cu `success: true` și `result: null` atunci când apelul nu
  a așteptat execuția; `FAILED` cu `success: false` și `error` care conține
  motivul (de exemplu, când spațiul de lucru rămâne fără credite AI în timpul execuției).

```ts src/roles/default-role.ts
import { defineApplicationRole, SystemPermissionFlag } from 'twenty-sdk/define';

export default defineApplicationRole({
  universalIdentifier: 'b648f87b-1d26-4961-b974-0908fd991061',
  label: 'Default function role',
  // runAgent() requires the AI permission flag on the app's default role.
  permissionFlagUniversalIdentifiers: [SystemPermissionFlag.AI],
});
```

<Warning>
  **Evită buclele:** dacă apelezi `runAgent()` dintr-un declanșator de tip eveniment de bază de date `*.updated`, iar agentul actualizează aceeași înregistrare, restrânge declanșatorul cu `updatedFields` la un câmp pe care agentul nu îl scrie niciodată (de exemplu, URL-ul sursă) sau verifică dacă vreun câmp țintă este încă gol înainte de a apela `runAgent()`.
</Warning>

### Trimiterea fișierelor cu un mesaj

Un mesaj `user` poate include `attachments`, astfel încât agentul vede o captură de ecran sau un
PDF în loc să vadă doar numele acestuia. Fiecare intrare face referire la un fișier pe care aplicația dvs. l-a
încărcat deja în folderul `agent-chat`:

```ts src/logic-functions/describe-screenshot.ts
const { result } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: [
    {
      role: 'user',
      content: 'What does this error screen say?',
      attachments: [{ fileId: uploadedFileId, filename: 'error.png' }],
    },
  ],
});
```

Încărcarea necesită indicatorul de permisiune `UPLOAD_FILE` în rolul implicit al aplicației,
alături de `AI`. `filename` este opțional și doar etichetează fișierul pentru model.

* Doar mesajele `user` pot include atașamente. Acestea nu pot fi reprezentate într-un
  tur al asistentului, astfel încât `runAgent()` le respinge acolo, în loc să le elimine.
* Cel mult **10** atașamente per mesaj.
* `fileId` trebuie să indice un fișier încărcat complet în același spațiu de lucru, în folderul
  `agent-chat`. Orice altceva face ca apelul să eșueze, în loc să
  răspundă în mod discret fără fișier.

### Solicitarea unui rezultat structurat

Transmiteți `responseFormat` pentru a obține un format numai pentru acest apel. Are prioritate față de
propriul `responseFormat` al agentului, astfel încât un agent poate deservi apelanți care au nevoie de
ieșiri diferite. Folosește aceeași schemă ca `defineAgent()`:

```ts src/logic-functions/score-lead.ts
const { result } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: `Score this lead: ${JSON.stringify(lead)}`,
  responseFormat: {
    type: 'json',
    schema: {
      type: 'object',
      properties: {
        score: { type: 'number', description: 'Lead score from 0 to 100' },
      },
      required: ['score'],
    },
  },
});
```

### Continuarea unei conversații

Transmiteți un `thread`, iar Twenty păstrează conversația pentru dvs.: fiecare apel trimite doar
noua intrare, iar agentul vede rândurile anterioare, inclusiv ceea ce au
returnat instrumentele sale. Utilizați ca cheie orice identificator stabil din partea dvs., cum ar fi un canal Slack
și marca temporală a firului de discuție:

```ts src/logic-functions/reply-in-thread.ts
const { result, threadId } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: 'What was the last touchpoint?',
  additionalInstructions: 'Answer in Slack markdown.',
  thread: { key: `${channelId}:${threadTs}`, title: 'Acme renewal' },
});
```

* Cheile sunt limitate la aplicația și agentul dvs., astfel încât două aplicații nu partajează niciodată o
  conversație. Numai tokenurile de acces ale aplicației pot transmite un `thread`.
* `input` poate conține numai mesaje `user`: conversația conține deja răspunsurile
  agentului.
* `additionalInstructions` sunt oferite modelului numai pentru acest apel și nu sunt
  stocate, ceea ce este potrivit pentru instrucțiuni per solicitare, cum ar fi reguli de formatare sau un
  termen-limită. Acestea funcționează și fără un `thread`.
* Fiecare rulare este stocată ca un tur cu starea sa, inclusiv cele eșuate. Utilizarea sa
  este stocată când agentul revine, chiar dacă a rămas fără credite. O
  rulare eșuată nu face parte din conversație, astfel încât următorul apel nu
  o vede.
* Apelurile din același fir de discuție rulează pe rând: un al doilea apel așteaptă ca
  primul să se termine, astfel încât fiecare îl vede pe cel dinaintea sa.
* Când rândurile rulează ca membri diferiți (vedeți mai jos), fiecare vede numai textul
  rândurilor celorlalți, niciodată rezultatele instrumentelor lor, deoarece acestea au fost citite cu
  permisiunile altcuiva.

### Rulare în numele unui membru al spațiului de lucru

Transmite `runAsWorkspaceMemberId` atunci când rularea este declanșată de o persoană — de exemplu, un chatbot care răspunde la un mesaj — astfel încât agentul să acționeze ca acel membru în loc să acționeze ca aplicația:

```ts src/logic-functions/answer-question.ts
const { result } = await runAgent({
  agentUniversalIdentifier: 'b3c4d5e6-f7a8-9012-bcde-f34567890123',
  input: 'How many open opportunities do we have?',
  runAsWorkspaceMemberId: '20202020-0687-4c41-b707-ed1bfca972a7',
});
```

Rularea acționează apoi cu **propriul rol al membrului**: poate face orice
poate face acel membru și nimic mai mult, înregistrările pe care le creează sunt atribuite lui, iar permisiunile lui la nivel de rând se aplică. Rolul agentului nu participă — este valoarea implicită a aplicației pentru rulările fără nicio persoană în spatele lor. Omite câmpul pentru
rulările autonome (joburi programate, declanșatoare de evenimente din baza de date): acelea păstrează propriul rol al agentului. Aplicația care acționează rămâne atașată la contextul rulării
pentru proveniență, fără a restrânge permisiunile membrului.

Aplicația ta este responsabilă să facă asocierea dintre persoana care a declanșat rularea și un membru al spațiului de lucru. A denumi unul necesită un token de acces al aplicației, iar ceea ce poate denumi un token depinde dacă acesta are sau nu un utilizator asociat:

* Un token **fără niciun utilizator atașat** poate denumi orice membru. O funcție logică rulează cu unul, la fel și tokenurile emise prin `client_credentials` sau dintr-o cheie API.
* Un token emis **în numele unui utilizator**, așa cum primește un front component, poate
  denumi doar propriul membru al acelui utilizator.

Orice altceva — o sesiune simplă de utilizator, o cheie API fără un token al aplicației — nu poate denumi deloc un membru.

<Warning>
  `runAgent()` aruncă o eroare atunci când membrul spațiului de lucru nu poate fi identificat — un membru necunoscut sau eliminat, ori unul fără niciun rol. Nu revine niciodată la
  propriul rol al agentului, deoarece acest lucru ar acorda mai mult acces decât a cerut apelantul.
</Warning>
