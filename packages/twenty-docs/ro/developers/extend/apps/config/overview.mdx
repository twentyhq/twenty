## Ce acoperă stratul de configurare

**Stratul de configurare** al unei aplicații Twenty este cel care descrie aplicația *pentru platformă* — identitatea ei, permisiunile pe care le deține și codul care rulează în timpul instalării sau actualizării. Aceste declarații nu adaugă noi structuri de date sau comportamente la rulare; ele îi spun lui Twenty *cine este aplicația* și *cum să fie configurată*.

```text
┌────────────────────────────────────────────────────────┐
│ Application — identity, default role, variables,       │
│               marketplace metadata                     │
│                                                        │
│   ┌──────────────────────────────────────────────────┐ │
│   │ Role — what the app's logic functions can read   │ │
│   │ and write (referenced by Application)            │ │
│   └──────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
                          │
                          ▼  (at install / upgrade time)
       ┌──────────────────────────────────┐
       │ Pre-install hook                 │  before metadata migration
       └──────────────────────────────────┘
       ┌──────────────────────────────────┐
       │ Post-install hook                │  after metadata migration
       └──────────────────────────────────┘
                          │
                          ▼  (at uninstall time)
       ┌──────────────────────────────────┐
       │ Uninstall hook                   │  before app removal
       └──────────────────────────────────┘
```

## Cum se leagă piesele

* **Cererea** este punctul de intrare. Fiecare aplicație are exact un apel `defineApplication()`, și indică ca implicit la unul **Role**.
* **Rolul** controlează funcțiile logice ale aplicației și componentele frontale pot citi și scrie. Urmărește cel mai puțin privilegiu: acordă doar permisiunile de care are nevoie codul tău.
* **Instalați Hooks** rulați în timpul instalării sau actualizării - preinstalați înainte de migrarea metadatelor (astfel încât poate refuza o actualizare riscantă), post-instalare după migrare (astfel încât să poată semăna date implicite cu noua schemă). Cârligul de dezinstalare rulează chiar înainte ca aplicația să fie eliminată, astfel încât să poată curăța resursele externe în timp ce datele aplicației sunt încă lizibile.

<Note>
Instalarea hook-urilor partajează [funcția logică](/ro/developers/extend/apps/logic/logic-functions) rulează - aceeași semnătură de manipulator, aceleași variabile de mediu, același client API tastat — dar sunt declarate cu propriile funcții de definire și trăiesc în afara modelului de declanșare regulat (HTTP, cron, baza de date evenimente).
</Note>
