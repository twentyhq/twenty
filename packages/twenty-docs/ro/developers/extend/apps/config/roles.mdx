## Prezentare generală

Un **rol** este un set de permisiuni: ce obiecte poate citi sau scrie o aplicație, ce câmpuri poate vedea și ce capabilități la nivel de platformă poate folosi. Funcțiile de logică și componentele front-end ale fiecărei aplicații moștenesc permisiunile rolului marcat cu `defineApplicationRole()` (consultați [Rolul implicit pentru funcții](#the-default-function-role) mai jos).

```ts src/roles/restricted-company-role.ts
import {
  defineRole,
  STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS,
  SystemPermissionFlag,
} from 'twenty-sdk/define';

export default defineRole({
  universalIdentifier: '2c80f640-2083-4803-bb49-003e38279de6',
  label: 'My new role',
  description: 'A role that can be used in your workspace',
  canUpdateAllSettings: false,
  canAccessAllAgentChatChannels: false,
  canBeAssignedToAgents: false,
  canBeAssignedToUsers: false,
  canBeAssignedToApiKeys: false,
  recordsPermissions: {
    canReadAllRecords: false,
    canUpdateAllRecords: false,
    canSoftDeleteAllRecords: false,
    canDestroyAllRecords: false,
    objects: [
      {
        objectUniversalIdentifier:
          STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS.company.universalIdentifier,
        canReadAllRecords: true,
        canUpdateAllRecords: true,
        canSoftDeleteAllRecords: false,
        canDestroyAllRecords: false,
        unreadableFields: [
          STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS.company.fields.name
            .universalIdentifier,
        ],
      },
    ],
  },
  permissionFlagUniversalIdentifiers: [SystemPermissionFlag.WORKSPACE_APPS],
});
```

`recordsPermissions` conține tot ce poate face un rol cu înregistrările:

* `canReadAllRecords`, `canCreateAllRecords`, `canUpdateAllRecords`, `canSoftDeleteAllRecords` și
  `canDestroyAllRecords` de la nivelul său superior se aplică **fiecărui obiect**. `canCreateAllRecords` îl urmează pe
  `canUpdateAllRecords` atunci când nu este definit.
* `objects` listează ce diferă pentru un obiect: aceleași cinci permisiuni pentru toate înregistrările sale,
  `unreadableFields` și `uneditableFields` (identificatori universali ai câmpurilor; un câmp care nu poate fi
  citit nu poate fi nici editat), precum și [permisiunile pentru înregistrări la nivel de rând](#row-level-security).

<Note>
  `SystemPermissionFlag.USER_APPS` și `SystemPermissionFlag.WORKSPACE_APPS`
  sunt disponibile începând cu versiunea 2.54 a `twenty-sdk`; versiunile anterioare le denumesc
  `CONNECTED_ACCOUNTS` și `APPLICATIONS`. Denumirile vechi sunt aliasuri depreciate
  pentru aceleași indicatori, iar un rol păstrează fiecare indicator o singură dată. Enumerarea
  `SystemPermissionFlag`, de exemplu cu `Object.keys`, încă afișează denumirile
  vechi. API-ul raportează, de asemenea, aceste indicatori sub cheile lor vechi, de exemplu în
  `currentUserWorkspace.permissionFlags`.
</Note>

## Securitate la nivel de rând

Permisiunile la nivel de rând necesită **planul Organization sau unul superior** — consultați
[pagina de prețuri](https://twenty.com/pricing). Ce se întâmplă într-un plan fără acest drept este prezentat în
notele de la finalul acestei secțiuni.

Permisiunile pentru obiecte și câmpuri decid *ce obiecte și câmpuri* poate accesa un rol. **Predicate de
permisiuni la nivel de rând** merg mai departe și decid *ce înregistrări* poate vedea și asupra cărora poate acționa un rol — de
exemplu, un rol de tip autoservire în care fiecare utilizator extern își vede doar propriile înregistrări.

Un obiect din `recordsPermissions.objects` poate restricționa anumite operațiuni la o parte dintre înregistrările sale cu
`rowLevelRecordsPermissions`, o listă de reguli. O regulă acordă operațiuni (`canReadRecords`,
`canCreateRecords`, `canUpdateRecords`, `canSoftDeleteRecords`, `canDestroyRecords`) asupra înregistrărilor
care corespund predicatelor imbricate în ea; `canCreateRecords` urmează `canUpdateRecords` atunci când
este omisă. O regulă poate avea și propriile `unreadableFields` și
`uneditableFields`, care se aplică înregistrărilor cărora le corespunde; o astfel de regulă necesită cel puțin un grup de predicate.

Un predicat face referire la un câmp prin `universalIdentifier`, un `operand` și (opțional) un
câmp workspaceMember a cărui valoare este injectată în momentul interogării — astfel încât poți exprima „relația de proprietar
a înregistrării **este** membrul curent al spațiului de lucru”. Cu `relationFieldUniversalIdentifier`, un predicat
compară în schimb un câmp al înregistrărilor corelate prin acel câmp de relație, de exemplu
`messageChannelId` al asocierilor de canal ale unui mesaj. Acest rol poate crea orice companie, dar citește
și actualizează numai companiile pe care le deține:

```ts src/roles/partner-role.ts
import {
  defineRole,
  RowLevelPermissionPredicateOperand,
  STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS,
} from 'twenty-sdk/define';

import { ACCOUNT_OWNER_FIELD_UNIVERSAL_IDENTIFIER } from '../fields/account-owner.field';

export default defineRole({
  universalIdentifier: 'c3c1dc2e-1a08-4de5-abb7-2139b3d99343',
  label: 'Partner',
  description: 'External partner — sees only its own records',
  canBeAssignedToUsers: true,
  recordsPermissions: {
    objects: [
      {
        objectUniversalIdentifier:
          STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS.company.universalIdentifier,
        canCreateAllRecords: true,
        rowLevelRecordsPermissions: [
          {
            universalIdentifier: 'a9e8d7c6-5b4a-4c3d-9e2f-000000000000',
            canReadRecords: true,
            canUpdateRecords: true,
            predicates: [
              {
                universalIdentifier: 'd0f0c1a2-3b4c-4d5e-8f60-111111111111',
                fieldUniversalIdentifier: ACCOUNT_OWNER_FIELD_UNIVERSAL_IDENTIFIER,
                operand: RowLevelPermissionPredicateOperand.IS,
                workspaceMemberFieldUniversalIdentifier:
                  STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS.workspaceMember.fields.id
                    .universalIdentifier,
              },
            ],
          },
        ],
      },
    ],
  },
});
```

Deoarece aceste permisiuni sunt livrate în manifest, ele sunt create, actualizate și eliminate împreună cu
rolul la fiecare instalare și actualizare — nu există un pas separat post-instalare pentru a le menține sincronizate.

<Warning>
  O operațiune acordată pentru **toate înregistrările** are prioritate față de reguli. Nu acorda cu `can…AllRecords`,
  pe obiect sau pentru fiecare obiect, operațiunile pe care o regulă trebuie să le restricționeze: când rolul
  acordă una pentru fiecare obiect, setează `can…AllRecords` al obiectului la `false`. `defineRole` avertizează
  când o regulă este umbrită în acest mod.
</Warning>

Un obiect poate declara mai multe reguli. O înregistrare este accesibilă pentru o operațiune de îndată ce o regulă
care acordă acea operațiune îi corespunde, astfel încât o regulă poate permite unui partener să citească conturile din regiunea sa
în timp ce alta îi permite să actualizeze doar conturile pe care le deține.

### Combinarea predicatelor cu grupuri

Predicatele unei reguli sunt combinate cu `AND`. Pentru a combina unele dintre ele cu `OR` (sau pentru a imbrica
logica), adaugă `predicateGroups` la regulă: un grup are un `logicalOperator`, propriile `predicates`,
și poate conține alte `predicateGroups`. Acest rol permite unui partener să vadă o oportunitate pe care fie o
**deține**, fie pentru care este **punctul de contact**:

```ts src/roles/partner-opportunities-role.ts
import {
  defineRole,
  RowLevelPermissionPredicateGroupLogicalOperator,
  RowLevelPermissionPredicateOperand,
  STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS,
} from 'twenty-sdk/define';

const OPPORTUNITY = STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS.opportunity;
const CURRENT_MEMBER =
  STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS.workspaceMember.fields.id
    .universalIdentifier;

export default defineRole({
  universalIdentifier: 'b2a1c0d9-8e7f-4a6b-9c5d-222222222222',
  label: 'Partner (opportunities)',
  canBeAssignedToUsers: true,
  recordsPermissions: {
    objects: [
      {
        objectUniversalIdentifier: OPPORTUNITY.universalIdentifier,
        rowLevelRecordsPermissions: [
          {
            universalIdentifier: 'f6e5d4c3-2a1b-4e0d-8a9f-666666666666',
            canReadRecords: true,
            predicateGroups: [
              {
                universalIdentifier: 'c3b2a1d0-9f8e-4b7a-8d6c-333333333333',
                logicalOperator:
                  RowLevelPermissionPredicateGroupLogicalOperator.OR,
                predicates: [
                  {
                    universalIdentifier: 'd4c3b2a1-0e9f-4c8b-9e7d-444444444444',
                    fieldUniversalIdentifier:
                      OPPORTUNITY.fields.owner.universalIdentifier,
                    operand: RowLevelPermissionPredicateOperand.IS,
                    workspaceMemberFieldUniversalIdentifier: CURRENT_MEMBER,
                  },
                  {
                    universalIdentifier: 'e5d4c3b2-1f0e-4d9c-8f8e-555555555555',
                    fieldUniversalIdentifier:
                      OPPORTUNITY.fields.pointOfContact.universalIdentifier,
                    operand: RowLevelPermissionPredicateOperand.IS,
                    workspaceMemberFieldUniversalIdentifier: CURRENT_MEMBER,
                  },
                ],
              },
            ],
          },
        ],
      },
    ],
  },
});
```

<Note>
  Serverele mai vechi decât Twenty 2.59 nu citesc `recordsPermissions`: declară `engines.twenty` ca
  `>=2.59.0` în `package.json` atunci când aplicația ta nu trebuie să se instaleze pe acestea.
</Note>

### Proprietăți învechite

Înainte de `recordsPermissions`, un rol declara aceleași permisiuni cu proprietăți separate. Acestea
încă funcționează, iar `defineRole` afișează un avertisment de depreciere care le numește pe cele pe care le utilizează un rol. Procesul de compilare
le trimite așa cum sunt scrise, iar Twenty le convertește când sincronizează aplicația. Un rol nu poate combina
`recordsPermissions` cu proprietățile de acordare învechite:

| Învechit                                                                                                              | Scrie în schimb                                                                             |
| --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `canReadAllObjectRecords`, `canUpdateAllObjectRecords`, `canSoftDeleteAllObjectRecords`, `canDestroyAllObjectRecords` | `recordsPermissions.canReadAllRecords` și celelalte `can…AllRecords`                        |
| `objectPermissions` cu `canReadObjectRecords`, …                                                                      | o intrare din `recordsPermissions.objects` cu `canReadAllRecords`, …                        |
| `fieldPermissions` cu `canReadFieldValue: false` / `canUpdateFieldValue: false`                                       | `unreadableFields` / `uneditableFields` pe obiect                                           |
| `rowLevelPermissionPredicates`, `rowLevelPermissionPredicateGroups`                                                   | `rowLevelRecordsPermissions` pe obiect, cu predicatele și grupurile imbricate într-o regulă |

Predicatele declarate pe rol nu aveau propriile acordări. Acestea sunt convertite într-o regulă pentru fiecare
grup de predicate de nivel superior și într-una pentru predicatele negrupate ale fiecărui obiect. Regula preia
operațiunile pe care rolul le avea asupra acelui obiect, iar `can…AllRecords` ale obiectului sunt setate la `false` astfel încât
predicatele să continue să îl restricționeze.

Notițe:

* Oferă fiecărei reguli, fiecărui predicat și fiecărui grup un `universalIdentifier` stabil (orice uuid) — acesta este cheia entității
  de-a lungul actualizărilor.
* Predicatele pot face referire la câmpuri deținute de aplicația ta sau de obiectele standard ale Twenty.
* Securitatea la nivel de rând este aplicată pentru spațiile de lucru din **planul Organization sau unul superior**. În alte
  planuri, regulile declarate într-un manifest de aplicație se sincronizează în continuare, dar pur și simplu nu sunt aplicate.
* API-ul Metadata se comportă diferit față de manifest aici: fără drept,
  `upsertRowLevelPermissionRules` este respins cu
  `ROW_LEVEL_PERMISSION_FEATURE_DISABLED` în loc să se sincronizeze. Prin urmare, un spațiu de lucru dintr-un plan care nu
  include securitatea la nivel de rând nu poate crea predicate în afara unui manifest de aplicație, chiar
  dacă câmpul `rowLevelPermissionPredicates` este prezent în tipul `Role` atunci când inspectați
  schema.

## Rolul implicit pentru funcții

Când generați o aplicație nouă, CLI creează un fișier de rol implicit declarat cu `defineApplicationRole()`:

```ts src/roles/default-role.ts
import { defineApplicationRole } from 'twenty-sdk/define';

export const DEFAULT_ROLE_UNIVERSAL_IDENTIFIER =
  'b648f87b-1d26-4961-b974-0908fd991061';

export default defineApplicationRole({
  universalIdentifier: DEFAULT_ROLE_UNIVERSAL_IDENTIFIER,
  label: 'Default function role',
  description: 'Default role for function Twenty client',
  canUpdateAllSettings: false,
  canBeAssignedToAgents: false,
  canBeAssignedToUsers: false,
  canBeAssignedToApiKeys: false,
  recordsPermissions: {
    canReadAllRecords: true,
    canUpdateAllRecords: false,
    canSoftDeleteAllRecords: false,
    canDestroyAllRecords: false,
  },
  permissionFlagUniversalIdentifiers: [],
});
```

`defineApplicationRole()` este un wrapper subțire în jurul `defineRole()` care marchează rolul utilizat ca implicit pentru aplicația dvs. în momentul instalării. Validarea este identică cu `defineRole`, dar pipeline-ul de build conectează automat `universalIdentifier` în `defaultRoleUniversalIdentifier` din manifestul aplicației — astfel încât nu trebuie să îl referiți manual din [`defineApplication`](/ro/developers/extend/apps/config/application).

Notițe:

* Exact **un** `defineApplicationRole(...)` este permis per aplicație — build-ul manifestului va eșua dacă găsește mai mult de unul.
* Utilizați `defineRole()` (nu `defineApplicationRole()`) pentru orice roluri **suplimentare** cu care este livrată aplicația.
* Setarea explicită a `defaultRoleUniversalIdentifier` în `defineApplication()` este în continuare acceptată pentru compatibilitate retroactivă, dar este considerată învechită în favoarea `defineApplicationRole()`. De asemenea, poate denumi un rol pe care aplicația dvs. nu îl definește, cum ar fi rolul implicit integrat al aplicației personalizate din spațiul de lucru, păstrat de `twenty app pull`; compilarea nu poate verifica acel rol, așadar acesta trebuie să existe în spațiul de lucru țintă.

### Roluri agent

Rolul aplicației este cel pe care un spațiu de lucru îl examinează atunci când îți instalează aplicația, deci trebuie să acopere tot ceea ce poate face aplicația însăși. Orice rol pe care îl atribui unui agent prin `roleUniversalIdentifier` în `defineAgent()` nu trebuie să acorde mai mult decât rolul aplicației: nicio acțiune asupra obiectelor, niciun acces la câmpuri, niciun indicator de permisiune sau domeniu de aplicare la nivel de rând pe care rolul aplicației nu le are. Dacă o face, compilarea eșuează cu o eroare care enumeră permisiunile acordate în exces. Rolurile pe care aplicația ta le furnizează pentru membrii spațiului de lucru sau cheile API nu sunt supuse acestei reguli, deoarece aplicația nu rulează niciodată cu acestea. Verificarea necesită rolul aplicației în sursa aplicației dvs., așadar este omisă atunci când rolul implicit este definit în altă parte.

## Cele mai bune practici

* Porniți de la rolul generat de scaffolding, apoi restrângeți-l progresiv — rolul implicit acordă acces larg la citire, ceea ce rareori este de dorit în producție.
* Listează în `recordsPermissions.objects` doar obiectele de care funcțiile tale au nevoie efectiv și folosește `unreadableFields` și `uneditableFields` pentru a ascunde sau bloca câmpurile de care acestea nu au nevoie.
* `permissionFlagUniversalIdentifiers` controlează accesul la capabilități la nivelul platformei. Mențineți-le la minimum.
* Un indicator de permisiune pe care aplicația dvs. îl declară cu `definePermissionFlag()` are un `permissionType`: `'tool'` (implicit) pentru o capabilitate care poate fi acordată unui agent sau unui utilizator și `'settings'` pentru un indicator care deblochează o zonă de setări.
* Vedeți un exemplu funcțional: [`examples/hello-world/src/roles/default-role.ts`](https://github.com/twentyhq/twenty/blob/main/packages/twenty-apps/examples/hello-world/src/roles/default-role.ts).
