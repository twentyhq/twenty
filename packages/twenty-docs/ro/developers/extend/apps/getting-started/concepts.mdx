## Cum funcționează aplicațiile

O aplicație este o colecție de **entități** declarate folosind funcțiile `defineEntity()` din pachetul `twenty-sdk`. CLI detectează aceste declarații prin intermediul analizei AST la momentul creării și produce un **manifest** — o descriere completă a ceea ce aplicația ta adaugă la un spațiu de lucru. Aceste funcții validează configurația în timpul build-ului și oferă completare automată în IDE și siguranța tipurilor.

```
your-app/
├── src/
│   ├── application-config.ts    ← defineApplication (required, one per app)
│   ├── roles/                   ← defineRole
│   ├── objects/                 ← defineObject
│   ├── fields/                  ← defineField
│   ├── logic-functions/         ← defineLogicFunction
│   ├── front-components/        ← defineFrontComponent
│   ├── skills/                  ← defineSkill
│   ├── agents/                  ← defineAgent
│   ├── views/                   ← defineView
│   ├── navigation-menu-items/   ← defineNavigationMenuItem
│   ├── settings-menu-items/     ← defineSettingsMenuItem
│   └── page-layouts/            ← definePageLayout
├── public/                      ← Static assets (images, icons)
└── package.json
```

<Note>
  **Organizarea fișierelor depinde de tine.** Detectarea entității este bazată pe AST - SDK
  găsește \`export default defineEntity(. .)" apelează indiferent de locul unde trăieşte fişierul
  . Structura de foldere de mai sus este o convenție, nu o cerință.
</Note>

## Izolare (sandboxing)

* **Funcțiile logice** rulează în procese Node.js izolate pe server. Accesează datele doar prin intermediul clientului tastat API, care acționează fie ca persoană care a declanșat rularea, fie ca aplicație în sine. Vezi [Cine accesează un apel utilizat](/ro/developers/extend/apps/logic/logic-functions#whose-access-a-call-uses).
* **Componentele front-end** rulează în Web Workers folosind Remote DOM — izolate de pagina principală, dar randând elemente DOM native (nu iframes). Acestea comunică cu Twenty printr-un API al gazdei bazat pe transmiterea de mesaje.
* **Permisiunile** sunt aplicate la nivelul API-ului. Două tokeni runtime sunt injectaţi, ambele derivate din rolul declarat cu \`defineApplicationRole()"; cea implicită este îngustată și mai mult la ceea ce persoana declanșatoare poate face ori de câte ori cineva se află în spatele rulării.

## Ciclul de viață al aplicației

```
┌─────────────────────────────────────────────────────────┐
│ Development                                             │
│   twenty app init → twenty app dev (live sync)   │
├─────────────────────────────────────────────────────────┤
│ Build & Deploy                                          │
│   twenty app build → twenty app publish        │
├─────────────────────────────────────────────────────────┤
│ Install flow                                            │
│   upload → [pre-install] → metadata migration →         │
│   generate SDK → [post-install] → … → [uninstall]       │
├─────────────────────────────────────────────────────────┤
│ Publish                                                 │
│   npm publish → appears in Twenty marketplace           │
└─────────────────────────────────────────────────────────┘
```

* **`douăzeci de aplicații dev`** — îți urmărește fișierele sursă și modificările live-syncs la un server conectat. Clientul API tipizat este regenerat automat atunci când schema se schimbă.
* **`douăzeci de aplicații construite`** — compilează TypeScript, împachetează funcțiile logice și componentele frontale cu esbuild, și produce un manifest.
* **Hook-uri pre/post-instalare și dezinstalare** — funcții opționale care rulează în timpul instalării sau chiar înainte de eliminare. Vezi [Install Hooks](/ro/developers/extend/apps/config/install-hooks) pentru detalii.
