## Обзор

`Toast` отображает одно уведомление. Ваше приложение управляет моментом его появления, его положением и моментом его удаления.

<StoryEmbed storyId="ui-feedback-toast--display" title="Пример Toast" height={120} />

## Использование

```tsx
import { useState } from 'react';
import { Toast } from 'twenty-ui/components/feedback';
import { Button } from 'twenty-ui/primitives/input';

export const SavedNotification = () => {
  const [isOpen, setIsOpen] = useState(true);

  return (
    <>
      <Button onClick={() => setIsOpen(true)}>Show notification</Button>
      {isOpen && (
        <Toast status="success" progress={100} onClose={() => setIsOpen(false)}>
          Changes saved
        </Toast>
      )}
    </>
  );
};
```

## Визуальные параметры

Сравните нейтральную, успешную, ошибочную, информационную и предупреждающую обратную связь с одинаковыми сообщением и ходом выполнения.

<StoryEmbed storyId="ui-feedback-toast--catalog" title="Статусы всплывающих уведомлений" height={530} />

Для уведомлений приложения оберните приложение в `ToastProvider`, разместите внутри него `Toaster` и используйте `useToast()` в дочерних компонентах. Каждый провайдер имеет независимое хранилище уведомлений, таймеры обратного отсчета и жизненный цикл закрытия. Несколько Toaster могут дублировать один и тот же провайдер.

## Уведомления приложения

```tsx
import { useState } from 'react';

import {
  ToastProvider,
  Toaster,
  useToast,
} from 'twenty-ui/components/feedback';
import { Button } from 'twenty-ui/primitives/input';

const SaveNotificationButton = () => {
  const { enqueueToast } = useToast();

  return (
    <Button
      onClick={() =>
        enqueueToast({
          children: 'Record saved',
          status: 'success',
        })
      }
    >
      Add saved notification
    </Button>
  );
};

export const Notifications = () => {
  const [limit, setLimit] = useState(3);

  return (
    <ToastProvider limit={limit}>
      <SaveNotificationButton />
      <Button onClick={() => setLimit(1)}>Keep one notification</Button>
      <Button onClick={() => setLimit(3)}>Keep three notifications</Button>
      <Toaster />
    </ToastProvider>
  );
};
```

`enqueueToast` принимает свойства Toast и необязательный `dedupeKey`, а возвращает ID уведомления. Совпадающий видимый ключ возвращает существующий ID без добавления другого уведомления. `updateToast({ id, ...changes })` обновляет это активное уведомление. `closeToast(id)` закрывает одно уведомление; `closeToast()` закрывает все видимые уведомления в провайдере.

По умолчанию провайдер отображает три уведомления. `limit` должен быть положительным целым числом и может изменяться, пока провайдер смонтирован. При его уменьшении или добавлении уведомлений сверх него сначала закрываются самые старые видимые уведомления. При увеличении существующие уведомления не изменяются, а закрытые уведомления не восстанавливаются. Изменения конфигурации сохраняют хранилище, сохранившиеся идентификаторы, порядок и оставшееся время обратного отсчета.

## Жизненный цикл провайдера

<StoryEmbed storyId="ui-feedback-toaster-lifecycle--documentation" title="Жизненный цикл общего уведомления" height={430} />

Несколько Toaster внутри провайдера отображают одни и те же уведомления. Обновления и закрытие применяются к каждому зеркальному экземпляру, а каждое уведомление имеет один общий обратный отсчет. Наведение или фокус внутри любого зеркального экземпляра приостанавливает его; отсчет возобновляется, когда все зеркальные экземпляры освобождают и наведение, и фокус. Монтирование другого Toaster не перезапускает обратный отсчет и не создает другой жизненный цикл обратного вызова. Используйте отдельные провайдеры для независимых очередей.

Для уведомлений провайдера истечение срока, кнопка закрытия, `closeToast` и вытеснение из-за лимита один раз вызывают последнюю версию `onClose`. Когда выполняется обратный вызов, уведомление уже закрыто, поэтому обновления и повторные запросы на закрытие для этого идентификатора не дают эффекта. `onCancel` остается отдельным обратным вызовом действия и не закрывает уведомление автоматически.

Закрытые уведомления неактивны во время анимаций выхода. Их записи удаляются после того, как все отображаемые зеркальные экземпляры завершат анимацию выхода или будут размонтированы. Размонтирование последнего Toaster очищает записи закрытых уведомлений и приостанавливает оставшееся время для видимых уведомлений. Повторное монтирование Toaster возобновляет этот отсчет времени. Размонтирование провайдера удаляет его уведомления и отменяет обратный отсчет и анимацию выхода без вызова `onClose`. Сохраненные операции `enqueueToast`, `updateToast` и `closeToast` этого провайдера не дают эффекта после его размонтирования.

`getToastProps` адаптирует содержимое и представление каждого уведомления. Задайте `duration` и `progress` в `enqueueToast` или `updateToast`, чтобы все зеркальные экземпляры использовали одинаковую конфигурацию времени. Существующие переопределения времени через `getToastProps` по-прежнему поддерживаются, если все зеркальные экземпляры возвращают одинаковые длительность и прогресс для уведомления. Провайдер сохраняет идентификатор, обработчик закрытия и общий обратный отсчет.

`container` выбирает назначение портала Toaster. Если параметр опущен, используется окружающий контейнер темы или `document.body`. Явно заданный элемент отображается там; `null` откладывает отображение. Видимые уведомления остаются в очереди, а их обратный отсчет приостанавливается, пока не отображается ни один Toaster. Порталы сохраняют окружающие тему и направление. Задайте `aria-label` для каждого Toaster, чтобы локализовать имя его региона по умолчанию, "Уведомления", и присвоить зеркальным регионам подходящие имена.

## Обновление активного уведомления

Используйте ID, возвращаемый `enqueueToast`, чтобы обновить содержимое, статус обратной связи, действия или обратные вызовы на месте. Обновления сохраняют идентификатор и положение уведомления. Неизвестные или закрытые идентификаторы не имеют эффекта, в том числе во время выполнения анимации закрытия. Каждый вызов `useToast()` нацелен на ближайший провайдер.

<StoryEmbed storyId="ui-feedback-toaster--updates-documentation" title="Обновление активного уведомления" height={380} />

```tsx
import { useToast } from 'twenty-ui/components/feedback';
import { Button } from 'twenty-ui/primitives/input';

type SaveButtonProps = {
  saveRecord: () => Promise<void>;
  onViewRecord: () => void;
};

export const SaveButton = ({ saveRecord, onViewRecord }: SaveButtonProps) => {
  const { enqueueToast, updateToast } = useToast();

  const save = async () => {
    const id = enqueueToast({
      children: 'Saving record',
      status: 'info',
      progress: 0,
    });

    try {
      await saveRecord();
      updateToast({
        id,
        children: 'Record saved',
        status: 'success',
        progress: undefined,
        action: <Button onClick={onViewRecord}>View record</Button>,
      });
    } catch {
      updateToast({
        id,
        children: 'Record could not be saved',
        status: 'error',
        progress: undefined,
      });
    }
  };

  return <Button onClick={save}>Save record</Button>;
};
```

`ToastUpdate` требует `id` и принимает частичные параметры Toast. Пропущенные поля сохраняют текущие значения. Явное значение `undefined` очищает необязательное поле или восстанавливает значение компонента по умолчанию, например `progress: undefined` или `status: undefined`. Передайте `null`, чтобы удалить слот содержимого, включая `description`, `icon` или `action`. Установка `cancelLabel: null` скрывает элемент управления отменой, сохраняя его обратный вызов. Изменения обратного вызова применяются к существующему уведомлению. `dedupeKey` относится к постановке в очередь и не может быть обновлён.

## Время закрытия

Обратный отсчёт по умолчанию составляет 6000 миллисекунд. Он приостанавливается, когда указатель находится над уведомлением или фокус клавиатуры находится внутри него, и возобновляется только после того, как исчезнут оба условия. При использовании нескольких Toaster состояние паузы является общим для их зеркальных экземпляров. Визуальный обратный отсчёт отображает оставшееся время до закрытия. Автоматическое закрытие также работает, когда уменьшение движения отключает анимацию.

<StoryEmbed storyId="ui-feedback-toaster-timing--documentation" title="Управление временем показа тостов" height={480} />

| Операция                                                       | Поведение обратного отсчета                                                                                                                                       |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Обновление содержимого, статуса, действий или обратных вызовов | Сохраняет оставшееся время. Повторные обновления не продлевают его.                                                                                               |
| Передать `duration` в `updateToast`                            | Запускает новый отсчет длительности, в том числе если значение не изменилось. `duration: undefined` восстанавливает значение по умолчанию и перезапускает отсчет. |
| Изменить свойство `duration` отдельного `Toast`                | Запускает новый отсчет длительности. Повторный рендеринг того же значения сохраняет оставшееся время.                                                             |
| Установить `duration: 0`                                       | Оставляет тост открытым, пока он не будет закрыт.                                                                                                                 |
| Передать `progress`                                            | Останавливает обратный отсчет, пока присутствует прогресс.                                                                                                        |
| Удалить `progress`                                             | Запускает новый отсчет длительности или оставляет тост открытым, если его длительность равна нулю.                                                                |
| Обновление при наведении указателя или фокусе                  | Применяет те же правила, сохраняя результирующий обратный отсчет на паузе, пока указатель и фокус не будут убраны.                                                |

Например, `updateToast({ id, children: 'Still saving' })` сохраняет оставшееся время, а `updateToast({ id, duration: 6000 })` дает читателю еще шесть секунд. Эти правила применяются к существующему уведомлению без изменения его идентификатора или позиции.

## Закрываемое уведомление

```tsx
import { useState } from 'react';
import { Toast } from 'twenty-ui/components/feedback';
import { Button } from 'twenty-ui/primitives/input';

export const SaveNotification = () => {
  const [visible, setVisible] = useState(false);

  return (
    <>
      <Button onClick={() => setVisible(true)}>Show saved notification</Button>
      {visible && (
        <Toast
          status="success"
          description="Your changes are available to your team."
          duration={6000}
          onClose={() => setVisible(false)}
        >
          Record saved
        </Toast>
      )}
    </>
  );
};
```

`onClose` вызывается один раз кнопкой закрытия или после завершения обратного отсчета. Удалите toast в этом обратном вызове. Используйте `duration={0}` для уведомления, которое остается открытым до закрытия.

## Ход выполнения и отмена

```tsx
import { Toast } from 'twenty-ui/components/feedback';

type ImportProgressProps = { progress: number; onCancel: () => void };

export const ImportProgress = ({ progress, onCancel }: ImportProgressProps) => (
  <Toast
    status="info"
    progress={progress}
    description="You can continue working while the import runs."
    onCancel={onCancel}
    cancelLabel="Cancel import"
  >
    Importing records: {progress}%
  </Toast>
);
```

Передача `progress` задаёт процентное значение и отключает обратный отсчёт. Удалите его после завершения операции, чтобы запустить новый отсчет длительности. При отмене вызывается `onCancel`; родительский компонент управляет отменой и удалением. `cancelLabel` принимает React-узел для содержимого кнопки. Дочерние элементы, `description`, `icon` и `action` также принимают React-узлы, принадлежащие вызывающему коду. Используйте элементы управления Twenty для интерактивных действий и указывайте их доступные имена.

## Внешний вид и объявления

`status` принимает `neutral`, `info`, `success`, `warning` или `error`; по умолчанию используется `neutral`. Он выражает смысл обратной связи и выбирает значок и палитру темы. Toast поддерживает один внешний вид, поэтому не предоставляет параметр `variant` для внешнего вида или параметр `color` для палитры. Используйте `icon` для замены значка, `icon={null}` для его исключения и `iconLabel`, когда значку по умолчанию требуется собственное доступное имя.

Роль по умолчанию — `status` с ненавязчивыми объявлениями. Используйте `role="alert"` для срочной обратной связи. Укажите `cancelLabel` и `closeLabel`, чтобы локализовать элементы управления, и предоставьте достаточно времени для чтения содержимого или взаимодействия с его действиями.
