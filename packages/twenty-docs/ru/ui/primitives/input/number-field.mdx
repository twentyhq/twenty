## Обзор

`NumberField` предоставляет все семь компонентов установленного числового поля Base UI: `Root`, `Group`, `Input`, `Decrement`, `Increment`, `ScrubArea` и `ScrubAreaCursor`. Импортируйте его из `twenty-ui/primitives/input`. Оно сохраняет числовое состояние, форматирование, пошаговое изменение, сведения о событиях и интеграцию с нативными формами из Base UI, добавляя стилизацию Twenty UI для поля ввода, группы и элементов управления изменением значения.

Для компактной предустановки с фиксированным форматированием и значениями шагов модификаторов по умолчанию используйте [NumberStepper](/ru/ui/components/input/number-stepper) из `twenty-ui/components/input`.

## Использование

`Root` управляет числовым состоянием. `Input` представляет собой видимое текстовое поле ввода. Используйте `Group`, чтобы разместить вокруг него необязательные элементы управления уменьшением и увеличением. Предоставьте содержимое и доступные имена для элементов управления; примитив не добавляет значки или метки.

```tsx
import { IconMinus, IconPlus } from 'twenty-ui/icon';
import { Field, NumberField } from 'twenty-ui/primitives/input';

export const QuantityInput = () => (
  <Field.Root>
    <Field.Label>Quantity</Field.Label>
    <NumberField.Root name="quantity" defaultValue={3} min={0} max={10}>
      <NumberField.Group>
        <NumberField.Decrement aria-label="Decrease quantity">
          <IconMinus size={16} />
        </NumberField.Decrement>
        <NumberField.Input />
        <NumberField.Increment aria-label="Increase quantity">
          <IconPlus size={16} />
        </NumberField.Increment>
      </NumberField.Group>
    </NumberField.Root>
    <Field.Description>Choose up to ten items.</Field.Description>
  </Field.Root>
);
```

`Field.Label`, `Field.Description` и `Field.Error` связываются с видимым полем ввода. В качестве альтернативы передайте `aria-label` или `aria-labelledby` в `Input`. Значение по умолчанию для `aria-roledescription` — `Number field`; оно не предоставляет доступное имя.

## Значения и обратные вызовы

Не указывайте `value` для неконтролируемого поля и передавайте числовой `defaultValue`, когда требуется начальное значение. Если не указать `defaultValue`, поле будет изначально пустым. Для контролируемого поля передайте число или `null` через `value` и обновляйте его из `onValueChange`.

```tsx
import { useState } from 'react';
import { Field, NumberField } from 'twenty-ui/primitives/input';

export const PriceInput = () => {
  const [price, setPrice] = useState<number | null>(null);
  const [savedPrice, setSavedPrice] = useState<number | null>(null);

  return (
    <Field.Root>
      <Field.Label>Price</Field.Label>
      <NumberField.Root
        value={price}
        onValueChange={setPrice}
        onValueCommitted={setSavedPrice}
      >
        <NumberField.Input placeholder="Enter a price" />
      </NumberField.Root>
      <Field.Description>
        Last committed price: {savedPrice ?? 'empty'}
      </Field.Description>
    </Field.Root>
  );
};
```

При очистке передаётся `null`, в том числе когда задано `min`. Незавершённые черновики, такие как `-`, остаются редактируемыми без передачи недопустимого числа. Вводимое значение, которое можно разобрать, обновляет числовое значение до подтверждения редактирования. Первый шаг от пустого значения начинается с нуля, ограниченного границами; последующие шаги используют активную величину шага.

`onValueChange(value, details)` сохраняет нативные `event`, `reason`, `cancel`, `allowPropagation`, `isCanceled`, `isPropagationAllowed`, `trigger` и необязательный `direction`. Причины различают ввод (`input-change`), очистку (`input-clear`), нормализацию при потере фокуса (`input-blur`), вставку (`input-paste`), нажатия клавиш, увеличение или уменьшение, колесо прокрутки, скраббинг и нативное автозаполнение (`none`). Вызов `cancel()` предотвращает обновление числового состояния; контролируемые вызывающие стороны по-прежнему выбирают принимаемое значение.

`onValueCommitted(value, details)` запускается при потере фокуса после редактирования, при отпускании указателя после изменения шага или скраббинга, а также сразу для корректировок с клавиатуры и колесом прокрутки. Очистка фиксирует `null` при потере фокуса. Сведения о фиксации содержат `event` и `reason`; это общие сведения без методов отмены изменения. Перевод фокуса на нетронутое поле и его потеря сами по себе не фиксируют значение, если числовая нормализация не требуется. Явные параметры округления могут нормализовать и зафиксировать нетронутое значение.

## Локаль и форматирование

Задайте `locale` и `format` для `Root`. Они сохраняют установленный контракт Base UI: `locale` принимает `Intl.LocalesArgument`, а `format` принимает `Intl.NumberFormatOptions`. Форматирование отображения отделено от необработанного числового значения, отправляемого формой. Примитив не принуждает к использованию латинских цифр, группировки, точности или шагов модификаторов.

<StoryEmbed storyId="ui-input-numberfield--locale-currency" title="Форматирование локали и валюты" height={140} />

```tsx
import { Field, NumberField } from 'twenty-ui/primitives/input';

export const AmountInput = () => (
  <Field.Root>
    <Field.Label>Amount in euros</Field.Label>
    <NumberField.Root
      name="amount"
      defaultValue={1234.5}
      locale="de-DE"
      format={{ style: 'currency', currency: 'EUR' }}
      step={0.5}
      smallStep={0.01}
      largeStep={10}
    >
      <NumberField.Input />
    </NumberField.Root>
  </Field.Root>
);
```

Ввод и вставка используют настроенную локаль и поддерживаемые символы формата. При потере фокуса отображаемый текст нормализуется. Явные параметры точности или округления также могут нормализовать зафиксированное число; без этих параметров одно лишь форматирование не заменяет нетронутое числовое значение округлённым отображаемым текстом.

## Шаг и границы

Значение `step` по умолчанию равно `1`, `smallStep` — `0.1` при удержании Alt, а `largeStep` — `10` при удержании Shift. Активный шаг применяется к кнопкам, Arrow Up и Arrow Down, колесу прокрутки и перемещению в области скраббинга. Значение `snapOnStep` по умолчанию — `false`; включите его, чтобы привязывать корректировки к активному шагу. Home и End выбирают соответствующую явно заданную границу. Нативные обработчики клавиш могут вызывать `event.preventBaseUIHandler()`, когда владельцу нужно переопределить поведение Base UI для клавиатуры.

`min` и `max` включительны. Взаимодействия с шагом остаются в заданных границах. По умолчанию введённые и вставленные значения также численно ограничиваются, а черновик нормализуется при потере фокуса. Задайте `allowOutOfRange`, чтобы принимать прямые изменения за пределами этих границ и позволить нативной проверке диапазона или проверке приложения сообщать о проблеме.

`step="any"` отключает нативную проверку шага, в то время как интерактивное изменение шага использует `1` и настроенные шаги модификаторов. При числовом шаге явно укажите `min`, если нативная отправка должна проверять выравнивание по шагу. Числовой шаг не округляет каждое введённое значение до шага.

## Скраббинг

`ScrubArea` изменяет числовое значение при перемещении указателя. Поддерживаются горизонтальное или вертикальное перемещение, `pixelSensitivity` и необязательный `teleportDistance`. Активный шаг и границы также применяются к скраббингу. Используйте видимую метку как цель скраббинга, сохраняя доступность поля ввода для редактирования с клавиатуры.

<StoryEmbed storyId="ui-input-numberfield--with-scrubbing" title="Скраббинг метки ширины" height={150} />

Составьте `ScrubAreaCursor` внутри `ScrubArea`, чтобы использовать пользовательский курсор во время скраббинга с блокировкой указателя. В активном состоянии он портализируется в тело документа. Base UI использует обычный курсор для сенсорного ввода, при отклонённой блокировке указателя и в WebKit. Задайте `allowWheelScrub` для `Root`, чтобы разрешить корректировку колесом прокрутки, пока поле ввода находится в фокусе и под указателем; по умолчанию используется `false`.

## Формы и отключённое состояние

`Root` отображает скрытый нативный `input type="number"` для отправки необработанного числового значения и нативной проверки. Задайте `name`, `form`, `required`, `min`, `max` и `step` для `Root`. `form` может связать поле с формой в другом месте документа. Элементы управления корректировкой по умолчанию используют `type="button"`, поэтому изменение шага не отправляет форму.

`disabled` предотвращает взаимодействие и исключает значение из отправки. `readOnly` предотвращает изменения, сохраняя возможность фокусировки видимого поля ввода и доступность его значения формы. Используйте контролируемое значение, когда приложению необходимо сбросить числовое состояние; нативный сброс формы не сбрасывает его.

## Цели DOM и настройка

| Часть или свойство        | Цель DOM и ref по умолчанию                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `Root` / `Root.ref`       | Внешний `div`                                                                                                 |
| `Root.inputRef`           | Скрытое нативное числовое поле ввода                                                                          |
| `Root.id`                 | Связывает ID видимого текстового поля ввода                                                                   |
| `Group` / `Group.ref`     | Групповой `div`                                                                                               |
| `Input` / `Input.ref`     | Видимый `input type="text"`                                                                                   |
| `Decrement` / `Increment` | Нативные кнопки                                                                                               |
| `ScrubArea`               | `span`                                                                                                        |
| `ScrubAreaCursor`         | `span`, портализируемый в тело документа в активном состоянии; в противном случае его ref имеет значение null |

Нативные атрибуты, `className`, `style` и `render` нацеливаются на часть, которая их получает. Настройка Input применяется к видимому элементу управления; настройка обёртки относится к `Root` или `Group`. Чтобы перевести элемент управления в фокус, используйте `Input.ref`, а не `Root.inputRef`.

Каждая часть принимает элемент или обратный вызов через `render` с соответствующим общедоступным типом состояния. Передайте предоставленные свойства и ref соответствующему элементу DOM, чтобы редактирование, фокус, метки и проверка продолжали работать. Когда элемент управления шагом отображает элемент, не являющийся кнопкой, задайте `nativeButton={false}`. `className` и `style` также принимают обратные вызовы состояния. Состояние включает числовой `value`, отформатированный `inputValue`, `required`, `disabled`, `readOnly`, `scrubbing` и унаследованное состояние Field.

Общедоступные точки входа экспортируют типы свойств и состояния для каждой части, а также `NumberFieldRootChangeEventDetails`, `NumberFieldRootChangeEventReason`, `NumberFieldRootCommitEventDetails` и `NumberFieldRootCommitEventReason`.

## Рендерер компонента Front

Фикстуры песочницы React и Preact проверяют начальное форматирование локали, локализованную вставку, необработанные числовые значения формы, доступные метки, ref, композицию рендеринга, фиксации при потере фокуса, сведения об изменении и фиксации с клавиатуры, а также сведения об изменении указателем.

Последовательный ввод после очистки контролируемого локализованного поля в настоящее время сбрасывает каретку в рендерере: ввод `2`, а затем `3` может привести к `32`. Форматированная корректировка указателем также может конфликтовать с потерей фокуса и оставить в видимом поле ввода предыдущее значение. Корректировки указателем сообщают об изменениях, но при отпускании указателя не передаётся соответствующий обратный вызов фиксации; вместо этого последующая потеря фокуса может зафиксировать значение с `input-blur`. Перетаскивание области скраббинга и использование её пользовательского курсора также недоступны в песочнице. Эти ограничения не влияют на обычные хосты React.
