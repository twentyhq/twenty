## Обзор

Используйте `Autocomplete` для предложений, связанных с текстовым полем. Поле ввода сохраняет положение курсора и фокус клавиатуры, пока клавиши со стрелками выделяют предложения. Используйте [Select](/ru/ui/primitives/input/select), когда пользователь должен выбрать значение из фиксированного списка. [Dropdown](/ru/ui/components/navigation/dropdown) остаётся компонентом более высокого уровня для меню и средств выбора.

## Использование

Передайте `items` в `Root` и отрисуйте их через `List`, чтобы фильтрация обновляла видимые предложения. `autoHighlight="always"` выделяет первый результат при каждом открытии списка.

```tsx
import { Autocomplete } from 'twenty-ui/primitives/input';

const FRUITS = ['Apple', 'Banana', 'Cherry'];

export const FruitInput = () => (
  <Autocomplete.Root items={FRUITS} autoHighlight="always">
    <Autocomplete.InputGroup>
      <Autocomplete.Input aria-label="Fruit" placeholder="Search fruits" />
    </Autocomplete.InputGroup>
    <Autocomplete.Portal>
      <Autocomplete.Positioner>
        <Autocomplete.Popup>
          <Autocomplete.Empty>No fruits found</Autocomplete.Empty>
          <Autocomplete.List>
            {(fruit: string) => (
              <Autocomplete.Item key={fruit} value={fruit}>
                {fruit}
              </Autocomplete.Item>
            )}
          </Autocomplete.List>
        </Autocomplete.Popup>
      </Autocomplete.Positioner>
    </Autocomplete.Portal>
  </Autocomplete.Root>
);
```

`value` и `onValueChange` управляют текстом поля ввода. Используйте `defaultValue` для неконтролируемого начального значения. Состояние открытия независимо: используйте `open` и `onOpenChange` или `defaultOpen`. `Item.onClick` обрабатывает как выбор указателем, так и нажатие Enter в поле ввода.

`mode="list"` фильтрует, не изменяя текст ввода при выделении. `mode="both"` также предоставляет встроенное дополнение. `mode="inline"` сохраняет все элементы и предоставляет встроенное дополнение; `mode="none"` сохраняет все элементы без встроенного дополнения. `readOnly` не позволяет встроенному дополнению изменять поле ввода.

## Структура

Размещайте связанные части внутри смонтированного `Autocomplete.Root`. Компонуйте назначение портала, оболочку позиционирования и содержимое отдельно. `InputGroup` при необходимости группирует поле ввода с соседними элементами управления и привязывает всплывающее окно к этой группе.

```text
Autocomplete.Root
├── Autocomplete.InputGroup (optional)
│   ├── Autocomplete.Input
│   ├── Autocomplete.Clear (optional)
│   └── Autocomplete.Trigger (optional)
│       └── Autocomplete.Icon (optional)
├── Autocomplete.Portal
│   ├── Autocomplete.Backdrop (optional)
│   └── Autocomplete.Positioner
│       └── Autocomplete.Popup
│           ├── Autocomplete.Arrow (optional)
│           ├── Autocomplete.Empty
│           └── Autocomplete.List
│               ├── Autocomplete.Item
│               ├── Autocomplete.Group (optional)
│               │   ├── Autocomplete.GroupLabel
│               │   └── Autocomplete.Collection
│               │       └── Autocomplete.Item
│               ├── Autocomplete.Row (optional, with Root.grid)
│               │   └── Autocomplete.Item
│               └── Autocomplete.Separator (optional)
├── Autocomplete.Status (optional)
└── Autocomplete.Value (optional)
```

| Часть        | Назначение и нативный целевой элемент                                                                 |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| `Root`       | Управляет значением поля ввода, фильтрацией, выделением и состоянием открытия. Не отображает элемент. |
| `Значение`   | Считывает текст ввода через дочерние элементы или функцию рендеринга. Не отображает элемент.          |
| `InputGroup` | Группирует поле ввода и соседние элементы управления. Нацелен на div.                                 |
| `Ввод`       | Отрисовывает поле ввода комбинированного списка и сохраняет фокус клавиатуры. Нацелен на input.       |
| `Триггер`    | Открывает или закрывает предложения. Нацелен на button.                                               |
| `Icon`       | Содержит индикатор триггера. Нацелен на span.                                                         |
| `Очистить`   | Очищает значение поля ввода. Нацелен на button.                                                       |
| `Portal`     | Выбирает назначение и политику монтирования. Нацелен на свой div портала.                             |
| `Backdrop`   | Предоставляет необязательное наложение под всплывающим окном. Нацелен на div.                         |
| `Positioner` | Управляет якорем, выравниванием, смещениями и обработкой коллизий. Нацелен на свой div.               |
| `Popup`      | Отображает содержимое предложений и необязательное поведение фокуса. Нацелен на свой div.             |
| `Arrow`      | Предоставляет необязательную позиционируемую стрелку внутри Popup. Нацелен на div.                    |
| `Список`     | Отображает отфильтрованные элементы. Нацелен на div с ролью listbox или grid.                         |
| `Item`       | Отрисовывает предложение и обрабатывает выбор указателем или с клавиатуры. Нацелен на div.            |
| `Группа`     | Группирует связанные элементы. Нацелен на div.                                                        |
| `GroupLabel` | Задаёт метку родительской группе. Нацелен на div.                                                     |
| `Row`        | Группирует строку элементов, когда включён `Root.grid`. Нацелен на div.                               |
| `Collection` | Отображает отфильтрованные элементы через дочернюю функцию. Не отображает элемент.                    |
| `Separator`  | Визуально разделяет элементы или группы. Нацелен на div.                                              |
| `Пусто`      | Сообщает, когда нет доступных совпадающих элементов. Нацелен на div.                                  |
| `Статус`     | Объявляет об изменениях, таких как статус асинхронной загрузки. Нацелен на div.                       |

Отображаемые части сохраняют нативные атрибуты, обработчики, ссылки, зависящие от состояния `className` и `style`, а также композицию `render` элемента/функции из установленного API Base UI. Нативные свойства и ссылки нацелены на собственный элемент части. Пользовательские компоненты должны перенаправлять предоставленные свойства и ссылки. Публичные свойства частей и типы состояния экспортируются из `twenty-ui/primitives/input` вместе с действиями Root и типами сведений о событиях изменения/выделения.

`Autocomplete.useFilter()` предоставляет учитывающее локаль сопоставление `contains`, `startsWith` и `endsWith`. `Autocomplete.useFilteredItems\<TItem>()` считывает внутренне отфильтрованную коллекцию в Root. Считайте этот результат доступным только для чтения.

## Объектные и сгруппированные элементы

Элементы могут быть строками или произвольными объектами. Используйте `itemToStringValue`, чтобы предоставить текст для фильтрации, дополнения и отправки формы. Объекты в виде `{ value, label }` автоматически используют свою метку. Отображайте то же значение элемента, что предоставляется через Root; специальная для Twenty структура элемента или свойство равенства выбора не требуются. Autocomplete управляет текстовым вводом, а не отдельным значением выбранного объекта.

Для сгруппированных данных передавайте группы с массивом `items`. Root сохраняет тип элемента для `itemToStringValue` и `onItemHighlighted`. Отображайте отфильтрованные дочерние элементы каждой группы через `Group` и `Collection`:

```tsx
import { Autocomplete } from 'twenty-ui/primitives/input';
import { Text } from 'twenty-ui/primitives/typography';

type City = { id: number; name: string; country: string };
type CityGroup = { label: string; items: City[] };

const CITY_GROUPS: CityGroup[] = [
  {
    label: 'Europe',
    items: [
      { id: 1, name: 'Paris', country: 'France' },
      { id: 2, name: 'Lisbon', country: 'Portugal' },
    ],
  },
];

export const GroupedCityInput = () => (
  <Text
    style={{ display: 'grid', alignContent: 'start', gap: 8, width: '100%' }}
  >
    <label htmlFor="grouped-city">
      <Text render={<span />}>City</Text>
    </label>
    <Autocomplete.Root
      items={CITY_GROUPS}
      itemToStringValue={(city) => city.name}
      autoHighlight="always"
    >
      <Autocomplete.Input id="grouped-city" placeholder="Search cities" />
      <Autocomplete.Portal>
        <Autocomplete.Positioner>
          <Autocomplete.Popup>
            <Autocomplete.Empty>No matching cities</Autocomplete.Empty>
            <Autocomplete.List>
              {(group: CityGroup) => (
                <Autocomplete.Group key={group.label} items={group.items}>
                  <Autocomplete.GroupLabel>
                    {group.label}
                  </Autocomplete.GroupLabel>
                  <Autocomplete.Collection>
                    {(city: City) => (
                      <Autocomplete.Item
                        key={city.id}
                        value={city}
                        description={city.country}
                      >
                        {city.name}
                      </Autocomplete.Item>
                    )}
                  </Autocomplete.Collection>
                </Autocomplete.Group>
              )}
            </Autocomplete.List>
          </Autocomplete.Popup>
        </Autocomplete.Positioner>
      </Autocomplete.Portal>
    </Autocomplete.Root>
  </Text>
);
```

`Item.startIcon`, `Item.endIcon` и `Item.description` предоставляют вспомогательное содержимое. Компонуйте `Trigger` и `Clear` с Twenty UI [Button](/ru/ui/primitives/input/button) через `render`. `Icon` может содержать значок из `twenty-ui/icon`. Сохраняйте `Status` и `Empty` смонтированными при обновлении их дочерних элементов, чтобы программы чтения с экрана могли объявлять об изменениях.

## Внешняя фильтрация и серверные предложения

Используйте `filteredItems`, когда фильтрацией управляет ваше приложение. Он должен сохранять плоскую или сгруппированную структуру `items`. `filter` принимает пользовательскую функцию сопоставления; `filter={null}` отключает внутреннюю фильтрацию для результатов, уже отфильтрованных сервером.

```tsx
import { useState } from 'react';
import { Autocomplete } from 'twenty-ui/primitives/input';

const CITIES = ['Paris', 'London', 'Lisbon'];

export const CityPrefixInput = () => {
  const [value, setValue] = useState('');
  const { startsWith } = Autocomplete.useFilter();
  const filteredItems = CITIES.filter((city) => startsWith(city, value));

  return (
    <Autocomplete.Root
      items={CITIES}
      filteredItems={filteredItems}
      value={value}
      onValueChange={setValue}
      autoHighlight="always"
    >
      <Autocomplete.Input aria-label="City prefix" />
      <Autocomplete.Portal>
        <Autocomplete.Positioner>
          <Autocomplete.Popup>
            <Autocomplete.Empty>No matching cities</Autocomplete.Empty>
            <Autocomplete.List>
              {(city: string) => (
                <Autocomplete.Item key={city} value={city}>
                  {city}
                </Autocomplete.Item>
              )}
            </Autocomplete.List>
          </Autocomplete.Popup>
        </Autocomplete.Positioner>
      </Autocomplete.Portal>
    </Autocomplete.Root>
  );
};
```

Сохраняйте Root смонтированным, когда результаты поступают асинхронно. Управляйте `open` независимо, чтобы ответ мог открыть предложения, пока поле ввода остаётся в фокусе. Смонтированный `Status` может объявлять о загрузке; обновляйте `Empty`, когда завершённый ответ не содержит результатов. Родительский компонент управляет устранением дребезга, отменой запросов и защитой от устаревших ответов.

`onValueChange` и `onOpenChange` получают сведения о событиях из исходного компонента, включая `reason`, нативный `event`, `trigger`, `cancel()` и `allowPropagation()`. Управляемые вызывающие компоненты решают, какие запрошенные обновления применять. Например, игнорируйте изменение значения `escape-key`, чтобы сохранить серверный запрос, или игнорируйте открытие `input-change` до поступления результатов. `onItemHighlighted` получает исходный типизированный элемент и причину его выделения. Отмена сохраняет семантику установленного Base UI; она не заменяет политику управляемого состояния приложения.

## Композиция ввода и нативные формы

`Input` принимает `size="sm"` или `size="md"` и использует те же стили, что и [Input](/ru/ui/primitives/input/input). Компонуйте его с существующим полем ввода, используя `render`. Составной элемент управления затем сам определяет свой внешний вид: `Input` не добавляет стили Input и игнорирует `size`, но по-прежнему передаёт ваши `className`, нативные атрибуты, обработчики, ref и атрибуты состояния. Передайте их фактическому элементу ввода. Отрисуйте `Input` Twenty, чтобы сохранить стандартный внешний вид.

`InputGroup` предоставляет компоновку и якорь, не добавляя границы поля ввода. Он может содержать чипы или отрисовывать существующую обёртку. Используйте [InputGroup](/ru/ui/primitives/input/input-group) через его свойство `render`, когда всей группе требуется стилизация ввода, как в примере с предложениями сгруппированных объектов. `Input` без `render` внутри него убирает собственную границу. Добавьте полю ввода доступную метку или скомпонуйте его с [Field](/ru/ui/primitives/input/field).

Root сохраняет исходные `name`, `form`, `disabled`, `readOnly` и поведение нативной формы. Нативные атрибуты и ссылка Input нацелены на его input. `submitOnItemClick` включает отправку формы при выборе предложения; по умолчанию форма не отправляется.

Input сохраняет нативную обработку IME из Base UI, включая события композиции и защиту подтверждения с клавиатуры.

Установленная версия Base UI сохраняет неуправляемый запрос при нативном сбросе формы. Для управляемого запроса обрабатывайте `onReset` формы и восстанавливайте начальное значение приложения.

## Размещение, назначение портала и закрытие

`Positioner` по умолчанию использует `side="bottom"`, `align="start"` и `sideOffset={8}`. Он сохраняет контракт якоря и позиционирования установленного Base UI, включая якоря в виде элемента/ссылки/функции/виртуального элемента, функциональные смещения, `positionMethod`, `collisionBoundary`, `collisionPadding`, `collisionAvoidance`, `arrowPadding`, `sticky` и `disableAnchorTracking`. Настраивайте их в Positioner. DirectionProvider управляет логическим размещением и направлением DOM.

`Popup` использует ширину якоря в качестве минимальной ширины. Задайте его `width`, чтобы указать фиксированную ширину содержимого. Его нативные свойства, стили, композиция рендеринга и ссылка нацелены на элемент содержимого независимо от Positioner и Portal. `initialFocus` и `finalFocus` Popup сохраняют исходные параметры фокуса. По умолчанию предложения сохраняют фокус в поле ввода.

Настраивайте `container` и `keepMounted` в `Portal`. При отсутствии container используется ближайшее назначение ThemeProvider с областью действия, затем родительский портал Base UI или тело документа. Явный `null` ожидает предоставления container без рендеринга. Назначения Element, ShadowRoot и ref передаются в Base UI. Неразрешённый ref сохраняет резервный вариант Base UI: родительский портал или body.

Назначение с областью действия по умолчанию сохраняет свои токены CSS и цветовую схему. Явное назначение наследует CSS из своей фактической области DOM, поэтому разместите его в предполагаемой области темы или предоставьте там эти стили. Контекст React и направление остаются доступными через порталы. Целевым элементам ShadowRoot нужны CSS библиотеки и стили темы в этом теневом дереве.

Клавиши со стрелками изменяют выделенный элемент, пока поле ввода сохраняет фокус. Enter выбирает его; Escape и взаимодействие вне компонента запрашивают закрытие с использованием исходной семантики. Нажатие вне компонента может активировать целевой элемент управления. Средства выбора более высокого уровня могут использовать другую политику активации в своём адаптере. Вызовите `event.preventBaseUIHandler()` в `onKeyDown` Input, чтобы пропустить встроенный обработчик для клавиши, которую вы обрабатываете самостоятельно. Также используйте `event.preventDefault()`, когда подавляете нативное действие браузера.

`Root.inline` с `open` отображает предложения без сборки всплывающего окна. Встроенные элементы сохраняют свои обратные вызовы выбора `onClick`, но установленный исходный компонент автоматически заполняет поле ввода только при наличии Popup. Обрабатывайте `Item.onClick`, когда встроенный выбор должен обновлять ваш управляемый текст. `Root.grid` и `Row` поддерживают навигацию по сетке. Эти режимы сохраняют API исходной коллекции и рендеринга.

## Миграция

Оберните Popup в `Autocomplete.Positioner` и `Autocomplete.Portal`. Positioner требует контекст Portal; встроенные предложения пропускают всю сборку всплывающего окна. Перенесите свойства размещения, якоря и коллизий из Popup в Positioner. Перенесите `container` и конфигурацию монтирования в Portal. Сохраняйте ширину, стили содержимого, нативные свойства, обработчики и ссылки в Popup. Используйте явный дочерний элемент `Arrow` для стрелки.

Внутри фронтальных компонентов сохраняйте существующую политику портала с областью действия. Этот API не расширяет назначения порталов рендерера, а также возможности работы с геометрией, прокруткой и закрытием; эти возможности рендерера имеют отдельное управление. Адаптеры средств выбора для production сохраняют свои преднамеренные рабочие процессы активации.
