**Канал сообщений** позволяет вашему приложению помещать переписки от внешнего провайдера — LinkedIn, WhatsApp, SMS, встроенного почтового ящика — в те же записи `Message` и `Message Thread`, которые Twenty использует для электронной почты. Импортированные вами цепочки отображаются в записях Person, Company и Opportunity людей, участвующих в них, на временной шкале и в поиске — без специального интерфейса.

Модель сообщений Twenty намеренно нейтральна к каналам: у сообщения есть участники, текст, временная метка и цепочка; у участника есть `handle` и необязательная связь с Person. В ней нет ничего специфичного для электронной почты. Канал связывает поток таких сообщений с одной учетной записью у одного провайдера.

<Note>
**Бета-версия — возможно, еще недоступна в вашем экземпляре.** Каналы сообщений, принадлежащие приложению, появились недавно; описанный здесь API может измениться и может быть недоступен в используемой вами версии Twenty. Прежде чем использовать `createMessageChannel`, убедитесь, что он существует в вашем SDK.
</Note>

## Требования

Канал всегда принадлежит одному из [подключений](/ru/developers/extend/apps/logic/connections) вашего приложения — учетным данным, через которые он взаимодействует. Прежде чем создать канал, вам нужен провайдер подключений.

## Создание канала

Создавайте канал один раз для каждой подключенной учетной записи из хука `onConnect` провайдера подключений. Так срок существования канала будет соответствовать сроку действия учетных данных.

```ts src/logic-functions/handlers/linkedin-register-connection-handler.ts
import { createMessageChannel, getConnection } from 'twenty-sdk/logic-function';
import { MessageChannelVisibility } from 'twenty-shared/types';

export const linkedinRegisterConnectionHandler = async (payload: {
  connectedAccountId: string;
}) => {
  const connection = await getConnection(payload.connectedAccountId);
  const profile = await fetchLinkedinProfile(connection.accessToken);

  const channel = await createMessageChannel({
    connectedAccountId: connection.id,
    handle: profile.memberUrn,
    displayName: profile.name,
    // LinkedIn DMs are personal, so other members see participants and dates
    // but not subjects or bodies.
    visibility: MessageChannelVisibility.METADATA,
  });

  return { channelId: channel.id };
};
```

### `идентификатор`

Идентификатор учетной записи **в том виде, в каком его называет провайдер** — URN участника LinkedIn, номер телефона E.164, идентификатор пользователя в рабочей области. Twenty рассматривает его как непрозрачный. Именно с ним вы сопоставляете входящие полезные нагрузки, и он определяет, является ли импортированное сообщение входящим или исходящим.

Выбирайте наиболее стабильный идентификатор, предлагаемый провайдером. Идентификатор, который меняется при переименовании пользователя, разделит его историю между двумя каналами.

### `visibility`

`visibility` является **обязательным**, без значения по умолчанию, поскольку он определяет, кто в рабочей области может читать эти переписки:

| Значение           | Другие участники видят                     |
| ------------------ | ------------------------------------------ |
| `METADATA`         | только участников и даты                   |
| `SUBJECT`          | вышеперечисленное, а также тему            |
| `SHARE_EVERYTHING` | вышеперечисленное, а также текст сообщения |

Участник, владеющий базовым подключением, всегда видит свои сообщения полностью, независимо от этой настройки.

Выбирайте значение исходя из степени приватности сообщений провайдера, а не из удобства отображения. Для личных почтовых ящиков (личные сообщения LinkedIn, личный WhatsApp) следует использовать `METADATA`; для общих (ящик поддержки, командный номер) — `SHARE_EVERYTHING`.

<Warning>
`visibility` — единственное, что отделяет личные переписки одного участника от остальной рабочей области. Twenty намеренно требует указывать это значение, а не наследовать значение по умолчанию, которое может открыть слишком много.
</Warning>

## Приём сообщений

После создания канала `ingestMessages` записывает в него беседы. Обработка цепочек, дедупликация, привязка к каналу и конфиденциальность каждого сообщения обрабатываются на стороне сервера — тем же способом, который Twenty использует для собственного импорта электронной почты.

```ts src/logic-functions/handlers/linkedin-inbound-handler.ts
import { ingestMessages } from 'twenty-sdk/logic-function';
import { MessageParticipantRole } from 'twenty-shared/types';

export const linkedinInboundHandler = async (payload: LinkedinWebhookPayload) => {
  const ingested = await ingestMessages({
    messageChannelId: payload.channelId,
    messages: payload.events.map((event) => ({
      externalId: event.messageUrn,
      threadExternalId: event.conversationUrn,
      text: event.body,
      receivedAt: new Date(event.createdAt),
      participants: [
        {
          role: MessageParticipantRole.FROM,
          handle: event.sender.memberUrn,
          displayName: event.sender.name,
        },
        ...event.recipients.map((recipient) => ({
          role: MessageParticipantRole.TO,
          handle: recipient.memberUrn,
          displayName: recipient.name,
        })),
      ],
    })),
  });

  return { ingested: ingested.length };
};
```

### Что сервер делает для вас

**Дедупликация.** `externalId` — это ключ. Повторный приём одного и того же сообщения ничего не создаёт и ничего не изменяет, поэтому повторно доставленный вебхук можно безопасно воспроизвести, а дозагрузка может пересекаться с потоком в реальном времени. Возвращаемый `messageId` остаётся неизменным при повторных воспроизведениях. Вызовы для одного канала выполняются последовательно, поэтому повторная доставка, поступившая, пока исходное сообщение ещё записывается, ожидает вместо одновременного выполнения с ним.

**Обработка цепочек.** Сообщения с общим `threadExternalId` попадают в одну цепочку сообщений, которая затем отображается в записях Person, Company и Opportunity её участников.

**Направление.** Определяется, а не указывается: сообщение является исходящим, если идентификатор участника `FROM` совпадает с идентификатором канала, и входящим в противном случае. Ровно один участник должен иметь `FROM` — направление, столбец отправителя цепочки и предпросмотр на временной шкале считывают его, поэтому сообщение без него отклоняется, а не отображается как пустая беседа.

**Дедупликация ограничена каналом.** `externalId` должен быть уникальным только в пределах одного канала, что фактически гарантирует большинство провайдеров — многие нумеруют сообщения по беседе или по учётной записи. В результате два участника одной беседы у провайдера получают каждый своё собственное сообщение, а не общее. Это сделано намеренно: их объединение потребовало бы от каждого приложения гарантировать глобальное пространство имён, которым оно не управляет, а ошибка привязала бы содержимое сообщения одного участника к каналу другого.

**Конфиденциальность.** Каждое сообщение наследует `visibility` своего канала. Ничто из того, что вы принимаете, не будет более видимым, чем канал, в который вы это принимаете.

### Пакетная обработка

Один вызов — это одна транзакция в пределах одного тайм-аута функции логики, с ограничением в **100 сообщений**. Разбивайте дозагрузку от провайдера на страницы, а не отправляйте её целиком:

```ts
for (const page of chunk(allHistoricalMessages, 100)) {
  await ingestMessages({ messageChannelId, messages: page });
}
```

Пакет обрабатывается по принципу «всё или ничего», а повторение одного `externalId` в одном пакете отклоняется — удалите дубликаты перед отправкой. Размер содержимого сообщения ограничен 256 КБ.

### Привязка участников к People

Twenty сопоставляет участников электронной почты с People по адресу электронной почты. Это не может соответствовать ни LinkedIn URN, ни номеру телефона, поэтому **приложение должно указать, кем является участник** — непривязанная цепочка не отображается на странице записи ни у кого.

Передайте `personId` вместе с идентификатором:

```ts
participants: [
  {
    role: MessageParticipantRole.FROM,
    handle: event.sender.memberUrn,
    displayName: event.sender.name,
    personId: await resolvePersonIdFromLinkedinUrn(event.sender.memberUrn),
  },
]
```

Определите идентификатор в зависимости от того, как хранится идентификатор вашего провайдера — через `Person.linkedinLink` или поле идентификатора, добавленное вашим приложением с помощью [`defineField`](/ru/developers/extend/apps/data/extending-objects). Неизвестные идентификаторы отклоняются сразу, а не сохраняются как висячие ссылки.

После привязки участника Twenty создаёт цели цепочки, и разговор отображается на странице записи этого Person и его компании, точно так же, как цепочка электронных писем.

Также принимается `workspaceMemberId` — для участника, который является участником этого рабочего пространства, а не контактом. Это **только для атрибуции**: цели цепочки создаются исключительно из `personId` — так же, как для электронной почты, — поэтому участник, привязанный только к участнику рабочего пространства, отображается в цепочке, но не привязывает разговор ни к одной странице записи. Передавайте `personId`, когда хотите привязать цепочку к какой-либо записи.

<Note>
Позднее сопоставление не теряется. Повторная загрузка сообщения с идентификатором, который вы с тех пор определили, привязывает уже существующего участника — сопоставленного по сообщению, идентификатору и роли, поэтому отображаемое имя, изменившееся или отсутствовавшее за это время, не разделяет его на два. Если имя не указано, сохраняется уже сохранённое; новое имя заменяет его. Передача другого `personId` исправляет предыдущую ссылку, а не добавляет вторую.

Пока нет способа *очистить* идентификатор: null воспринимается как "оставить без изменений", а не как "отвязать". Исправление неверной ссылки означает передачу правильной.
</Note>

Участники, которых вы оставляете непривязанными, всё равно сохраняются и отображаются в цепочке — они просто не привязывают разговор к записи.

## Просмотр и обновление каналов

```ts
import {
  listMessageChannels,
  updateMessageChannel,
} from 'twenty-sdk/logic-function';

// Every channel this app owns, across all its connections
const channels = await listMessageChannels();

// Just the ones on a given connection
const forConnection = await listMessageChannels({
  connectedAccountId: connection.id,
});

// Rename it, re-scope who can read it, or pause ingestion
await updateMessageChannel({ id: channel.id, displayName: 'Ada (LinkedIn)' });
await updateMessageChannel({ id: channel.id, isSyncEnabled: false });
```

Изменение `visibility` через `updateMessageChannel` меняет область доступа для всех сообщений, уже импортированных в канал, а не только для последующих. Приём в канал с `isSyncEnabled: false` отклоняется, поэтому приостановка канала останавливает поток, ничего не удаляя.

Ваше приложение видит только каналы, созданные для его собственных подключений. Каналы, принадлежащие другим приложениям, а также собственные почтовые каналы Twenty для него невидимы.

Канал также доступен только человеку, через чье подключение он взаимодействует, если это подключение является личным. Запуск, инициированный другим участником рабочего пространства, не может его видеть, изменять или принимать в него сообщения; запуск без пользователя — cron, вебхук, хук установки — действует от имени приложения и получает доступ ко всем каналам, которыми владеет приложение.

## Удаление канала

Вызовите `deleteMessageChannel(id)` из хука `onDisconnect` провайдера подключений, чтобы канал никогда не существовал дольше учетных данных, через которые он взаимодействует.

```ts src/logic-functions/handlers/linkedin-disconnect-handler.ts
import {
  deleteMessageChannel,
  listMessageChannels,
} from 'twenty-sdk/logic-function';

export const linkedinDisconnectHandler = async (payload: {
  connectedAccountId: string;
}) => {
  const channels = await listMessageChannels({
    connectedAccountId: payload.connectedAccountId,
  });

  await Promise.all(channels.map((channel) => deleteMessageChannel(channel.id)));
};
```

При удалении канала удаляются сообщения, импортированные через него, а также все цепочки, в которых не осталось сообщений. Чтобы прекратить импорт, сохранив историю, установите вместо этого `isSyncEnabled: false`.

## Чего канал не делает

* **Он не опрашивается.** Конвейер импорта Twenty опрашивает провайдеров почтовых ящиков по cron-расписанию. Каналы приложений работают только через отправку: ничего не загружается от вашего имени, поэтому ваше приложение отвечает за получение сообщений через маршрут вебхука или функцию логики cron.
* **Он не отправляет.** Исходящая доставка пока не направляется в приложения; ответ, составленный в Twenty, не может быть доставлен вашему провайдеру. Пока это не реализовано, добавьте ссылку на собственный интерфейс провайдера для ответов.
* **Он не сопоставляет контакты.** Twenty сопоставляет участников электронной переписки с People по адресу электронной почты, который не может соответствовать LinkedIn URN, поэтому каналы приложений вместо этого [явно привязывают участников при загрузке](#linking-participants-to-people).
* **Он не создаёт контакты.** Автоматическое создание в Twenty выводит людей и компании из доменов электронной почты, что не имеет смысла для большинства провайдеров, поэтому для каналов приложений оно отключено. Создайте Person самостоятельно, затем передайте его `personId`.
