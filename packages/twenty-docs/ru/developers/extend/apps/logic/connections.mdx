Подключения — это учетные данные, которыми пользователь располагает для внешнего сервиса (Linear, GitHub, Slack, ...). Ваше приложение определяет, **как** получают эти учетные данные — через **провайдера подключения** — и использует их во время выполнения для выполнения аутентифицированных вызовов к стороннему API.

На данный момент поддерживается только OAuth 2.0. Будущие типы учетных данных (персональные токены доступа, ключи API, базовая аутентификация) будут подключаться к тому же интерфейсу — приложения, уже использующие `defineConnectionProvider({ type: 'oauth', ... })` не потребуют миграции.

<Accordion title="defineConnectionProvider" description="Определите, как в вашем приложении получаются подключения">

Провайдер подключения описывает процедуру OAuth-обмена, которая требуется вашему приложению. Для провайдера `WORKSPACE` (по умолчанию) участник нажимает «Добавить подключение» в настройках вашего приложения, завершает процесс на экране согласия провайдера, и в его рабочем пространстве создается запись `ConnectedAccount`. См. раздел «Подключения рабочего пространства или личные подключения» для провайдеров `USER`.

Рабочей конфигурации нужны **два файла** — провайдер подключения и соответствующее объявление `serverVariables` в `defineApplication`, которое содержит учетные данные клиента OAuth.

```ts src/connection-providers/linear-connection.ts
import { defineConnectionProvider } from 'twenty-sdk/define';

export default defineConnectionProvider({
  universalIdentifier: '9c7d1f5e-6a0b-4d44-be0c-3f8b5a9d4e6f',
  name: 'linear',
  displayName: 'Linear',
  icon: 'IconBrandLinear',
  // Optional: a logo bundled in your app's public/ folder, shown next to the
  // provider in the app's General tab.
  logo: 'public/linear-logomark.svg',
  type: 'oauth',
  scope: 'WORKSPACE',
  oauth: {
    authorizationEndpoint: 'https://linear.app/oauth/authorize',
    tokenEndpoint: 'https://api.linear.app/oauth/token',
    scopes: ['read', 'write'],
    // These must match keys in `defineApplication.serverVariables` below.
    clientIdVariable: 'LINEAR_CLIENT_ID',
    clientSecretVariable: 'LINEAR_CLIENT_SECRET',
    // Optional: defaults to 'json'. Some providers (Linear, Slack) want
    // 'form-urlencoded' for the token request.
    tokenRequestContentType: 'form-urlencoded',
    // Optional: defaults to true. Disable only if the provider rejects PKCE.
    usePkce: false,
    // Optional: extra query params on the authorize URL.
    // authorizationParams: { prompt: 'consent' },
    // Optional: provider's RFC 7009 token revocation endpoint, called on disconnect.
    // revokeEndpoint: 'https://example.com/oauth/revoke',
  },
  // Optional: a logic function in this app that returns a stable id for the
  // upstream account, run before the tokens are saved. See "Identify the
  // connected account".
  // identifyAccountLogicFunction: { universalIdentifier: '2f1e0d9c-...-...' },
  // Optional: a logic function in this app to run right after a connection is
  // established. See "Run a logic function on connect".
  // onConnectLogicFunction: { universalIdentifier: '3a2b1c0d-...-...' },
  // Optional: a logic function in this app to run right after a connection is
  // removed. See "Run a logic function on disconnect".
  // onDisconnectLogicFunction: { universalIdentifier: '4d5e6f70-...-...' },
});
```

```ts src/application.config.ts
import { defineApplication } from 'twenty-sdk/define';

export default defineApplication({
  universalIdentifier: '...',
  displayName: 'Linear',
  description: 'Connect Linear to Twenty.',
  // OAuth client credentials live on the app registration (one OAuth app per
  // Twenty server, configured by the admin) — not per-workspace. Declare them
  // as serverVariables so the admin can fill them in once for all installs.
  serverVariables: {
    LINEAR_CLIENT_ID: {
      description: 'OAuth client ID from your Linear OAuth application.',
      isSecret: false,
      isRequired: true,
    },
    LINEAR_CLIENT_SECRET: {
      description: 'OAuth client secret from your Linear OAuth application.',
      isSecret: true,
      isRequired: true,
    },
  },
});
```

Основные моменты:

* `name` — это уникальная строка-идентификатор, используемая в `listConnections({ providerName })` (kebab-case, должна соответствовать `^[a-z][a-z0-9-]*$`).
* `displayName` отображается на вкладке «Общие» приложения и в списке инструментов ИИ.
* `scope` определяет, кто подключается: `'WORKSPACE'` (по умолчанию) для подключений, общих для всего рабочего пространства, и `'USER'` для подключений, которые каждый участник создает для себя. См. ниже раздел «Подключения рабочего пространства или личные подключения».
* `logo` — это путь к ресурсу, включенному в папку `public/` вашего приложения и обслуживаемому через публичные ресурсы приложения. Если параметр не указан, на вкладке «Общие» используется заполнитель, созданный на основе `displayName`.
* `clientIdVariable` / `clientSecretVariable` — это **имена**, а не значения — они должны совпадать с ключами, объявленными в `defineApplication.serverVariables`. Фактические `client_id` и `client_secret` вводятся администратором сервера через интерфейс регистрации приложения и никогда не коммитятся в ваш репозиторий.
* Используйте `serverVariables` (не `applicationVariables`) — учетные данные OAuth являются общими для сервера, и на каждом сервере Twenty используется одно приложение OAuth.
* Пока оба `serverVariables` не заполнены, на вкладке «Общие» приложения отображается подсказка «нужен администратор сервера», а кнопка «Добавить подключение» отключена.
* `type: 'oauth'` — единственное поддерживаемое сегодня значение. Дискриминатор совместим с будущими версиями: будущие типы (`'pat'`, `'api-key'`, ...) добавят новые блоки подконфигурации рядом с `oauth`.

URL обратного вызова OAuth, который вашему провайдеру нужно добавить в список разрешенных:

```
https://<your-twenty-server>/auth/apps/callback
```

<Accordion title="Определите подключенную учетную запись" description="Не допускайте незаметной смены вышестоящих учетных записей при повторном подключении">

Когда пользователь нажимает **Повторное подключение**, ничто не мешает ему авторизовать другую вышестоящую учетную запись вместо той, с которой было установлено подключение: рабочую область Slack B вместо рабочей области A, другую организацию GitHub или другую учетную запись Google. Не имея способа отличить их друг от друга, Twenty перезапишет токены A токенами B, и все, что ваше приложение создало на основе этого подключения, незаметно начнет взаимодействовать с B.

Укажите для `identifyAccountLogicFunction` функцию логики в том же приложении, которая возвращает стабильный идентификатор учетной записи, связанной с только что выданным токеном:

```ts src/connection-providers/slack-connection.ts
import { defineConnectionProvider } from 'twenty-sdk/define';

import { SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER } from 'src/constants/universal-identifiers';

export default defineConnectionProvider({
  universalIdentifier: '...',
  name: 'slack',
  displayName: 'Slack',
  type: 'oauth',
  oauth: {
    /* ... */
  },
  identifyAccountLogicFunction: {
    universalIdentifier: SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER,
  },
});
```

**Когда выполняется.** Синхронно в обработчике обратного вызова OAuth, сразу после обмена кода авторизации на токены и **до** сохранения каких-либо данных. Пользователь ожидает перенаправления, поэтому при установке или синхронизации приложения Twenty ограничивает `timeoutSeconds` функции значением 10 независимо от того, что указано в манифесте; выполняйте только один запрос к конечной точке провайдера "who am I". Хук on-connect, если он есть, всё равно запускается позже, после сохранения подключения.

**Полезная нагрузка.** Обработчик получает предварительный токен доступа. Он ещё не сохранён, поэтому `getConnection` не может его вернуть; используйте его напрямую и не записывайте в журнал.

```ts
type IdentifyAccountPayload = {
  connectionProviderId: string;
  connectionProviderName: string; // e.g. 'slack'
  accessToken: string;
};
```

**Результат.** Верните id учётной записи и, при необходимости, отображаемый идентификатор:

```ts
type IdentifyAccountResult = {
  externalAccountId: string | null; // non-empty, at most 512 characters; null opts out
  handle?: string; // non-empty when present
};
```

* `externalAccountId` должен быть неизменным на протяжении всего существования вышестоящей учётной записи (id команды, id организации, id пользователя), а не именем, которое пользователь может изменить. Twenty обрезает его и сохраняет в подключении при первом подключении.
* `handle`, если он возвращён, заменяет идентификатор, который иначе определил бы Twenty (электронный адрес из OIDC `id_token` или электронный адрес подключающегося пользователя). Верните то, что пользователь узнает, например имя рабочего пространства Slack.
* Верните `{ externalAccountId: null }`, когда провайдер не может предоставить неизменный id. Тогда Twenty ведёт себя так, как если бы функция идентификации не была объявлена: id не сохраняется, повторное подключение очищает любой ранее сохранённый id, а повторные подключения не проверяются. Простой `null` или отсутствие возвращаемого значения считается ошибкой, поэтому обработчик, который забыл вернуть значение, не сможет незаметно отключить проверку.
* Если функция генерирует исключение, превышает время ожидания или возвращает что-либо иное, подключение **не** сохраняется, а пользователь возвращается на страницу настроек с ошибкой. Генерируйте исключение только тогда, когда действительно не можете идентифицировать учётную запись.

**Отклонение повторного подключения.** При повторном подключении Twenty сравнивает возвращённый `externalAccountId` с сохранённым в подключении. Если они различаются, обратный вызов отклоняется до внесения каких-либо записей: существующие токены, дескриптор и область действия остаются без изменений, хук подключения не запускается, а пользователь видит, какую учетную запись он авторизовал и какой учетной записи принадлежит подключение. Подключения, созданные до того, как ваше приложение объявило функцию, ещё не имеют сохранённого id; при следующем повторном подключении он будет сохранён.

Twenty не устраняет дубликаты по `externalAccountId`: повторное подключение той же вышестоящей учётной записи через **Добавить подключение** создаёт два подключения. Id доступен в `listConnections` и `getConnection`, поэтому приложение, которому нужно одно подключение для каждой вышестоящей учётной записи, может самостоятельно обнаруживать дубликаты (например, в своём хуке on-connect).

**Написание функции.** Большинство провайдеров предоставляют одну конечную точку, описывающую текущий токен. Для Slack это `auth.test`, который возвращает рабочее пространство (`team_id`, `team`) и пользователя, которому принадлежит токен:

```ts src/logic-functions/slack-identify-account.ts
import { defineLogicFunction } from 'twenty-sdk/define';
import type {
  IdentifyAccountPayload,
  IdentifyAccountResult,
} from 'twenty-sdk/logic-function';

import { SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER } from 'src/constants/universal-identifiers';

export default defineLogicFunction({
  universalIdentifier: SLACK_IDENTIFY_ACCOUNT_LOGIC_FUNCTION_UNIVERSAL_IDENTIFIER,
  name: 'slack-identify-account',
  timeoutSeconds: 10,
  handler: async ({
    accessToken,
  }: IdentifyAccountPayload): Promise<IdentifyAccountResult> => {
    const response = await fetch('https://slack.com/api/auth.test', {
      method: 'POST',
      headers: { Authorization: `Bearer ${accessToken}` },
    });
    const { ok, error, team_id, team } = await response.json();

    if (!ok) {
      throw new Error(`auth.test failed: ${error}`);
    }

    return { externalAccountId: team_id, handle: team };
  },
});
```

Другие провайдеры используют тот же шаблон независимо от того, является ли их конечная точка "who am I" REST или GraphQL. Генерируйте исключение, когда провайдер отклоняет токен, и возвращайте id как строку: преобразуйте числовые id, например id пользователей GitHub, с помощью `String(id)`.

Идентификация доступна в Twenty 2.48.0. Если ваше приложение зависит от неё, объявите `"engines": { "twenty": ">=2.48.0" }` в его `package.json`.

<Accordion title="Запускайте логическую функцию при подключении" description="Реагируйте в момент установления соединения">

Некоторые провайдеры передают вам данные в момент подключения, которые нужно сохранить до того, как соединение станет пригодным к использованию — классический пример — Slack, где OAuth-ответ указывает `team_id` рабочей области, по которому будут определяться входящие события. Установите `onConnectLogicFunction`, чтобы сослаться на логическую функцию в том же приложении (по её `universalIdentifier`), и она будет выполнена сразу после создания `ConnectedAccount`.

```ts src/connection-providers/slack-connection.ts
export default defineConnectionProvider({
  universalIdentifier: '...',
  name: 'slack',
  displayName: 'Slack',
  type: 'oauth',
  oauth: {
    /* ... */
  },
  // Runs claimSlackTeam after every successful Slack connection.
  onConnectLogicFunction: {
    universalIdentifier: '3a2b1c0d-1111-4222-8333-444455556666',
  },
});
```

Хук выполняется **асинхронно в подключающейся рабочей области** (он ставится в очередь, а не ожидается), поэтому медленный или падающий хук никогда не блокирует и не ломает OAuth-callback — сделайте его идемпотентным и обеспечьте собственную обработку повторных попыток. Обработчик получает:

```ts
type OnConnectPayload = {
  connectionProviderId: string;
  connectionProviderName: string; // e.g. 'slack'
  connectedAccountId: string;
};
```

Оттуда используйте `getConnection(connectedAccountId)`, чтобы прочитать новый access token и вызвать API провайдера (например, Slack `auth.test`) или сохранить отображение с помощью [key-value store](/ru/developers/extend/apps/logic/key-value-store).

</Accordion>

<Accordion title="Запускайте логическую функцию при отключении" description="Выполняйте очистку при удалении подключения">

Всё, на что приложение заявляет права при подключении, должно быть освобождено, когда подключение прекращается. Интеграция со Slack, которая, например, заявляет `team_id` при подключении, должна освободить это право, чтобы другое рабочее пространство могло подключить ту же Slack-команду. Задайте для `onDisconnectLogicFunction` ссылку на функцию логики в том же приложении; она выполняется непосредственно перед удалением `ConnectedAccount` и его токена, поэтому обработчик все еще может вызвать провайдер с помощью `getConnection`, чтобы удалить все, что хук подключения настроил удаленно.

```ts src/connection-providers/slack-connection.ts
export default defineConnectionProvider({
  universalIdentifier: '...',
  name: 'slack',
  displayName: 'Slack',
  type: 'oauth',
  oauth: {
    /* ... */
  },
  // Runs releaseSlackTeam after every Slack disconnection.
  onDisconnectLogicFunction: {
    universalIdentifier: '4470aba8-5ff5-4800-88db-2a427cd8677c',
  },
});
```

В отличие от хука подключения, она выполняется **встроенно в отключаемом рабочем пространстве**, один раз, без повторных попыток: сбой фиксируется, а отключение все равно завершается. Обработчик получает тот же формат полезной нагрузки:

```ts
type OnDisconnectPayload = {
  connectionProviderId: string;
  connectionProviderName: string; // e.g. 'slack'
  connectedAccountId: string;
};
```

Когда выполняется хук, `ConnectedAccount` и его токен все еще существуют, поэтому `getConnection(connectedAccountId)` возвращает новый токен доступа, и обработчик может удалить все, что он зарегистрировал удаленно. Данные состояния, которые провайдер не может вернуть (например, `team_id`, внешний идентификатор подписки), по-прежнему следует хранить в [key-value store](/ru/developers/extend/apps/logic/key-value-store), записывая их при подключении и используя `connectedAccountId` в качестве ключа. Не усложняйте обработчик: он выполняется в рамках запроса на отключение, поэтому его `timeoutSeconds` определяет максимальную длительность этого запроса.

Hook срабатывает, когда соединение удаляется само по себе. При удалении приложения его соединения удаляются каскадом на уровне базы данных, поэтому hook в этом случае не запускается. Объявите `uninstallLogicFunction` в `defineApplication` для этого сценария: она запускается до удаления метаданных приложения, поэтому всё ещё может вызвать `listConnections` и выполнить оставшуюся очистку.

</Accordion>

<Accordion title="listConnections / getConnection" description="Используйте подключения из логической функции">

Внутри обработчика логической функции `listConnections({ providerName })` возвращает записи `ConnectedAccount` этого приложения для указанного провайдера с обновленными токенами доступа.

```ts src/logic-functions/handlers/create-linear-issue-handler.ts
import { listConnections } from 'twenty-sdk/logic-function';

export const createLinearIssueHandler = async (input: {
  teamId?: string;
  title?: string;
}) => {
  if (!input.teamId || !input.title) {
    return { success: false, error: 'teamId and title are required' };
  }

  const connections = await listConnections({ providerName: 'linear' });

  // Workspace-shared credentials win when present; fall back to the first
  // personal one. For HTTP-route triggers you typically pick the
  // request user's connection via event.userWorkspaceId instead.
  const connection =
    connections.find((c) => c.scope === 'WORKSPACE') ?? connections[0];

  if (!connection) {
    return {
      success: false,
      error:
        'Linear is not connected. Open the app settings and click "Add connection".',
    };
  }

  // Use connection.accessToken to call the third-party API.
  const response = await fetch('https://api.linear.app/graphql', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${connection.accessToken}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      query: `mutation { issueCreate(input: { teamId: "${input.teamId}", title: "${input.title}" }) { success } }`,
    }),
  });

  return { success: response.ok };
};
```

Каждое подключение имеет:

| Поле                | Описание                                                                                                                                                                                                                                                                                                        |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                | Уникальный идентификатор записи; передайте его в `getConnection(id)`, чтобы повторно получить одну запись                                                                                                                                                                                                       |
| `scope`             | `'USER'` (приватно для одного участника рабочего пространства) или `'WORKSPACE'` (доступно всем участникам)                                                                                                                                                                                                     |
| `visibility`        | Устарело: `scope` в нижнем регистре (`'user'` или `'workspace'`). Используйте `scope` вместо этого                                                                                                                                                                                                              |
| `scopes`            | Разрешения OAuth, предоставленные внешним провайдером (в отличие от `scope` — это несвязанные вещи)                                                                                                                                                                                                             |
| `userWorkspaceId`   | Идентификатор userWorkspace владельца — полезно для выбора "подключения пользователя запроса" в триггерах HTTP-маршрутов                                                                                                                                                                                        |
| `workspaceMemberId` | Идентификатор участника рабочего пространства владельца или `null`, если он с тех пор покинул рабочее пространство                                                                                                                                                                                              |
| `accessToken`       | Актуальный токен доступа OAuth (обновляется автоматически при истечении срока действия)                                                                                                                                                                                                                         |
| `name`              | Отображаемое имя подключения (автоматически определяется при обратном вызове OAuth, может быть переименовано пользователем)                                                                                                                                                                                     |
| «Обработка»         | Метка подключённой вышестоящей учётной записи, обновляемая при каждом повторном подключении: `handle`, возвращённый функцией идентификации, если он есть, иначе адрес электронной почты из OIDC `id_token`, возвращённого при обмене токенами, либо адрес электронной почты подключающегося пользователя Twenty |
| `externalAccountId` | Неизменный id вышестоящей учётной записи, возвращаемый функцией идентификации, или `null`, если провайдер не объявляет его либо подключение было создано до этого. Не уникален: используйте его для самостоятельного устранения дубликатов подключений                                                          |
| `authFailedAt`      | Устанавливается, когда последнее обновление завершилось сбоем или когда приложение сообщило, что учетные данные недействительны, через `reportConnectionAuthFailure`; пользователь должен повторно подключиться                                                                                                 |
| `authFailedReason`  | Понятное человеку объяснение для `authFailedAt`, если отправитель его указал; отображается на странице сведений о подключении в настройках                                                                                                                                                                      |

Основные моменты:

* Передайте `{ providerName }`, чтобы отфильтровать по провайдеру; опустите, чтобы получить все подключения этого приложения у всех провайдеров.
* Сервер прозрачно обновляет токен доступа перед возвратом. Ваш обработчик всегда получает рабочий токен (или установлено `authFailedAt`).
* `getConnection(id)` — эквивалент для одной записи.

</Accordion>

<Accordion title="reportConnectionAuthFailure" description="Сообщить платформе, что учетные данные недействительны">

Платформа самостоятельно устанавливает `authFailedAt` только при сбое обновления OAuth. Провайдеры, чьи токены никогда не обновляются (например, токен бота Slack), дают сбой только во время вызова внутри ваших обработчиков, поэтому строка подключения в настройках продолжит показывать **Подключено**, хотя каждый вызов будет завершаться ошибкой. Когда ваш код получает однозначный отказ в аутентификации, сообщите о нём:

```ts
import { reportConnectionAuthFailure } from 'twenty-sdk/logic-function';

await reportConnectionAuthFailure({
  connectionId: connection.id,
  reason:
    'Slack rejected the stored token (invalid_auth). Reconnect to restore the integration.',
});
```

Это устанавливает `authFailedAt` и необязательную причину для подключения. Строка в настройках изменится на **Требуется повторное подключение** с кнопкой «Повторно подключить», страница сведений о подключении покажет причину, а `getConnection` начнёт выбрасывать `AppConnectionAuthFailedError` для этой строки. Флаг и причина автоматически очищаются, когда пользователь повторно подключается. `reason` длиной более 1000 символов отклоняется, поэтому сокращайте полезные нагрузки провайдера перед их передачей.

Сообщайте только о сбоях, которые действительно исправит повторное подключение (отказе класса `invalid_auth` от провайдера), и никогда — о временных сетевых ошибках. Приложение может сообщать только о собственных подключениях, а пользователь запроса — только о собственных личных учетных данных.

Мутация, лежащая в основе этого помощника, поставляется вместе с Twenty 2.40.0, поэтому её вызов на более старом сервере завершится ошибкой. Если ваше приложение использует её, укажите зависимость в `package.json`: `"engines": { "twenty": ">=2.40.0" }`.

</Accordion>

<Accordion title="Подключения рабочего пространства или личные подключения" description="Выберите, кто подключается, с помощью области действия провайдера">

Каждое подключение имеет одну из двух областей действия:

* **Общее для рабочего пространства** (`'WORKSPACE'`) — любой участник рабочего пространства может использовать эти учетные данные. Триггеры cron/базы данных также видят их, поскольку у них нет пользователя запроса.
* **Только для меня** (`'USER'`) — учетные данные доступны только подключившемуся участнику. Любая логическая функция, вызываемая от его имени (триггер HTTP-маршрута с `isAuthRequired: true`), видит их; триггеры cron и события базы данных — нет.

`scope` провайдера определяет, какую область действия получат его новые подключения:

* `scope: 'WORKSPACE'` (по умолчанию) — приложение работает с подключениями, общими для рабочего пространства. **Добавить подключение** в настройках приложения создает подключение, общее для рабочего пространства.
* `scope: 'USER'` — каждый участник подключает свою учетную запись, создавая личные подключения. Участники будут подключаться через свои **Настройки приложения**, которые пока недоступны: до тех пор у провайдера `USER` нет кнопки **Добавить подключение**, а в настройках приложения перечислены только подключения, которые участник уже может видеть.

У провайдера может быть только одна область действия. Если вашему приложению для одного сервиса нужны как общие учетные данные, так и отдельные для каждого участника (например, токен бота и собственная учетная запись каждого участника), объявите два провайдера.

Подключение всегда имеет область действия своего поставщика, и область действия поставщика является частью его идентичности: более поздняя версия не может изменить `scope` существующего поставщика, и обновление отклоняется, если оно пытается это сделать. Чтобы переместить службу из одной области действия в другую, объявите нового поставщика с новым `universalIdentifier` и удалите старого. При обновлении старый поставщик и все подключения, созданные с его помощью, удаляются через обычный путь отключения (`onDisconnectLogicFunction`, отзыв токена, очистка канала), а участники снова подключаются через нового поставщика.

Добавление или повторное подключение соединения **Just for me** требует разрешения `CONNECTED_ACCOUNTS`, а добавление или повторное подключение соединения **Workspace shared** требует разрешения `APPLICATIONS`.

Используйте подходящее подключение для каждого обработчика:

```ts
// HTTP-route trigger — prefer the request user's own connection.
const conn =
  connections.find((c) => c.userWorkspaceId === event.userWorkspaceId) ??
  connections.find((c) => c.scope === 'WORKSPACE');

// Cron trigger — no request user; only shared credentials are sensible.
const conn = connections.find((c) => c.scope === 'WORKSPACE');
```

Допускается несколько подключений на пару (пользователь, провайдер), поэтому один и тот же пользователь может иметь "Personal Linear" и "Work Linear" одновременно.

Область действия провайдера доступна в Twenty 2.49.0. Если ваше приложение объявляет `scope`, укажите `"engines": { "twenty": ">=2.49.0" }` в его `package.json`. В той же версии `scope` подключения заменяет его `visibility`, который остается доступным как устаревший псевдоним в нижнем регистре. `listConnections` и `getConnection` из `twenty-sdk` 2.49.0 считывают `scope`, поэтому приложениям, созданным с его помощью, требуется сервер версии 2.49.0.

</Accordion>

<Accordion title="Единоразовая настройка провайдера" description="Зарегистрируйте свое приложение OAuth у стороннего сервиса">

Для каждого провайдера подключения администратору сервера сначала нужно зарегистрировать у стороннего сервиса приложение OAuth.

1. Перейдите в настройки разработчика провайдера (например, https://linear.app/settings/api/applications/new).
2. Установите **Redirect URI** в значение `\<SERVER_URL>/auth/apps/callback`.
3. Скопируйте сгенерированные **Client ID** и **Client Secret**.
4. Откройте установленное приложение в Twenty под учетной записью администратора сервера → задайте значения в соответствующих `serverVariables`.
5. Затем участники рабочего пространства смогут добавлять подключения к провайдерам `WORKSPACE` в разделе **Подключения** конкретного приложения.

</Accordion>
