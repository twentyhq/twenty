## Добавить метаданные маркетплейса

[Конфигурация приложения](/ru/developers/extend/apps/config/application) содержит
сведения, отображаемые в маркетплейсе: автора, категорию, логотип и ссылки
на поддержку. Поместите логотип в `public/` и укажите его в `logo`.

```ts filename="src/application-config.ts"
import { defineApplication } from 'twenty-sdk/define';

export default defineApplication({
  universalIdentifier: APPLICATION_UNIVERSAL_IDENTIFIER,
  displayName: 'Document Generator',
  description:
    'Create reusable document templates and generate personalized documents from your CRM records.',
  logo: 'public/document-generator.svg',
  author: 'Twenty',
  category: 'Productivity',
  websiteUrl: 'https://docs.twenty.com/ru/developers/extend/apps',
  termsUrl: 'https://www.twenty.com/terms',
  emailSupport: 'contact@twenty.com',
  issueReportUrl: 'https://github.com/twentyhq/twenty/issues',
});
```

<Tip>
  Роль по умолчанию объявляется с помощью `defineApplicationRole()` в отдельном файле —
  здесь больше не нужно передавать `defaultRoleUniversalIdentifier`.
</Tip>

Также добавьте ключевое слово `twenty-app` в `package.json`, чтобы приложение можно было найти:

```json filename="package.json"
{ "keywords": ["twenty-app"] }
```

## Добавьте скриншоты в галерею

Страница приложения в маркетплейсе говорит сама за себя благодаря скриншотам. Поместите несколько PNG-файлов в
`public/gallery/` и укажите их в `galleryImages` — они будут отображаться как галерея
на странице каталога, в порядке следования в массиве.

```ts filename="src/application-config.ts"
export default defineApplication({
  // ...identity from above
  galleryImages: [
    'public/gallery/01-generated-document.png',
    'public/gallery/02-command-menu.png',
    'public/gallery/03-template-editor.png',
    'public/gallery/04-documents.png',
  ],
});
```

<Tip>
  Начните с результата: сделайте первым скриншотом готовый результат (сгенерированный
  документ), а затем покажите, как он запускается и создается. Используйте четкие,
  высококачественные скриншоты — это первое, что видит пользователь.
</Tip>

Уделите `README.md` такое же внимание — это главная страница на npm и GitHub.
Начните с описания ценностного предложения и скриншота, перечислите ключевые функции,
а затем поместите технические детали ниже основной части страницы.

## Проверьте перед выпуском

Выполните те же проверки, что и CI:

```bash filename="Terminal"
yarn lint          # oxlint
yarn typecheck     # tsgo
yarn test:unit     # unit tests
twenty app plan   # preview the metadata diff
```

План точно показывает, что изменится на сервере, не применяя эти изменения —
хорошая финальная проверка. См.
[Тестирование](/ru/developers/extend/apps/operations/testing) и
[Синхронизация и восстановление](/ru/developers/extend/apps/operations/sync-and-recovery).

## Публикация

```bash filename="Terminal"
# Public app → npm (default)
twenty app publish

# Or deploy privately to a specific server's registry
twenty app publish --private -r <remote>
```

`twenty app publish` по умолчанию собирает и публикует приложение в npm; `--private` вместо этого загружает
tarball в частный реестр сервера Twenty. Чтобы опубликованное приложение появилось
в маркетплейсе экземпляра, дождитесь синхронизации каталога маркетплейса сервером.

Подробности и контрольный список для выпуска:
[Публикация](/ru/developers/extend/apps/operations/publishing).

## Вы создали приложение 🎉

За шесть глав вы использовали большую часть возможностей SDK:

* **Объекты, поля и связь** для моделирования данных
* **Функция логики**, представленная как **инструмент ИИ**, **действие workflow** и **маршруты HTTP**
* **Представления, навигация, команда и фронтенд-компонент** для интерфейса
* **Агент и навык** для генерации на естественном языке
* **Метаданные маркетплейса** и процесс публикации

Готовое приложение находится по адресу
[`packages/twenty-apps/examples/document-generator`](https://github.com/twentyhq/twenty/tree/main/packages/twenty-apps/examples/document-generator).
