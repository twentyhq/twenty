## Обзор

В каждом приложении должен быть ровно один вызов `defineApplication`. Он объявляет:

* **Идентификация** — универсальный идентификатор, отображаемое имя, описание.
* **Разрешения** — от имени какой роли выполняются его логические функции и фронтенд-компоненты.
* **Возможности доступа к медиа** *(необязательно)*: доступ к микрофону или камере, запрашиваемый фронтенд-компонентами, утверждается отдельно от ролевых разрешений.
* **Переменные** *(необязательно)* — пары ключ–значение, доступные вашему коду как переменные окружения.
* **Хуки предустановки / постустановки / удаления** *(необязательно)* — см. [Логические функции](/ru/developers/extend/apps/logic/logic-functions).
* **Платёжные данные** *(необязательно)* — `billing.recurring` для автоматически взимаемых платформой платежей за подписку, `billing.operations` для операций, за которые ваше приложение списывает кредиты, и `billing.description` для маркетплейса; см. [Списание кредитов](/ru/developers/extend/apps/logic/credits).

```ts src/application-config.ts
import { defineApplication } from 'twenty-sdk/define';

export default defineApplication({
  universalIdentifier: '39783023-bcac-41e3-b0d2-ff1944d8465d',
  displayName: 'My Twenty App',
  description: 'My first Twenty app',
  applicationVariables: {
    DEFAULT_RECIPIENT_NAME: {
      universalIdentifier: '19e94e59-d4fe-4251-8981-b96d0a9f74de',
      label: 'Default recipient name',
      description: 'Default recipient name for postcards',
      value: 'Jane Doe',
      isSecret: false,
    },
    API_KEY: {
      universalIdentifier: '6b1f5a02-7c4d-4a19-9e63-2f0c8a5d1b47',
      label: 'API key',
      description: 'Key used to reach the postcard provider',
      isSecret: true,
      isRequired: true,
    },
  },
});
```

Заметки:

* Поля `universalIdentifier` — это UUID, которые вы создаёте один раз и которыми владеете. Сохраняйте их неизменными при синхронизации. Собственный `universalIdentifier` приложения должен быть допустимым UUID: сервер отклоняет манифест, идентификатор которого не является UUID. Он уникален в пределах всего экземпляра и привязан к рабочему пространству, которому принадлежит его регистрация, поэтому синхронизировать приложение может только это рабочее пространство — см. [Владение регистрацией](/ru/developers/extend/apps/operations/publishing#registration-ownership).
* `applicationVariables` принимает необязательный параметр `label` — понятное пользователю имя, отображаемое на странице настроек приложения вместо исходного ключа переменной.
* `applicationVariables` становятся переменными окружения для ваших функций и фронтенд-компонентов. В логических функциях (на стороне сервера) они доступны как `process.env.VARIABLE_NAME`. Во фронтенд-компонентах используйте `getApplicationVariable('VARIABLE_NAME')` из `twenty-sdk/front-component`. Переменные, помеченные как `isSecret: true`, внедряются только в логические функции. Фронтенд-компоненты получают только несекретные переменные. Переменная с `scope: 'USER'` хранит значение участника, для которого выполняется код: см. [Переменные рабочей области и пользователя](#workspace-and-user-variables).
* Ваше приложение также может считывать и обновлять значения собственных переменных во время выполнения. Именно так пользовательский компонент настроек сохраняет введённые пользователем данные: см. [Чтение и обновление переменных во время выполнения](/ru/developers/extend/apps/layout/front-components#reading-and-updating-variables-at-runtime). Приложение имеет доступ только к собственным переменным в собственном рабочем пространстве.
* Роль по умолчанию автоматически определяется из файла роли, помеченного с помощью [`defineApplicationRole()`](/ru/developers/extend/apps/config/roles) — вам не нужно ссылаться на неё из `defineApplication()`.
* Функции предустановки, постустановки и удаления, а также проверка работоспособности, обнаруживаются автоматически во время сборки манифеста — вам не нужно указывать их в `defineApplication()`.
* Явная передача `defaultRoleUniversalIdentifier` по-прежнему поддерживается для обратной совместимости, но считается устаревшей и вместо неё рекомендуется использовать `defineApplicationRole()`.
* `serverVariables` — это параметры конфигурации и секреты в области экземпляра (например, ключи API). В отличие от `applicationVariables`, значения для них не указываются в манифесте — оператор рабочего пространства заполняет их в настройках приложения, и они внедряются в логические функции только после того, как будут заданы.
* Приложение может сообщать о собственном состоянии конфигурации с помощью [`defineHealthCheck()`](/ru/developers/extend/apps/logic/logic-functions#health-check) для того, о чём может знать только само приложение, — например, ключ присутствует, но отозван, или сторонняя учётная запись использует неподходящий тарифный план. `isRequired` охватывает то, что Twenty может увидеть самостоятельно; проверка работоспособности охватывает остальное.
* Оба типа переменных принимают `isRequired: true`. Обязательная переменная, которую рабочая область ещё не заполнила, оставляет приложение ненастроенным: на странице его настроек отображается баннер с указанием отсутствующих переменных и кнопкой для перехода на вкладку, где они задаются. Отмечайте как обязательное только то, без чего приложение действительно не может работать — необязательная переменная с разумным значением по умолчанию должна оставаться необязательной.
* Оба типа переменных принимают `isDeprecated: true`. Используйте это, чтобы вывести переменную из обращения вместо её удаления: сохранение объявленного ключа сохраняет хранимое значение (удаление уничтожает значение, введённое пользователем), а переменная по-прежнему внедряется, поэтому код сможет обратиться к ней — `process.env.NEW_API_KEY ?? process.env.API_KEY`. Устаревшая переменная исчезает из настроек приложения, как только у неё больше нет значения, и никогда не учитывается при проверке конфигурации приложения, поэтому `isDeprecated` имеет приоритет над `isRequired`.
* Twenty задаёт эти имена для каждого запуска логической функции, поэтому они зарезервированы: `TWENTY_API_URL`, `TWENTY_APP_ACCESS_TOKEN`, `TWENTY_APP_APPLICATION_ACCESS_TOKEN`, `TWENTY_API_KEY`, `TWENTY_FUNCTIONS_URL` и `APPLICATION_ID`. Манифест, объявляющий любое из них как переменную приложения или сервера, отклоняется при синхронизации или публикации приложения.
* Чтобы добавить собственные элементы в меню настроек приложения (вместо созданной страницы **Variables**), объявите фронтенд-компонент и укажите его в [`defineSettingsMenuItem()`](/ru/developers/extend/apps/layout/front-components#settings-menu-items) в отдельном файле. Объявите столько элементов, сколько необходимо, и упорядочьте их с помощью `position`; `scope` размещает элемент в настройках рабочего пространства или в настройках каждого участника. Системный элемент **Общие** (автообновление, URL приложения, подключения) всегда отображается первым, а URL приложения показывается только если в приложении есть функции, запускаемые по HTTP.

## Запрашиваемые возможности доступа к медиа

Укажите `requestedCapabilities`, когда фронтенд-компонент использует `navigator.mediaDevices.getUserMedia()`. Необязательный массив принимает `'microphone'`, `'camera'` или оба значения. Не указывайте его или используйте пустой массив, если приложению не требуется захват медиа.

```ts
import { defineApplication } from 'twenty-sdk/define';

export default defineApplication({
  universalIdentifier: '39783023-bcac-41e3-b0d2-ff1944d8465d',
  displayName: 'Media recorder',
  description: 'Record audio and video in your workspace',
  requestedCapabilities: ['microphone', 'camera'],
});
```

Заявленные возможности отображаются во время установки. Для утверждения требуется участник рабочего пространства, который может управлять приложениями; оно применяется ко всему рабочему пространству. Эти разрешения отделены от ролевых разрешений приложения и не заменяют разрешения браузера или операционной системы.

Установленное приложение без необходимого разрешения приостанавливает захват и при первом использовании показывает диалог утверждения, включая старые приложения без заявленных возможностей. При отказе захват остаётся заблокированным до запроса разрешений браузера. Обновления пакета не предоставляют дополнительный доступ автоматически. Локально синхронизированные приложения для разработки получают возможности, заявленные в их манифесте.

См. [Захват медиа](/ru/developers/extend/apps/layout/front-components#media-capture) для получения сведений о поведении захвата и индикаторах записи.

## Типы переменных

И `applicationVariables`, и `serverVariables` принимают необязательный `type` (а для `SELECT` / `MULTI_SELECT` — список `options`). Поддерживаемые типы: `TEXT` (по умолчанию), `BOOLEAN`, `NUMBER`, `NUMERIC`, `DATE`, `DATE_TIME`, `SELECT`, `MULTI_SELECT`, `ARRAY`, `RAW_JSON`, `RICH_TEXT`.

```ts src/application-config.ts
import { defineApplication, FieldType } from 'twenty-sdk/define';

export default defineApplication({
  // ...identity, role...
  applicationVariables: {
    MAX_POSTCARDS: {
      universalIdentifier: '5f4497e4-9030-4085-85eb-2c48b8d53713',
      description: 'Maximum postcards per batch',
      type: FieldType.NUMBER,
      value: 10,
    },
    DEFAULT_REGION: {
      universalIdentifier: '76c5c321-b6b6-46eb-b4fc-f9f04bb04227',
      description: 'Default shipping region',
      type: FieldType.SELECT,
      options: [
        { label: 'Europe', value: 'eu' },
        { label: 'United States', value: 'us' },
      ],
      value: 'eu',
    },
  },
});
```

Свойство `type` влияет только на **отображение и валидацию** — оно выбирает соответствующий ввод в UI настроек рабочего пространства (переключатель, числовое поле, раскрывающийся список, выбор даты, JSON‑редактор, …) и позволяет сборке проверить вашу конфигурацию (например, `SELECT` / `MULTI_SELECT` должны объявить непустой список `options`). Оно **не** меняет то, как значение попадает в ваш код.

Значения **всегда внедряются как строки** — это заложено в природу переменных окружения (`process.env.*` содержит только строки). Когда выполняется ваша логическая функция, исполнитель сериализует каждое значение в соответствии с объявленным `type` при построении `process.env`, так что строковый формат остается единым, независимо от того, как было задано значение (значение по умолчанию в манифесте, UI настроек или предыдущая версия):

| Тип                                   | строка в `process.env`                              |
| ------------------------------------- | --------------------------------------------------- |
| `TEXT`, `SELECT`, `DATE`, `DATE_TIME` | непреобразованное значение (`"eu"`, `"2026-01-01"`) |
| `BOOLEAN`                             | `"true"` / `"false"`                                |
| `NUMBER`, `NUMERIC`                   | десятичная строка (`"10"`, `"2.5"`)                 |
| `MULTI_SELECT`, `ARRAY`               | JSON‑массив (`'["email","postcard"]'`)              |
| `RAW_JSON`, `RICH_TEXT`               | JSON‑объект (`'{"retries":3}'`)                     |

Преобразуйте строку обратно в ожидаемый вами тип:

```ts
const maxCards = Number(process.env.MAX_POSTCARDS); // "10" -> 10
const enabled = process.env.ENABLE_TRACKING === 'true'; // "true" -> true
const channels = JSON.parse(process.env.ENABLED_CHANNELS ?? '[]'); // '["email"]' -> ["email"]
const config = JSON.parse(process.env.PROVIDER_CONFIG ?? '{}'); // '{"retries":3}' -> { retries: 3 }
```

Это же относится к фронтенд‑компонентам, читающим значения через `getApplicationVariable('VARIABLE_NAME')` — возвращаемое значение является строкой; при необходимости преобразуйте его.

## Переменные рабочей области и пользователя

У каждой переменной приложения есть `scope`:

* **`WORKSPACE`** (по умолчанию): одно значение для всей рабочей области, заданное участником, который может управлять приложениями.
* **`USER`**: каждый участник хранит собственное значение.

```ts src/application-config.ts
import { defineApplication, FieldType } from 'twenty-sdk/define';

export default defineApplication({
  // ...identity, role...
  applicationVariables: {
    RECORD_MY_MEETINGS: {
      universalIdentifier: '0b6f3c1e-8a2d-4f57-9c1b-7e4d2a9f6c30',
      label: 'Record my meetings',
      type: FieldType.BOOLEAN,
      value: true,
      scope: 'USER',
    },
  },
});
```

`value` пользовательской переменной является её значением по умолчанию: участник, не задавший собственное значение, читает его, а новая версия вашего приложения может его изменить. Секретная переменная не может иметь значения по умолчанию. Без него участник, не задавший собственное значение, читает пустую строку, поэтому ваше приложение определяет, что означает незаданное значение.

Администратор рабочей области не может задать значение для пользовательской переменной: её значения принадлежат каждому участнику.

Область действия переменной задаётся при её создании и не может быть изменена. Чтобы изменить её, объявите переменную с новым `universalIdentifier`: синхронизация удалит старую переменную вместе со значениями её участников и создаст новую.

Пользовательские переменные могут быть `isSecret`, `isRequired` или обоими. Например, для личного ключа API можно объявить `scope: 'USER', isSecret: true, isRequired: true`. Значения шифруются при хранении.

Для пользовательских переменных `isRequired` описывает требование для каждого участника. Участник, для которого не задано значение, собственное или по умолчанию, видит ваше приложение с пометкой **Отсутствует конфигурация** в настройках приложений и баннером с названиями переменных. Это не влияет на предупреждение о конфигурации рабочего пространства, и ничто не обеспечивает это во время выполнения: ваш код по-прежнему определяет, что означает неустановленное значение.

Пользовательская переменная внедряется со значением участника, для которого выполняется ваш код, или со значением по умолчанию, пока он не задаст собственное:

* В логической функции `process.env` содержит значения участника, который инициировал запуск, то есть того же участника, от имени которого действует `TWENTY_APP_ACCESS_TOKEN`. Запуск, за которым никто не стоит, например задание cron или хук установки, вообще не получает пользовательских переменных.
* Во фронтальном компоненте `getApplicationVariable` возвращает значения участника, который его просматривает. Секретные пользовательские переменные исключаются, как и секретные переменные рабочей области.

Участник, который инициировал запуск, не всегда является участником, которого он касается: событие базы данных выполняется от имени того, кто отредактировал запись. Если запуск касается другого участника или всех участников, считывайте значения с помощью `myUserApplicationVariables` через `MetadataApiClient`. Он перечисляет всех участников со значениями пользовательских переменных вашего приложения и работает при каждом запуске логической функции, включая задания cron и вебхуки. Каждая запись содержит `userWorkspaceId`, `workspaceMemberId` и `variables` участника: объявление каждой пользовательской переменной (`label`, `description`, `type`, `options`, `isSecret`, `isRequired`, `isDeprecated`) и значение участника либо значение по умолчанию, пока он не задаст собственное. Запрашивайте его как приложение, чтобы получить фактические значения: с токеном, за которым стоит пользователь, он возвращает только запись этого пользователя с замаскированными секретами.

```ts
import { MetadataApiClient } from 'twenty-client-sdk/metadata';

// In a logic function, for example a cron job
const client = new MetadataApiClient({ runAs: 'application' });

const { myUserApplicationVariables } = await client.query({
  myUserApplicationVariables: {
    workspaceMemberId: true,
    variables: { key: true, value: true },
  },
});
```

Значения являются строками в том же формате, что и `process.env` (см. [Типы переменных](#variable-types)).

`updateMyUserApplicationVariable` сохраняет собственное значение участника. Он получает `applicationUniversalIdentifier` вашего приложения и записывает значение человека, стоящего за токеном: собственный сеанс участника или токен вашего приложения, когда за ним стоит участник, например во фронтенд-компоненте или логической функции, выполняемой для участника. Токен вашего приложения может указывать только ваше собственное приложение, а токен, за которым никто не стоит, например в задании cron или хуке установки, отклоняется. Пустое значение удаляет собственное значение участника, поэтому он снова получает значение по умолчанию или пустую строку для переменной без значения по умолчанию.

Ему не требуется разрешение `APPLICATIONS`, но требуется `CONNECTED_ACCOUNTS`: в роли участника, а также в роли по умолчанию вашего приложения, если она объявлена, когда вызов выполняется токеном вашего приложения. Если ваше приложение сохраняет пользовательские переменные, добавьте `SystemPermissionFlag.CONNECTED_ACCOUNTS` в `permissionFlagUniversalIdentifiers` его [роли](/ru/developers/extend/apps/config/roles).

## Роль функции по умолчанию

Роль, объявленная с помощью [`defineApplicationRole()`](/ru/developers/extend/apps/config/roles), определяет, к чему могут получать доступ логические функции и фронтенд‑компоненты приложения:

* Токены времени выполнения, подставляемые в ваши функции логики, формируются из этой роли. Вызов, выполняемый от имени пользователя, дополнительно ограничен тем, что может делать этот пользователь, поэтому он никогда не может превышать ни один из них. См. [Чей доступ использует вызов](/ru/developers/extend/apps/logic/logic-functions#whose-access-a-call-uses).
* Типизированный клиент API ограничен правами, предоставленными этой роли.
* Следуйте принципу наименьших привилегий: объявляйте только те разрешения, которые действительно нужны вашим функциям.

Когда вы создаёте новое приложение с помощью шаблона, CLI создаёт стартовый файл роли по адресу `src/roles/default-role.ts`. Полную справочную информацию см. в разделе [Роли и разрешения](/ru/developers/extend/apps/config/roles).

## Метаданные маркетплейса

Если вы планируете [опубликовать приложение](/ru/developers/extend/apps/operations/publishing), эти необязательные поля определяют, как оно отображается в маркетплейсе:

| Поле                  | Описание                                                                                                                                                                                                                   |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `author`              | Имя автора или название компании                                                                                                                                                                                           |
| `category`            | Категория приложения для фильтрации в маркетплейсе                                                                                                                                                                         |
| `logo`                | Путь к вашему логотипу приложения в `public/` (например, `public/logo.png`)                                                                                                                                                |
| `galleryImages`       | Массив путей галереи изображений в комплекте `public/` (например, `public/screenshot-1.png`)                                                                                                                               |
| `aboutDescription`    | Расширенное описание в Markdown для вкладки "About". Если опущено, маркетплейс использует `README.md` пакета из npm. Изображения не отображаются, а необработанный HTML показывается как обычный текст                     |
| `billing.description` | Стоимость приложения одной короткой дружелюбной строкой для карточки в маркетплейсе (например, `$0.02 за записанную минуту`). Укажите его, если ваше приложение [списывает кредиты](/ru/developers/extend/apps/logic/credits) |
| `websiteUrl`          | Ссылка на ваш сайт                                                                                                                                                                                                         |
| `termsUrl`            | Ссылка на условия предоставления услуг                                                                                                                                                                                     |
| `emailSupport`        | Адрес электронной почты поддержки                                                                                                                                                                                          |
| `issueReportUrl`      | Ссылка на систему отслеживания проблем                                                                                                                                                                                     |

<Note>
«logoUrl» и «screenshots» являются устаревшими псевдонимами «logo» и «galleryImages». Внешние абсолютные URL-адреса (`http://` или `https://`) не поддерживаются для этих полей: они удаляются с предупреждением на время сборки. Вместо этого объедините изображения в папку `public/` вашего приложения.
</Note>
