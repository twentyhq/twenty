## Обзор

Email-канал предоставляет вашему рабочему пространству общий адрес, например `contact@yourcompany.com`. Почта, отправленная на этот адрес, должна каким-то образом попадать в Twenty. Для этого настройте перенаправление почтового ящика на предоставленный Twenty приватный адрес.

Настройка состоит из двух частей: создайте канал в Twenty, затем укажите его в Microsoft.

## Часть 1. Создание канала в Twenty

1. Перейдите в **Настройки → Коммуникации**.
2. Нажмите **Добавить email-канал**.

<img src="/images/user-guide/emails/inbound-channels/03-twenty-add-email-channel.png" style={{ width: '100%' }} />

3. В поле **Исходный адрес электронной почты** введите общий адрес, на который хотите получать почту, например `contact@yourcompany.com`.
4. В поле **Отображаемое имя** введите имя, которое увидят получатели, например `Twenty Contact`.
5. Нажмите **Сохранить**.

<img src="/images/user-guide/emails/inbound-channels/04-twenty-new-channel-form.png" style={{ width: '100%' }} />

6. Теперь Twenty отображает **Адрес перенаправления**. Он выглядит так: `ch_2cd282d193b5@inbound.twenty.com`. Нажмите **Копировать**.

<img src="/images/user-guide/emails/inbound-channels/05-twenty-forwarding-address.png" style={{ width: '100%' }} />

<Note>
  У каждого канала есть собственный адрес перенаправления. Никогда не направляйте два почтовых ящика на
  один и тот же адрес, иначе их почта будет попадать в одно место.
</Note>

## Часть 2. Создание общего почтового ящика

Пропустите эту часть, если `contact@yourcompany.com` уже существует в Microsoft 365.

1. Откройте [центр администрирования Exchange](https://admin.cloud.microsoft/exchange).
2. Перейдите в **Получатели → Почтовые ящики**.
3. Нажмите **Добавить общий почтовый ящик**.

<img src="/images/user-guide/emails/inbound-channels/01-exchange-add-shared-mailbox.png" style={{ width: '100%' }} />

4. Заполните поле **Отображаемое имя**.
5. Заполните поле **Адрес электронной почты** и выберите домен.
6. Нажмите **Создать**. Почтовый ящик появится в списке через минуту.

<img src="/images/user-guide/emails/inbound-channels/02-exchange-shared-mailbox-form.png" style={{ width: '100%' }} />

## Часть 3. Перенаправление почтового ящика в Twenty

1. В разделе **Получатели → Почтовые ящики** нажмите почтовый ящик, чтобы открыть его.
2. Нажмите **Перенаправление электронной почты**.

<img src="/images/user-guide/emails/inbound-channels/06-exchange-email-forwarding-link.png" style={{ width: '100%' }} />

3. Включите **Пересылать все сообщения, отправленные в этот почтовый ящик**.
4. Выберите **Пересылать на внешний адрес электронной почты** и вставьте адрес перенаправления, скопированный из Twenty.
5. Установите флажок **Доставлять сообщение и на адрес перенаправления, и в почтовый ящик**, чтобы у вашей команды сохранялась копия в Outlook.
6. Нажмите **Сохранить**.

<img src="/images/user-guide/emails/inbound-channels/07-exchange-manage-forwarding.png" style={{ width: '100%' }} />

<img src="/images/user-guide/emails/inbound-channels/08-exchange-forwarding-saved.png" style={{ width: '100%' }} />

По данным Microsoft, применение изменений может занять до 5 минут.

## Часть 4. Разрешение перенаправления на внешние адреса

Этот шаг легко упустить. Без него почта не будет поступать в Twenty.

По умолчанию Microsoft 365 блокирует автоматическое перенаправление на адреса за пределами вашей организации. Почта отклоняется, а исходный отправитель получает сообщение о недоставке со следующим текстом:

```
5.7.520 Access denied, Your organization does not allow external forwarding.
```

Чтобы разрешить это:

1. Откройте [портал Microsoft Defender](https://security.microsoft.com).
2. Перейдите в **Электронная почта и совместная работа → Политики и правила → Политики угроз → Защита от спама**.
3. Откройте свою **Политику защиты от исходящего спама** или создайте новую, применяемую только к общим почтовым ящикам.
4. Нажмите **Изменить параметры защиты**.
5. Установите для **Правила автоматического перенаправления** значение **Вкл. — перенаправление разрешено**.
6. Сохранить.

<Warning>
  Включение этого параметра для всего клиента позволит любой скомпрометированной учетной записи перенаправлять
  почту наружу. Создайте политику, применяемую только к общим почтовым ящикам, которые вы
  подключаете, вместо изменения политики по умолчанию.
</Warning>

## Часть 5. Проверка

Отправьте письмо с внешнего адреса (подойдет личный Gmail) на `contact@yourcompany.com`. Оно должно появиться в Twenty в течение одной-двух минут.

## Устранение неполадок

<Accordion title="Отправители получают сообщение о недоставке 5.7.520">
  Перенаправление на внешние адреса всё ещё заблокировано. Повторите часть 4 и убедитесь, что измененная вами политика
  применяется к этому почтовому ящику.
</Accordion>

<Accordion title="Ничего не приходит и нет сообщения о недоставке">
  Посимвольно сравните адрес перенаправления в Exchange с адресом
  в Twenty. Один неверный символ означает, что почта не будет доставлена
  куда-либо и будет незаметно отброшена.
</Accordion>

<Accordion title="Почта больше не появляется в Outlook">
  Флажок **Доставлять сообщение и на адрес перенаправления, и в почтовый ящик** не был установлен.
  Установите его и сохраните изменения.
</Accordion>

<Accordion title="Канал получает почту, но не может отправлять">
  Получение и отправка — это отдельные процессы. Для отправки ваш домен должен быть
  подтверждён в разделе **Домен отправки** канала, что означает добавление
  записей **Аутентификация домена**, перечисленных там Twenty. См. Каналы
  электронной почты, чтобы узнать, какие
  записи требуются для каждого варианта использования.
</Accordion>

Используете другого провайдера? См. [Google Workspace](/ru/user-guide/calendar-emails/how-tos/forward-a-shared-inbox-from-google-workspace) или [любого другого почтового провайдера](/ru/user-guide/calendar-emails/how-tos/forward-a-shared-inbox-from-any-mail-provider).
