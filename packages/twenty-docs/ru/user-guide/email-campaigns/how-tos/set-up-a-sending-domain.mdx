## Обзор

Кампании отправляются с адреса в вашем домене, например `news@yourcompany.com`. Прежде чем Twenty сможет отправлять сообщения с него, Gmail, Outlook и другие провайдеры должны убедиться, что домен принадлежит вам. Для этого добавьте DNS-записи там, где управляется ваш домен.

Вы создадите адрес в Twenty, добавите DNS-записи, а затем подтвердите их.

Ответить только из общей папки "Входящие", не отправлять кампании? Вы можете пропустить записи отписки. Смотрите [Каналы электронной почты](/ru/user-guide/calendar-emails/capabilities/email-channels).

<Note>
  Записи Twenty используют собственные имена хостов, например
  `twenty-bounce.yourcompany.com` и `links.yourcompany.com`. Они не
  изменяют записи, от которых зависит ваша повседневная электронная почта, поэтому можно использовать основной
  домен. Единственное исключение — DMARC, который применяется ко всему домену.
  Twenty предлагает его, только если у вас его ещё нет.
</Note>

## Перед началом

Перед началом убедитесь, что у вас есть:

* **Доступ к вашему DNS-провайдеру**: компании, в которой вы управляете записями домена, например Cloudflare, GoDaddy или Namecheap. Это не всегда та компания, у которой вы купили домен.
* **Разрешение на настройки рабочего пространства** в Twenty.

## Часть 1: Создание адреса в Twenty

Домен отправки определяется каналом электронной почты. Если вы уже настроили общий входящий ящик в Twenty, домен уже добавлен. Перейдите к части 2.

1. Перейдите в **Настройки → Коммуникации**.
2. Нажмите **Добавить канал электронной почты**.

<img src="/images/user-guide/email-campaigns/channels-list.png" style={{ width: '100%' }} />

3. В поле **Исходный адрес электронной почты** введите адрес, который хотите использовать, например `news@yourcompany.com`. Twenty использует часть после `@` как домен отправки.
4. В поле **Отображаемое имя** введите имя, которое люди видят в своём входящем ящике, например `Acme Newsletter`.
5. Нажмите **Сохранить**.

<img src="/images/user-guide/email-campaigns/new-channel-form.png" style={{ width: '100%' }} />

Twenty открывает канал. Прокрутите до раздела **Домен отправки**. В нём перечислены необходимые DNS-записи, рядом с каждым значением есть кнопка копирования.

<img src="/images/user-guide/email-campaigns/sending-domain-records.png" style={{ width: '100%' }} />

<Note>
  Домен можно подтвердить только в одном рабочем пространстве Twenty. Twenty сообщит вам, если он
  уже используется в другом месте.
</Note>

## Часть 2: Описание записей

| Группа                    | Записи                                                                                                | Что делает                                                                                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Аутентификация домена** | Три записи `CNAME`, заканчивающиеся на `._domainkey`, а также записи `MX` и `TXT` для `twenty-bounce` | Показывает, что Twenty может отправлять сообщения от имени вашего домена (DKIM и SPF). Записи `twenty-bounce` также отправляют отчёты о недоставке обратно в Twenty.   |
| **Политика DMARC**        | Одна запись `TXT` для `_dmarc`                                                                        | Сообщает провайдерам, как обрабатывать письма, не прошедшие проверки. Twenty отображает её, только если у вас нет записи DMARC.                                        |
| **Ссылка для отписки**    | Две записи `CNAME`: для `links` и `_acme-challenge.links`                                             | Размещает страницу отписки и отслеживаемые ссылки в вашем домене, например `links.yourcompany.com`. Вы не сможете отправлять кампании, пока это не будет подтверждено. |

Добавьте все записи, которые показывает Twenty. Gmail, Yahoo и Outlook отклоняют неаутентифицированные массовые рассылки.

<Warning>
  Если в вашем домене уже есть запись DMARC, сохраните её. Не добавляйте ещё одну:
  провайдеры считают две записи DMARC отсутствием записи DMARC.
</Warning>

## Часть 3: Добавление записей у DNS-провайдера

Для каждой записи добавьте новую запись у вашего DNS-провайдера и скопируйте эти значения из Twenty:

* **Тип**: `CNAME`, `MX` или `TXT`.
* **Имя**: иногда называется **Хост**.
* **Значение**: иногда называется **Цель**, **Указывает на**, **Содержимое** или **Ответ**.

Для записи `MX` Twenty указывает приоритет перед значением, например `10 feedback-smtp.eu-central-1.amazonses.com`. У большинства провайдеров есть отдельное поле **Приоритет**. Укажите там `10`, а остальное — в значении.

<Warning>
  Многие провайдеры автоматически добавляют ваш домен в конец **Имени**. Если ваш провайдер
  делает это, вводите только часть перед вашим доменом. Для
  `twenty-bounce.yourcompany.com` введите `twenty-bounce`. Иначе запись
  станет `twenty-bounce.yourcompany.com.yourcompany.com` и не будет подтверждена.
</Warning>

## Часть 4: Подтверждение

Twenty проверяет ваши записи каждый час. Чтобы проверить сейчас, нажмите **Проверить подтверждение** в разделе **Домен отправки**.

Изменения DNS обычно применяются в течение часа, но у некоторых провайдеров это занимает до 48 часов. Статус домена изменится с **Ожидает** на **Подтверждён**, когда Twenty найдёт записи аутентификации. Перед отправкой кампаний **Ссылка для отписки** также должна иметь статус **Подтверждён**.

<img src="/images/user-guide/email-campaigns/sending-domain-verified.png" style={{ width: '100%' }} />

В строке **Политика DMARC** всегда отображается **Не задано**. Это ожидаемо: Twenty предлагает запись, но не проверяет её.

## Устранение неполадок

<Accordion title="Домен остаётся в статусе «Ожидает» в течение нескольких часов">
  Откройте интерфейс DNS-провайдера и сравните каждое **Имя** со значением в Twenty.
  Обычная проблема заключается в том, что провайдер добавил ваш домен второй раз, как
  описано в части 3. Также убедитесь, что вы добавили записи там, где ваш DNS
  действительно размещён. Записи в панели регистратора не работают, если ваши серверы
  имён указывают на другое место.
</Accordion>

<Accordion title="Cloudflare: записи есть, но никогда не подтверждаются">
  Установите для каждой записи `CNAME` параметр **Только DNS**. Когда включено оранжевое облако, Cloudflare
  возвращает собственные серверы вместо значения, предоставленного Twenty.
</Accordion>

<Accordion title="Домен имеет статус «Сбой»">
  Twenty прекращает проверку домена со сбоем. Исправьте записи, затем нажмите **Проверить
  подтверждение**.
</Accordion>

<Accordion title="Домен имеет статус «Временный сбой»">
  Ваш DNS-провайдер не ответил, когда Twenty выполнял проверку. Twenty продолжает проверять
  каждый час, поэтому проблема обычно устраняется сама.
</Accordion>

<Accordion title="Аутентификация подтверждена, но ссылка для отписки остаётся в статусе «Ожидает»">
  Две записи для отписки проверяются отдельно, и это может занять больше времени, поскольку
  Twenty также создаёт для них сертификат безопасности. Убедитесь, что обе записи `CNAME`
  существуют — для `links` и `_acme-challenge.links`, — затем подождите
  до часа.
</Accordion>

<Accordion title="Мой провайдер отклоняет запись MX">
  Укажите `10` в поле **Приоритет**, а в значении — только имя хоста, например
  `feedback-smtp.eu-central-1.amazonses.com`. Не указывайте `10` в значении.
</Accordion>
