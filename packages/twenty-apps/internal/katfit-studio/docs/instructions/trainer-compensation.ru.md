# Оплата тренеров

Реализовано в приложении KATFIT Studio. Настройки и команды появятся в CRM после применения приложения к workspace. Конкретные суммы не зашиты в код и не заполняются примером 1500 ₽.

## Первичная настройка

1. В «Тренеры» создайте тренера, укажите имя и включите «Активен».
2. В «Тарифы тренеров» создайте версию тарифа: название, номер версии от 1, формат «Группа на реформере», четыре суммы за 1, 2, 3 и 4 участников. Все четыре значения обязательны для публикации. Ноль указывается явно.
3. В карточке тарифа запустите «Опубликовать тариф тренера». Команда сохранит опубликованный снимок четырёх ставок и автора публикации.
4. В «Назначения тарифов» свяжите тренера с опубликованным тарифом и задайте период. Начало включается, окончание не включается; пустое окончание означает бессрочное действие. Для одного тренера и формата периоды не должны пересекаться.
5. Для изменения ставок создайте новую версию, опубликуйте её и настройте новое назначение. Старое назначение завершите датой начала нового.

Ставка выбирается по **времени начала занятия**, включая внесённые задним числом занятия. После публикации рабочим источником является поле «Опубликованные условия». Изменение черновых денежных полей не обновляет опубликованные условия: нужна новая карточка версии. Не изменяйте технические поля публикации вручную.

Пока реализован расчёт групп на реформере для 1–4 участников. Для нуля посетивших, персональных занятий и сплитов автоматическое начисление блокируется: ставки и правила для них пока не согласованы.

## Закрытие занятия

1. Проверьте, что занятие закончилось и имеет статус «Проведено».
2. Отметьте окончательные статусы всех записанных. «Записан» оставаться не должно.
3. В карточке занятия выберите «Начислить / исправить оплату тренера».
4. Выберите фактического тренера; при необходимости укажите основание.
5. Нажмите «Проверить расчёт». Проверьте состав, число посетивших, версию тарифа и итог.
6. Нажмите «Подтвердить начисление».

Считаются только записи «Посетил». «Неявка» и «Поздняя отмена» не увеличивают оплату тренеру, даже если посещение списано у клиента. При пакетном посещении команда проверяет наличие завершённого списания.

Группа из четырёх клиентов даёт одну затрату за занятие. При заднем внесении клиентов в одну группу выбирайте общее существующее занятие: команда не разрешает создавать ещё один групповой слот на то же время, если уже найден подходящий слот. Разные реальные параллельные группы создаются явно через календарь, затем выбираются по идентификатору.

Сумма появляется в поле занятия «Оплата тренеру», а в «Начисления тренерам» создаётся операция. Закрытые занятия защищены от последующих команд записи/отмены/внесения посещения; факт посещения исправляется специальной командой.

## Что хранит журнал

- Связи с занятием, тренером и тарифом, ревизию, тип операции, сумму, валюту и состояние.
- Дату занятия, время записи, автора из контекста исполнения, основание и ключ исходного запроса. Для API-ключа без пользователя автор остаётся пустым, выдуманный оператор не подставляется.
- Снимок занятия: название, формат, время, статус, вместимость, тренера.
- Все записи занятия, включая отсутствовавших и отменённых: идентификатор, название, статус, тип, оплату, признак списания, даты создания/внесения/отмены, внешние ключи и сведения об источнике посещения.
- Идентификаторы и имена клиентов, ссылки и названия пакетов, продуктов и пар.
- Связанные с записями операции пакетов: тип, количество посещений/дней, время, основание и ключи.
- Назначение тарифа и его период, опубликованную версию, все четыре ставки, выбранную ступень и список учтённых участников.
- Изменения отметок посещения при исправлении, ссылку на прежнее начисление и контрольный отпечаток подтверждённого расчёта.

Полный снимок доступен в поле «Полный снимок расчёта». Исходные записи не удаляются при исправлении.

## Исправление начисления

Откройте ту же команду в закрытом занятии. Выберите тренера, при необходимости исправьте «Посетил / Неявка / Поздняя отмена» у участников и обязательно укажите причину. Проверьте новый расчёт и подтвердите.

Команда сохраняет сторно прежней суммы и новое начисление следующей ревизии. История остаётся на месте. При смене тренера сторно относится к прежнему тренеру, новое начисление — к фактическому. Исправление отметки присутствия в этой форме **не возвращает клиентское посещение** и не меняет журнал пакета: оно корректирует факт присутствия и оплату тренеру. Возврат посещения оформляется отдельно.

Для нового расчёта используется тариф по дате занятия. Если новый тариф действует только с будущей даты, он не применяется к прошлому занятию. Для исправления исторической ставки сначала настройте соответствующее историческое назначение без пересечений.

## Отчёт за период

В карточке тренера откройте «Рассчитать зарплату за период», выберите даты «с / по» включительно. Границы дней считаются по Москве. Отчёт показывает количество занятий, начисленную сумму и ссылки на начисления.

Исправленное занятие учитывается один раз по последней завершённой ревизии. Незавершённое исправление не обнуляет исходную оплату: отчёт показывает последнюю завершённую сумму с предупреждением, что итог предварительный. Это отчёт о начислениях, а не об остатке к выплате; фактические выплаты пока не учитываются.

Представления: «Начисления тренерам», «Незавершённые начисления» и «Проведены — не закрыты». В техническом журнале не суммируйте строки незавершённой коррекции вручную: для итогов используйте отчёт тренера.

## Сбой и повтор

Повтор подтверждения не создаёт второй расход. При незавершённой операции повторное открытие команды загружает сохранённый расчёт и предлагает «Завершить начисление». При восстановлении используется исходный тарифный снимок, а не изменившиеся ставки.

Все защищённые команды состава и закрытие используют общий CAS-протокол `ClassSession.mutationLock`; зарплатные команды дополнительно используют уникальную запись `StudioSessionLock`. Одновременная команда получает сообщение «С занятием уже выполняется операция». Повторите после завершения первой.

При принудительном завершении функции блокировка может остаться. Она намеренно не истекает автоматически: медленно работающая функция не должна потерять защиту и изменить закрытое занятие. При неподтверждённой мутации (503) сохраняются обе блокировки. Администратор сначала подтверждает завершение всех исходных запросов и сверяет журнал; затем освобождает только CAS своего владельца по точному токену и техническую запись `StudioSessionLock`, после чего повторяет исходное закрытие. Нельзя освобождать блокировку только по истечению времени. Начисления и снимки не удаляются.

Если состав или другие проверяемые сведения изменились вне команды, начисление остаётся незавершённым с ошибкой проверки. Нельзя подтверждать его изменением технических полей: администратор сначала разбирает исходный снимок и состояние данных.

## Доступ и выпуск

Схема, функции, индексы, формы и права служебной роли находятся только в приложении. Ядро Twenty не изменяется. Служебная роль получает право физически удалять только технические блокировки; право удаления финансовых записей не добавляется.

Перед рабочим использованием настройте роли workspace: обычные операторы не должны напрямую редактировать журнал начислений, опубликованные снимки, блокировки, сумму/дату закрытия занятия или закрытые посещения. Администраторам доступны технические записи, поэтому прямой CRUD администратора способен обойти командные ограничения. Права пользователей workspace и назначение ролей приложение автоматически не меняет.

Все HTTP-команды требуют аутентификации. Разделение допуска между администратором тарифов и оператором закрытия на уровне HTTP в этой версии отдельно не реализовано: используйте доступ доверенных сотрудников. Публикацию тарифа и изменение назначений поручайте администратору.

Перед применением на stage просмотрите app plan, проверьте уникальные индексы блокировок и операций, права удаления блокировок и реальные GraphQL-связи. Затем выполните живой сценарий закрытия, повтор, исправление, отчёт и регрессию списаний/записей. Локальные проверки не заменяют эту проверку workspace. Старые занятия автоматически не начисляются.


## Каталог и закрепление тренера

В навигации приложения добавлены отдельные разделы «Тренеры», «Тарифы тренеров», «Назначения тарифов» и «Начисления тренерам». В карточке тренера есть вкладки с его тренировками, начислениями и назначениями тарифов. Неактивные тренеры сохраняют историю и отчёт за период, но не предлагаются для новых назначений.

На одном занятии закрепляется один тренер. Его можно выбрать при создании тренировки в календаре, изменить в форме редактирования или назначить из карточки занятия командой «Назначить тренера». Имя видно в расписании и списке занятий. Черновой слот можно оставить без тренера; перед начислением тренер обязателен.

API создания занятия принимает необязательный `trainerId`. API начисления при отсутствии `trainerId` использует закреплённого за занятием тренера. Команда назначения `/studio/sessions/assign-trainer` сохраняет прежнего и нового тренера, автора и ключ запроса в журнале событий; незавершённое назначение блокирует начисление до восстановления операции. После начисления тренер меняется через исправление со сторно.

Зарплата за период складывается из завершённых начислений, связанных с этим тренером, с учётом исправлений. Назначение другого тренера на будущую тренировку не переносит уже начисленную зарплату. Фактические выплаты остаются отдельным контуром.
